# 주간 파이프라인 리뷰 운영 가이드
<!--meta: doc=FCT-03; doc_type=revops; tier=1; topic=SALES; disclosure=internal; status=active-->

## 주간 리뷰의 목적과 다루지 않는 것
<!--meta: sec=s1; dept=SALES; level=주니어|시니어; ct_band=하; related=s2-->
주간 파이프라인 리뷰의 목적은 다음 한 주에 실제로 움직일 딜을 선정하고, 진행을 막는 장애물을 제거하는 것입니다. 참석자는 현황을 설명하는 데 그치지 않고 `전환 대상 선정 → 장애 확인 → 책임자 지정 → 완료기한 확정`까지 마쳐야 합니다.

리뷰의 기본 단위는 고객사가 아니라 CRM 기회 레코드입니다. 단계 정의와 전환 기준은 FCT-01을 적용하며, 회의에서는 정의를 다시 해석하지 않고 해당 기회가 다음 단계로 이동하기 위해 필요한 행동만 결정합니다.

**리뷰에서 반드시 만드는 결과**

| 결과 | 판정 기준 | 기록 형태 |
| --- | --- | --- |
| 이번 주 전환 대상 | 7일 안에 다음 단계 진입을 시도할 기회 | 목표 단계와 전환 예정일 |
| 장애 제거 과제 | 내부 승인·자료·인력·고객 응답 중 진행을 막는 사항 | 과제 담당자와 완료기한 |
| 정체 딜 처분 | 계속 추진·보류·실패 처리 중 하나를 결정할 기회 | 처분 결정과 근거 |
| 신규 발굴 행동 | 파이프라인 보완을 위해 이번 주 실행할 활동 | 대상·행동·완료일 |
| 관리자의 지원 | 담당자 권한만으로 해결할 수 없는 사항 | 지원 책임자와 회신기한 |

회의 종료 시 각 검토 딜에는 다음 액션이 1개 이상 있어야 합니다. 다음 액션 없이 “계속 접촉”, “추후 확인”으로 끝난 건은 리뷰를 완료한 것으로 보지 않습니다.

**다루지 않는 주제**

| 제외 주제 | 제외 이유 | 처리 경로 |
| --- | --- | --- |
| 개인·지점 실적 질책 | 방어적 보고를 유발해 위험 신호가 늦게 공개됩니다. | 별도 성과관리 면담 |
| 제품·서비스 교육 | 참석자 전체의 의사결정 시간이 교육 시간으로 대체됩니다. | 별도 교육 세션 |
| 중장기 영업 전략 | 7일 이내 실행할 딜 행동과 시간축이 다릅니다. | 분기·연간 전략회의 |
| 개별 고객 기술 토론 | 한 건의 상세 설계가 나머지 기회 검토를 잠식합니다. | DSC-xx 참조 |

제외 주제가 섞이면 담당자는 문제를 조기에 공개하기보다 완성된 설명을 준비하게 됩니다. 그 결과 정체 딜이 숨겨지고, 검토 가능한 딜 수가 줄며, 책임자와 기한이 없는 토론만 남습니다.

**운영자의 중단 기준**

- 한 주제가 5분을 넘고 파이프라인 행동 결정이 나오지 않으면 별도 회의로 전환합니다.
- 교육·평가·기술 설계가 시작되면 주제 소유자와 후속 일정만 정하고 종료합니다.
- 고객 비난이나 담당자 평가 발언은 즉시 중단하고 사실·다음 행동·기한으로 질문을 바꿉니다.

## 운영 주기·시간·참석자
<!--meta: sec=s2; dept=SALES; level=주니어; ct_band=중; related=s1|s3-->
서울·경기·인천 각 지점은 매주 지점 단위 리뷰를 운영합니다. 정기 일정은 고객 미팅보다 우선해 캘린더에 반복 등록하며, 공휴일이 있으면 해당 주의 다음 영업일 같은 시간으로 이동합니다.

전사 리뷰는 월 1회 실시합니다. 지점 주간 리뷰를 대체하지 않으며, 같은 기회를 중복 설명하지 않도록 전사 검토 대상으로 지정된 건만 다룹니다.

**운영 일정**

| 회의 | 주기·시각 | 기본 길이 | 필수 참석자 |
| --- | --- | --- | --- |
| 서울 지점 리뷰 | 매주 화요일 09:30 | 60분 | SALES 지점 부장 또는 대행자, 기회 소유자, RevOps 운영자 |
| 경기 지점 리뷰 | 매주 화요일 14:00 | 60분 | SALES 지점 부장 또는 대행자, 기회 소유자, RevOps 운영자 |
| 인천 지점 리뷰 | 매주 수요일 09:30 | 60분 | SALES 지점 부장 또는 대행자, 기회 소유자, RevOps 운영자 |
| 전사 월간 리뷰 | 매월 첫째 수요일 14:00 | 90분 | SALES 부장, 3개 지점 책임자, RevOps 운영자 |

기회 소유자가 휴가·외근으로 불참하면 CRM에 대리 발표자를 회의 전 영업일 18:00까지 지정합니다. 대리 발표자가 없으면 해당 건은 의사결정 불가로 표시하고, 지점 책임자가 당일 17:00까지 임시 소유자를 지정합니다.

**참석 구분**

| 구분 | 대상 | 참석 범위 |
| --- | --- | --- |
| 필수 | 회의 운영자, 지점 책임자, 검토 대상 기회 소유자 | 전체 회의 |
| 조건부 필수 | 공동 영업 담당자, 승인 요청의 책임자 | 관련 블록 |
| 선택 | CNS·AIAX·BE·DATA 실무자 | 사전 초대된 딜 블록만 참석 |
| 참관 | 신규 SALES 입사자 또는 전입자 | 발언권 없이 최대 2회 |

기술 인력을 상태 공유 목적으로 상시 참석시키지 않습니다. 기술 검토가 필요한 딜의 초대와 처리 방식은 이 문서 s9 및 DSC-xx를 따릅니다.

**시간별 검토 딜 상한**

| 회의 길이 | 전체 검토 상한 | 심층 점검 상한 |
| --- | ---: | ---: |
| 60분 | 12건 | 4건 |
| 75분 | 15건 | 5건 |
| 90분 | 18건 | 6건 |

검토 대상이 상한을 넘으면 회의를 연장하지 않습니다. 운영자는 전환 예정일, 정체 여부, 금액 영향도를 기준으로 상한까지 선별하고 나머지는 다음 회차 또는 별도 30분 세션으로 분리합니다.

## 리뷰 전 준비 — 데이터 마감과 사전 점검
<!--meta: sec=s3; dept=SALES; level=주니어|시니어; ct_band=중; related=s2|s4|FCT-05#s1-->
CRM 데이터는 리뷰 전 영업일 18:00에 마감합니다. 동일한 시점의 스냅샷을 사용해야 단계·금액·종료예정일을 놓고 참석자마다 다른 화면을 보는 일을 막을 수 있으며, 운영자가 회의 전에 예외 건을 선별할 시간도 확보할 수 있습니다.

입력 규칙과 필드별 작성 방법은 FCT-05를 따릅니다. 이 섹션에서는 리뷰용 데이터 마감과 예외 추출만 규정하며, 회의 중에는 입력 규칙을 교육하거나 필드 정의를 다시 논의하지 않습니다.

**마감 절차**

| 시점 | 작업 | 담당 | 산출물 |
| --- | --- | --- | --- |
| D-1 15:00 | 1차 오류 목록 자동 배포 | RevOps 운영자 | 담당자별 수정 목록 |
| D-1 17:30 | 오류 수정 및 누락 근거 보완 | 기회 소유자 | 수정 완료 레코드 |
| D-1 18:00 | CRM 데이터 마감 | RevOps 운영자 | 리뷰 기준 스냅샷 |
| D-1 18:10~19:10 | 최종 점검과 검토 딜 선별 | RevOps 운영자 | 예외 목록·아젠다 |
| D일 08:30 | 자료와 예외 목록 배포 | RevOps 운영자 | 읽기 전용 리뷰 자료 |

운영자는 최종 점검에 최대 60분을 배정합니다. 자동 검증 결과만 사용하지 않고, 정체 딜과 담당자 연락처 검증 상태처럼 규칙이 놓칠 수 있는 항목을 다시 확인합니다.

**사전 점검 목록**

| 점검 항목 | 오류 판정 | 리뷰 표시 |
| --- | --- | --- |
| 필수 필드 | 하나 이상 공백 또는 허용값 외 입력 | `필수값 누락` |
| 종료예정일 | 마감일 기준 과거 날짜인 열린 기회 | `종료일 경과` |
| 다음 액션 | 공백이거나 실행일·행동이 식별되지 않음 | `액션 없음` |
| 정체 딜 | FCT-01의 단계 체류일 기준 초과 | `정체` |
| 소유자·상태 | 소유자 없음 또는 상태와 단계가 불일치 | `소유권/상태 오류` |
| 담당자 연락처 | 최근 검증 여부가 미입력 또는 만료 | `연락처 미검증` |

점검 결과는 CRM 값을 회의 화면에서 고치는 용도로 사용하지 않습니다. 회의 중 수정하면 검토 시간이 소모되고, 마감 스냅샷과 실제 레코드 간 차이가 생겨 결정 근거를 추적할 수 없기 때문입니다.

오류가 있는 딜도 사업상 판단이 필요하면 검토할 수 있지만, 화면에는 오류 표식을 유지합니다. 수정 책임자와 당일 17:00 기한을 액션으로 등록하며, 포캐스트 변경 반영은 이 문서 s11을 따릅니다.

## 표준 아젠다와 시간 배분
<!--meta: sec=s4; dept=SALES; level=주니어|시니어; ct_band=중; related=s3|s5-->
표준 아젠다는 숫자 확인으로 시작해 실행 액션 확정으로 끝냅니다. 진행자는 블록별 종료 시각을 화면에 표시하고, 시간이 끝나면 미결 쟁점을 별도 액션으로 전환합니다.

90분 회의는 최대 18건을 전제로 합니다. 60분 회의에서는 아래 블록을 같은 순서로 유지하되 `10분 → 25분 → 12분 → 5분 → 8분`으로 축소합니다.

**90분 표준 아젠다**

| 시간 | 블록 | 목적 | 필수 산출 |
| --- | --- | --- | --- |
| 00:00~00:10 | 숫자 확인 | CRM 스냅샷과 회의 기준값 일치 확인 | 데이터 이슈 목록 |
| 00:10~00:45 | 이번 주 전환 대상 | 7일 안에 움직일 기회 선정 | 목표 단계·행동·예정일 |
| 00:45~01:05 | 정체·위험 딜 | 장애와 처분 필요 건 결정 | 제거 과제 또는 처분 결정 |
| 01:05~01:15 | 신규 발굴 | 단기 파이프라인 보완 행동 지정 | 대상·담당·완료일 |
| 01:15~01:30 | 액션 확정 | 결정사항의 책임과 기한 검증 | 최종 액션 로그 |

숫자 확인에서는 활성 기회 건수·금액, Commit·Best Case 금액, 단계 이동 건수, 정체 딜 수만 확인합니다. 포캐스트 범주와 계산 규칙은 FCT-02, 목표와 커버리지는 FCT-06을 참조합니다.

**블록별 진행 규칙**

1. 숫자 확인은 대시보드를 읽는 시간이 아니라 불일치만 찾는 시간으로 운영합니다.
2. 전환 대상은 딜별로 목표 행동, 고객 측 상대방, 실행일을 확정합니다.
3. 정체·위험 딜은 장애 제거가 가능한지 먼저 판단하고, 설명만 반복하는 건은 처분 결정을 요청합니다.
4. 신규 발굴 블록에서는 장기 캠페인을 설계하지 않고 이번 주 실행할 접촉 행동만 지정합니다.
5. 액션 확정에서는 담당자 1명과 날짜 1개가 없는 항목을 승인하지 않습니다.

숫자 리뷰를 10분보다 길게 운영하면 데이터 검증과 성과 해석이 회의의 중심이 되어 실제 딜 결정 시간이 줄어듭니다. 숫자 오류는 원인 조사 담당과 완료기한만 정하고, 계산·수정은 회의 후 처리합니다.

진행자는 종료 5분 전 신규 토론을 받지 않습니다. 마지막 블록이 생략되면 결정사항이 실행 항목으로 전환되지 않으므로, 앞 블록이 지연되더라도 액션 확정 15분은 줄이지 않습니다.

## 딜 인스펙션 질문 세트
<!--meta: sec=s5; dept=SALES; level=시니어; ct_band=상; related=s4|s6-->
**15분 인스펙션 운영 원칙**
딜 인스펙션은 담당자의 낙관적 설명이 아니라 고객이 실제로 한 행동과 확인 가능한 증거를 검증합니다. 답변에는 고객 발언일, 회의 기록, 이메일, 일정 초대, 문서 링크 중 하나가 포함되어야 합니다.
진행자는 15분이 끝나면 `검증됨 / 추가 확인 필요 / 핵심 가정 붕괴` 중 하나로 판정합니다. 단계 변경이 필요하면 FCT-01, 포캐스트 범주 변경이 필요하면 FCT-02를 적용합니다.

**시간대별 질문 묶음**
| 시간 | 검증 영역 | 필수 질문 | 인정하는 증거 |
| --- | --- | --- | --- |
| 0~2분 | 현황 | 고객이 해결하려는 문제와 현재 단계의 핵심 근거는 무엇입니까? | 최근 14일 이내 고객 발언 또는 활동 기록 |
| 2~5분 | 의사결정 구조 | 최종 승인자, 실무 평가자, 예산 통제자, 반대 가능자는 누구입니까? 누가 빠져 있습니까? | 역할별 성명·직책, 승인 절차 또는 회의 참석 이력 |
| 5~7분 | 왜 지금인가 | 고객이 이번 기간에 결정해야 하는 사건과 미룰 때 발생하는 손실은 무엇입니까? | 예산 만료일, 오픈 목표일, 규제·조직 일정 등 날짜 |
| 7~9분 | 대안 | 경쟁사, 내부 개발, 현행 유지, 일정 연기 중 고객이 비교하는 대안은 무엇입니까? | 비교 요청, 평가표, 경쟁사 언급 또는 무결정 가능성 |
| 9~12분 | 다음 약속 | 다음 고객 접점은 누구와 언제 무엇을 결정하기 위한 약속입니까? | 확정된 일시·참석자·목적이 있는 일정 또는 회신 |
| 12~15분 | 비통제 변수 | 조달, 법무, 보안, 데이터 제공, 경영진 교체 등 우리가 통제할 수 없는 변수는 무엇입니까? | 변수별 고객 책임자, 해소 예정일, 우회안 |

**의사결정 구조 확인 순서**
의사결정권자를 직급만으로 추정하지 않습니다. 담당자에게 아래 질문을 순서대로 묻고, 동일 인물이 여러 역할을 겸하면 각 권한을 별도로 확인합니다.
1. “제안 내용을 실제로 평가하고 탈락시킬 수 있는 사람은 누구입니까?”
2. “예산 사용을 승인하거나 중단할 수 있는 사람은 누구입니까?”
3. “계약·보안·구매 절차에서 거부권을 가진 부서는 어디입니까?”
4. “우리 편에서 내부 설득을 수행하는 고객 측 인물은 누구이며, 최근 수행한 행동은 무엇입니까?”
5. “최종 회의 전에 반드시 동의를 받아야 하지만 아직 만나지 못한 사람은 누구입니까?”

**‘아마도’ 답변의 후속 질문**
“아마도”, “긍정적입니다”, “문제없을 것 같습니다”는 미확인 답변으로 처리합니다. 진행자는 의견을 더 요구하지 않고 확인 가능한 사건·인물·날짜로 질문을 좁힙니다.
| 모호한 답변 | 즉시 이어서 물을 질문 | 확인 기한 |
| --- | --- | --- |
| “아마 이번 달에 결정합니다.” | “고객이 말한 결정일은 며칠이며, 그날 열리는 승인 절차는 무엇입니까?” | 2영업일 |
| “임원이 긍정적입니다.” | “임원이 직접 한 말과 날짜는 무엇이며, 다음 행동을 약속했습니까?” | 2영업일 |
| “예산은 있을 겁니다.” | “예산 코드, 보유 부서, 승인자 중 확인된 항목은 무엇입니까?” | 3영업일 |
| “경쟁사는 약합니다.” | “고객의 평가 기준에서 경쟁사가 앞서는 항목은 무엇입니까?” | 다음 고객 접점 |
| “일정은 문제없습니다.” | “조달·법무·보안 각각의 소요일과 시작일을 확인했습니까?” | 3영업일 |
확인 기한까지 증거가 없으면 해당 가정을 미검증으로 표시하고, 그 가정에 의존한 종료예정일과 포캐스트 범주를 재검토합니다.
인스펙션 마지막 30초에는 담당자·완료일·고객 측 확인 대상을 포함한 후속 액션 하나를 확정합니다.

## 정체 딜 처리 절차
<!--meta: sec=s6; dept=SALES; level=시니어; ct_band=상; related=s5|s7|FCT-01#s1-->
**적용 원칙**
정체 판정은 FCT-01의 단계 체류일 기준을 사용합니다. 리뷰에서는 정체 원인을 장시간 설명하지 않고 `재가동 / 보류 / 실패 / 담당 변경` 중 하나를 반드시 선택합니다.
정체 딜은 회의 종료 시 결론과 처리 기한이 모두 있어야 합니다. “조금 더 기다림”, “다음 주 재논의”, “고객 반응 확인”처럼 담당자·날짜·완료 조건이 없는 문구는 결론으로 인정하지 않습니다.

**처리 절차**
`정체 목록 확인 → 최근 고객 행동 검증 → 잔존 기회 판단 → 네 가지 결론 선택 → 소유자·기한 지정 → CRM 반영 확인` 순서로 처리합니다.
1. 담당자는 최근 고객 접점, 미응답 횟수, 미해결 차단 요인, 마지막으로 확인된 구매 의사를 90초 안에 보고합니다.
2. 리뷰 리더는 고객이 실제로 추진 중인지, 단순 관심만 남았는지, 기존 담당자가 접근 가능한지를 판정합니다.
3. 결론이 정해지면 RevOps 담당이 회의 중 액션 기록을 생성하고 처리 완료 시점을 지정합니다.
4. 담당자는 기한 내 결과와 증거 링크를 등록하며, RevOps 담당은 다음 리뷰 전에 미완료 건을 별도 표시합니다.

**네 가지 결론의 판정 기준**
| 결론 | 선택 조건 | 필수 조치 | 처리 기한 |
| --- | --- | --- | --- |
| 구체적 액션으로 재가동 | 고객 문제와 추진 의사가 남아 있고, 접촉 가능한 이해관계자와 다음 행동을 특정할 수 있음 | 고객 회의·자료 검토·승인자 연결 중 하나를 확정 | 5영업일 이내 |
| 보류 전환 | 예산 동결, 조직 개편, 선행 사업 지연처럼 재개 사건과 예상 시점이 있으나 현재 활동이 불가능함 | 재개 조건, 재확인일, 고객 측 확인자를 기록 | 당일 전환, 재확인일은 90일 이내 |
| 실패 처리 | 고객이 중단·타사 선정·내부 수행을 통보했거나, 3개 채널로 4회 이상 접촉 후 20영업일 동안 반응이 없음 | 실패 확정 및 사유 코드 입력 | 1영업일 이내 |
| 담당 변경 | 관계 단절, 산업 전문성 부족, 지역 이관 또는 10영업일 이상 담당 수행 불가가 확인됨 | 신규 담당자 지정과 인수인계 일정 확정 | 지정 1영업일, 인계 3영업일 이내 |

보류·실패의 CRM 처리 기준과 단계 역행 규칙은 FCT-01을 적용합니다. 담당 변경에 따른 레코드 이관 방식은 FCT-05를 적용합니다.
재가동 액션은 “연락하기”가 아니라 `누가 / 누구에게 / 언제까지 / 무엇을 요청하여 / 어떤 결과를 얻을지`가 모두 기록되어야 유효합니다.

**무결론 이월 차단 장치**
| 통제 장치 | 발동 조건 | 책임자 | 조치 |
| --- | --- | --- | --- |
| 회의 중 결정 잠금 | 네 가지 결론이 선택되지 않음 | 리뷰 리더 | 다음 딜로 넘어가지 않고 최대 2분 내 판정 |
| 당일 미반영 경보 | 회의일 18시까지 CRM 상태가 미변경 | RevOps 담당 | 담당자와 영업 관리자에게 자동 알림 |
| 2회 연속 미완료 | 동일 재가동 액션이 2주 연속 미완료 | 지점 SALES 과장 이상 | 보류·실패·담당 변경 중 재판정 |
| 3회 반복 정체 | 동일 담당자의 딜 3건 이상이 월내 재정체 | 지점 SALES 부장 | 원인 점검 및 액션 승인권 상향 |
리뷰 리더가 판단에 필요한 정보가 부족하다고 보더라도 임시 결론은 지정해야 합니다. 이 경우 기본값은 재가동이 아니라 보류이며, 3영업일 이내 추가 증거를 확보하면 다시 활성화합니다.
예외적으로 고객의 공식 발표나 조달 결과가 5영업일 이내 예정된 경우에만 단기 대기를 허용하며, 발표일 다음 영업일까지 결론을 갱신합니다.

## 상위 딜 집중 점검 기준
<!--meta: sec=s7; dept=SALES; level=시니어; ct_band=상; related=s6|s8-->
**매주 필수 점검 대상**
집중 점검 대상은 금액이 크다는 이유만으로 선정하지 않습니다. 금액 노출, 분기 마감 영향, 전략적 중요도, 경쟁 압력을 각각 평가하고 하나라도 기준을 충족하면 매주 점검합니다.
대상 목록은 중복을 제거하되 제외하지 않습니다. 한 딜이 여러 기준을 충족하면 그 사유를 모두 표시하여 자원 투입 우선순위 판단에 사용합니다.

| 선정 유형 | 필수 포함 기준 | 점검에서 확인할 핵심 |
| --- | --- | --- |
| 금액 상위 | 지점별 열린 기회 금액 상위 5건 또는 상위 20%에 해당하는 건 | 금액 근거, 범위 변동 가능성, 단일 딜 의존도 |
| 분기 마감 영향 | 당분기 종료예정이며 미수주 시 지점 목표 달성률이 5%p 이상 하락하는 건 | 고객 결정일, 계약 선행 절차, 일정 미끄러짐 |
| 커버리지 영향 | 해당 딜 제외 시 목표 대비 파이프라인 커버리지가 3배 미만이 되는 건 | 대체 가능 기회, 종료예정일 신뢰도 |
| 전략 고객 | 전사 지정 전략 업종·고객군의 신규 진입 또는 확장 건 | 레퍼런스 가치, 관계 지도, 지점 간 이해관계 |
| 경쟁 상황 | 경쟁사·내부 개발·무결정 대안이 실제 평가 중인 건 | 평가 기준, 우열 근거, 경쟁 대응 마감일 |

커버리지 산정 기준은 FCT-06을 적용합니다. 포캐스트 범주와 수주 확률은 FCT-02의 값을 사용하며, 집중 점검 회의에서 임의 확률을 만들지 않습니다.
선정 목록은 리뷰 전 영업일 15시 기준으로 고정합니다. 이후 새로 발생한 중대 경쟁 정보나 고객의 결정일 변경만 당일 추가를 허용합니다.

**상위 딜 점검 양식**
| 항목 | 기록 기준 | 미충족 시 조치 |
| --- | --- | --- |
| 고객 과제와 기한 | 고객이 해결하려는 과제 1문장과 결정 필요일 | 필요일을 고객에게 재확인 |
| 의사결정 구조 | 승인자·평가자·예산 통제자·내부 지지자 | 누락 역할 접촉 계획 수립 |
| 상업 조건 | 예상 계약금액, 범위, 주요 협상 쟁점 | PRP-xx 기준에 따라 담당 지정 |
| 경쟁 구도 | 대안별 강점, 고객 평가 기준, 현재 우열 | 비교 근거 확보일 지정 |
| 다음 고객 약속 | 확정 일시, 참석자, 결정할 항목 | 2영업일 내 일정 확정 시도 |
| 비통제 변수 | 조달·법무·보안·데이터·조직 변수 | 변수 소유자와 해소 예정일 기록 |
| 내부 지원 요청 | 필요한 부서, 산출물, 투입시간, 마감일 | 승인자 또는 수행자를 회의 중 지정 |

상위 딜의 상태는 `정상 / 주의 / 위험`으로 표시합니다. 고객 증거가 있고 다음 약속이 확정되면 정상, 핵심 가정 하나가 미검증이면 주의, 결정일·예산·승인자 중 하나가 붕괴하면 위험으로 판정합니다.
위험 판정 건은 같은 회의에서 복구 액션 또는 종료예정일 재검토를 지정하며, 낙관적 구두 설명만으로 정상 등급을 유지하지 않습니다.

**상위 딜 편중 방지**
상위 딜 집중 점검은 초기 단계의 작은 기회를 방치할 위험이 있습니다. 이를 막기 위해 지점별로 상위 목록 밖의 열린 기회 3건을 매주 무작위 추출하며, 담당자와 단계가 전주 표본과 겹치지 않게 합니다.
또한 전체 열린 기회는 매주 소유자, 상태, 다음 액션, 고객 담당자 연락처의 최근 검증 여부를 확인합니다. 필드 정의와 검증 방식은 FCT-05를 적용합니다.
무작위 표본에서 동일 결함이 2건 이상 발견되면 해당 결함을 지점 전체 점검 항목으로 전환합니다. 상위 딜 수주만으로 일반 파이프라인의 누락이나 장기 약화를 상쇄하여 보고해서는 안 됩니다.

## 지점별 리뷰와 전사 리뷰의 역할 분담
<!--meta: sec=s8; dept=SALES; level=시니어; ct_band=중; related=s7|s9-->
**리뷰 단위별 책임**
지점 리뷰는 서울·경기·인천 각 지점이 보유한 개별 딜의 진척과 실행을 결정합니다. 고객 접점, 다음 액션, 정체 처리, 상위 딜 위험, 담당자 수행 여부는 지점에서 종결하는 것을 원칙으로 합니다.
전사 리뷰는 개별 딜 설명을 반복하지 않습니다. 여러 지점에서 나타나는 전환 저하·패배 패턴을 식별하고, CNS·AIAX·BE·DATA 인력의 지점 간 배분과 전사 승인 안건을 결정합니다.

| 구분 | 지점별 리뷰 | 전사 리뷰 |
| --- | --- | --- |
| 기본 분석 단위 | 개별 기회와 담당자 액션 | 지점 간 패턴, 포트폴리오, 자원 충돌 |
| 주요 참석 | 지점 SALES, 필요 시 해당 지점 수행팀 | 전사 SALES 책임자, RevOps, 관련 부서 책임자 |
| 결정 권한 | 접촉 계획, 정체 결론, 담당 변경 제안 | 지점 간 우선순위, 공용 인력 배정, 전사 에스컬레이션 |
| 입력 자료 | CRM 기회 레코드와 고객 증거 | 지점 요약표, 예외 안건서, 비교 지표 |
| 산출물 | 딜별 액션·담당·기한 | 자원 배정 결정, 승인 경로, 전사 개선 과제 |

지점 리뷰는 모든 열린 기회를 주간 점검 범위에 포함하고, 집중 인스펙션 대상만 상세 검토합니다. 지점장은 사실관계와 고객 증거가 확인되지 않은 안건을 전사 리뷰로 넘기지 않습니다.
전사 리뷰 운영자는 안건을 `결정 요청 / 자원 요청 / 반복 패턴`으로 구분합니다. 단순 현황 공유는 서면 보고로 대체하며 회의 안건으로 채택하지 않습니다.

**전사 리뷰 상정 기준**
| 안건 유형 | 상정 임계값 | 필수 제출 내용 | 전사 결정 |
| --- | --- | --- | --- |
| 지점 간 자원 요청 | 타 지점 또는 2개 이상 수행팀에서 총 40시간 이상, 또는 2주 이상 투입 필요 | 요청 역할, 예상 시간, 시작일, 미지원 영향 | 투입 지점·부서·기간·우선순위 |
| 자원 충돌 | 같은 기간 동일 전문인력에 2건 이상 요청이 중복 | 딜별 금액, 고객 마감일, 대체 인력 가능성 | 배정 순서 또는 외부 조달 검토 |
| 승인 필요 할인 | 지점 권한을 초과하는 할인 또는 예외 상업 조건 | 기준가, 요청가, 할인 사유, 교환 조건 | 승인자 지정 또는 반려 |
| 반복 패배 원인 | 동일 실패 사유가 최근 8주 내 3건 이상이거나 2개 지점에서 반복 | 해당 딜 목록, 손실 단계, 고객 근거 | 전사 개선 과제와 소유 부서 |
| 전략 고객 충돌 | 둘 이상의 지점이 같은 고객군·계열 접점을 보유 | 접촉 이력, 관계자, 제안 범위 | 대표 지점과 단일 연락 창구 지정 |

할인 한도와 가격·계약 승인 규칙은 PRP-xx를 적용합니다. 지점 간 기회 귀속은 FCT-01을 적용합니다.
상정 안건서는 전사 리뷰 전 영업일 12시까지 제출합니다. 필수 제출 내용이 빠지면 의사결정 안건에서 제외하고 보완 기한을 1영업일로 지정합니다.

**중복 논의 방지와 결정 이행**
전사 리뷰에서는 지점 리뷰에서 확정한 딜 액션을 다시 승인하지 않습니다. 다만 전사 자원 배정, 권한 초과 승인, 다른 지점에 영향을 주는 결정이 필요한 부분만 논의합니다.
전사 결정에는 실행 책임자 1명, 협조 부서, 완료일, 미이행 시 에스컬레이션 대상을 기록합니다. 자원 배정은 회의 후 1영업일 이내 관련 부서장이 수락 여부를 확정하고, 수락 불가 시 대체안을 함께 제출합니다.
반복 패배 원인은 한 건의 담당자 문제로 환원하지 않습니다. 동일 원인이 기준 이상 누적되면 제안 역량, 기술 조건, 타겟 적합성 중 어느 운영 체계에서 수정할지 지정하고 해당 문서 체계로 이관합니다.

## 기술 검토가 걸린 딜의 처리
<!--meta: sec=s9; dept=SALES|CNS|AIAX; level=시니어; ct_band=상; related=s8|s10-->
기술 검토 대기 딜은 일반 영업 후속 조치와 분리해 표시합니다. SALES 소유자는 리뷰 전까지 대기 사유, 검토 요청일, 약속 회신일, 검토 담당 부서와 대체 진행 가능 여부를 CRM에 입력합니다.

리뷰 운영자는 검토 요청이 실제 접수되었는지 확인하며, 구두 문의나 메신저 질문만 있는 건은 접수로 인정하지 않습니다. CNS·AIAX 담당자가 회신일을 수락하지 않았다면 약속 회신일은 `미확정`으로 표시합니다.

**대기 딜 필수 확인 항목**
| 항목 | 리뷰 판정 기준 | 미충족 시 조치 |
| --- | --- | --- |
| 대기 사유 | 검토할 기술 쟁점이 한 문장으로 특정됨 | SALES가 당일 보완 |
| 요청일 | 업무 시스템에 요청한 날짜가 기록됨 | 요청 전이면 대기열에서 제외 |
| 약속 회신일 | CNS·AIAX 담당자가 수락한 날짜가 있음 | 1영업일 내 일정 확정 |
| 대체 진행 | 제안 목차, 고객 질의 회수 등 병행 업무가 명시됨 | 다음 액션 신규 등록 |
| 검토 소유자 | 담당 부서와 실명 대신 직무 역할이 지정됨 | 해당 팀 과장이 배정 |

약속 회신일이 지난 건은 지연 일수와 고객 영향만 확인하며 회의 중 기술 토론을 시작하지 않습니다. 대체 진행이 가능하면 영업 액션은 유지하고, 검토 결과가 없으면 진행할 수 없는 항목만 차단 상태로 둡니다.

**검토 공수 경쟁 시 우선순위 점수**
| 평가 항목 | 배점 | 최고점 조건 |
| --- | ---: | --- |
| 고객 약속 긴급성 | 0~3점 | 5영업일 이내 확정 일정 |
| 기술 검토의 차단성 | 0~3점 | 검토 전 고객 대응 불가 |
| 상업적 중요도 | 0~2점 | 해당 지점 활성 딜 금액 상위 25% |
| 재사용 가능성 | 0~1점 | 복수 제안에 재사용 가능 |
| 요청 완전성 | 0~1점 | 질문·입력자료·회신 형식이 모두 준비됨 |

우선순위 점수는 10점 만점으로 합산하며, 높은 점수부터 CNS·AIAX 검토 슬롯을 배정합니다.
8점 이상은 2영업일 이내, 5~7점은 5영업일 이내, 4점 이하는 다음 가용 슬롯을 기준으로 약속 회신일을 정합니다.
동점이면 고객 확정 일정이 빠른 건, 요청일이 오래된 건, 대체 진행이 불가능한 건 순으로 앞세웁니다.

**리뷰 처리 순서**
1. SALES가 대기 사유와 고객 영향을 60초 이내로 설명합니다.
2. CNS·AIAX가 회신 가능일 또는 추가 입력자료를 확정하고 CRM에 남깁니다.
3. 공수 충돌이 해소되지 않으면 관련 팀 과장 이상이 당일 배정하며, 지점 간 충돌은 부장에게 올립니다.
기술 타당성의 판단 기준과 검토 산출물은 DSC-xx를 참조합니다.

## 리뷰에서 나온 액션의 기록·추적
<!--meta: sec=s10; dept=SALES; level=주니어; ct_band=중; related=s9|s11-->
리뷰 액션은 논의 내용이 아니라 실행 약속으로 기록합니다. 모든 액션에는 `무엇을 / 누가 / 언제까지 / 완료 판정 기준`이 있어야 하며, 공동 소유자는 허용하지 않습니다.

액션의 기준 기록 위치는 CRM 기회 레코드의 `주간 리뷰 액션` 영역입니다. 메신저, 전자우편, 개인 메모는 알림 수단으로만 사용하며 완료 여부의 원본 기록으로 인정하지 않습니다.

**액션 필수 필드**
| 필드 | 작성 기준 | 입력 예시 |
| --- | --- | --- |
| 무엇을 | 동사로 시작하며 결과물 1개만 지정 | 고객 담당자에게 일정 확인 |
| 누가 | 실행 책임자 1명 지정 | 기회 소유자 |
| 언제까지 | 날짜와 시각을 함께 입력 | 11월 13일 17:00 |
| 완료 판정 | 제3자가 확인 가능한 조건 | 고객 회신을 CRM에 첨부 |
| 증빙 링크 | 메일·문서·활동 기록 위치 | CRM 활동 ID |

한 액션에 결과물이 둘 이상이면 행을 분리합니다. 10영업일을 넘는 작업은 중간 산출물 기준으로 쪼개며, `계속 협의`, `빠르게 확인` 같은 표현은 등록하지 않습니다.

**상태값과 갱신 규칙**
| 상태 | 사용 조건 | 필수 기록 |
| --- | --- | --- |
| Open | 담당자가 착수할 수 있음 | 마감일 |
| Blocked | 외부 입력이나 선행 작업을 기다림 | 차단 사유·해제 예정일 |
| Done | 완료 판정 기준을 충족함 | 완료일·증빙 |
| Cancelled | 필요성이 소멸하거나 다른 액션으로 대체됨 | 취소 사유·대체 ID |

기록 담당자는 회의 중 SALES 서기이며, 각 액션 소유자는 종료 후 30분 이내 내용을 확인합니다.
소유자는 상태 변화가 발생한 날 18:00까지 갱신하며, RevOps 담당자가 대신 완료 처리하지 않습니다.

**다음 리뷰 첫 5분**
다음 리뷰는 미완료 액션 목록을 화면에 띄우고 `기한 초과 → Blocked → 이번 주 만기` 순으로 확인합니다.
1주 연속 미완료이면 새 마감일과 지연 사유를 기록하고, 원래 액션의 기한은 덮어쓰지 않습니다.
2주 연속 미완료이면 SALES 과장이 범위 축소, 소유자 변경 또는 선행 조건 해소 중 하나를 결정합니다.
3주 연속 미완료이면 부장에게 에스컬레이션하고 `재배정·기회 보류·액션 취소` 중 하나를 당일 확정합니다.
장기 작업을 동일 문구로 다시 생성해 연속 미완료 횟수를 초기화하는 행위는 금지합니다.

## 포캐스트 변경을 리뷰에서 반영하는 방법
<!--meta: sec=s11; dept=SALES; level=시니어; ct_band=중; related=s10|s12|FCT-02#s1-->
리뷰 중 포캐스트 범주 변경 의견이 나오면 토론만 남기지 않고 `변경 제안 → 근거 확인 → 결정 → CRM 반영 → 검증` 순서로 처리합니다. 범주명은 Commit, Best Case, Pipeline, Omitted, Closed만 사용합니다.

범주 변경은 낙관도나 참석자 다수 의견으로 결정하지 않습니다. 고객의 날짜가 확인된 활동 기록, 승인 진행 상태, 계약 관련 증빙 등 변경 시점에 존재하는 자료를 기준으로 판단합니다.

**회의 중 변경 절차**
1. 기회 소유자가 현재 범주, 제안 범주, 변경 사유를 각각 한 문장으로 설명합니다.
2. SALES 관리자가 적용 기준을 질문하고 증빙의 작성일과 출처를 확인합니다.
3. 근거가 충족되면 관리자가 변경 여부를 명시적으로 승인합니다.
4. 기회 소유자가 회의 화면에서 범주와 종료예정일을 즉시 수정합니다.
5. RevOps 담당자가 이전 값, 새 값, 승인자, 변경 시각이 이력에 남았는지 확인합니다.

| 변경 유형 | 회의에서 확인할 핵심 증빙 | 처리 |
| --- | --- | --- |
| Pipeline→Best Case·Commit | 고객 일정과 남은 조건의 최근 확인 기록 | 근거 충족 시 변경 |
| Best Case→Commit | 기간 내 종결을 뒷받침하는 고객 측 진전 | 승인 후 변경 |
| Commit→Best Case·Pipeline | 지연·조건 미충족을 보여주는 신규 사실 | 발견 즉시 하향 |
| 활성 범주→Omitted | 해당 기간 제외 사유와 재검토일 | 재검토일 필수 |
| 활성 범주→Closed | 수주 또는 실패를 확정하는 기록 | 상태와 함께 반영 |

근거가 완비되고 승인권자가 참석한 경우에는 회의 중 결정합니다. 금액이 크다는 이유, 영업 담당자의 확신, 고객의 비공식 기대만 있는 경우에는 변경하지 않습니다.

**그 자리에서 결정하지 않는 경우**
| 사유 | 보류 처리 | 재판정 기한 |
| --- | --- | --- |
| 고객 근거가 없거나 14일보다 오래됨 | 확인 액션 등록 | 2영업일 |
| CNS·AIAX 검토 결과가 미확정임 | 현재 범주 유지 | 약속 회신일 |
| 가격·계약 승인권자가 부재함 | 승인 요청 기록 | 1영업일 |
| 포캐스트 마감 잠금 이후 변경임 | 예외 승인 경로 사용 | FCT-02 기준 |

보류 건은 현재 범주를 유지하고, 소유자·확인 자료·재판정일을 액션으로 남깁니다.
변경 사유는 기회 소유자가 작성하며 RevOps 담당자는 사유 코드와 증빙 링크의 누락만 교정합니다.
범주 판정, 잠금 예외, 계산식과 가중치 적용은 FCT-02를 참조합니다.

## 월말·분기말 주간 리뷰의 변형 운영
<!--meta: sec=s12; dept=SALES; level=시니어; ct_band=상; related=s11|s13-->
월말·분기말 마감 주차에는 전체 파이프라인을 순회하지 않습니다. 해당 기간에 종료예정일이 있는 Commit·Best Case, 계약 절차가 진행 중인 건, 종료예정일 이월 가능성이 발생한 건으로 점검 대상을 축소합니다.

마감 5영업일 전부터는 주간 회의를 유지하되 15분 일일 점검을 추가합니다. 일일 점검은 신규 제안 논의가 아니라 종결 장애물, 당일 고객 약속, 계약 절차의 실제 진행 여부만 확인합니다.

**마감 구간별 운영 변형**
| 구간 | 점검 범위 | 운영 방식 |
| --- | --- | --- |
| T-10~T-6영업일 | 해당 기간 Commit·Best Case 전체 | 주간 리뷰에서 경로 점검 |
| T-5~T-3영업일 | 미종결 Commit과 계약 진행 건 | 매일 16:30, 15분 |
| T-2~T-1영업일 | 서명·발주·최종 승인 잔여 건 | 오전·오후 상태 확인 |
| 분기 마지막 주 | 분기 종결 건과 다음 분기 이월 건 | 이월 사유를 별도 기록 |

일일 점검에서는 `오늘 완료할 단계 / 책임자 / 고객 측 대기사항 / 다음 확인 시각`만 기록합니다. Pipeline 건은 범주 변경 근거가 제출된 경우에만 다룹니다.

**계약 절차 역산용 기본 소요일**
| 절차 | 미확정 시 적용할 기본값 | 확인 책임 |
| --- | ---: | --- |
| 고객 최종 승인 | 3영업일 | SALES |
| 계약 문안 검토·수정 | 5영업일 | SALES |
| 내부 결재 | 2영업일 | 승인 요청자 |
| 서명·날인 | 2영업일 | SALES |
| 발주서 수령 | 3영업일 | SALES |

목표 종결일에서 해당되는 절차의 순차 소요일과 1영업일 완충일을 역산해 각 마일스톤 기한을 정합니다.
필요 소요일이 남은 영업일보다 길면 종결일을 이동하며, 고객이나 내부 담당자에게 비정상 단축을 요구하지 않습니다.
계약 절차의 상세 승인·문서 기준은 PRP-xx를 참조합니다.

**분기말 밀어내기 방지 원칙**
1. 고객이 확인하지 않은 종결일을 유지하거나 Commit으로 올리지 않습니다.
2. 마감일만을 이유로 할인, 무상 범위, 허위 긴급성을 제시하지 않습니다.
3. 구축 딜은 수행 부서의 착수 가능일, 운영·유지보수 딜은 계약 공백 여부를 확인합니다.
4. 미완료 계약을 완료로 표시하지 않으며 이월은 실패가 아닌 정확한 상태 보고로 처리합니다.

## 리뷰 운영자(RevOps 담당)의 사전·사후 업무
<!--meta: sec=s13; dept=SALES; level=시니어; ct_band=중; related=s12|s14-->
리뷰 운영자는 회의 진행, 입력 자료의 기준 시점, 액션 기록 완결성을 소유합니다. 개별 딜의 수주 가능성 판단과 영업 전략 결정은 영업 관리자와 기회 소유자가 담당합니다.

운영자는 회의 직전까지 계속 변하는 CRM 화면을 사용하지 않고 데이터 마감 시점의 스냅샷을 기준 자료로 사용합니다. 검증 규칙이나 라우팅의 구조적 문제는 RevOps가 수정하며, 딜 근거와 종료예정일의 확인 책임은 영업 관리자에게 있습니다.

**사전 업무 체크리스트**
| 시점 | 업무 | 완료 기준 | 표준 소요 시간 |
| --- | --- | --- | ---: |
| T-24시간 | 데이터 마감 안내 | 마감 시각, 대상 기회, 수정 책임자를 참석자에게 공지합니다. | 5분 |
| T-4시간 | 기준 스냅샷 추출 | 열린 기회의 금액·단계·종료예정일·포캐스트 범주를 고정합니다. | 10분 |
| T-4시간 | 필수 상태 점검 | 모든 열린 기회의 owner, status, next step, 담당자 연락처 최근 검증 여부를 확인합니다. | 15분 |
| T-3시간 | 예외 목록 생성 | 검증 규칙 위반, 라우팅 실패, 필수값 누락, 전주 이후 위험 변경을 분리합니다. | 10분 |
| T-3시간 | 아젠다 확정 | 정체 딜, 상위 딜, 기술 검토 딜과 의사결정 필요 건의 순서를 고정합니다. | 5분 |
| T-2시간 | 자료 배포 | 스냅샷 시각과 문서 버전이 표시된 링크를 참석자에게 배포합니다. | 5분 |
| 합계 | 표준 사전 준비 | 오류 수정 작업을 제외한 운영자 기준입니다. | 50분 |

자료를 배포한 뒤 발견된 오류는 원본 스냅샷을 덮어쓰지 않습니다. 운영자는 정정 예정 표시를 남기고 회의에서 기존 값과 정정 요청을 함께 보여줍니다.

**사후 업무 체크리스트**
| 기한 | 업무 | 완료 기준 | 표준 소요 시간 |
| --- | --- | --- | ---: |
| T+30분 | 액션 등록 | 담당자·기한·완료 조건이 있는 액션을 회의 기록에 등록합니다. | 10분 |
| T+60분 | 종료 스냅샷 보관 | 리뷰 종료 시점의 수치와 회의 전 기준값을 구분하여 저장합니다. | 5분 |
| T+90분 | 데이터 교정 요청 | 회의 중 확인된 누락·오류를 레코드별 작업으로 발행합니다. | 5분 |
| T+2시간 | 결과 배포 | 결정, 미결 사항, 에스컬레이션 대상을 참석자에게 전달합니다. | 5분 |
| 매주 금요일 | 반복 이슈 집계 | 동일 원인이 3건 이상이거나 2주 연속 발생한 문제를 유형별로 집계합니다. | 10분 |
| 합계 | 표준 사후 처리 | 개별 딜의 실제 수정 시간은 포함하지 않습니다. | 35분 |

반복 이슈는 `입력 교육 → 검증 규칙 보완 → 권한·자동화 수정 → 관리자 점검 강화` 중 하나로 분류합니다. 시스템 통제가 필요한 건은 RevOps가 소유하고, 사용자 행동 교정 건은 해당 영업 관리자가 소유합니다.

**운영 흐름**
`데이터 마감 → 스냅샷 추출 → 예외 식별 → 아젠다 확정 → 자료 배포 → 리뷰 → 액션 등록 → 종료 스냅샷 → 반복 이슈 집계`

사전 준비가 70분을 초과하면 운영자는 초과 원인과 구조적 개선 필요 여부를 월간 운영 로그에 남깁니다. CRM 필드와 위생 규칙은 FCT-05, 포캐스트 범주 변경 기준은 FCT-02를 참조합니다.

## 참석자가 하지 말아야 할 행동
<!--meta: sec=s14; dept=SALES; level=주니어|시니어; ct_band=중; related=s13|s15-->
주간 리뷰는 공동 판단을 위한 제한된 시간이며, 즉석 데이터 정비나 개인 경험 공유를 위한 자리가 아닙니다. 참석자는 발언이 의사결정, 위험 확인, 액션 확정 중 하나에 기여하는지 확인합니다.

금지 행동은 직급과 관계없이 동일하게 적용합니다. 운영자는 행동이 처음 발생했을 때 즉시 중단시키며, 발언자의 의도나 성과를 평가하지 않고 회의에 미치는 영향만 설명합니다.

**금지 행동과 영향**
| 금지 행동 | 리뷰를 망치는 방식 | 허용되는 대체 행동 |
| --- | --- | --- |
| 자리에서 CRM을 수정합니다. | 참석자가 서로 다른 수치를 보게 되고 변경 전 근거가 사라집니다. | 정정 액션을 등록하고 리뷰 종료 후 수정합니다. |
| 고객 담당자의 뒷이야기나 개인적 추측을 말합니다. | 검증되지 않은 정보가 판단 근거로 남고 고객 비밀 노출 위험이 생깁니다. | 의사결정에 필요한 확인된 조직·계약 사실만 말합니다. |
| 근거 없이 낙관적인 수주 전망을 주장합니다. | 위험 신호가 가려지고 포캐스트 범주가 과대 평가됩니다. | 고객 행동, 문서, 일정 등 날짜가 있는 증거를 제시합니다. |
| 질문을 비판으로 받아 방어적으로 답합니다. | 사실 확인이 중단되고 필요한 반대 증거가 나오지 않습니다. | 모르는 항목은 확인 기한과 확인 방법으로 답합니다. |
| 다른 사람의 딜에 끼어들어 조언을 길게 합니다. | 딜 소유자의 설명 시간이 줄고 아젠다가 지연됩니다. | 운영자 허가 후 60초 안에 한 가지 제안만 말합니다. |
| 메신저·이메일·다른 회의를 병행합니다. | 질문이 반복되고 결정 사항의 책임자가 불명확해집니다. | 긴급 대응이 필요하면 운영자에게 알리고 퇴장합니다. |
| 과거 책임 소재를 장시간 따집니다. | 현재 딜의 다음 액션이 정해지지 않은 채 시간이 소진됩니다. | 원인 분석이 필요하면 별도 액션과 참석자를 지정합니다. |

고객과 관련된 발언은 회의 목적에 필요한 최소 정보로 제한합니다. 개인 성향, 사내 평판, 사생활 또는 출처가 불명확한 소문은 회의록에도 남기지 않습니다.

**운영자의 개입 기준**
| 발생 상황 | 운영자 개입 | 시간 제한 |
| --- | --- | ---: |
| 첫 번째 이탈 발언 | “근거 또는 다음 액션으로 연결해 주십시오”라고 요청합니다. | 10초 |
| CRM 즉석 수정 시도 | 화면 수정을 중단하고 정정 액션으로 전환합니다. | 즉시 |
| 장시간 조언 | 핵심 제안 한 문장만 받고 별도 협의로 이동합니다. | 60초 |
| 고객 뒷이야기 | 발언을 중단하고 관련 기록을 회의록에서 제외합니다. | 즉시 |
| 동일 참석자의 2회 반복 | 해당 발언을 종료하고 회의 후 관리자 면담 대상으로 표시합니다. | 30초 |

개입을 받은 참석자는 현장에서 해명 토론을 시작하지 않습니다. 사실관계가 잘못되었다고 판단하면 리뷰 종료 후 1영업일 이내에 운영자에게 정정을 요청합니다.

**발언 전 자가 점검**
`확인된 사실인가 → 현재 판단에 필요한가 → 60초 안에 말할 수 있는가 → 담당자와 기한으로 끝나는가`

고객의 긴급 연락이나 서비스 장애 대응은 예외적으로 즉시 처리할 수 있습니다. 참석자는 운영자에게 퇴장 사유와 복귀 가능 시각을 알리고, 대리 참석자 또는 후속 확인자를 지정합니다.

동일 금지 행동이 4주 동안 3회 발생하면 운영자는 영업 관리자에게 행동 교정 액션을 발행합니다. 포캐스트 근거와 범주 판정은 FCT-02를 참조합니다.

## 리뷰 품질 점검 — 운영 자체를 평가하는 기준
<!--meta: sec=s15; dept=SALES; level=시니어; ct_band=상; related=s14|s16-->
리뷰 품질은 회의 분위기나 참석자의 주관적 만족만으로 판정하지 않습니다. 운영 효율, 후속 실행, 파이프라인 변화, 정체 해소, 참석자 유용성을 서로 분리하여 측정합니다.

각 지표는 분기 단위로 보고하되 매주 원자료를 누적합니다. 하나의 종합 평균으로 합치지 않으며, 한 지표의 높은 값이 다른 지표의 결함을 가리지 못하도록 항목별 상태를 표시합니다.

**핵심 품질 지표**
| 지표 | 산식·측정 기준 | 분기 목표 |
| --- | --- | --- |
| 시간 준수율 | 정시 시작 2분 이내, 종료 5분 이내, 아젠다별 초과 10% 이내를 모두 충족한 회의 수 ÷ 전체 회의 수 | 90% 이상 |
| 액션 완료율 | 기한 내 완료된 액션 수 ÷ 기한이 도래한 액션 수. 승인받아 취소된 액션은 분모에서 제외합니다. | 85% 이상 |
| 리뷰 후 단계 전환 발생률 | 리뷰된 열린 기회 중 14일 이내 유효한 다음 단계 전환이 발생한 기회 수 ÷ 리뷰된 열린 기회 수 | 25% 이상 |
| 정체 딜 해소 기간 | 정체 표시일부터 전환·보류·실패 확정일까지의 달력일 중앙값과 80백분위값 | 중앙값 14일 이하, 80백분위 21일 이하 |
| 참석자 설문 | 5점 척도 평균. 응답률이 70% 미만이면 판정하지 않습니다. | 평균 4.2점 이상 |

단계 전환 발생률은 리뷰의 직접적인 인과 효과로 해석하지 않습니다. 근거 없는 단계 변경으로 수치를 높이는 행위를 막기 위해 전환의 유효성은 FCT-01 기준을 충족한 건만 인정합니다.

정체 딜 해소에는 단순 삭제를 포함하지 않습니다. 소유자와 처리 사유가 남아 있고 다음 상태가 확정된 경우에만 해소 건으로 계산합니다.

**상태 판정**
| 상태 | 판정 조건 | 운영 조치 |
| --- | --- | --- |
| 녹색 | 5개 지표 중 4개 이상 목표 달성, 적색 지표 없음 | 현 운영 방식을 유지합니다. |
| 황색 | 2~3개 지표 달성 또는 단일 지표가 목표의 80% 미만 | 다음 분기 개선 액션을 2개 이내로 지정합니다. |
| 적색 | 0~1개 지표 달성 또는 같은 지표가 2분기 연속 미달 | SALES 부장에게 원인과 교정 계획을 보고합니다. |
| 판정 보류 | 회의 수 6회 미만 또는 핵심 원자료 누락 | 누락 원인을 명시하고 다음 분기에 재측정합니다. |

운영자는 분기 종료 후 5영업일 이내에 품질 보고서를 작성합니다. 지점별 표본 수가 다른 경우 단순 평균 순위를 만들지 않고 회의 수와 대상 기회 수를 함께 표시합니다.

**분기 보고서 필수 항목**
1. 지표별 목표, 실제값, 전 분기 대비 증감폭을 기록합니다.
2. 미달 지표마다 데이터 문제와 운영 문제를 구분합니다.
3. 반복 이슈 상위 3개와 발생 횟수를 제시합니다.
4. 개선 액션별 담당자, 완료 기한, 검증 방법을 지정합니다.

수치 개선을 위해 리뷰 대상 딜을 임의로 제외하거나 액션 기한을 사후 변경하면 해당 분기 지표를 무효 처리합니다. 무효 사유와 영향을 받은 지표는 별도로 표시합니다.

참석자 설문은 분기 마지막 리뷰 직후 익명으로 실시하며 `시간 활용`, `질문의 유용성`, `의사결정 명확성`, `후속 액션 명확성`을 각각 평가합니다. CRM 데이터 품질 점수는 FCT-05에서 별도로 관리합니다.

## 신규 참석자 온보딩 안내
<!--meta: sec=s16; dept=SALES; level=주니어; ct_band=하; related=s15|s17-->
처음 참석하는 사원은 3주 동안 관찰, 단일 딜 발표, 본인 보유 딜 전체 발표 순서로 참여 범위를 넓힙니다. 온보딩 기간에도 CRM 입력과 사전 자료 제출 기한은 기존 참석자와 동일하게 적용합니다.

직속 관리자는 첫 참석 전 파이프라인 단계, 포캐스트 범주, CRM 필수 필드 관련 문서를 읽었는지 확인합니다. 리뷰 시간에는 용어 교육을 별도로 진행하지 않으며 질문은 종료 후 15분 코칭에서 처리합니다.

**첫 3주 참여 계획**
| 주차 | 역할 | 사전 준비 | 통과 기준 |
| --- | --- | --- | --- |
| 1주차 | 관찰 | 회의 자료를 읽고 근거 질문 3개와 결정 방식 2개를 기록합니다. | 종료 후 관리자에게 관찰 메모를 제출합니다. |
| 2주차 | 본인 딜 1건 발표 | 발표 템플릿 작성 후 관리자와 15분 예행연습을 합니다. | 발표 3분, 질의응답 2분 안에 필수 항목을 답합니다. |
| 3주차 | 본인 보유 열린 딜 전체 발표 | 전체 딜을 1행씩 정리하고 상위 2건의 상세 근거를 준비합니다. | 총 10분 이내에 상태·위험·다음 액션을 빠짐없이 설명합니다. |

1주차 관찰자는 질문이 있어도 발표를 중단시키지 않습니다. 사실 오류나 고객 긴급 이슈를 발견한 경우에만 운영자에게 메신저로 알리고, 나머지 질문은 관찰 메모에 적습니다.

**발표 준비 템플릿**
| 항목 | 작성 내용 |
| --- | --- |
| 기회 식별 | CRM 기회 ID와 고객사 업종을 적습니다. |
| 계약 형태 | 구축 프로젝트 또는 운영·유지보수 계약으로 구분합니다. |
| 현재 위치 | 현재 단계와 해당 단계 진입일을 적습니다. |
| 금액·일정 | 예상 계약 금액과 종료예정일을 적습니다. |
| 포캐스트 | 현재 포캐스트 범주와 직전 주 대비 변경 여부를 적습니다. |
| 최신 근거 | 최근 7일 안에 확인된 고객 행동이나 문서를 적습니다. |
| 다음 액션 | 행동, 담당자, 완료일을 한 문장으로 적습니다. |
| 위험·지원 요청 | 장애 요인과 필요한 의사결정 또는 지원을 적습니다. |
| 데이터 확인 | owner, status, next step, 담당자 연락처 최근 검증 여부를 표시합니다. |

발표자는 자료를 그대로 읽지 않고 `사실 → 지난주 변화 → 다음 액션 → 지원 요청` 순서로 말합니다. 확인하지 못한 내용은 추정하지 않고 확인 담당자와 기한을 답합니다.

**발표 직전 점검**
`CRM 마감 완료 → 템플릿 9개 항목 확인 → 근거 링크 확인 → 3분 또는 10분 타이머 연습 → 질문 예상 3개 작성`

2주차에 필수 항목이 2개 이상 누락되거나 제한 시간을 1분 이상 초과하면 다음 주에도 단일 딜 발표를 반복합니다. 이는 인사 평가가 아니라 리뷰 참여 준비 상태를 확인하기 위한 조치입니다.

3주차 통과 여부는 직속 관리자와 리뷰 운영자가 공동 확인합니다. 단계 정의는 FCT-01, 포캐스트 범주는 FCT-02, CRM 입력 기준은 FCT-05를 참조합니다.

## 원격·지점 분산 환경에서의 진행 요령
<!--meta: sec=s17; dept=SALES; level=주니어|시니어; ct_band=중; related=s16|s18-->
3개 지점이 참여하는 주간 리뷰는 전원이 동일한 온라인 회의 링크와 CRM 화면을 기준으로 진행합니다. 지점별 별도 회의 후 결과만 합치는 방식은 질문 누락과 판정 시차를 만들므로 사용하지 않습니다.
진행자는 회의 시작 5분 전 접속 상태를 확인하고, 각 지점 참석자는 개인 헤드셋을 사용합니다. 같은 회의실에서 2대 이상의 장비가 접속하면 보조 장비의 마이크와 스피커를 모두 끕니다.
**접속 및 화면 공유 기준**
`공통 링크 접속 → 음성 확인 → 기록 담당 확인 → CRM 저장 보기 공유 → 지점별 리뷰 → 미결 항목 확인`
| 시점 | 운영 기준 | 책임자 |
| --- | --- | --- |
| 입장 | 시작 5분 전까지 접속하고 표시명을 `지점-이름-직급`으로 설정합니다. | 전 참석자 |
| 화면 준비 | 알림·메신저를 끄고 고객 문서와 개인 폴더를 닫습니다. | 화면 공유자 |
| 화면 공유 | CRM의 승인된 저장 보기만 공유하며 전체 바탕화면 공유는 금지합니다. | 진행자 또는 RevOps |
| 회의 시작 | 100~125% 배율에서 기회명, 단계, 종료예정일, 다음 액션이 한 화면에 보이게 합니다. | 화면 공유자 |
| 딜 점검 | 발표자가 직접 화면을 전환하지 않고 진행자에게 기회 ID를 말합니다. | 발표자 |
| 회의 종료 | 공유 중인 필터와 정렬 조건을 원래 저장 상태로 복구합니다. | RevOps |
화면 공유 권한은 원칙적으로 진행자와 RevOps에게만 부여합니다. 기술 자료 확인이 필요한 경우 해당 참석자에게 최대 5분간 임시 권한을 부여하고 확인 종료 즉시 회수합니다.
**발언 순서**
1. 지점 순서는 매주 `서울→경기→인천`, `경기→인천→서울`, `인천→서울→경기`로 순환합니다.
2. 지점 내부에서는 기회 소유자가 90초 이내로 보고하고, 지점 영업 관리자가 추가 설명합니다.
3. 다른 지점 참석자는 온라인 손들기 기능을 사용하며 진행자가 지명한 뒤 발언합니다.
4. 반론이나 추가 질문은 발표 중 끼어들지 않고 해당 딜의 기본 보고가 끝난 뒤 최대 60초간 제기합니다.
진행자는 한 사람이 3분 이상 연속 발언하면 결론이 필요한 질문 1개로 좁힙니다. 채팅에 올라온 질문은 기록 담당이 중복을 제거한 뒤 해당 딜 종료 전에 진행자에게 전달합니다.
**음성 품질 문제 처리**
| 상황 | 즉시 조치 | 중단 기준 |
| --- | --- | --- |
| 10초 이내 끊김·잡음 | 카메라를 끄고 마이크를 다시 연결합니다. | 회의는 계속합니다. |
| 동일 문제가 2회 반복 | 퇴장 후 2분 내 재접속하고 채팅으로 상태를 알립니다. | 다음 발표자로 이동합니다. |
| 발표자 접속 불가 | 채팅에 `기회 ID/요청사항/복귀 예상시각`을 남깁니다. | 해당 딜을 회의 후반으로 이월합니다. |
| 지점 전체 회선 장애 | 지점 대표 1인이 전화 음성으로 접속합니다. | 5분 초과 시 해당 지점 순서를 마지막으로 이동합니다. |
음성이 복구되지 않은 상태에서는 해당 기회의 변경 사항을 확정하지 않습니다. 소유자는 회의 종료 후 다음 영업일 12시까지 기록 담당에게 확인 내용을 전달합니다.
**기록 담당 고정**
1. 기록 담당은 회의 초대장에 지정된 RevOps 1인으로 고정합니다.
2. 결석 시 대체자는 회의 시작 전 영업일 17시까지 지정하며 회의 도중 교대하지 않습니다.
3. 기록 담당은 화면 공유와 회의 진행을 동시에 맡지 않습니다.
4. 자동 전사 기능은 보조 수단으로만 사용하며 최종 기록은 지정 담당자가 확정합니다.
진행자는 종료 직전 3분 동안 미결 딜, 연결 장애로 보류된 딜, 확인 기한만 낭독합니다. 참석자는 자신의 발언이 잘못 기록된 경우 종료 후 2시간 이내에 정정 요청합니다.

## 기록 보관과 공개 범위
<!--meta: sec=s18; dept=SALES; level=시니어; ct_band=하; related=s17-->
주간 리뷰 기록은 승인된 사내 협업 저장소에만 보관합니다. 개인 PC, 개인 클라우드, 메신저 대화방, 이메일 받은편지함을 공식 보관 위치로 사용하지 않습니다.
기록 제목은 `YYYY-MM-DD_지점 또는 전사_주간파이프라인리뷰`로 작성합니다. 고객사는 실제 명칭 대신 CRM 기회 ID와 `제조업 고객사`, `유통 고객사` 같은 업종 익명명으로 식별합니다.
**기록 유형별 보관 기간**
| 기록 유형 | 보관 기간 | 만료 후 처리 |
| --- | --- | --- |
| 확정 회의록·참석 이력 | 회의일로부터 3년 | 만료 월의 익월 10영업일 내 삭제합니다. |
| 리뷰 액션 이력 | 완료일로부터 3년 | 관련 회의록과 함께 삭제합니다. |
| 회의 녹화·자동 전사 원본 | 회의일로부터 30일 | 확정 회의록 검수 후 영구 삭제합니다. |
| 임시 화면 캡처·보조 첨부 | 회의일로부터 90일 | 승인된 원본 링크를 확인한 뒤 삭제합니다. |
분쟁, 감사 또는 법적 보존 지시가 걸린 기록은 일반 삭제 대상에서 제외합니다. RevOps는 보존 표시와 해제일을 기록하며, 해제 승인 전에는 파일명 변경이나 이동도 하지 않습니다.
**접근 권한**
| 역할 | 허용 범위 | 권한 수준 |
| --- | --- | --- |
| RevOps 담당 | 전 지점 리뷰 기록 | 생성·수정·권한 관리 |
| SALES 기회 소유자 | 본인 소유 기회가 포함된 기록 | 열람·정정 요청 |
| 지점 영업 관리자 | 소속 지점 기록 | 열람 |
| CNS·AIAX·BE·DATA 참석자 | 초대받은 기술 검토 건 | 해당 기록 열람, 14일 후 회수 |
| SALES 부장·지정 경영진 | 전사 리뷰 기록 | 열람 |
공유 링크는 사용자 지정 방식으로 발급하고 조직 전체 공개 링크를 만들지 않습니다. 퇴사, 부서 이동 또는 담당 변경이 확인되면 RevOps가 1영업일 이내에 권한을 회수합니다.
**고객 관련 민감 내용의 기록 제외 기준**
회의록에는 결정, 리스크 분류, 확인 담당, 기한만 남깁니다. 판단에 필요하더라도 아래 정보는 원문·화면 캡처·자동 전사 형태로 저장하지 않습니다.
1. 고객 담당자의 개인 전화번호, 사적 이메일, 건강·인사·가족 관련 정보
2. 비밀번호, API 키, 접근 토큰, 서버 주소와 상세 보안 구성
3. 고객 원천 데이터, 상담 원문, 로그, 소스코드, 학습용 샘플 데이터
4. 공식 확인되지 않은 퇴사·조직 개편·예산 삭감 관련 발언이나 소문
5. 고객 내부 평가 문구, 경쟁 제안서 원문, 비공개 가격표와 계약 문서 사본
민감 정보가 회의 중 노출되면 기록 담당은 해당 구간을 회의록에서 제외하고 녹화본 삭제 시점을 기다리지 않고 당일 삭제를 요청합니다. 필요한 근거는 승인된 원본 시스템의 접근 제한 링크로 대체합니다.
**외부 공유 금지**
1. 회의록, 녹화본, 자동 전사본, 화면 캡처는 고객사를 포함한 외부에 공유하지 않습니다.
2. 개인 이메일 전송, 공개 링크 생성, 외부 메신저 업로드, 비승인 생성형 AI 도구 입력을 금지합니다.
3. 고객에게 후속 내용을 전달해야 하면 내부 리뷰 기록을 복사하지 않고 별도의 대외 문서를 작성합니다.
4. 외부 기관의 제출 요구를 받은 참석자는 직접 회신하지 않고 SALES 부장과 지정 정보보호 책임자에게 즉시 이관합니다.
외부 오발송이나 공개 링크 노출을 발견한 사람은 30분 이내에 링크를 차단하고 RevOps와 SALES 부장에게 알립니다. 임의 삭제로 흔적을 없애지 않으며 발생 시각, 노출 범위, 회수 여부만 내부 사고 기록에 남깁니다.
