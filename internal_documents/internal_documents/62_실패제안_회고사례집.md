# 실패 제안 회고 사례집
<!--meta: doc=PRP-06; doc_type=retrospective; tier=2; topic=SALES; disclosure=internal; status=active-->

## 사례집의 목적과 사용 방법
<!--meta: sec=s1; dept=SALES|CNS; level=주니어|시니어; ct_band=하; related=none-->
승패 분석은 수주·실주 종료 후 구매자 인터뷰, 담당자 디브리프, 거래 기록에서 증거를 모아 결과를 실제로 좌우한 요인을 찾는 구조화된 절차입니다.  
단순한 소감이나 결과 설명이 아니라, 확인된 사실과 해석을 구분하여 다음 제안의 판단 재료로 남기는 활동입니다.

이 사례집은 내부 회고에서 확인된 사건과 패인을 재사용할 수 있도록 정리한 업무 자료입니다.

| 사용 시점 | 사용 목적 | 확인할 내용 |
|---|---|---|
| 신규 제안 착수 전 | 유사 패인을 사전에 점검합니다. | 요구 형태, 가격 구조, 수행 조직, 실적 적합성, 일정, 성능 약속을 확인합니다. |
| 제안 전략 수립 시 | 과거의 전환점과 대응 결과를 비교합니다. | 같은 조건에서 어떤 판단이 실패 가능성을 높였는지 확인합니다. |
| 제안 검토 시 | 검토자가 놓치기 쉬운 위험을 찾습니다. | 사례의 증거, 패인 코드, 재발 방지 조치를 대조합니다. |
| 가이드 개정 시 | 규칙을 추가하거나 수정할 근거로 사용합니다. | 반복 발생 여부와 기존 기준의 공백을 확인합니다. |
| 교육·온보딩 시 | 실제 실패 양상을 짧은 시간에 학습합니다. | 사건의 순서와 판단 오류 사이의 연결을 읽습니다. |

다음 용도로는 사용하지 않습니다.

- 제안 참여자의 개인 평가나 인사 조치 자료로 사용하지 않습니다.
- 고객의 판단, 담당자 또는 평가 방식을 비판하는 자료로 사용하지 않습니다.
- 확인되지 않은 추정을 사실처럼 인용하지 않습니다.
- 한 사례를 모든 고객과 사업에 그대로 적용하지 않습니다.
- 수주 여부만으로 제안 품질 전체를 단정하지 않습니다.

수록 사례는 내부 회고 기록에서 추출하며, 고객사명·개인명·사업명·연락처·세부 금액 등 식별 가능 정보를 제거합니다.  
산업이나 지역 정보도 사건 이해에 필수적인 범위만 남기며, 조합을 통해 고객사나 개인을 특정할 수 있으면 더 넓은 표현으로 바꿉니다.  
직접 인용은 발언자를 추정할 수 없도록 요약하고, 의미가 달라질 우려가 있으면 인용 자체를 제외합니다.

읽는 순서는 다음과 같습니다.

1. 먼저 해당 사례의 배경과 결과를 읽어 사건의 범위를 확인합니다.
2. 다음으로 관찰된 증거와 해석이 분리되어 있는지 확인합니다.
3. 패인 코드에서 결과에 직접 영향을 준 요인과 보조 요인을 구분합니다.
4. 전환점에서 결과를 바꿀 수 있었던 시점과 당시 선택지를 확인합니다.
5. 재발 방지 조치가 현재 제안에 적용 가능한지 점검합니다.
6. 마지막으로 반복 패인 집계를 확인하여 단일 사건인지 구조적 문제인지 판단합니다.

사례를 현재 제안에 적용할 때에는 고객 조건과 평가 방식이 같은지 먼저 확인합니다.  
조건이 다르면 사례의 결론을 복사하지 않고, 질문 목록과 점검 항목만 활용합니다.

## 회고 운영 절차와 시한
<!--meta: sec=s2; dept=SALES; level=시니어; ct_band=중; related=s1-->
회고 일정은 고객사의 결과 통보일을 기준일로 계산합니다.  
구두 통보와 공식 문서의 날짜가 다르면 먼저 확인된 결과 통보일에 기록을 시작하고, 공식 통보일을 별도 항목으로 남깁니다.

| 기한 | 수행 작업 | 책임자 | 완료 증거 |
|---|---|---|---|
| 결과 통보 당일 | 결과, 통보 경로, 확보 자료와 미확인 사항을 기록합니다. | 거래 책임자 | 초기 회고 기록 |
| 3영업일 이내 | 내부 디브리프를 실시합니다. | 거래 책임자 | 참석자, 답변, 근거 링크가 포함된 회의 기록 |
| 10영업일 이내 | 고객 인터뷰를 요청하고 응답 여부를 기록합니다. | 영업팀 지정 담당자 | 요청 메일 또는 연락 기록 |
| 15영업일 이내 | 사실·해석·패인·조치를 확정합니다. | 거래 책임자 | 확정 상태의 회고 기록 |
| 분기 종료 후 | 사례별 코드를 합산하여 반복 패인을 집계합니다. | 영업팀 집계 담당자 | 분기 집계표 |

결과 통보 당일에는 제안서 최종본, 제출본, 발표자료, 질의응답 기록, 가격 승인 기록과 평가 결과를 한 위치에 연결합니다.  
평가 세부점수가 제공되지 않은 경우에는 해당 항목을 미확인으로 표시하며 추정 점수를 입력하지 않습니다.

회고 대상은 다음 기준으로 선정합니다.

1. 해당 분기에 승인된 회고 기준금액 이상인 제안은 수주 여부와 관계없이 전부 포함합니다.
2. 기준금액 미만 제안은 산업, 제안 유형, 결과가 편중되지 않도록 표본을 선정합니다.
3. 비표준 계약 조건, 큰 폭의 할인, 짧은 제출 일정 또는 신규 역량이 포함된 제안은 금액과 무관하게 포함합니다.
4. 제출 전 철회된 건은 철회 사유가 내부 판단이나 준비 실패와 관련된 경우 포함합니다.
5. 참가 자격 미충족으로 제출하지 않은 건은 제안 작업이 시작되지 않았다면 대상에서 제외합니다.

수주 건도 회고 대상입니다.  
수주 과정에는 결과를 뒤집을 뻔한 약점이 존재할 수 있으며, 이 지점은 실제 경쟁 상황에서 드러난 개선 가능성이 가장 큰 항목입니다.  
수주 건의 회고에서는 성공 요인만 기록하지 않고, 거의 잃을 뻔한 시점과 회복에 사용한 행동을 함께 확인합니다.

거래 책임자는 회고 개설, 일정 확정, 참석 요청과 기록 확정을 담당합니다.  
필수 참석자는 거래 책임자, 제안 집필자와 주요 주제전문가입니다.  
가격 또는 기술 내용이 결과에 영향을 주었다는 근거가 있으면 해당 내용을 작성하거나 승인한 부서의 담당자를 추가합니다.  
참석하지 못한 필수 인원은 회의 전 서면 답변과 근거 자료를 제출합니다.

진행자는 회의 시작 시 확인된 사실, 참여자의 해석, 후속 확인이 필요한 가설을 구분하여 기록하도록 안내합니다.  
기록 담당자는 근거가 없는 발언에 ‘추정’ 표시를 붙이고, 확인 담당자와 확인 기한을 지정합니다.  
15영업일 안에 검증되지 않은 내용은 미확인 상태로 확정하며 패인으로 단정하지 않습니다.

회고가 늦어지면 제안 당시의 판단 순서, 대안과 승인 경로가 기억에서 사라집니다.  
그 결과 남아 있는 최종 문서만으로 원인을 추정하게 되며, 실제 전환점에 대한 증거를 확보하기 어렵습니다.  
기한 지연이 예상되면 거래 책임자는 만료 전까지 사유와 새 완료일을 영업팀 승인권자에게 보고합니다.

## 내부 디브리프 질문 세트
<!--meta: sec=s3; dept=SALES|CNS|AIAX; level=시니어; ct_band=상; related=s2|s4-->
내부 디브리프에는 제안 집필자, 주제전문가와 거래 책임자가 함께 참석합니다.  
진행자는 질문별 답변을 사실, 해석, 미확인 가설로 나누고 근거 자료의 위치를 기록합니다.

| 묶음 | 질문 | 답변을 뒷받침할 기록 |
|---|---|---|
| 판정 | 참여 판정 점수는 현재 확보한 정보로 다시 보아도 타당합니까? | 최초 판정표, 승인 의견, 당시 전제 |
| 판정 | 어느 평가 축을 과대평가하거나 과소평가했습니까? | 축별 점수, 근거 메모, 결과 통보 내용 |
| 판정 | 참여 결정 당시 알지 못했던 사실은 무엇이며, 언제 확인됐습니까? | 공고 변경 이력, 질의응답, 연락 기록 |
| 판정 | 조건부 참여 사항은 착수 후 실제로 해소됐습니까? | 조건 목록, 담당자 배정, 완료 기록 |
| 준비 | 공고 또는 제안 기회를 처음 안 날짜와 실제 착수일은 언제입니까? | 접수 기록, 착수 회의 일정, 작업 이력 |
| 준비 | 일정 역산에서 최초로 깨진 마감은 무엇입니까? | 작업계획표, 초안 제출 시각, 변경 이력 |
| 준비 | 지연이 뒤 단계의 검토·수정 시간을 얼마나 줄였습니까? | 계획 대비 실적, 문서 버전 시각 |
| 준비 | 늦게 확보된 자료는 무엇이며 대체 자료를 검토했습니까? | 자료 요청 내역, 회신 시각, 대안 메모 |
| 내용 | 평가표 기준의 자체 채점은 몇 점이었습니까? | 제출 전 자체 평가표 |
| 내용 | 공개된 실제 점수와 자체 채점의 차이는 어느 항목에서 발생했습니까? | 평가 결과표, 항목별 비교표 |
| 내용 | 평가 동사에 맞지 않는 서술·표·증빙은 무엇이었습니까? | 요구 문구, 제출본 페이지, 검토 의견 |
| 내용 | 요구사항을 다뤘지만 고객 문제에 답하지 못한 부분은 어디입니까? | 요구사항 대응표, 제안 본문, 발표 질의 |
| 내용 | 주장에 필요한 수치·사례·증빙 중 빠진 것은 무엇입니까? | 근거 목록, 증빙 파일, 최종 제출본 |
| 가격 | 내부 산정가와 최종 제시가는 각각 얼마였습니까? | 원가 산정표, 견적서, 제출 가격 |
| 가격 | 두 금액의 차이를 만든 할인 또는 조건 조정은 무엇입니까? | 할인 요청서, 조건 변경 기록 |
| 가격 | 할인 결정은 어떤 순서로 요청·검토·승인됐습니까? | 결재 이력, 승인 시각, 검토 의견 |
| 가격 | 가격 조정으로 범위·인력·기간의 가정이 바뀌었습니까? | 산정 버전 비교, 범위표, 투입 계획 |
| 내부 장애물 | 필요한 승인 중 지연되거나 누락된 것은 무엇입니까? | 결재 요청 및 완료 시각 |
| 내부 장애물 | 제안서에 기재한 핵심 인력을 실제로 확보했습니까? | 가용 인력 확인, 투입 동의 기록 |
| 내부 장애물 | 실적·재무·기술 증빙 중 기한까지 확보하지 못한 것은 무엇입니까? | 자료 요청 목록, 파일 등록 시각 |
| 내부 장애물 | 부서 간 상충된 의견은 누가 언제 어떤 근거로 결정했습니까? | 회의록, 결정 기록, 승인 메시지 |
| 전환점 | 결과를 바꿀 수 있었던 단 하나의 시점은 언제입니까? | 당시 일정, 의사결정 기록, 제출 버전 |
| 전환점 | 그 시점에 실제로 선택 가능했던 대안은 무엇입니까? | 검토안, 자원 가용성, 승인 가능 시간 |
| 전환점 | 대안을 선택하지 않은 이유는 정보 부족, 시간 부족, 권한 부족 중 무엇입니까? | 요청·응답 기록, 일정표, 권한 확인 자료 |
| 전환점 | 같은 상황이 재발하면 어떤 신호에서 행동을 시작해야 합니까? | 선행 사건 시각, 경고 기록, 작업 이력 |

실제 평가점수가 공개되지 않았다면 자체 채점과 결과의 차이를 숫자로 추정하지 않습니다.  
이 경우 발표 질의, 보완 요청, 고객이 직접 전달한 의견과 내부 기록만으로 차이를 설명합니다.

회의는 다음 규칙으로 진행합니다.

1. 발언은 사람의 능력이나 태도가 아니라 입력, 절차, 결정과 산출물을 대상으로 합니다.
2. “누가 잘못했는가” 대신 “어떤 확인 단계가 없었는가”를 질문합니다.
3. 기억에 의존한 답변에는 근거 파일 또는 기록의 위치를 요구합니다.
4. 서로 다른 기억이 나오면 다수 의견으로 확정하지 않고 각각의 근거를 확인합니다.
5. 결과를 알고 난 뒤 당시 판단을 비합리적으로 단정하지 않으며, 당시 이용 가능했던 정보만으로 평가합니다.
6. 한 질문에는 주된 답변 하나를 기록하고 부수 요인은 별도 항목으로 분리합니다.
7. 조치 제안은 원인 확인이 끝난 뒤 작성하며, 회의 중 즉시 결론으로 고정하지 않습니다.
8. 확인되지 않은 고객 의도나 경쟁사의 행동은 가설로만 남깁니다.

진행자는 종료 전에 전환점 하나, 내부 장애물, 추가 확인 항목과 증거 소유자를 읽어 확인합니다.  
참석자는 기록이 자신의 발언 취지를 바꾸지 않았는지만 검토하며, 불리한 사실이라는 이유로 삭제를 요구하지 않습니다.

## 고객 인터뷰 질문 세트와 요청 방법
<!--meta: sec=s4; dept=SALES; level=시니어; ct_band=상; related=s3-->
고객 인터뷰는 평가 결과를 통보받은 뒤 고객의 기억이 남아 있고 계약 후속 업무가 본격화되기 전 요청합니다. 거래 책임자는 결과 통보 후 2영업일 이내에 요청하고, 첫 요청에 답이 없으면 3영업일 뒤 한 번만 재요청합니다.

| 요청 항목 | 적용 원칙 | 금지 사항 |
|---|---|---|
| 목적 | 향후 제안 방식 개선을 위한 의견 청취라고 밝힙니다. | 결과 번복이나 이의 제기처럼 표현하지 않습니다. |
| 소요 시간 | 20분 이내로 제안합니다. | 1시간 이상의 회의를 요구하지 않습니다. |
| 참석자 | 거래 책임자 1명과 기록자 1명 이내로 제한합니다. | 제안팀 전원이 참석하지 않습니다. |
| 방식 | 고객이 선택할 수 있도록 통화·화상·서면 답변을 제시합니다. | 대면 회의만 고집하지 않습니다. |
| 정보 처리 | 내부 학습용이며 인용 시 익명화한다고 고지합니다. | 고객명이나 평가자 발언을 외부 활용한다고 암시하지 않습니다. |

요청 문안에는 감사, 개선 목적, 예상 시간, 선택 가능한 방식, 답변 거절 가능성을 포함합니다. 수주 건에는 계약 협의와 분리된 일정으로 요청하여 추가 판매 활동으로 오해받지 않게 합니다.

> 제안 결과와 관련하여 내부 개선에 활용할 의견을 듣고자 합니다. 20분 이내의 통화·화상 회의 또는 서면 답변 중 편한 방식을 선택해 주시면 됩니다. 답변은 내부 학습 목적으로만 사용하고, 사례 인용 시 고객사와 응답자를 식별할 수 없도록 처리합니다. 참여가 어려우시면 회신하지 않으셔도 됩니다.

질문은 한 번에 하나씩 열린 형태로 묻습니다. “가격 때문에 탈락한 것이 맞습니까?”처럼 답을 전제하지 않고, “가격은 결정 과정에서 어떤 역할을 했습니까?”라고 묻습니다.

| 묶음 | 질문 |
|---|---|
| 실주 건 | 최종 결정에서 저희를 선택하지 않은 가장 큰 이유는 무엇이었습니까? |
| 실주 건 | 선정된 제안은 어떤 점에서 더 적합했습니까? |
| 실주 건 | 선정된 제안자에게 있었지만 저희에게는 없었던 요소가 무엇이었습니까? |
| 실주 건 | 평가 과정에서 저희 제안의 우려 요소는 무엇이었습니까? |
| 수주 건 | 최종적으로 저희를 선택하게 한 요소는 무엇이었습니까? |
| 수주 건 | 다른 제안자를 택할 뻔한 지점은 무엇이었습니까? |
| 수주 건 | 계약 또는 착수 전에 추가 확인이 필요했던 요소는 무엇이었습니까? |
| 공통 | 제안 전과 평가 후 저희에 대한 인식은 어떻게 달라졌습니까? |
| 공통 | 가격은 후보 비교와 최종 결정에서 실제로 어떤 역할을 했습니까? |
| 공통 | 다음 제안에서 한 가지를 바꾼다면 무엇을 바꾸는 것이 좋겠습니까? |

내부 담당자에게 묻는 질문 묶음은 PRP-06#s3을 참조합니다. 인터뷰 진행자는 다음 규칙을 적용합니다.

1. 고객의 답변이 끝날 때까지 반론하거나 설명하지 않습니다.
2. 모호한 표현에는 “그 판단을 하게 된 구체적인 장면이나 자료가 있었습니까?”라고 후속 질문합니다.
3. 경쟁 제안자의 기밀 가격, 인력 명단 또는 비공개 제안서 제공을 요구하지 않습니다.
4. 답변을 자사에 유리하게 정리해 확인받지 않습니다.
5. 인터뷰 중 신규 과제, 할인 또는 재제안을 영업하지 않습니다.
6. 법률·계약상 공개 가능 범위는 사안별 확인이 필요합니다.

기록자는 질문, 원문 요지, 후속 질문, 근거 수준을 분리해 작성합니다. 직접 인용은 고객이 사용한 표현을 유지하되 고객사명, 개인명, 제품명, 지역과 고유 사업명을 일반 명칭으로 치환합니다.

인터뷰가 거절되거나 응답이 없으면 다음 순서로 대체 근거를 확보합니다.

- 공식 평가 의견서 또는 평가 결과 공개 자료를 확인합니다.
- 공개된 항목별 점수와 제안 당시 자체 채점 결과를 대조합니다.
- 정정공고, 질의응답, 발표 질의 기록에서 평가 쟁점을 추출합니다.
- 확보하지 못한 선정 사유는 사실로 확정하지 않고 미확인 가설로 표시합니다.
- 공개 자료만으로 경쟁사의 전략이나 가격을 추정해 단정하지 않습니다.

## 패인 분류 체계
<!--meta: sec=s5; dept=SALES|CNS; level=시니어; ct_band=중; related=s3|s13-->
패인 코드는 평가 결과에 영향을 준 직접 원인을 동일한 기준으로 집계하기 위해 부여합니다. 거래 책임자가 초안을 작성하고, 내부 디브리프 참석자가 근거와 코드 적합성을 확인합니다.

| 코드 | 대분류 | 판정 기준 |
|---|---|---|
| L-A | 판정 오류 | 참여 전 확인 가능한 치명적 열위가 있었고, 정상적인 참여 판정이라면 제안하지 않았어야 한 경우입니다. |
| L-B | 요구 이해 부족 | 요구사항, 평가 의도, 고객 문제 또는 요구 동사를 잘못 해석하거나 누락한 경우입니다. |
| L-C | 제안 품질 | 이해한 내용을 구조, 논리, 증빙, 문장, 도표 또는 발표물로 충분히 구현하지 못한 경우입니다. |
| L-D | 가격 구조 | 가격 수준, 산정 방식, 조건, 옵션 구성 또는 평가 산식 대응이 경쟁력을 훼손한 경우입니다. |
| L-E | 역량·실적 부족 | 필수 기술, 인력 자격, 유사 실적 또는 객관적 증빙이 부족한 경우입니다. |
| L-F | 수행 체계 신뢰 | 역할, 책임자, 투입 확약, 품질관리 또는 사후지원 체계가 실행 신뢰를 주지 못한 경우입니다. |
| L-G | 관계·선점 | 고객 접점, 사전 문제 이해 또는 의사결정자 신뢰가 경쟁 후보보다 뒤처진 경우입니다. |
| L-H | 절차·형식 | 제출 시각, 파일 형식, 필수 서류, 서명, 분량 또는 발표 규칙을 위반한 경우입니다. |
| L-I | 통제 불가 | 규격 고착, 예산 변경, 사업 취소 등 제안팀이 합리적으로 통제하거나 사전 회피하기 어려운 외부 사건입니다. |

한 제안에는 최대 2개 코드만 부여합니다. 결과를 가장 직접적으로 설명하는 코드를 주코드로, 주원인의 영향을 확대했지만 단독으로 같은 결과를 만들 가능성이 낮은 코드를 부코드로 기록합니다.

코드 선택 시 다음 구분 규칙을 적용합니다.

1. 요구를 잘못 읽어 불필요한 범위를 포함했고 그 결과 가격이 높아졌다면 주코드는 L-B, 부코드는 L-D입니다.
2. 요구 범위는 정확했으나 할인, 옵션 또는 지급 조건이 평가 산식과 맞지 않았다면 L-D입니다.
3. 수행 역량은 있었지만 이를 입증할 증빙을 넣지 못했다면 L-C입니다.
4. 필요한 자격이나 유사 실적 자체가 없었다면 L-E입니다.
5. 조직도를 제출했지만 책임과 투입 확약이 불명확했다면 L-F입니다.
6. 필수 문서를 이해했으나 제출 파일에서 빠뜨렸다면 L-H입니다.
7. 고객 문제를 잘못 파악해 제안 논리가 빗나갔다면 L-B이며, 단순한 문장 완성도 문제는 L-C입니다.
8. 참여 전에 필수 자격 미충족을 확인할 수 있었다면 L-H보다 L-A를 우선합니다.
9. 관계 열위만으로 L-G를 부여하지 않고, 고객 인터뷰나 접점 기록에서 선점 효과가 확인되어야 합니다.

L-I는 다음 세 조건을 모두 충족해야 사용할 수 있습니다.

- 결과 통보, 공개 자료 또는 고객 답변으로 외부 사건이 확인됩니다.
- 제안팀이 해당 사건을 통제할 수 없었다는 기록이 있습니다.
- 다른 내부 원인이 결과에 미친 영향을 먼저 검토했습니다.

“내정된 것 같다”, “예산이 없었던 것 같다”와 같은 추정만으로 L-I를 부여하지 않습니다. 근거가 확보되지 않으면 코드를 확정하지 않고 미확인 상태로 남깁니다.

주코드와 부코드가 경합하면 평가 점수 차, 고객 발언, 제출본 순서로 직접성을 판단합니다. 반복 패인의 집계 방식은 PRP-06#s13을 참조합니다.

## 사례 L-01 요구 동사를 놓친 제안
<!--meta: sec=s6; dept=SALES|CNS; level=시니어; ct_band=상; related=s5-->
이 사례는 고객이 요구한 행위와 제안서의 응답 형식이 어긋나 정성평가 점수를 잃은 가상 사례입니다.

| 항목 | 내용 |
|---|---|
| 업종 | 수도권 유통 고객사 |
| 규모 | 컨설팅·구축 합계 12 M/M |
| 수행 기간 | 4개월 |
| 결과 | 협상 순위 2위 |
| 종합점수 차 | 1순위와 3.6점 차 |
| 패인 코드 | 주코드 L-B, 부코드 L-C |

RFP에는 현행 방식과 제안 방식의 장단점, 적용 조건과 기대 효과를 “비교하여 제시하라”는 요구가 있었습니다. 제안팀은 이를 제안 접근법 설명 항목으로 해석하고 자사 방법론과 단계별 수행 절차를 서술했습니다.

초안에는 비교 대상, 비교 기준과 차이 요약이 없었습니다. 최종본에도 현행 방식과 제안 방식이 같은 기준으로 배치된 표가 포함되지 않았습니다. 발표 자료는 제안 방식의 효과를 다시 설명했으나 비교 결과를 보완하지 못했습니다.

| 확인 항목 | 자체 채점 | 실제 점수 | 차이 |
|---|---:|---:|---:|
| 해당 정성평가 항목 | 18점/20점 | 10점/20점 | -8점 |
| 전체 기술평가 | 86점 | 78점 | -8점 |

자체 채점자는 접근법의 구체성과 수행 절차를 근거로 해당 항목을 18점으로 예상했습니다. 실제 평가에서는 비교 요구에 대한 직접 응답이 부족하다는 의견과 함께 10점이 부여되었습니다.

고객 인터뷰에서는 “제안 방식 자체는 이해할 수 있었으나 무엇과 비교해 우수한지 한 화면에서 판단하기 어려웠다”는 취지의 답변이 확인되었습니다. 공개된 평가 의견에도 비교 기준과 선택 근거가 명확하지 않다는 지적이 있었습니다.

확인된 인과관계는 다음과 같습니다.

1. 요구 동사인 “비교하여 제시”를 일반적인 설명 요구로 해석했습니다.
2. 집필 구조에 비교 대상과 공통 평가 기준을 배정하지 않았습니다.
3. 리뷰에서 내용 존재 여부만 확인하고 응답 형식의 적합성을 확인하지 않았습니다.
4. 해당 항목의 자체 점수와 실제 점수 사이에 8점 차이가 발생했습니다.
5. 이 차이는 최종 종합점수 차 3.6점보다 컸습니다.

주코드는 고객의 요구 행위를 잘못 해석했으므로 L-B로 판정했습니다. 부코드는 비교표와 판단 근거가 최종 산출물에 구현되지 않았으므로 L-C로 판정했습니다. 가격이나 보유 역량은 고객 의견과 점수 자료에서 직접 패인으로 확인되지 않아 코드를 부여하지 않았습니다.

회고 후 PRP-01#s4에 요구 동사 대응표를 신설했습니다. 적용 방법과 작성 기준은 PRP-01#s4를 참조합니다.

재발 방지 검토자는 제출 전 다음 항목에 각각 근거 페이지를 적습니다.

- “비교하라”는 요구에 동일 기준의 비교표가 배치되어 있습니까?
- 비교 대상이 고객의 현행 상태와 제안 상태를 모두 포함합니까?
- 장점뿐 아니라 제약, 적용 조건과 선택 기준이 기재되어 있습니까?
- 목차 제목에 고객이 사용한 요구 동사가 반영되어 있습니까?
- 발표 자료에서도 비교 결론을 한 화면에서 확인할 수 있습니까?
- 자체 채점 근거가 단순한 내용 존재가 아니라 요구 행위의 충족을 입증합니까?

근거 페이지를 적을 수 없는 항목은 완료로 판정하지 않습니다. 제출 직전 발견된 누락은 설명 문장을 추가하는 방식으로 처리하지 않고, 요구된 비교 구조를 본문과 발표 자료에 반영한 뒤 다시 채점합니다.

## 사례 L-02 가격 구조가 평가 구조와 어긋난 제안
<!--meta: sec=s7; dept=SALES; level=시니어; ct_band=상; related=s5;-->
이 사례는 기술 90점, 가격 10점 구조에서 가격점수 확보를 위해 투입 공수를 줄였다가 기술 정성평가의 손실이 더 커진 가상 사례입니다.

| 항목 | 내용 |
|---|---|
| 고객 유형 | 수도권 서비스 고객사입니다. |
| 평가 구조 | 기술 90점, 가격 10점입니다. |
| 최초 산정 가격 | 5억 원입니다. |
| 제출 가격 | 4억 5천만 원입니다. |
| 가격 할인율 | 최초 산정 가격 대비 10%입니다. |
| 최초 계획 공수 | 14 M/M입니다. |
| 제출 계획 공수 | 11 M/M입니다. |
| 결과 | 기술평가 배점한도의 85%인 76.5점에 근접한 77.2점입니다. |
| 패인 코드 | 주코드 L-D, 부코드 L-A입니다. |

가격평가 시뮬레이션에서는 5억 원 제출 시 8.0점, 4억 5천만 원 제출 시 9.0점으로 예상했습니다.  
따라서 가격점수 1.0점을 얻기 위해 최초 산정 가격의 10%인 5천만 원을 할인한 셈입니다.

| 비교 항목 | 할인 전 계획 | 실제 제출안 | 점수·공수 차이 |
|---|---:|---:|---:|
| 가격평가 예상점수 | 8.0점 | 9.0점 | +1.0점 |
| 기술평가 예상점수 | 81.7점 | 77.2점 | -4.5점 |
| 종합 예상점수 | 89.7점 | 86.2점 | -3.5점 |
| 투입 공수 | 14 M/M | 11 M/M | -3 M/M |

감축한 3 M/M은 제안 조직의 분석, 설계와 품질확인 역할에서 차감했습니다.  
평가 의견 요지에는 수행 방법의 구체성이 부족하고 단계별 산출물 검증 인력이 충분하지 않다는 판단이 포함됐습니다.  
내부 재채점에서는 공수 감축으로 기술·지식능력 2.0점, 사업수행계획 1.5점, 지원기술·사후관리 1.0점을 잃은 것으로 추정했습니다.

1. 가격에서 얻은 1.0점과 기술에서 잃은 4.5점을 동일한 평가표에 놓고 비교하지 않았습니다.
2. 영업 단계에서는 할인율만 승인 대상으로 보았고, 할인 재원을 마련하기 위해 삭제한 역할은 검토하지 않았습니다.
3. 기술평가 적격선과의 여유가 0.7점에 불과해 정성평가의 작은 변동에도 협상적격 여부가 바뀔 수 있었습니다.
4. 기술 비중이 90%인 사업에서 가격 경쟁력을 종합점수 우위로 오인한 것이 직접 패인입니다.

이 사례 이후 평가 배점별 목표점수와 손실 허용치를 먼저 계산하는 절차를 필수화했습니다. 구체적인 역산 방법은 PRP-02#s5를 참조합니다.  
할인 승인 요청에는 할인율, 감축 공수, 삭제 역할, 기술평가 예상 손실과 적격선 여유를 함께 기재하도록 변경했습니다. 승인 항목은 PRP-03#s12를 참조합니다.

- 가격점수 1점을 얻기 위해 기술점수를 1점 넘게 포기하는 안은 거래 책임자가 재산정합니다.
- 기술평가 적격선과의 예상 차이가 3점 미만이면 공수 감축을 할인 재원으로 사용하지 않습니다.
- 할인 전후의 종합점수 차이를 계산하지 못하면 가격안을 확정하지 않습니다.

## 사례 L-03 수행 조직 신뢰를 주지 못한 제안
<!--meta: sec=s8; dept=SALES|CNS; level=시니어; ct_band=상; related=s5;-->
이 사례는 핵심 인력의 중복 투입 상태와 발표 답변 불일치로 수행 조직의 실현 가능성을 의심받은 가상 사례입니다.

| 항목 | 내용 |
|---|---|
| 고객 유형 | 수도권 제조 고객사입니다. |
| 제안 수행 기간 | 5개월입니다. |
| 핵심 인력 | 총괄 책임자 1명, 분석 책임자 1명, 개발 책임자 1명입니다. |
| 확인된 중복 | 총괄 책임자와 분석 책임자가 다른 사업 수행계획에 포함돼 있었습니다. |
| 제안서 기재 | 두 인력 모두 착수일부터 투입률 100%로 기재했습니다. |
| 결과 | 인력·조직관리기술 항목에서 감점됐습니다. |
| 패인 코드 | 주코드 L-F, 부코드 L-H입니다. |

발표 전 내부 확인에서는 총괄 책임자의 기존 일정이 종료될 예정이라는 구두 답변만 확보했습니다.  
종료일을 증명하는 배치표, 승인 기록이나 대체 인력 지정서는 제출 자료에 포함하지 못했습니다.

발표 질의에서 평가위원은 두 핵심 인력이 착수일부터 전담 가능한지 질문했습니다.  
발표자는 두 인력 모두 즉시 100% 투입한다고 답했습니다.  
동석한 주제전문가는 분석 책임자가 착수 후 첫 달에는 50%만 투입될 수 있다고 추가 답변했습니다.  
거래 책임자는 기존 사업 종료 일정이 조정 중이라고 다시 설명했습니다.

| 증거 | 확인된 내용 | 판정 |
|---|---|---|
| 평가 의견 | 핵심 인력의 실제 가용성과 투입계획에 대한 신뢰가 부족하다는 취지입니다. | 직접 근거입니다. |
| 발표 기록 | 동일 질문에 100%, 50%, 일정 조정 중이라는 세 답변이 남았습니다. | 직접 근거입니다. |
| 인력 배치표 | 두 핵심 인력의 기간 중복이 표시돼 있습니다. | 사전 확인 가능 근거입니다. |
| 발표 리허설 기록 | 투입률 질문과 답변 담당자가 지정되지 않았습니다. | 절차상 보조 근거입니다. |

내부 회고에서는 인력 보유 여부가 아니라 제안 기간 중 실제 가용 시간이 평가 대상이었다고 판정했습니다.  
중복 상태를 알고도 제안서의 100% 투입 표기를 수정하지 않은 점을 주패인으로 확정했습니다.  
발표자의 직급이나 설명 능력보다 배치 현황을 직접 확인할 권한과 자료가 없었던 점도 확인했습니다.

1. 제안 조직표에 포함할 인력별 기존 배정 기간과 투입률을 대조합니다.
2. 중복 기간이 하루라도 있으면 종료 확정, 투입률 조정 또는 대체 인력 중 하나를 제안서에 반영합니다.
3. 확인 책임자는 거래 책임자와 별도로 지정하며, 확인 일자와 근거 자료를 남깁니다.
4. 발표 답변자는 인력 배치표를 확인할 수 있고 투입 변경 권한을 설명할 수 있는 사람으로 선정합니다.

이 사례는 투입률 100%로 계획된 인력을 같은 기간의 다른 제안에 동시에 기재하지 않는 규칙의 출발점이 됐습니다.  
제안 전 중복 확인 절차와 책임자 지정 기준은 PRP-01#s11을 참조합니다.  
발표자 선정과 질의 대응 역할 기준은 PRP-02#s12를 참조합니다.

- “기존 사업이 곧 끝납니다”와 같이 확정일이 없는 답변은 가용성 증거로 인정하지 않습니다.
- 대체 인력을 제시할 때는 이름만 추가하지 않고 해당 역할의 투입률과 전환 시점을 표시합니다.
- 리허설에서 답변이 엇갈리면 사실관계를 확정할 때까지 해당 인력의 전담 표기를 보류합니다.

## 사례 L-04 레퍼런스가 요구 실적과 불일치한 제안
<!--meta: sec=s9; dept=SALES; level=시니어; ct_band=중; related=s5;-->
이 사례는 이행실적 정량 배점의 요건을 충족하지 못해 정성평가가 시작되기 전에 점수 열위가 확정된 가상 사례입니다.

| 항목 | 내용 |
|---|---|
| 고객 유형 | 수도권 제조 고객사입니다. |
| 이행실적 배점 | 4점입니다. |
| 요구 업종 | 제조업입니다. |
| 요구 규모 | 단일 계약금액 5억 원 이상입니다. |
| 인정 기간 | 공고일 기준 최근 3년 이내 완료 실적입니다. |
| 제출 결과 | 세 조건을 모두 충족한 증빙이 없었습니다. |
| 패인 코드 | 주코드 L-E, 부코드 L-A입니다. |

제안팀은 계약금액 6억 원인 비제조업 실적과 제조업 계약금액 3억 원인 실적을 각각 보유하고 있었습니다.  
전자는 규모와 기간을 충족했지만 업종이 달랐고, 후자는 업종과 기간을 충족했지만 규모가 부족했습니다.  
서로 다른 두 계약의 조건을 합산할 수 있다는 근거는 RFP와 질의응답에서 확인되지 않았습니다.

| 제출 후보 | 동일 업종 | 동일 규모 | 기간 충족 | 획득 가능점수 |
|---|---:|---:|---:|---:|
| 비제조업 6억 원 실적 | 아니요 | 예 | 예 | 0점 |
| 제조업 3억 원 실적 | 예 | 아니요 | 예 | 0점 |
| 세 조건 동시 충족 실적 | 없음 | 없음 | 없음 | 0점 |

제안팀은 유사성이 정성평가에서 설명될 수 있다는 판단으로 참여를 계속했습니다.  
그러나 이행실적 4점은 제출 서류의 요건 충족 여부로 먼저 확정되는 점수였습니다.  
경쟁사가 요건을 충족했다면 정성평가 시작 전부터 최대 4점의 격차가 발생하는 구조였습니다.  
최종 종합점수 차이는 2.7점이었으므로 해당 정량 열위가 결과를 바꿀 수 있는 크기였습니다.

1. 참여 판정 당시에는 보유 레퍼런스의 명칭과 계약금액만 확인했습니다.
2. 업종, 단일 계약 규모, 완료일을 하나의 증빙 단위로 대조하지 않았습니다.
3. 실적증명서 발급 가능 여부와 발급 소요기간을 제안 일정에 반영하지 않았습니다.
4. 획득 가능한 정량점수를 4점으로 가정해 승률을 실제보다 높게 판단했습니다.

회고에서는 정성 서술로 정량 요건 미충족을 보완할 수 없다는 점을 직접 교훈으로 확정했습니다.  
게이트 2 채점 전에 증빙 기준으로 정량 획득 가능점수를 먼저 계산하도록 변경했습니다. 세부 절차는 PRP-02#s5를 참조합니다.  
실적 증빙 묶음의 상시 관리와 유효기간 점검 기준은 PRP-01#s8을 참조합니다.

- 원본 계약, 실적증명서와 완료일 자료가 연결되지 않으면 해당 점수를 0점으로 계산합니다.
- 발급 예정인 증빙은 발급 주체와 완료 예정일이 확인된 경우에만 조건부 점수로 분리합니다.
- 정량 열위가 확인되면 이를 숨기지 않고 참여 판정표의 최대 획득점수와 예상 순위에 반영합니다.

## 사례 L-05 일정이 늦어 품질이 무너진 제안
<!--meta: sec=s10; dept=SALES|CNS; level=시니어; ct_band=중; related=s5-->
이 사례는 공고 인지가 늦어진 상태에서 참여를 강행한 결과, 필수 리뷰가 생략되고 미완성 응답이 제출본에 남은 가상 사례입니다.

| 항목 | 내용 |
|---|---|
| 공고 인지 | 표준 착수 시점을 지난 뒤 공고를 확인했습니다. |
| 참여 판정 | D-18 기준을 지키지 못했습니다. |
| RFP 해체 | D-16 완료 기준을 지키지 못했습니다. |
| 집필 시작 | D-6에 본문 집필을 시작했습니다. |
| 생략 단계 | 2차 교차 리뷰와 최종 리뷰를 실시하지 않았습니다. |
| 제출본 결함 | 요구사항 미대응 2건과 수치 근거 누락이 남았습니다. |
| 패인 코드 | 주코드 L-C, 부코드 L-H입니다. |

거래 책임자는 남은 기간에 맞춰 작성 분량을 줄였지만, 요구사항 추적표 기준의 응답 완결 여부까지 확인하지 못했습니다.  
집필자는 담당 절을 개별 검토했으나 다른 작성자가 전제한 내용과 증빙 위치를 교차 확인하지 않았습니다.  
최종본 편집 과정에서도 본문 수치와 근거 자료의 연결 상태를 판정하는 독립 검토자가 없었습니다.

제출 후 자체 대조에서 다음 결함을 확인했습니다.

1. 요구사항 두 건에 대응하는 본문과 증빙 위치가 추적표에 연결되지 않았습니다.
2. 기대 효과를 수치로 제시했지만 산출 근거가 기재되지 않았습니다.
3. 검토 이력에는 생략 승인자와 잔여 위험이 기록되지 않았습니다.
4. 제출 완료 자체를 품질 확보로 오인해 미대응 항목을 차단하지 못했습니다.

직접 원인은 리뷰 시간 부족이 아니라, 부족한 시간을 확인한 뒤에도 참여 중단 기준을 적용하지 않은 데 있습니다.  
압축 일정에서도 PRP-01#s13의 2차 교차 리뷰는 면제하지 않습니다.  
최종 리뷰를 수행할 시간과 독립 검토자를 확보하지 못하면 제출 가능 여부를 다시 판정합니다.

| 개선 조치 | 적용 기준 | 확인 증거 |
|---|---|---|
| 필수 단계 고정 | 2차 교차 리뷰를 일정 단축 대상에서 제외합니다. | 리뷰 의견과 반영 기록 |
| 탐색 경로 보강 | 공고 탐색 조치는 PRP-02#s2를 적용합니다. | 공고 접수 기록 |
| 중단 기준 추가 | 필수 리뷰 시간을 확보할 수 없으면 참여하지 않는 선택을 우선 검토합니다. | 재판정 결과 |
| 잔여 결함 차단 | 미대응 요구사항이나 근거 없는 수치가 한 건이라도 남으면 제출 승인을 보류합니다. | 제출 전 결함 목록 |

이 사례의 판단 기준은 “기한 내 파일을 낼 수 있는가”가 아니라 “면제 불가 단계를 완료한 제출본을 낼 수 있는가”입니다.

## 사례 L-06 성능을 과대 약속해 신뢰를 잃은 제안
<!--meta: sec=s11; dept=AIAX|DATA|SALES; level=시니어; ct_band=상; related=s5-->
이 사례는 제안서에 특정 정확도 수치를 조건 없이 기재하고, 발표 질의에서 측정 조건을 설명하지 못해 기술 신뢰를 잃은 가상 사례입니다.

| 항목 | 내용 |
|---|---|
| 제안 표현 | 특정 정확도를 달성한다고 단정했습니다. |
| 누락 정보 | 데이터셋 성격, 표본 수와 평가 방식이 없었습니다. |
| 발표 질의 | 수치의 산출 조건과 재현 절차를 답변하지 못했습니다. |
| 평가 영향 | 성능 수치뿐 아니라 기술 설명 전반의 신뢰도가 낮아졌습니다. |
| 패인 코드 | 주코드 L-C, 부코드 L-F입니다. |
| 잠재 계약 위험 | 해당 문구가 계약 문서에 편입될 가능성이 있었습니다. |

제안 단계에서 AIAX와 DATA는 내부 실험 결과의 적용 범위를 확인했지만, 문안에는 그 범위가 반영되지 않았습니다.  
SALES는 차별성을 강조하기 위해 수치를 유지했고, 발표자는 어떤 데이터와 절차를 전제로 한 값인지 확인하지 않은 채 답변에 참여했습니다.

평가위원 질의는 다음 세 지점에 집중되었습니다.

1. 고객사 데이터와 내부 검증 데이터의 성격이 같은지 확인했습니다.
2. 정확도를 계산한 표본 수와 표본 선정 방식을 물었습니다.
3. 단일 측정값인지 반복 평가 결과인지 확인했습니다.
4. 구축 완료 후 동일한 기준으로 합격 여부를 판정할 수 있는지 질의했습니다.

발표팀은 조건별 답변을 연결하지 못했고, 수치가 목표인지 보장값인지도 일관되게 구분하지 못했습니다.  
그 결과 제안서의 다른 기술 설명까지 검증되지 않은 주장으로 받아들여질 여지가 생겼습니다.

더 큰 위험은 실주가 아니라 수주였을 때 발생할 수 있었습니다.  
조건 없는 수치가 계약 문서의 일부가 되면 검수 또는 하자 판단의 기준으로 해석될 가능성이 있으므로 문서 우선순위는 PRP-04#s2를 확인합니다.  
AI 관련 성능 조건의 계약 반영 방식은 PRP-04#s16을 적용하며, 구체적 법적 효과는 사안별 확인이 필요합니다.

| 개선 조치 | 적용 방법 | 통과 기준 |
|---|---|---|
| 수치 기재 통제 | PRP-01#s7의 수치 기재 4요소를 모두 작성합니다. | 한 요소라도 없으면 수치를 삭제하거나 보완합니다. |
| 검증 책임 지정 | AIAX 또는 DATA 검토자가 성능 문안을 승인합니다. | 승인자와 근거 위치가 기록돼야 합니다. |
| 발표 답변 정합화 | 제안서 조건과 발표 답변 자료를 같은 근거에 연결합니다. | 조건·수치·검증 절차가 서로 모순되지 않아야 합니다. |
| 약속 형식 전환 | PRP-01#s15에 따라 성능 약속을 합격 기준과 평가 절차 문안으로 전환합니다. | 측정 가능하고 재현 가능한 판정 문안이어야 합니다. |

이 사례는 패배 원인인 동시에 수주 후 분쟁 가능성을 피한 사례입니다.  
따라서 회고에서는 “어떻게 이길 것인가”뿐 아니라 “이겼을 때 이행할 수 있는 약속인가”를 별도 질문으로 남깁니다.

## 수주했지만 위험했던 사례
<!--meta: sec=s12; dept=SALES|CNS; level=시니어; ct_band=상; related=s2-->
수주 건 회고에서는 최종 결과와 별개로, 결과가 바뀔 수 있었던 지점과 계약 이행을 위협한 판단을 확인합니다.  
다음 사례들은 수주 성공이 당시 절차의 적정성을 증명하지 않는다는 점을 보여줍니다.

| 사례 | 거의 진 지점 또는 수행 위험 | 회고에서 확인한 사실 | 변경한 조치 |
|---|---|---|---|
| W-01 의도와 다른 결정 요인 | 2위와의 점수 차가 작았습니다. | 고객이 선택한 주된 이유는 제안팀이 강조한 기술 강점이 아니라 대금 조건이었습니다. | 의도한 강점과 고객이 실제로 인식한 결정 요인을 분리해 기록하도록 했습니다. |
| W-02 여력 과대평가 | 착수 후 핵심 인력을 확보하지 못했습니다. | 참여 판정 당시 여력 점수가 실제 가용 상태보다 높았고, 착수 후 2개월 동안 핵심 인력 배치가 지연됐습니다. | 여력 점수에는 예정 인력의 가용 시점과 중복 계획 확인 자료를 첨부하도록 했습니다. |
| W-03 버퍼의 할인 전용 | 가격 승인 과정에서 수행 여유가 사라졌습니다. | 리스크 대응용 버퍼가 할인 재원으로 사용됐지만 잔여 위험은 다시 산정되지 않았습니다. | 버퍼를 일반 할인 재원에서 제외하고, 예외 사용 시 가격과 위험을 함께 재검토하도록 했습니다. |

W-01에서는 수주 제안서의 핵심 메시지가 고객의 실제 선택 논리와 일치하지 않았습니다.  
같은 메시지를 다음 제안에 그대로 재사용하면 우연한 성공을 반복 가능한 강점으로 오판할 수 있었습니다.  
이후 회고 기록에는 “제안팀이 의도한 승리 요인”과 “고객이 확인한 승리 요인”을 별도 항목으로 둡니다.

W-02에서는 참여 당시 조직도에 인력 이름이 기재돼 있었지만, 해당 인력의 실제 배치 가능 상태가 확인되지 않았습니다.  
수주 직후 대체 인력을 찾는 동안 초기 의사결정과 고객 협의가 지연됐습니다.  
이후에는 인력 명단만으로 여력을 인정하지 않고, 가용 시점과 중복 투입 여부를 판정 근거로 남깁니다.

W-03에서는 가격을 낮추는 과정에서 명시적 버퍼가 먼저 삭감됐습니다.  
계약금액은 승인 범위에 들어왔지만, 위험 발생 시 사용할 재원이 없어져 수행 손익의 변동 가능성이 커졌습니다.  
구체적인 할인 승인과 버퍼 통제는 PRP-03#s9 및 PRP-03#s10을 참조합니다.

수주 건 회고는 다음 순서로 판정합니다.

1. 2위 또는 차순위와의 격차가 작았다면 결과를 바꿀 수 있었던 단일 요인을 찾습니다.
2. 고객이 선택한 이유와 내부에서 예상한 이유가 일치하는지 비교합니다.
3. 참여 판정 당시의 전제가 착수 시점에도 유효했는지 확인합니다.
4. 가격 승인으로 제거된 공수·버퍼·조건이 수행 위험으로 이전됐는지 점검합니다.
5. 확인된 취약점은 실주 사례와 동일하게 패인 후보로 등록합니다.

좋은 결과는 절차상 결함을 상쇄하지 않습니다.  
수주했더라도 같은 판단을 다시 적용했을 때 실패하거나 손실이 발생할 수 있다면 개선 조치를 완료할 때까지 위험 사례로 유지합니다.

## 패턴 집계와 반복 패인
<!--meta: sec=s13; dept=SALES; level=시니어; ct_band=상; related=s5-->
SALES 과장 이상 담당자는 매 분기 종료 후 10영업일 이내에 해당 분기의 수주·실주 회고를 합산합니다. 집계 단위는 제안 건이며, 하나의 제안에 복수 코드가 있으면 주코드 건수와 부코드 건수를 분리합니다. 코드 부여 기준은 PRP-06#s5를 따릅니다.

| 집계 축 | 필수 열 | 산식 또는 표시 방법 | 확인 목적 |
|---|---|---|---|
| 패인 코드별 건수 | 주코드, 부코드, 건수, 비율 | 코드 건수÷회고 완료 건수 | 반복 패인 식별 |
| 발주 유형별 패인 분포 | 발주 유형, 주코드, 건수 | 유형별 교차표 | 특정 발주 방식의 취약점 확인 |
| 금액 구간별 승률 | 제안금액 구간, 수주, 실주, 미결 | 수주÷결과 확정 건수 | 거래 규모별 결과 차이 확인 |
| 참여 판정 점수대별 결과 | 점수대, 수주, 실주, 철회 | 결과별 건수와 승률 병기 | 사전 판정의 구분력 확인 |
| 조건부 Go 결과 | 부가 조건, 이행 여부, 결과 | 이행·미이행별 결과 분리 | 승인 조건의 실효성 확인 |

금액 구간과 참여 판정 점수대는 분기 중 임의로 바꾸지 않습니다. 구간 변경이 필요하면 기존 기준과 변경 기준을 함께 적용한 연결표를 1회 작성하여 시계열 단절을 표시합니다.

반복 패인은 같은 주코드가 한 분기 안에 3건 이상 확인된 경우로 판정합니다. 부코드만 3건 이상인 경우에는 반복 징후로 표시하되 반복 패인으로 확정하지 않습니다.

1. 분모에는 결과가 확정되고 회고가 완료된 건만 포함합니다.
2. 철회, 무효, 결과 미통보 건은 승률 산식에서 제외하고 별도 건수로 표시합니다.
3. 조건부 Go는 승인 당시 조건과 실제 이행 여부를 나누어 집계합니다.
4. 발주 유형을 확인할 수 없는 건은 추정하지 않고 ‘미확인’으로 분류합니다.
5. 주코드 변경 이력이 있으면 최종 확정 코드로 집계하고 변경 전 코드는 주석에 남깁니다.

분기 보고서의 모든 비율에는 분자와 분모를 함께 기재합니다. “승률이 낮습니다”라고만 쓰지 않고 “결과 확정 8건 중 수주 2건, 25%”와 같이 표시합니다.

- 표본이 5건 미만인 구간은 ‘소표본’으로 표시하고 전사 경향으로 일반화하지 않습니다.
- 단일 고객사 또는 단일 발주 유형이 표본의 절반을 초과하면 편중 여부를 주석으로 남깁니다.
- 전 분기 대비 증감은 동일한 집계 기준이 유지된 경우에만 계산합니다.
- 인터뷰가 확보되지 않은 건의 원인은 내부 근거 기반이라는 제한을 명시합니다.
- 수치 없이 참석자의 인상만으로 증가·감소·주요 원인을 결론 내리지 않습니다.

집계 결과 중 요구 해석·표현 문제는 제안 가이드 개정 후보로, 원가·할인·난이도 문제는 단가 및 계수 재검토 후보로 보냅니다. 역량 부족이 반복된 항목은 해당 수행 부서의 역량 투자 제안으로 전환합니다. 실제 반영 절차는 PRP-06#s14를 따릅니다.

분기 보고서에는 원자료 목록, 제외 건과 제외 사유, 반복 패인, 검토 요청 항목을 첨부합니다. SALES 부장은 보고서의 산식과 표본 수를 확인한 뒤 관련 부서에 배포합니다.

## 조치 반영 경로
<!--meta: sec=s14; dept=SALES|CNS; level=시니어; ct_band=중; related=s13-->
회고 조치는 담당 문서, 승인자, 완료일과 검증 방법이 지정된 경우에만 확정 조치로 등록합니다. 단순 의견은 후보 상태로 두며 담당자나 시한을 임의로 채우지 않습니다.

| 조치 유형 | 대상 문서·절차 | 승인자 | 반영 시한 | 확인 방법 |
|---|---|---|---|---|
| 가이드 개정 | PRP-01 해당 섹션 | SALES 부장 | 승인 후 10영업일 | 개정 이력과 적용본 확인 |
| 체크리스트 항목 추가 | PRP-01 제출 체크리스트 또는 PRP-02 입찰 절차 | SALES 부장 | 승인 후 5영업일 | 다음 제안 체크 기록 확인 |
| 단가·계수 변경 | PRP-03 산정 기준 | SALES 부장과 수행 주관 부서 부장 | 다음 견적 착수 전 | 산정표 버전과 계산 결과 대조 |
| 판정 가중치 변경 | PRP-05 판정 기준 | SALES 부장 | 다음 분기 시작 전 | 변경 전후 과거 건 재계산 |
| 템플릿 추가 | 해당 문서의 부속 양식 | 문서 소관 부서 부장 | 승인 후 10영업일 | 저장소 등록과 사용 기록 확인 |
| 교육 | 관련 부서 교육 자료 | 교육 대상 부서 부장 | 승인 후 20영업일 | 참석 기록과 적용 과제 확인 |

수행 주관 부서는 조치 내용에 따라 CNS, AIAX, BE 또는 DATA로 지정합니다. 둘 이상의 부서에 영향을 주면 각 부서 승인 의견을 받은 뒤 소관 부서 부장이 최종본을 확정합니다.

1. 거래 책임자는 회고 조치 등록부에 조치 ID, 근거 사례, 패인 코드와 제안자를 입력합니다.
2. 문서 소관자는 3영업일 이내에 수용, 보완 요청, 보류 또는 기각으로 상태를 지정합니다.
3. 수용 건에는 대상 버전, 담당자, 예정일과 검증 제안을 기록합니다.
4. 보류·기각 건에는 비용, 적용 충돌, 표본 부족 등 판단 근거를 한 줄 이상 남깁니다.
5. 완료 건은 개정 문서 링크 또는 교육 기록이 첨부된 때에만 닫습니다.

미결 목록은 `제안 조치 등록부`에서 단일 관리합니다. 상태는 후보, 검토 중, 승인, 반영 완료, 효과 확인, 종결로 제한하며, 예정일이 지난 건은 지연 일수와 차단 사유를 표시합니다.

SALES 과장 이상 담당자는 매월 첫 영업주에 미결 목록을 확인합니다. 10영업일 이상 지연된 건은 승인자에게 재확인을 요청하고, 20영업일 이상 지연된 건은 SALES 부장과 대상 부서 부장에게 함께 보고합니다.

반영 효과는 적용 후 동일 패인 코드가 포함된 제안 3건 또는 1개 분기가 지난 시점 중 먼저 도래한 때 확인합니다. 확인 결과에는 재발 건수, 조치 적용 여부와 적용했음에도 재발한 사유를 구분하여 적습니다.

재발이 없더라도 표본이 3건 미만이면 효과가 입증됐다고 판정하지 않습니다. 재발 건이 확인되면 조치 미준수와 조치 자체의 부족을 분리하여 후속 항목을 등록합니다.

새 규칙이 작성 시간을 늘리거나 예외 승인을 반복 발생시키면 폐지·완화 후보로 올립니다. 폐지와 완화도 신규 조치와 동일한 승인자, 시한, 검증 절차를 적용하며 구두 합의만으로 기존 기준을 중단하지 않습니다.

## 기록 보관과 열람 범위
<!--meta: sec=s15; dept=SALES; level=주니어|시니어; ct_band=하; related=s1-->
회고 자료는 회사가 승인한 사내 문서 저장소의 제안 회고 영역에 보관합니다. 개인 PC, 개인 메일함, 외부 메신저 또는 승인되지 않은 클라우드에는 저장하지 않습니다.

| 기록 구분 | 포함 자료 | 기본 보관 기간 | 열람 범위 |
|---|---|---|---|
| 원본 기록 | 고객 인터뷰 메모, 평가 의견 원문, 원본 증빙 | 결과 확정일로부터 3년 | 거래 책임자, SALES 과장 이상, 관련 부서 부장 |
| 내부 작업본 | 디브리프 메모, 코드 검토표, 조치 초안 | 조치 종결 후 1년 | 해당 회고 참석자와 조치 담당자 |
| 사례집 수록본 | 고객·담당자 식별 정보를 제거한 사례 | 현행 사례집 수록 기간 | 임직원 |
| 분기 집계본 | 건수, 비율, 반복 패인과 조치 후보 | 작성일로부터 3년 | 임직원 |

계약상 보관·삭제 조건이 기본 기간과 다르면 해당 조건을 우선 검토합니다. 개인정보, 영업비밀 또는 분쟁 관련 보존 의무는 사안별 확인이 필요합니다.

원본 기록과 사례집 수록본은 같은 폴더에 두지 않습니다. 원본은 발언의 문맥과 증거를 보존하기 위한 자료이며, 수록본은 재사용 과정에서 고객사와 개인이 식별되지 않도록 가공한 자료입니다.

고객 발언을 사례집에 인용할 때에는 고객사명, 인물명, 직책, 사업명, 지역·업종·금액의 고유한 조합을 제거합니다. 직접 인용이 식별 가능성을 높이면 의미를 바꾸지 않는 범위에서 간접 인용으로 전환합니다.

- 고객이 비공개를 요청한 내용은 원본 접근 제한 영역에만 보관합니다.
- 비공개 발언은 사례집, 분기 보고서, 교육 자료와 발표 슬라이드에 옮기지 않습니다.
- 인터뷰 메모를 다른 제안의 고객 증빙이나 레퍼런스로 사용하지 않습니다.
- 원본의 화면 캡처나 파일 사본을 교육 참석자에게 배포하지 않습니다.

사례집은 내부 업무와 사내 교육에만 사용합니다. 고객사, 협력사, 입찰 관계자 또는 외부 강사에게 열람시키거나 파일로 전달해서는 안 됩니다.

신규 입사자 교육본에서는 고객사 식별 단서, 제안금액, 평가위원 발언 원문, 담당자 이름, 연락처, 문서 링크와 미공개 계약 조건을 제거합니다. 교육 담당자는 배포 전에 SALES 과장 이상의 확인을 받습니다.

열람 권한 변경과 퇴직자 권한 회수는 승인된 사내 저장소의 접근 권한으로 처리합니다. 보관 기간이 끝난 자료는 소관자가 삭제 후보를 확인하고, 진행 중인 조치나 분쟁과 연결되지 않은 경우에만 삭제합니다.

## 회고에서 하지 않는 것
<!--meta: sec=s16; dept=SALES|CNS; level=주니어|시니어; ct_band=중; related=s3-->
회고는 잘못한 사람을 찾는 자리가 아니라, 당시의 판단 조건과 업무 구조에서 다시 발생할 수 있는 실패 요인을 제거하는 자리입니다. 책임 범위 확인은 필요하지만 인격, 태도 또는 의도를 평가 대상으로 삼지 않습니다.

| 금지 사항 | 금지 이유 | 대신 할 일 |
|---|---|---|
| 개인의 실수나 역량 부족으로 결론냅니다. | 참석자가 불리한 정보를 숨기고 방어적으로 답하게 됩니다. | 의사결정 시점의 정보, 역할 배분, 검토 지점과 승인 조건을 확인합니다. |
| 결과를 알고 난 뒤 당시 판단을 당연한 오판으로 평가합니다. | 사후에 확보된 정보를 과거에도 알 수 있었던 것처럼 취급하게 됩니다. | 당시 열람 가능했던 문서와 날짜가 남은 기록만으로 판단의 합리성을 검토합니다. |
| 고객의 평가 방식, 담당자 성향 또는 이해 부족을 패인으로 단정합니다. | 내부에서 바꿀 수 있는 응답 방식과 사전 확인 기회를 놓치게 됩니다. | 관찰된 고객 행동과 우리 측 대응을 분리하고, 다음 제안에서 통제할 수 있는 항목을 찾습니다. |
| 모든 원인을 외부 변수나 통제 불가 항목으로 처리합니다. | 위험 노출을 줄이거나 대응할 수 있었던 선택까지 분석에서 제외됩니다. | 외부 사건 자체와 사전 탐지, 완화 조치, 대응 속도를 각각 판정합니다. |
| 원인 확인만 하고 후속 조치 없이 종료합니다. | 동일한 조건이 다음 제안에 그대로 남습니다. | 실행 가능한 조치 후보를 작성하고 확정 절차는 PRP-06#s14를 따릅니다. |
| “더 신경 씁니다”, “주의합니다”, “역량을 높입니다”로 조치를 끝냅니다. | 완료 여부와 재발 방지 효과를 확인할 수 없습니다. | 필수 입력란, 검토 게이트, 자동 확인 또는 승인 조건처럼 실행 흔적이 남는 통제로 바꿉니다. |

회고 진행자는 다음 발언 규칙을 적용합니다.

1. 사람 이름 대신 사건, 역할과 결정 시점을 주어로 사용합니다.
2. “왜 그것도 몰랐습니까” 대신 “그 시점에 확인 가능했던 정보는 무엇이었습니까”라고 질문합니다.
3. 동기나 의도를 추정하는 발언이 나오면 근거가 있는 행동 또는 기록으로 다시 표현하도록 요청합니다.
4. 비꼼, 인신평가, 공개 사과 요구와 개인별 서열화 발언은 즉시 중단시킵니다.
5. 반대 의견을 발언자의 직급으로 기각하지 않으며, 질문별 증거 취급 기준은 PRP-06#s3을 적용합니다.
6. 특정 개인에게 답변이 집중되면 관련 역할별로 확인 순서를 나누고, 다른 참석자의 보완 또는 이견을 받습니다.
7. 회고 중 계약상 책임이나 법률 판단이 제기되면 현장에서 확정하지 않으며 사안별 확인이 필요하다고 기록합니다.

다음 신호 중 하나라도 나타나면 진행자는 형식적 회고로 판정하고 해당 안건을 보완 대상으로 남깁니다.

- 모든 실주 건의 결론이 가격 또는 고객 사정으로 동일합니다.
- 참석자 전원의 의견이 근거 확인 없이 처음부터 일치합니다.
- 질문마다 “특이사항 없음”이 반복되지만 제안 결과와 평가 의견의 차이는 설명되지 않습니다.
- 원인 문장에 사건이나 조건 없이 사람 이름만 남습니다.
- 조치 문장이 주의, 독려, 교육 강화와 같은 표현으로만 구성됩니다.
- 이전 회고와 같은 문제가 발생했는데 기존 조치의 적용 여부를 확인하지 않습니다.
- 불편한 쟁점이 회의록에서 삭제되거나 미확인 상태인 항목이 확정 사실로 바뀝니다.

진행자는 형식화 신호를 발견한 경우 회고 완료로 표시하지 않으며, 누락된 근거 또는 실행 가능한 조치가 보완된 뒤 종료합니다.
