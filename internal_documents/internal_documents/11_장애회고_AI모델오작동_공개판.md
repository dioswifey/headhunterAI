# INC-AI-01 콜센터 AI 응답 오류 — 요약
<!--meta: doc=INC-AI-PUB; doc_type=incident; tier=2; topic=CC; disclosure=abstract; status=resolved-->

## 개요
<!--meta: sec=s1; dept=AIAX; level=주니어|시니어; ct_band=중; related=PRJ-CC-PUB-->
콜센터 AI 상담 시스템 도입 2주 차에, 매뉴얼에 없는 내용을 AI가 지어내 상담사에게 보여주는 사례가 일부 발견되었습니다. 발견 즉시 해당 기능을 제한하고 수정했습니다.

본 장애는 AI가 직접 고객에게 답변하는 자동 상담 단계가 아니라, 상담사가 참고할 답변을 생성하는 상담 지원 단계에서 확인되었습니다. 상담사는 화면에 표시된 문장을 검토한 뒤 고객에게 안내하도록 운영되고 있었으며, 확인된 부정확한 문장은 상담사 검토 과정에서 발견되었습니다.

오류의 핵심은 검색된 근거가 충분하지 않은 상황에서도 시스템이 자연스러운 문장을 완성하려 한 것입니다. 문장 자체는 읽기 자연스러웠지만, 일부 내용은 등록된 상담 매뉴얼과 지식 문서에서 확인할 수 없었습니다. 헤드헌터랩은 이를 단순 문장 품질 문제가 아니라 업무 근거가 없는 답변 생성 문제로 분류했습니다.

공개판에서는 고객사 식별 정보, 실제 상담 문장, 내부 모델 설정값, 검색 인덱스 구성, 배포 환경 정보 및 상세 임계값을 제외하고 장애의 원인 유형과 재발 방지 원칙을 설명합니다.

## 장애 분류
<!--meta: sec=s2a; dept=AIAX; level=주니어|시니어; ct_band=하; related=INC-AI-PUB-->
INC-AI-01은 다음과 같이 분류되었습니다.

- 장애 영역: 콜센터 AI 상담 지원
- 장애 유형: 근거 없는 응답 생성
- 사용자 노출 범위: 상담사 지원 화면
- 고객 직접 응답 여부: 직접 자동 응답 단계 아님
- 주요 위험: 잘못된 업무 안내 가능성
- 탐지 경로: 상담사 검토 및 운영 피드백
- 즉시 조치: 관련 답변 생성 기능 제한
- 최종 상태: 수정 및 검증 완료
- 공개 등급: 요약 공개
- 후속 관리: 정기 품질 점검 항목으로 전환

이번 장애에서 사용하는 “오작동”은 시스템 전체가 중단되거나 모델 서버가 응답하지 않은 상태를 뜻하지 않습니다. 시스템은 기술적으로 응답을 생성했지만, 응답 내용이 업무상 요구되는 근거 기준을 충족하지 못했습니다.

## 고객 및 업무 영향
<!--meta: sec=s2b; dept=CONSULT; level=주니어|시니어; ct_band=중; related=PRJ-CC-PUB-->
확인된 오류는 상담사의 업무 보조 화면에 표시되는 추천 답변 일부에서 발생했습니다. 상담사가 최종 안내 전 내용을 검토하는 절차가 있었기 때문에, 발견 즉시 문제 문장을 사용하지 않고 담당자에게 전달할 수 있었습니다.

잠재 영향은 다음과 같이 평가했습니다.

1. 상담사가 생성 답변을 그대로 사용할 경우 잘못된 정책이나 절차가 안내될 수 있음
2. 실제 매뉴얼과 다른 표현이 반복되면 상담 품질의 일관성이 저하될 수 있음
3. 답변이 자연스러울수록 근거가 없는 내용을 식별하기 어려울 수 있음
4. 상담사가 AI 추천 결과를 신뢰하지 않게 되어 시스템 활용률이 낮아질 수 있음
5. 오류 정정에 추가 확인 시간이 필요해 평균 상담 시간이 늘어날 수 있음

장애 대응에서는 실제 발생한 영향뿐 아니라 발생 가능한 업무 영향도 함께 평가했습니다. 특히 생성형 AI의 오류는 시스템 장애처럼 명확한 실패 신호를 남기지 않을 수 있으므로, 문장이 생성되었다는 사실과 업무상 올바른 답변이라는 판단을 분리했습니다.

## 발견 경위
<!--meta: sec=s3; dept=CONSULT; level=주니어; ct_band=하; related=PRJ-CC-PUB-->
도입 초기 안정화 기간 중 상담사가 추천 답변과 기존 매뉴얼을 비교하는 과정에서 내용 불일치를 발견했습니다. 해당 상담사는 추천 문장이 자연스럽지만 본인이 알고 있는 업무 기준과 다르다고 판단해 운영 담당자에게 확인을 요청했습니다.

운영 담당자는 동일한 유형의 질문을 재확인하고 다음 항목을 점검했습니다.

- 답변에 표시된 근거 문서가 실제로 존재하는지
- 표시된 문서에 해당 안내 내용이 포함되어 있는지
- 질문 표현을 바꾸어도 동일한 내용이 생성되는지
- 검색 결과가 없는 상태에서도 답변이 생성되는지
- 유사한 상담 유형에서 같은 문제가 나타나는지

점검 결과, 시스템이 충분한 검색 근거를 확보하지 못했음에도 일반적인 문장 패턴을 이용해 답변을 완성할 수 있는 상태임을 확인했습니다. 이후 운영 담당자가 AI/AX개발팀에 장애로 접수했습니다.

## 초기 대응
<!--meta: sec=s4; dept=AIAX; level=주니어|시니어; ct_band=중; related=INC-AI-PUB-->
장애 접수 직후 정확하지 않은 답변이 추가로 제시되지 않도록 관련 기능의 사용 범위를 제한했습니다. 대응 순서는 다음과 같습니다.

1. 문제 질문과 생성 결과 보존
2. 관련 상담 유형의 추천 답변 생성 제한
3. 상담사에게 매뉴얼 우선 확인 안내
4. 동일하거나 유사한 질문의 재현 시험
5. 검색 결과와 생성 답변 간 일치 여부 점검
6. 근거 부족 시 답변을 중단하는 임시 규칙 적용
7. 수정 버전 검증 후 제한적 재개
8. 안정화 확인 후 정상 운영 전환

초기 대응의 우선순위는 원인 분석보다 잘못된 답변의 추가 노출을 막는 것이었습니다. 세부 원인을 아직 확정하지 못한 단계에서도 안전한 방향으로 기능을 축소할 수 있도록 운영 권한과 대응 절차를 사용했습니다.

## 장애 타임라인
<!--meta: sec=s5; dept=AIAX; level=주니어|시니어; ct_band=중; related=INC-AI-PUB-->
공개 가능한 범위의 상대 타임라인은 다음과 같습니다.

| 단계 | 주요 내용 | 판단 기준 |
|---|---|---|
| 도입 2주 차 | 상담사가 매뉴얼과 다른 추천 답변 발견 | 업무 기준 불일치 |
| 최초 접수 | 운영 담당자가 문제 사례 확보 | 재현 가능한 입력 및 출력 보존 |
| 즉시 제한 | 관련 답변 기능의 사용 범위 축소 | 추가 노출 방지 |
| 원인 확인 | 검색 근거가 부족해도 답변이 생성되는 흐름 확인 | 검색 결과와 답변의 근거 일치 여부 |
| 수정 적용 | 근거 부족 시 답변 중단 및 확인 필요 표시 | 안전한 응답 우선 |
| 회귀 검증 | 정상 질문, 모호한 질문, 근거 없는 질문을 구분해 시험 | 기존 정상 기능 유지 여부 |
| 운영 재개 | 제한된 범위부터 단계적으로 재개 | 검증 항목 통과 |
| 사후 관리 | 정기 평가 및 운영 점검 항목 추가 | 재발 징후 조기 탐지 |

장애 대응 시간의 세부 수치는 공개판에서 제공하지 않습니다. 다만 최초 확인 후 기능 제한이 우선 수행되었고, 수정과 검증을 마친 뒤 단계적으로 운영을 재개했습니다.

## 핵심 원인
<!--meta: sec=s6; dept=AIAX; level=시니어; ct_band=상; related=INC-AI-PUB-->
핵심 원인은 검색 결과가 충분하지 않은 경우에도 생성 단계가 답변 작성을 계속할 수 있었던 점입니다. 시스템은 질문과 관련된 문서를 검색한 뒤 해당 내용을 바탕으로 답변하도록 설계되었으나, 당시 응답 흐름에는 “근거가 약하면 반드시 답변을 중단한다”는 통제가 충분히 강하게 적용되지 않았습니다.

생성형 AI는 다음 단어를 확률적으로 이어 자연스러운 문장을 만들 수 있습니다. 이 특성 때문에 검색 문서에 답이 없더라도 일반적으로 그럴듯한 절차나 표현을 조합할 수 있습니다. 그러나 콜센터 상담 업무에서는 자연스러운 문장보다 승인된 매뉴얼에 근거한 정확한 문장이 우선입니다.

원인 분석에서는 모델 자체의 특성만을 문제로 보지 않았습니다. 모델이 근거 없이 문장을 생성할 가능성을 전제로 시스템이 이를 차단했어야 하므로, 다음과 같은 통제 부족을 함께 원인으로 판단했습니다.

- 검색 근거 부족 상태를 명확히 판정하는 규칙 부족
- 근거 부족 판정과 생성 중단 동작의 결합 부족
- 답변 문장별 근거 확인 절차 미흡
- 정상 질문 중심의 시험 비중이 높았던 점
- “답변하지 않는 것이 더 안전한 질문”에 대한 검증 부족
- 운영 화면에서 확인 필요 상태를 구분하는 표현 부족

## 기여 요인
<!--meta: sec=s7; dept=AIAX; level=시니어; ct_band=상; related=INC-AI-PUB-->
장애를 직접 발생시킨 단일 조건 외에도 여러 기여 요인이 확인되었습니다.

### 질문 표현의 다양성

상담사는 동일한 업무 내용을 여러 방식으로 질문합니다. 질문이 짧거나 주어가 생략된 경우 검색어가 충분히 구성되지 않을 수 있습니다. 일상적인 상담 표현은 매뉴얼의 공식 용어와 다를 수 있어 관련 문서가 검색되지 않거나 연관성이 낮은 문서가 선택될 가능성이 있습니다.

### 자연스러움과 정확성의 혼동

언어 모델의 답변은 문법적으로 자연스럽고 설명 구조도 완성되어 보일 수 있습니다. 이 때문에 일반적인 소프트웨어 오류처럼 즉시 비정상으로 인식되지 않을 수 있습니다. 자연스러운 문장 품질과 업무 정확도를 별도로 평가해야 했습니다.

### 정상 사례 중심 검증

도입 전 검증에는 자주 발생하는 상담 질문과 정상적인 매뉴얼 조회가 포함되어 있었습니다. 반면 매뉴얼에 답이 없는 질문, 여러 정책이 섞인 질문, 지나치게 짧은 질문처럼 답변을 거절해야 하는 사례의 비중은 상대적으로 충분하지 않았습니다.

### 생성 우선 동작

기존 흐름은 상담사에게 가능한 한 도움을 주는 방향으로 답변 생성을 우선했습니다. 장애 이후에는 도움을 주는 것보다 근거가 불충분한 답변을 만들지 않는 것을 우선하도록 정책을 변경했습니다.

## 근본 원인 분석 방식
<!--meta: sec=s8; dept=AIAX; level=시니어; ct_band=상; related=INC-AI-PUB-->
근본 원인 분석은 “모델이 틀렸다”는 결론에서 멈추지 않고, 오류가 상담사 화면까지 전달될 수 있었던 시스템 조건을 역순으로 확인하는 방식으로 수행했습니다.

1. 왜 잘못된 내용이 표시되었는가  
   생성 단계가 매뉴얼에 없는 내용을 포함한 문장을 만들었기 때문입니다.

2. 왜 생성 단계가 문장을 만들었는가  
   검색 근거가 충분하지 않아도 답변 생성을 중단하지 않았기 때문입니다.

3. 왜 근거 부족 상태에서 중단되지 않았는가  
   근거 판정 결과와 최종 응답 정책의 연결이 충분히 강하지 않았기 때문입니다.

4. 왜 검증 단계에서 발견되지 않았는가  
   정상적인 질문과 검색 성공 사례에 비해 근거 없는 질문의 시험 범위가 부족했기 때문입니다.

5. 왜 운영에서 상담사 검토에 의존했는가  
   AI 추천 결과가 보조 정보라는 운영 원칙은 있었지만, 시스템 수준의 자동 차단 장치가 그 원칙을 충분히 뒷받침하지 못했기 때문입니다.

따라서 근본 원인은 생성형 AI의 일반적 한계, 검색 결과의 불확실성, 응답 통제 및 시험 설계 부족이 결합된 것으로 정리했습니다.

## 재발 방지
<!--meta: sec=s2; dept=AIAX; level=주니어|시니어; ct_band=중; related=PRJ-CC-PUB-->
검색 결과에 없는 내용은 답변하지 않고 "확인 필요"로 표시하도록 응답 로직을 변경했습니다.

수정된 응답 원칙은 다음과 같습니다.

- 승인된 자료에서 확인할 수 있는 내용만 답변합니다.
- 검색 결과가 없거나 관련성이 부족하면 답변을 생성하지 않습니다.
- 서로 충돌하는 근거가 검색되면 하나를 임의로 선택하지 않습니다.
- 질문이 모호하면 추정하지 않고 추가 확인을 요청합니다.
- 답변에 필요한 핵심 조건이 누락되면 “확인 필요”로 처리합니다.
- 답변과 함께 상담사가 확인할 근거 위치를 제공합니다.
- 근거에 없는 숫자, 기간, 자격 조건 및 예외 절차를 새로 만들지 않습니다.
- 시스템이 답변하지 않은 사례도 품질 개선 자료로 분류합니다.

“확인 필요”는 시스템 실패 메시지가 아니라 안전한 업무 상태입니다. 상담사는 이 표시를 확인하면 기존 매뉴얼을 직접 조회하거나 담당 부서에 문의할 수 있습니다.

## 수정된 응답 흐름
<!--meta: sec=s9; dept=AIAX; level=주니어|시니어; ct_band=중; related=INC-AI-PUB-->
수정 이후의 공개 수준 응답 흐름은 다음과 같습니다.

1. 상담사의 질문을 접수합니다.
2. 질문에서 상담 업무에 필요한 핵심 용어와 조건을 확인합니다.
3. 승인된 상담 자료만 검색합니다.
4. 검색 결과가 질문과 직접 관련되는지 평가합니다.
5. 답변에 필요한 근거가 모두 포함되었는지 확인합니다.
6. 근거가 충분하면 해당 범위 안에서 답변을 작성합니다.
7. 근거가 없거나 불충분하면 답변 생성을 중단합니다.
8. 상담사 화면에 “확인 필요” 상태와 후속 확인 방법을 표시합니다.
9. 생성된 답변은 최종 표시 전에 근거 범위를 벗어나는 표현이 있는지 추가 확인합니다.
10. 운영 로그에는 질문, 검색 성공 여부, 응답 상태 및 확인 필요 사유를 구분해 남깁니다.

이 흐름은 검색된 문서를 그대로 화면에 보여주는 것과 다릅니다. 검색 결과를 이용해 문장을 생성하더라도, 생성 문장의 각 핵심 내용은 검색된 근거 범위 안에 있어야 합니다.

## 응답 상태 체계
<!--meta: sec=s10; dept=AIAX; level=주니어; ct_band=하; related=INC-AI-PUB-->
상담사가 AI 답변의 상태를 쉽게 구분할 수 있도록 응답 상태를 단순화했습니다.

| 상태 | 의미 | 상담사 행동 |
|---|---|---|
| 근거 확인 | 승인된 자료에서 답변 근거가 확인됨 | 근거와 답변을 검토한 뒤 사용 |
| 추가 질문 필요 | 질문에 필수 조건이 부족함 | 누락된 조건을 확인해 다시 질문 |
| 확인 필요 | 근거가 없거나 충분하지 않음 | 매뉴얼 직접 조회 또는 담당자 문의 |
| 자료 충돌 | 둘 이상의 근거가 서로 일치하지 않음 | 최신 기준을 담당 부서에 확인 |
| 일시 제한 | 해당 상담 유형의 AI 추천이 제한됨 | 기존 상담 절차 사용 |

상태를 색상만으로 구분하지 않고 문구로 함께 표시하는 것을 원칙으로 했습니다. 상담사는 “확인 필요”를 오류가 아닌 정상적인 안전 동작으로 인식하도록 안내받았습니다.

## 근거 표시 원칙
<!--meta: sec=s11; dept=CONSULT; level=주니어|시니어; ct_band=중; related=PRJ-CC-PUB-->
답변이 어떤 자료를 바탕으로 생성되었는지 상담사가 확인할 수 있도록 근거 표시 원칙을 정비했습니다.

- 답변과 관련된 자료명을 함께 표시합니다.
- 상담사가 원문을 확인할 수 있는 위치를 제공합니다.
- 검색된 문서가 여러 개인 경우 주요 근거와 참고 근거를 구분합니다.
- 문서 제목만 일치하고 본문에 답이 없는 경우 근거로 인정하지 않습니다.
- 오래된 자료와 최신 자료가 함께 검색되면 자동으로 섞어 답변하지 않습니다.
- 근거가 특정 조건에만 적용되는 경우 해당 조건을 답변에서 생략하지 않습니다.
- 예외 사항이 근거에 명시되어 있으면 일반 규칙과 함께 확인합니다.
- 답변 문장보다 근거 문서를 우선 판단하도록 화면 안내를 제공합니다.

근거 표시 기능은 답변의 정확성을 보장하는 유일한 장치가 아닙니다. 잘못 검색된 문서가 표시될 수도 있으므로 검색 적합성 평가와 상담사 검토가 함께 필요합니다.

## 검증 시나리오 확대
<!--meta: sec=s12; dept=AIAX; level=주니어|시니어; ct_band=중; related=INC-AI-PUB-->
수정 검증에서는 정상 답변 생성 여부뿐 아니라 답변하지 않아야 할 상황을 별도 시험했습니다.

### 정상 답변 사례

- 질문과 동일한 업무 기준이 승인된 매뉴얼에 존재하는 경우
- 질문 표현과 매뉴얼 용어가 다르지만 의미가 일치하는 경우
- 여러 문서에 나뉜 근거를 함께 확인해야 하는 경우
- 일반 규칙과 예외 조건이 모두 문서에 존재하는 경우

### 답변 제한 사례

- 매뉴얼에 관련 내용이 전혀 없는 경우
- 질문에 대상, 기간 또는 처리 유형이 빠진 경우
- 서로 다른 상담 업무가 한 문장에 섞인 경우
- 최신 자료와 이전 자료의 내용이 충돌하는 경우
- 검색 결과가 질문의 일부에만 답하는 경우
- 질문이 의견, 추정 또는 미래 정책 예측을 요구하는 경우
- 내부 승인 없이 확정할 수 없는 예외 처리를 묻는 경우

### 표현 안전성 사례

- 근거에 없는 숫자가 추가되지 않는지
- 가능성을 확정 표현으로 바꾸지 않는지
- 예시를 실제 정책처럼 안내하지 않는지
- 조건부 규칙에서 조건을 생략하지 않는지
- 여러 문서의 문장을 잘못 결합하지 않는지
- “모른다”는 상태를 임의의 답변으로 채우지 않는지

검증 결과는 단순 성공·실패뿐 아니라 정확한 답변, 확인 필요, 추가 질문 필요, 자료 충돌 및 시스템 오류로 구분해 기록합니다.

## 품질 지표
<!--meta: sec=s13; dept=DA; level=주니어|시니어; ct_band=상; related=INC-AI-PUB-->
운영 품질은 답변 생성량만으로 평가하지 않습니다. 다음 지표를 함께 관찰합니다.

### 근거 답변률

전체 질문 중 승인된 자료에 근거해 답변한 비율입니다. 비율이 높더라도 잘못된 근거를 사용하면 좋은 결과로 보지 않습니다.

### 근거 불일치율

답변의 핵심 내용이 표시된 근거에서 확인되지 않는 비율입니다. INC-AI-01과 직접 관련된 핵심 품질 지표입니다.

### 안전 중단률

근거가 부족하거나 질문이 모호해 “확인 필요” 또는 “추가 질문 필요”로 처리된 비율입니다. 무조건 낮추는 대상이 아니며, 업무 자료 범위와 함께 해석합니다.

### 상담사 수정률

AI 추천 답변을 상담사가 사용하기 전에 의미 있는 내용을 수정한 비율입니다. 단순한 말투 수정과 정책·조건 수정은 구분합니다.

### 근거 열람률

상담사가 추천 답변과 함께 제공된 근거 문서를 확인한 비율입니다. 초기 안정화 기간에는 적극적인 근거 확인을 권장합니다.

### 반복 오류율

동일한 질문 유형에서 같은 근거 불일치가 다시 나타나는 비율입니다. 반복 오류는 개별 문장 수정이 아니라 검색 및 응답 정책 개선 대상으로 분류합니다.

### 미응답 적정률

시스템이 답변을 중단한 사례 중 실제로 근거가 없거나 추가 확인이 필요했던 비율입니다. 안전 중단이 과도해 업무 활용성을 저해하지 않는지 확인하는 데 사용합니다.

구체적인 내부 기준값과 운영 수치는 공개판에 포함하지 않습니다. 품질 지표는 단독으로 판단하지 않고 상담 유형, 자료 범위, 질문 난이도 및 운영 단계와 함께 분석합니다.

## 모니터링 및 경보
<!--meta: sec=s14; dept=AIAX|DA; level=시니어; ct_band=상; related=INC-AI-PUB-->
재발 징후를 조기에 확인하기 위해 응답 결과를 상태별로 집계하고 변화 추세를 점검합니다.

주요 감시 대상은 다음과 같습니다.

- 특정 상담 유형에서 근거 불일치 신고가 반복되는 현상
- 이전보다 “확인 필요” 상태가 급격히 증가하는 현상
- 특정 자료만 과도하게 근거로 선택되는 현상
- 최신 자료가 등록된 후에도 이전 자료가 반복 검색되는 현상
- 상담사 수정률이 특정 질문 유형에서 증가하는 현상
- 근거가 없는 숫자나 기간 표현이 생성되는 현상
- 자료 충돌 상태가 정상 답변으로 처리되는 현상
- 같은 질문에 대한 응답 상태가 비정상적으로 자주 달라지는 현상

경보가 발생했다고 해서 곧바로 장애로 확정하지는 않습니다. 자료 변경, 상담 질문 증가, 새로운 업무 유형 유입 등 정상적인 원인도 함께 확인합니다. 다만 근거 불일치가 확인되면 발생 건수가 적더라도 안전 우선 원칙에 따라 기능 제한 여부를 검토합니다.

## 운영자 대응 절차
<!--meta: sec=s15; dept=CONSULT|AIAX; level=주니어|시니어; ct_band=중; related=INC-AI-PUB-->
상담사 또는 운영자가 의심스러운 답변을 발견하면 다음 절차를 따릅니다.

1. 해당 답변을 고객 안내에 사용하지 않습니다.
2. 질문 문장, 답변, 표시된 근거 및 발생 화면을 보존합니다.
3. 매뉴얼 원문과 추천 답변의 차이를 확인합니다.
4. 단순 문장 표현 문제인지 업무 내용 오류인지 구분합니다.
5. 업무 내용 오류 또는 근거 없는 내용이면 장애 채널로 접수합니다.
6. 같은 상담 유형의 사용 제한이 필요한지 운영 담당자가 판단합니다.
7. AI/AX개발팀은 재현 및 원인 분석을 수행합니다.
8. 수정 전까지 상담사는 기존 매뉴얼 조회 절차를 사용합니다.
9. 수정 후 동일 입력과 유사 입력을 함께 검증합니다.
10. 운영 담당자가 정상화 여부를 확인한 뒤 사용 제한을 해제합니다.

신고자는 기술 원인을 추정할 필요가 없습니다. “답변이 이상하다”는 표현만으로도 접수할 수 있으며, 운영 담당자가 필요한 정보를 추가로 확인합니다.

## 역할과 책임
<!--meta: sec=s16; dept=AIAX|CONSULT|BE|DA; level=주니어|시니어; ct_band=중; related=INC-AI-PUB-->
장애 대응과 재발 방지는 한 부서만의 책임으로 처리하지 않습니다.

### 컨설팅팀

- 상담 업무 기준과 실제 운영 절차 확인
- 답변이 업무상 사용 가능한지 판단
- 고객 및 상담사 피드백 정리
- 매뉴얼의 모호하거나 충돌하는 기준 식별
- 기능 제한 및 운영 재개 시 업무 영향 검토

### AI/AX개발팀

- 오류 재현과 기술 원인 분석
- 근거 부족 시 응답 중단 로직 적용
- 생성 답변과 검색 근거의 일치성 검증
- 평가 시나리오 확대
- 수정 버전 배포와 회귀 시험 수행

### 백엔드팀

- 응답 상태와 오류 상태가 안정적으로 전달되도록 지원
- 운영 로그의 누락 여부 점검
- 기능 제한 설정과 단계적 재개 지원
- 장애 시 기존 상담 절차로 전환할 수 있는 연계 상태 확인

### 데이터분석팀

- 품질 지표 정의 및 추세 분석
- 반복 오류 유형 분류
- 상담 유형별 수정률과 안전 중단률 비교
- 이상 징후 탐지 결과 제공

업무 책임은 분리하되 장애 상황에서는 하나의 대응 흐름으로 협업합니다. 기술적으로 정상인 답변이라도 업무 기준에 맞지 않을 수 있으므로 컨설팅팀과 운영 담당자의 확인을 필수로 포함합니다.

## 변경 관리
<!--meta: sec=s17; dept=AIAX|CONSULT; level=시니어; ct_band=상; related=INC-AI-PUB-->
INC-AI-01 이후에는 모델, 검색 설정 또는 상담 자료를 변경할 때 근거 기반 응답 품질이 유지되는지 확인하도록 변경 관리 항목을 강화했습니다.

변경 유형별 주요 확인 항목은 다음과 같습니다.

| 변경 유형 | 주요 확인 항목 |
|---|---|

| 답변 정책 변경 | 근거 밖 표현 생성 여부, 확인 필요 동작 |
| 화면 변경 | 응답 상태와 근거 표시의 가시성 |
| 모델 변경 | 동일 평가 질문에 대한 정확성 및 안전 중단 |
| 연계 변경 | 질문·근거·응답 상태 전달 누락 여부 |

변경 후에는 정상 사례만 확인하지 않고 INC-AI-01과 같은 근거 부족 사례를 반드시 다시 시험합니다. 변경 범위가 작더라도 안전 통제에 영향을 줄 수 있으면 단계적 적용을 원칙으로 합니다.

## 단계적 운영 재개
<!--meta: sec=s18; dept=AIAX|CONSULT; level=시니어; ct_band=중; related=INC-AI-PUB-->
수정 완료만으로 즉시 전체 기능을 정상화하지 않았습니다. 운영 재개는 제한된 범위에서 시작해 검증 결과를 확인하는 방식으로 진행했습니다.

단계적 운영 재개의 원칙은 다음과 같습니다.

- 검증이 완료된 상담 유형부터 적용
- 초기 운영 중 근거 확인 비중 강화
- 확인 필요 상태의 사유를 집중 점검
- 상담사 피드백을 짧은 주기로 확인
- 반복 오류가 발견되면 해당 유형을 다시 제한
- 정상 사례와 미응답 사례를 함께 검토
- 운영 담당자 확인 후 적용 범위 확대

운영 재개 판단에서는 답변 수가 늘었는지보다 잘못된 답변을 차단하면서 필요한 질문에 적절히 답하는지를 우선 확인했습니다.

## 후속 유사 사례 INC-AI-02
<!--meta: sec=s19; dept=AIAX|CONSULT; level=주니어|시니어; ct_band=중; related=INC-AI-PUB-->
INC-AI-01 조치 이후 별도 운영 점검에서 최신 상담 자료와 이전 자료가 함께 검색되는 유사 위험 사례를 확인했습니다. 이 사례는 근거가 전혀 없는 답변을 생성한 INC-AI-01과 달리, 서로 다른 시점의 자료가 동시에 존재해 답변 기준이 불명확해질 수 있는 유형이었습니다.

사례 번호는 INC-AI-02로 관리했으며, 핵심 위험은 이전 기준과 최신 기준이 한 답변에 섞일 가능성이었습니다. 실제 운영에서는 자료 간 충돌 상태를 확인한 뒤 해당 질문에 대해 자동 답변을 제공하지 않고 최신 기준 확인 절차로 전환했습니다.

주요 조치는 다음과 같습니다.

- 자료의 적용 상태를 현행, 예정 및 종료로 구분
- 종료된 자료를 일반 검색 결과에서 제외
- 최신 여부를 판정할 수 없는 경우 “자료 충돌”로 표시
- 서로 다른 버전의 내용을 자동 결합하지 않도록 제한
- 자료 변경 시 이전 자료의 처리 상태를 함께 점검
- 최신 자료 등록 후 대표 질문을 다시 검증

INC-AI-02는 검색 결과가 존재한다는 사실만으로 답변 가능 상태라고 판단해서는 안 된다는 교훈을 제공했습니다. 검색된 자료가 현재 적용 가능한 기준인지도 함께 확인해야 합니다.

## 후속 유사 사례 INC-AI-03
<!--meta: sec=s20; dept=AIAX|CONSULT; level=주니어|시니어; ct_band=중; related=INC-AI-PUB-->
후속 품질 점검에서는 상담사가 앞선 대화의 대상을 생략하고 짧게 추가 질문했을 때, 시스템이 대상을 잘못 추정할 수 있는 유사 사례를 확인했습니다. 사례 번호는 INC-AI-03으로 관리했습니다.

이 사례의 핵심은 자료에 없는 내용을 새로 만든 것이 아니라, 질문의 대상이 불명확한 상태에서 이전 대화의 일부를 잘못 연결할 수 있다는 점이었습니다. 예를 들어 “그 경우에도 가능한가요?”와 같은 질문은 앞선 대화의 대상과 조건을 정확히 유지해야 합니다.

주요 조치는 다음과 같습니다.

- 지시어와 생략 표현이 포함된 질문을 별도 감지
- 대상이 둘 이상일 수 있으면 자동으로 하나를 선택하지 않음
- 핵심 대상과 조건을 상담사에게 다시 확인
- 긴 대화에서 현재 질문과 무관한 이전 내용을 분리
- 대화 맥락을 사용한 경우 확인된 조건을 답변에 명시
- 다중 대화 평가 시나리오를 정기 검증에 추가

INC-AI-03을 통해 근거 문서가 정확하더라도 질문의 의미를 잘못 해석하면 부정확한 답변이 나올 수 있음을 확인했습니다. 이에 따라 문서 근거와 질문 의미를 각각 검증하도록 점검 범위를 확대했습니다.

## 세 사례의 차이
<!--meta: sec=s21; dept=AIAX; level=시니어; ct_band=상; related=INC-AI-PUB-->
INC-AI-01, INC-AI-02 및 INC-AI-03은 모두 상담 답변의 정확성과 관련되지만 원인 유형이 다릅니다.

| 사례 | 주요 문제 | 안전 동작 |
|---|---|---|
| INC-AI-01 | 검색 결과에 없는 내용 생성 | 확인 필요로 전환 |
| INC-AI-02 | 현행 자료와 이전 자료의 충돌 가능성 | 자료 충돌로 전환 |
| INC-AI-03 | 생략된 질문 대상을 잘못 추정할 가능성 | 추가 질문 필요로 전환 |

세 사례를 동일하게 “모델 오류”로만 분류하면 적절한 개선책을 선택하기 어렵습니다. 근거 부재, 자료 충돌 및 질문 모호성은 각각 다른 탐지 규칙과 운영 절차가 필요합니다.

공통 원칙은 불확실한 상태에서 자연스러운 답변을 우선하지 않는 것입니다. 시스템이 불확실성의 원인을 구분해 표시하면 상담사는 매뉴얼 확인, 최신 자료 확인 또는 질문 보완 중 적절한 후속 조치를 선택할 수 있습니다.

## 용어 설명
<!--meta: sec=s22; dept=AIAX; level=주니어; ct_band=하; related=INC-AI-PUB-->
### 생성형 AI

입력된 질문과 제공된 정보를 바탕으로 새로운 문장을 생성하는 AI입니다. 자연스러운 문장을 만들 수 있지만, 업무 자료에 없는 내용을 사실처럼 표현할 가능성이 있습니다.

### 환각

AI가 근거 자료에서 확인되지 않는 내용을 사실인 것처럼 생성하는 현상을 뜻합니다. INC-AI-01에서는 공개적으로 이해하기 쉬운 표현인 “근거 없는 응답 생성”을 함께 사용합니다.

### 검색 근거

AI가 답변을 작성할 때 참고하도록 제공된 승인 자료의 내용입니다. 문서가 검색되었다는 사실만으로 충분한 근거가 확보된 것은 아닙니다.

### 근거 불일치

답변의 핵심 내용이 표시된 자료에서 확인되지 않거나, 자료의 적용 조건과 답변 조건이 일치하지 않는 상태입니다.

### 안전 중단

정확한 답변을 보장하기 어려울 때 임의로 답변하지 않고 확인 필요, 추가 질문 필요 또는 자료 충돌 상태로 전환하는 동작입니다.

### 회귀 검증

수정한 기능뿐 아니라 기존에 정상적으로 동작하던 기능이 계속 정상인지 다시 확인하는 시험입니다.

### 가드레일

AI가 허용된 범위 안에서 답변하도록 제한하는 정책과 기술적 통제를 통칭합니다. 단일 문구가 아니라 검색, 생성, 검증, 화면 표시 및 운영 절차를 포함합니다.

## 잘못된 대응 방식
<!--meta: sec=s23; dept=AIAX|CONSULT; level=주니어|시니어; ct_band=중; related=INC-AI-PUB-->
유사 장애에서 피해야 할 대응은 다음과 같습니다.

- 문제 문장 하나만 수정하고 원인 유형을 확인하지 않는 것
- 같은 질문의 답변만 고정해 유사 질문 검증을 생략하는 것
- 모델이 자연스럽게 답했다는 이유로 정확하다고 판단하는 것
- 근거가 부족한데도 상담 편의를 위해 추정 답변을 허용하는 것
- 상담사의 검토만을 유일한 안전장치로 두는 것
- 미응답 증가를 무조건 품질 저하로 판단하는 것
- 오래된 자료를 삭제하지 않고 최신 자료만 추가하는 것
- 질문이 모호한데 이전 대화를 임의로 연결하는 것
- 장애 신고 건수가 적다는 이유로 영향 가능성을 낮게 평가하는 것
- 기술팀만 원인을 판단하고 실제 업무 담당자의 확인을 생략하는 것

생성형 AI 장애는 특정 문장을 금지하는 방식만으로 해결하기 어렵습니다. 질문, 검색 자료, 답변 생성, 근거 검증 및 운영 화면이 연결된 전체 흐름을 점검해야 합니다.

## 조직 학습 사항
<!--meta: sec=s24; dept=AIAX|CONSULT|DA; level=주니어|시니어; ct_band=중; related=INC-AI-PUB-->
INC-AI-01을 통해 다음 사항을 조직 학습 항목으로 정리했습니다.

1. 답변을 생성하지 않는 능력도 AI 품질의 일부입니다.
2. 문장 자연스러움은 업무 정확성의 대체 지표가 될 수 없습니다.
3. 검색 결과 존재 여부와 답변 근거 충분성은 별도로 평가해야 합니다.
4. 상담사 검토는 중요하지만 시스템 통제를 대신할 수 없습니다.
5. 정상 질문보다 경계 사례에서 안전성이 더 분명하게 드러납니다.
6. 최신 자료 관리와 답변 생성 품질은 분리된 문제가 아닙니다.
7. 질문의 의미가 모호하면 문서 근거가 있어도 정확한 답변을 만들 수 없습니다.
8. 공개 장애 회고는 민감 정보를 제외하되 원인과 개선 원칙을 명확히 설명해야 합니다.
9. 작은 품질 이상도 반복되면 신뢰 저하로 이어질 수 있습니다.
10. 장애 수정 후에는 기술 검증과 실제 업무 검증을 모두 수행해야 합니다.

이 학습 사항은 콜센터 AI 상담 시스템에 우선 적용하며, 이후 다른 생성형 AI 기반 업무 지원 기능의 검토 기준에도 참고합니다.

## 향후 개선 계획
<!--meta: sec=s25; dept=AIAX|DA|CONSULT; level=시니어; ct_band=상; related=INC-AI-PUB-->
향후 개선은 단기 수정에 그치지 않고 자료 관리, 품질 평가 및 운영 절차를 함께 강화하는 방향으로 진행합니다.

### 평가 자료 확대

실제 상담 표현을 반영하되 개인정보와 고객 식별 정보는 제거한 평가 질문을 지속적으로 추가합니다. 정상 답변 사례뿐 아니라 미응답, 자료 충돌 및 추가 질문이 필요한 사례를 균형 있게 관리합니다.

### 업무 기준 정비

하나의 질문에 대해 여러 매뉴얼이 다른 내용을 제시하지 않도록 자료 소유 부서와 적용 상태를 확인합니다. 시스템이 해결할 수 없는 업무 기준 충돌은 문서 담당자가 먼저 정리합니다.

### 답변 검증 강화

생성된 문장이 검색 근거 범위를 벗어나는지 추가로 확인하고, 숫자·기간·자격·예외 조건처럼 업무 영향이 큰 항목을 우선 점검합니다.

### 운영 피드백 구조화

상담사가 부정확, 근거 부족, 자료 오래됨, 질문 오해 및 표현 개선으로 피드백 유형을 구분할 수 있도록 운영 절차를 개선합니다.

### 정기 재검증

모델, 검색 방식, 상담 자료 또는 화면이 변경되면 INC-AI-01부터 INC-AI-03까지의 대표 시나리오를 다시 실행합니다. 변경이 없더라도 운영 중 누적된 실패 사례를 반영해 정기적으로 검증합니다.

## 공개 범위와 제한
<!--meta: sec=s26; dept=CONSULT|SALES; level=주니어|시니어; ct_band=하; related=INC-AI-PUB-->
이 문서는 장애 대응의 원칙과 공개 가능한 교훈을 공유하기 위한 요약본입니다. 다음 정보는 공개 범위에서 제외합니다.

- 고객사 식별 정보
- 실제 상담 질문과 고객 관련 내용
- 내부 시스템 주소와 계정 정보
- 모델 및 검색 설정의 상세 값
- 보안 설정과 접근 권한 구성
- 세부 로그와 원문 데이터
- 내부 품질 기준값
- 배포 환경과 인프라 구성
- 개인별 대응 기록
- 계약 및 운영 조건

공개판의 목적은 기술적 세부 구현을 제공하는 것이 아니라, 근거 없는 AI 답변을 어떻게 인식하고 어떤 원칙으로 통제했는지 설명하는 것입니다. 상세한 기술 분석과 내부 설정은 별도의 상세판 및 내부 관리 자료에서 다룹니다.

## 최종 결론
<!--meta: sec=s27; dept=AIAX; level=주니어|시니어; ct_band=중; related=INC-AI-PUB-->
INC-AI-01은 콜센터 AI 상담 시스템 도입 2주 차에 매뉴얼에 없는 내용을 AI가 생성한 사례입니다. 헤드헌터랩은 해당 사례를 확인한 즉시 관련 기능을 제한하고, 검색 결과에 없는 내용은 답변하지 않도록 응답 로직을 수정했습니다.

이번 장애의 핵심 교훈은 생성형 AI가 답변을 만들 수 있다는 사실과 업무상 답변해도 된다는 판단이 서로 다르다는 점입니다. 정확한 근거가 없거나 질문이 모호하거나 자료가 충돌하면 시스템은 자연스러운 추정 답변 대신 “확인 필요”, “추가 질문 필요” 또는 “자료 충돌” 상태를 제공해야 합니다.

헤드헌터랩은 수정된 응답 정책, 확대된 검증 시나리오, 운영 모니터링, 자료 최신성 관리 및 상담사 피드백 절차를 통해 동일 유형의 재발을 방지합니다. 장애 상태는 해결되었으며, 관련 품질 항목은 정기 운영 점검 대상으로 계속 관리합니다.
