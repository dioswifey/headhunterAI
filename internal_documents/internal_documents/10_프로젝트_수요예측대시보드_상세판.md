# 수요예측 대시보드 구축 프로젝트 — 상세판

## 고객사 정보
<!--meta: sec=s1; dept=DATA|BE|SALES|DE; level=시니어; ct_band=중; related=PRJ-FC-PUB-->
<!--forbid: 한빛유통|PRJ-FC-->
고객사는 중견 유통업체 "한빛유통"이며, 전국 지점 45곳의 발주 업무에 적용했습니다.

한빛유통은 본사 상품운영 조직이 공통 상품 정책과 프로모션 일정을 관리하고, 각 지점의 발주 담당자가 지역별 판매 상황과 재고 수준을 반영해 최종 발주량을 조정하는 방식으로 운영하고 있었습니다. 프로젝트 착수 전에는 최근 판매량, 전년 동기 실적, 담당자 경험을 기준으로 스프레드시트에서 발주량을 계산했습니다.

기존 업무에서는 다음 문제가 반복적으로 확인되었습니다.

- 지점과 담당자에 따라 발주 기준이 달라 동일 조건에서도 발주량 편차가 발생했습니다.
- 프로모션 시작·종료 시점을 수기로 반영해 일정 누락과 입력 오류가 발생했습니다.
- 판매량이 급증한 품목과 일시 품절 품목을 구분하기 어려웠습니다.
- 신상품은 판매 이력이 없어 담당자의 정성 판단에 크게 의존했습니다.
- 전 지점의 품목별 예측값과 실제 판매량을 한 화면에서 비교하기 어려웠습니다.
- 예측 실패 원인을 상품, 지점, 프로모션, 재고 상태별로 추적할 수 없었습니다.

헤드헌터랩은 데이터분석팀을 중심으로 예측 모델과 성과 검증 체계를 설계했고, 백엔드팀은 데이터 집계, 예측 결과 제공, 사용자 보정 이력 관리 기능을 구축했습니다. 영업팀은 고객사 현업 부서와 적용 범위, 검수 기준, 사용자 교육 일정을 조율했습니다.

## 모델 세부
<!--meta: sec=s2; dept=DATA|DE; level=주니어|시니어; ct_band=상; related=PRJ-FC-PUB-->
<!--forbid: 한빛유통|PRJ-FC-->
시계열 예측 모델은 품목별 계절성·프로모션 일정을 변수로 포함합니다. 신상품처럼 과거 데이터가 없는 품목은 유사 품목 군집으로 대체 예측합니다.

예측 단위는 기본적으로 `지점-품목-영업일` 조합입니다. 일별 예측 결과는 화면에서 주간 단위와 발주 주기 단위로도 집계할 수 있도록 구성했습니다. 모델은 단순히 전체 판매량을 예측하는 것이 아니라 지점별 수요 차이, 품목별 반복 패턴, 행사 전후의 판매 이동을 분리해 반영하도록 설계했습니다.

주요 입력 변수는 다음과 같습니다.

- 최근 일별 판매량과 이동평균
- 동일 요일의 과거 판매량
- 전주 및 전월 대비 판매 증감률
- 품목별 주간·월간 계절성
- 명절과 공휴일 여부
- 프로모션 유형과 할인 구간
- 프로모션 시작 전후 경과 일수
- 지점별 영업일과 휴점 여부
- 품목의 정상 판매, 품절, 판매 중단 상태
- 상품군, 가격대, 보관 방식 등 품목 속성
- 지점 규모와 지역 유형
- 신상품 출시 후 경과 일수

장기 추세와 반복 계절성이 안정적인 품목에는 시계열 기반 모델을 적용했고, 프로모션과 지점 속성의 영향이 큰 품목에는 외생 변수를 활용할 수 있는 회귀형 예측 모델을 적용했습니다. 최종 예측값은 품목군별 검증 결과에 따라 단일 모델 또는 가중 결합 방식으로 산출했습니다.

모델 선택은 모든 품목에 동일한 알고리즘을 강제하는 방식이 아니라, 검증 구간의 오차와 예측 안정성을 비교해 품목군별로 결정했습니다. 오차가 유사한 경우에는 운영 복잡도가 낮고 결과 설명이 쉬운 모델을 우선했습니다.

## 테스트 결과
<!--meta: sec=s3; dept=DATA|BE|DE; level=주니어|시니어; ct_band=중; related=PRJ-FC-PUB-->
<!--forbid: 한빛유통|PRJ-FC-->
도입 후 3개월, 예측 오차(MAPE)가 평균 22%에서 11%로 줄었고, 재고 과잉으로 인한 폐기 비용이 약 15% 감소했습니다. 명절 등 비정기 성수기 예측은 여전히 오차가 커 담당자 수동 보정을 병행합니다.

성과 평가는 도입 전 기준 예측과 도입 후 운영 예측을 비교하는 방식으로 진행했습니다. 단순 평균 오차만으로 결과를 판단하지 않고 지점, 상품군, 판매량 구간, 프로모션 여부를 나누어 분석했습니다.

검증 결과에서 확인된 주요 경향은 다음과 같습니다.

- 판매 이력이 충분하고 반복 주기가 뚜렷한 품목은 오차 감소 폭이 컸습니다.
- 상시 판매되는 중·고빈도 품목은 지점별 편차를 비교적 안정적으로 반영했습니다.
- 판매량이 매우 적은 품목은 소량 차이도 비율 오차를 크게 만들기 때문에 MAPE 해석에 주의가 필요했습니다.
- 대규모 할인 행사 품목은 행사 강도와 진열 위치에 따라 실적 차이가 커졌습니다.
- 품절 기간이 판매량 0으로 처리된 과거 데이터는 실제 잠재 수요를 과소평가하는 경향이 있었습니다.
- 명절처럼 날짜가 매년 이동하고 사전 구매가 발생하는 구간은 일반 계절성만으로 설명하기 어려웠습니다.

폐기 비용 감소는 예측 정확도 향상만으로 달성된 성과로 단정하지 않았습니다. 현업의 발주 검토 강화, 재고 정책 조정, 프로모션 운영 변화도 함께 영향을 미칠 수 있으므로 고객사 보고에서는 복합적인 운영 개선 효과로 표현했습니다.

## 도입 중 이슈
<!--meta: sec=s4; dept=DATA|BE|DE; level=주니어|시니어; ct_band=상; related=INC-SV-DET-->
<!--forbid: 한빛유통|PRJ-FC|INC-->
배치 파이프라인이 대량 데이터 처리 시 서버 자원을 과도하게 점유해 장애가 발생한 사례가 있습니다. 상세는 INC-SV-DET 참고.

본 문서에서는 장애의 상세 원인, 자원 사용 추이, 복구 타임라인, 코드 수준의 개선 사항을 중복 기록하지 않습니다. 프로젝트 관점에서는 해당 사례 이후 다음 운영 원칙을 반영했습니다.

- 대량 재처리는 정규 예측 작업과 분리해 승인 후 수행합니다.
- 데이터 적재 완료 여부와 예측 완료 여부를 별도 상태로 표시합니다.
- 최신 예측 결과 생성에 실패하더라도 직전 정상 결과를 조회할 수 있게 합니다.
- 작업 실패 시 화면에 오래된 결과가 최신 결과처럼 표시되지 않도록 기준 시각을 노출합니다.
- 지점 전체 재계산과 특정 지점·품목 재계산을 구분합니다.
- 운영 변경은 백엔드팀과 데이터분석팀의 상호 검토 후 반영합니다.

장애 관련 면접이나 기술 검토에서는 본 문서의 프로젝트 범위와 INC-SV-DET의 장애 분석 범위를 구분해야 합니다. 본 문서는 비즈니스 요구사항, 예측 설계, 화면 활용, 성과 측정에 초점을 둡니다.

## 프로젝트 목표와 성공 기준
<!--meta: sec=s5; dept=DATA|BE|SALES|DE; level=주니어|시니어; ct_band=중; related=PRJ-FC-PUB-->
<!--forbid: 한빛유통|PRJ-FC-->
프로젝트의 1차 목표는 발주 담당자의 판단을 완전히 자동화하는 것이 아니라, 일관된 기준으로 생성된 수요예측값과 판단 근거를 제공하는 것이었습니다. 최종 발주 책임은 고객사 담당자에게 유지하고, 시스템은 예측과 검토 우선순위를 지원하도록 정의했습니다.

성공 기준은 다음 네 영역으로 구분했습니다.

1. **예측 성능**
   - 기존 기준 대비 평균 예측 오차를 줄일 것
   - 지점·품목군별 오차 편차를 확인할 수 있을 것
   - 프로모션 구간과 일반 구간의 성능을 분리해 평가할 것

2. **업무 효율**
   - 담당자가 여러 파일을 취합하지 않고 단일 화면에서 검토할 수 있을 것
   - 예외 품목을 우선 확인할 수 있을 것
   - 담당자의 수동 보정 사유를 기록할 수 있을 것

3. **운영 안정성**
   - 데이터 기준 시각과 예측 생성 시각을 확인할 수 있을 것
   - 일부 데이터가 누락된 경우 전체 결과를 정상으로 오인하지 않게 할 것
   - 오류 발생 시 직전 정상 결과와 실패 상태를 구분할 것

4. **성과 추적**
   - 예측값, 담당자 보정값, 실제 판매량을 비교할 수 있을 것
   - 모델 성능과 현업 보정 성과를 분리해 분석할 수 있을 것
   - 폐기 비용과 재고 과잉 지표의 변화를 추적할 수 있을 것

## 구축 범위와 제외 범위
<!--meta: sec=s6; dept=DATA|BE|SALES|DE; level=주니어; ct_band=하; related=PRJ-FC-PUB-->
<!--forbid: 한빛유통|PRJ-FC-->
구축 범위에는 전국 지점 45곳의 판매 및 발주 관련 데이터를 활용한 수요예측, 결과 조회 대시보드, 담당자 보정, 성과 분석 기능이 포함되었습니다.

주요 구축 범위는 다음과 같습니다.

- 지점·품목별 일별 수요예측
- 주간 및 발주 주기 단위 집계
- 프로모션 일정 반영
- 신상품 대체 예측
- 예측값과 실제 판매량 비교
- 오차가 큰 품목의 우선 표시
- 담당자 수동 보정과 사유 기록
- 결과 다운로드
- 사용자 권한별 조회 범위 제한
- 운영 상태와 데이터 기준 시각 표시

초기 범위에서 제외한 항목은 다음과 같습니다.

- 공급업체에 대한 발주서 자동 전송
- 물류센터 재배치 자동 의사결정
- 가격 자동 변경
- 프로모션 예산 자동 최적화
- 점포별 진열 공간 자동 배정
- 외부 기상 데이터 기반의 실시간 재예측
- 담당자 승인 없이 수행되는 완전 자동 발주

제외 범위는 기술적으로 불가능해서가 아니라 데이터 준비 수준, 고객사 승인 체계, 운영 책임 범위를 고려해 단계적으로 분리한 것입니다.

## 사용자와 이해관계자
<!--meta: sec=s7; dept=SALES|DATA|BE|DE; level=주니어|시니어; ct_band=하; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
주요 사용자는 지점 발주 담당자, 본사 상품운영 담당자, 관리자, 데이터 검토 담당자로 구분했습니다.

| 사용자 유형 | 주요 업무 | 주요 화면 및 기능 |
|---|---|---|
| 지점 발주 담당자 | 담당 지점의 예측 검토 및 보정 | 지점 요약, 품목별 예측, 보정 입력 |
| 본사 상품운영 담당자 | 전 지점 상품 흐름과 프로모션 영향 확인 | 상품군 비교, 행사 품목 모니터링 |
| 관리자 | 사용자 권한과 운영 상태 확인 | 권한 관리, 처리 현황, 다운로드 이력 |
| 데이터 검토 담당자 | 예측 오차와 입력 데이터 이상 확인 | 성능 분석, 누락 현황, 품질 경고 |

헤드헌터랩 내부의 책임 구분은 다음과 같았습니다.

- 데이터분석팀: 데이터 정의, 특징 설계, 모델 검증, 성과 분석
- 백엔드팀: 집계 처리, 결과 저장, 조회 인터페이스, 권한 및 이력 기능
- 영업팀: 요구사항 합의, 일정 조율, 고객 커뮤니케이션, 검수 지원

중요한 정책이나 수치 정의는 회의 구두 합의로 종료하지 않고 용어, 산식, 예외 조건을 문서화한 뒤 고객사 담당자의 확인을 받았습니다.

## 업무 흐름
<!--meta: sec=s8; dept=DATA|BE|DE; level=주니어; ct_band=하; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
일반적인 일일 업무 흐름은 다음과 같습니다.

1. 전일 판매, 재고, 품절, 상품 상태, 프로모션 일정 데이터를 수집합니다.
2. 데이터의 기준일, 지점 수, 품목 수, 주요 누락 여부를 확인합니다.
3. 학습 및 예측에 사용할 수 있는 상태로 데이터를 정제합니다.
4. 지점·품목 단위의 예측값을 생성합니다.
5. 결과를 주간 및 발주 단위로 집계합니다.
6. 예측 결과와 품질 경고를 대시보드에 반영합니다.
7. 지점 담당자가 결과와 권장 검토 항목을 확인합니다.
8. 필요 시 예측값을 보정하고 사유를 입력합니다.
9. 실제 판매량이 확정되면 예측값 및 보정값과 비교합니다.
10. 성능 지표와 보정 효과를 정기적으로 검토합니다.

담당자 보정은 원본 예측값을 덮어쓰지 않습니다. 시스템은 모델 예측값, 사용자 보정값, 최종 검토값을 구분해 저장함으로써 모델 자체 성능과 현업 판단의 추가 효과를 별도로 평가할 수 있게 했습니다.

## 데이터 원천과 논리 구조
<!--meta: sec=s9; dept=DATA|BE|DE; level=주니어|시니어; ct_band=중; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
프로젝트에서 사용한 데이터는 판매, 재고, 상품, 지점, 프로모션, 운영 달력 영역으로 구분했습니다.

| 데이터 영역 | 주요 항목 | 예측 활용 목적 |
|---|---|---|
| 판매 | 판매일, 지점, 품목, 판매수량, 취소수량 | 목표값 및 수요 패턴 구성 |
| 재고 | 기초재고, 입고, 기말재고, 품절 상태 | 판매 0과 수요 0의 구분 보조 |
| 상품 | 상품군, 가격대, 출시일, 판매 상태 | 유사 품목 탐색 및 군집화 |
| 지점 | 지점 유형, 지역 구분, 영업 상태 | 지점별 수요 차이 반영 |
| 프로모션 | 행사 기간, 행사 유형, 할인 구간 | 일시적 수요 상승 반영 |
| 달력 | 요일, 공휴일, 명절, 휴점일 | 반복 계절성과 영업 가능일 반영 |

판매수량은 단순 집계 전에 취소와 반품 처리 기준을 적용했습니다. 동일 품목이라도 상품 코드 변경이나 포장 단위 변경이 발생할 수 있어, 분석용 품목 식별자와 업무용 품목 코드를 구분했습니다.

운영 데이터의 원본 값은 수정하지 않고 정제 규칙과 매핑 결과를 별도 관리했습니다. 이를 통해 결과 검증 시 원천 데이터, 정제 데이터, 예측 입력 데이터 사이의 차이를 추적할 수 있도록 했습니다.

## 데이터 품질 규칙
<!--meta: sec=s10; dept=DATA|BE|DE; level=주니어|시니어; ct_band=중; related=ISS-DATA-LINK-->
<!--forbid: 한빛유통|PRJ-FC-->
예측 모델의 성능은 알고리즘뿐 아니라 입력 데이터의 일관성에 크게 좌우되므로, 모델 실행 전 품질 검사를 수행했습니다.

주요 검사 항목은 다음과 같습니다.

- 필수 키인 지점, 품목, 영업일 누락 여부
- 동일 지점·품목·일자 데이터의 중복 여부
- 음수 판매량과 비정상적으로 큰 판매량 존재 여부
- 판매 중단 품목의 판매 발생 여부
- 휴점일 판매 데이터 존재 여부
- 프로모션 종료일이 시작일보다 빠른지 여부
- 지점 코드와 기준 정보의 매핑 실패 여부
- 상품군이 지정되지 않은 신규 품목 여부
- 판매량 0이 품절로 인한 것인지 확인 가능한지 여부
- 기준일 이후 데이터가 포함된 미래 정보 누출 여부

품질 경고는 `차단`, `주의`, `정보` 수준으로 나눴습니다. 예측 결과를 신뢰할 수 없을 정도의 필수 데이터 누락은 작업 차단 대상으로 분류했습니다. 일부 품목 속성 누락처럼 대체 규칙을 적용할 수 있는 항목은 주의로 기록하고 해당 범위를 운영 화면에서 확인할 수 있게 했습니다.

고객사 데이터 연동 자체의 장기 안정화 과제는 별도 문서에서 관리하며, 본 문서에서는 예측 프로젝트가 요구한 품질 판정 기준만 다룹니다.

## 예측 대상 분류
<!--meta: sec=s11; dept=DATA|DE; level=주니어|시니어; ct_band=중; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
모든 품목을 동일한 방식으로 처리하면 저판매 품목과 행사 품목에서 불안정한 결과가 발생할 수 있으므로, 예측 대상을 운영 특성에 따라 분류했습니다.

- **상시 고빈도 품목**: 판매 이력이 충분하고 반복 패턴이 뚜렷한 품목
- **상시 저빈도 품목**: 판매가 간헐적으로 발생하는 품목
- **프로모션 민감 품목**: 행사 여부에 따라 판매량 변화가 큰 품목
- **계절 품목**: 특정 월, 기온 구간, 명절에 수요가 집중되는 품목
- **신상품**: 자체 판매 이력이 부족한 품목
- **판매 중단 예정 품목**: 종료 계획에 따라 발주 축소가 필요한 품목
- **품절 영향 품목**: 판매 실적이 실제 수요보다 낮게 관측될 가능성이 큰 품목

분류 결과는 모델 선택뿐 아니라 화면의 경고와 현업 검토 우선순위에도 활용했습니다. 예를 들어 신상품과 품절 영향 품목은 예측값을 단정적으로 제시하기보다 낮은 신뢰도 또는 추가 확인 필요 상태로 표시했습니다.

## 계절성과 달력 변수 처리
<!--meta: sec=s12; dept=DATA|DE; level=시니어; ct_band=상; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
계절성은 주간 반복, 월간 변화, 연간 행사 효과로 구분했습니다. 단순히 전년 동일 날짜를 비교하면 요일과 명절 위치가 달라질 수 있으므로 업무 달력을 기준으로 정렬했습니다.

주간 계절성에서는 평일과 주말의 차이, 지점별 휴점 패턴, 특정 요일의 입고 및 발주 관행을 고려했습니다. 연간 계절성에서는 월과 주차뿐 아니라 명절 전후 상대 일자를 사용했습니다.

명절 구간은 다음 특성 때문에 일반 기간과 별도로 해석했습니다.

- 명절 날짜가 매년 이동합니다.
- 구매가 명절 당일이 아니라 사전 기간에 집중됩니다.
- 품목군별 수요 상승 시점이 다릅니다.
- 행사 구성과 할인 폭이 해마다 달라질 수 있습니다.
- 명절 직후 반동 감소가 발생할 수 있습니다.

비정기 성수기는 과거 반복 횟수가 적어 통계적 학습이 제한됩니다. 따라서 모델 결과에 더해 전년도 유사 행사, 최근 프로모션 반응, 담당자 보정값을 함께 검토하는 절차를 유지했습니다.

## 프로모션 효과 반영
<!--meta: sec=s13; dept=DATA|SALES|DE; level=주니어|시니어; ct_band=중; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
프로모션은 행사 여부만 이진 값으로 반영하지 않고, 가능한 범위에서 행사 유형과 시간적 위치를 구분했습니다.

주요 파생 항목은 다음과 같습니다.

- 프로모션 시작 전 남은 일수
- 프로모션 시작 후 경과 일수
- 프로모션 종료 후 경과 일수
- 정상가 대비 할인 구간
- 단일 품목 행사와 묶음 행사 구분
- 전 지점 행사와 일부 지점 행사 구분
- 반복 행사 여부
- 동일 품목의 최근 행사 간격

행사 판매량은 정상 수요와 동일하게 해석하지 않았습니다. 행사 종료 후 판매 감소가 발생하거나, 행사 전 구매 대기로 판매가 일시적으로 줄 수 있기 때문입니다. 예측 검증에서도 행사 기간과 비행사 기간을 분리해 평가했습니다.

프로모션 정보가 늦게 등록되거나 행사 내용이 변경되면 모델이 최신 계획을 반영하지 못할 수 있습니다. 이에 따라 화면에는 예측 생성 시점에 사용한 프로모션 기준 시각을 표시하고, 변경 이후 재계산이 필요한 항목을 구분했습니다.

## 신상품 대체 예측
<!--meta: sec=s14; dept=DATA|DE; level=시니어; ct_band=상; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
신상품은 판매 이력이 충분하지 않으므로 자체 시계열만으로 안정적인 예측을 생성하기 어렵습니다. 이를 보완하기 위해 상품 속성과 초기 판매 반응을 이용한 유사 품목 군집 대체 방식을 적용했습니다.

유사도 산정에는 다음 특성을 활용했습니다.

- 상품군과 세부 분류
- 가격대
- 보관 방식
- 포장 및 판매 단위
- 출시 시기
- 프로모션 적용 방식
- 유사 지점에서의 초기 판매 패턴
- 기존 대체 또는 후속 상품 관계

대체 예측 절차는 다음과 같습니다.

1. 신상품의 기준 속성을 정리합니다.
2. 판매 종료 또는 비정상 품목을 후보군에서 제외합니다.
3. 속성이 유사한 기존 품목군을 탐색합니다.
4. 후보 품목의 출시 초기 판매 곡선을 정규화합니다.
5. 지점 규모와 지역 특성에 맞춰 기준 수요를 조정합니다.
6. 신상품의 실제 판매 데이터가 축적되면 대체 예측의 가중치를 줄입니다.

유사 품목이 존재한다는 이유만으로 높은 신뢰도를 부여하지 않았습니다. 상품명이 비슷해도 가격, 행사, 진열 위치, 대체 관계에 따라 판매 반응이 달라질 수 있기 때문입니다. 신상품 예측에는 별도 상태를 표시하고 담당자가 참고 품목을 확인할 수 있게 했습니다.

## 품절과 잠재 수요 해석
<!--meta: sec=s15; dept=DATA|DE; level=시니어; ct_band=상; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
판매량은 실제 수요와 항상 동일하지 않습니다. 재고가 없어 판매하지 못한 경우 기록된 판매량은 0 또는 낮은 값이지만, 잠재 수요는 그보다 클 수 있습니다.

품절 영향 처리는 다음 원칙을 적용했습니다.

- 기말재고가 0이면서 판매가 발생한 날은 품절 가능 구간으로 표시합니다.
- 연속된 판매량 0이 품절, 휴점, 판매 중단 중 어느 사유인지 구분합니다.
- 품절이 장기간 지속된 구간은 정상 수요 학습에서 가중치를 낮추거나 제외합니다.
- 품절 직전 판매 속도가 급증한 경우 재고 소진 효과를 별도로 검토합니다.
- 재입고 직후 판매 급증은 미충족 수요가 이월된 결과인지 확인합니다.

재고 정보만으로 모든 품절 시점을 정확히 복원할 수 없으므로, 잠재 수요 보정값을 확정 사실처럼 다루지 않았습니다. 품절 영향이 큰 품목은 모델 성능 표에 별도 표시해 일반 품목과 직접 비교하지 않도록 했습니다.

## 학습·검증 설계
<!--meta: sec=s16; dept=DATA|DE; level=주니어|시니어; ct_band=상; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
시계열 데이터는 미래 정보를 무작위로 학습 구간에 섞으면 실제 운영 성능이 과대평가될 수 있습니다. 따라서 시간 순서를 유지한 검증 방식을 사용했습니다.

검증 설계의 핵심 원칙은 다음과 같습니다.

- 검증 시점보다 미래의 판매 데이터는 입력 변수에 포함하지 않습니다.
- 이동평균과 누적 통계는 해당 예측 시점 이전 데이터만 사용합니다.
- 프로모션 정보는 당시 사전에 확인 가능했던 일정 범위로 제한합니다.
- 상품 분류 변경 이력은 적용 시점을 기준으로 반영합니다.
- 여러 시점의 검증 구간을 사용해 특정 기간 편향을 줄입니다.
- 일반 기간과 성수기 성능을 별도로 기록합니다.

비교 기준에는 최근 판매량 기반의 단순 예측, 전주 동일 요일, 전년 유사 기간 등 현업에서 이해하기 쉬운 기준을 포함했습니다. 복잡한 모델이 기준 모델보다 일관되게 우수하지 않으면 운영 적용 대상에서 제외하거나 제한적으로 사용했습니다.

모델 평가는 오차 크기뿐 아니라 예측 변동성, 음수 예측 발생 여부, 급격한 변화에 대한 과민 반응, 설명 가능성, 운영 시간도 함께 고려했습니다.

## 성능 지표 정의
<!--meta: sec=s17; dept=DATA|DE; level=주니어|시니어; ct_band=중; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
대표 지표로 MAPE를 사용했지만, 판매량이 0에 가깝거나 매우 작은 품목에서는 비율 오차가 과도하게 커질 수 있어 보조 지표를 함께 확인했습니다.

주요 지표의 해석은 다음과 같습니다.

- **MAPE**: 실제값 대비 절대 오차의 비율 평균입니다. 이해하기 쉽지만 실제값이 0인 경우 계산이 어렵습니다.
- **MAE**: 예측값과 실제값 차이의 절대값 평균입니다. 품목의 실제 수량 오차를 직관적으로 확인할 수 있습니다.
- **WAPE**: 전체 절대 오차를 전체 실제 판매량으로 나눕니다. 판매량이 큰 품목의 영향을 반영할 수 있습니다.
- **Bias**: 지속적인 과대예측 또는 과소예측 방향을 확인합니다.
- **적중 구간 비율**: 허용 범위 안에 들어온 예측의 비율을 봅니다.

도입 후 3개월의 평균 MAPE 11%는 전체 평균 결과이며, 모든 지점과 모든 품목의 오차가 동일하다는 의미가 아닙니다. 운영 회의에서는 평균값과 함께 상위 오차 품목, 판매량 구간별 결과, 지점별 편차를 제시했습니다.

## 모델 선택과 결합 원칙
<!--meta: sec=s18; dept=DATA|DE; level=시니어; ct_band=상; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
후보 모델은 품목군별 검증 성능을 비교해 선택했습니다. 단일 검증 구간에서 우수한 모델이 다른 기간에는 불안정할 수 있으므로 여러 검증 시점의 평균과 편차를 함께 평가했습니다.

모델 결합 시에는 다음 기준을 적용했습니다.

- 서로 유사한 오류를 내는 모델을 불필요하게 다수 결합하지 않습니다.
- 특정 성수기에만 과도하게 우수한 모델은 일반 기간 성능을 함께 확인합니다.
- 결합 후 평균 오차가 낮아져도 편향이 커지면 적용을 재검토합니다.
- 가중치는 검증 데이터에 과적합되지 않도록 단순한 구간으로 제한합니다.
- 운영 중 원인을 설명할 수 없는 복잡한 규칙은 최소화합니다.

예측값 후처리에서는 음수 수요를 0 미만으로 표시하지 않도록 제한하고, 판매 중단 품목과 휴점일에는 별도 업무 규칙을 적용했습니다. 다만 임의의 상한·하한으로 모든 급증을 제거하면 실제 행사 수요를 놓칠 수 있으므로 품목군별 검토 기준을 사용했습니다.

## 대시보드 정보 구조
<!--meta: sec=s19; dept=BE|DATA|DE; level=주니어|시니어; ct_band=중; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
대시보드는 사용자가 전체 현황에서 예외 항목으로 단계적으로 이동할 수 있도록 구성했습니다.

주요 화면은 다음과 같습니다.

1. **전국 요약 화면**
   - 전체 예측 대상 현황
   - 지점별 오차와 경고 상태
   - 데이터 및 예측 기준 시각
   - 전일 대비 주요 변화

2. **지점 상세 화면**
   - 담당 지점의 품목별 예측
   - 품절 및 데이터 누락 경고
   - 보정이 필요한 우선 검토 항목
   - 발주 주기별 예상 수요

   - 모델 예측값과 사용자 보정값
   - 유사 품목 및 신뢰 상태

4. **성과 분석 화면**
   - 기간별 예측 오차
   - 상품군·지점별 비교
   - 과대예측과 과소예측 비율
   - 보정 전후 성과 비교

5. **운영 상태 화면**
   - 데이터 수집 상태
   - 예측 생성 상태
   - 최근 정상 처리 시각
   - 재처리 필요 범위

화면에서 색상만으로 상태를 구분하지 않고 문구, 아이콘, 상태값을 함께 표시했습니다. 경고가 많을 때 사용자가 중요한 항목을 놓치지 않도록 영향 범위와 우선순위 필터를 제공했습니다.

## 담당자 수동 보정 정책

명절, 지역 행사, 매장 공사, 진열 변경처럼 시스템이 적시에 알기 어려운 정보는 담당자가 보정할 수 있도록 했습니다.

보정 입력 시에는 다음 정보를 기록합니다.

- 원본 모델 예측값
- 보정 후 값
- 보정 수량과 비율
- 보정 사유
- 입력 사용자
- 입력 시각
- 대상 지점과 품목
- 적용 기간

보정값은 모델 재학습 데이터에 자동으로 포함하지 않았습니다. 담당자 보정이 실제 수요를 반영한 것인지, 안전 재고를 추가한 것인지, 단순 입력 실수인지 구분해야 하기 때문입니다. 실제 판매 결과와 보정 사유를 검토한 뒤 재학습 활용 여부를 결정했습니다.

## 권한과 감사 이력
<!--meta: sec=s21; dept=BE|SALES|DE; level=주니어|시니어; ct_band=중; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
사용자 권한은 조회 범위와 변경 가능 기능을 기준으로 구분했습니다.

- 지점 사용자는 원칙적으로 담당 지점의 상세 데이터만 조회합니다.
- 본사 사용자는 승인된 범위에서 여러 지점을 비교합니다.
- 보정 권한이 없는 사용자는 예측값을 조회만 할 수 있습니다.
- 관리자는 사용자 상태와 권한 범위를 관리합니다.
- 다운로드 기능은 업무상 필요한 역할에만 제공합니다.

중요 변경에는 감사 이력을 남겼습니다.

- 예측값 보정
- 보정값 취소 또는 재수정
- 사용자 권한 변경
- 대량 다운로드
- 기준 정보 매핑 변경
- 운영 재처리 요청

감사 이력은 누가 어떤 값을 언제 변경했는지 확인하는 용도이며, 원본 예측 결과를 사후에 조용히 덮어쓰지 않도록 설계했습니다. 사용자가 보정값을 다시 수정한 경우에도 이전 이력을 유지합니다.

## 결과 제공과 조회 기준
<!--meta: sec=s22; dept=BE|DATA|DE; level=시니어; ct_band=상; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
대시보드 결과는 단일 수치만 제공하지 않고 결과의 기준 시점을 함께 제공합니다. 사용자는 다음 시각을 구분할 수 있어야 합니다.

- 원천 데이터 기준 시각
- 데이터 정제 완료 시각
- 예측 생성 시각
- 화면 반영 시각
- 사용자 보정 시각

동일한 지점과 품목이라도 조회 기간, 집계 단위, 보정 반영 여부에 따라 값이 달라질 수 있으므로 화면과 다운로드 파일에서 조건을 명시했습니다.

조회 결과는 다음 원칙을 따릅니다.

- 최신 예측 생성에 실패하면 실패 상태를 표시합니다.
- 직전 정상 결과를 제공하는 경우 해당 결과의 생성 시각을 명확히 표시합니다.
- 일부 지점만 처리된 결과는 전체 완료로 표시하지 않습니다.
- 사용자 보정 포함 여부를 선택할 수 있게 합니다.
- 집계값에서 제외된 품목이 있다면 제외 사유와 건수를 제공합니다.
- 다운로드 결과에는 조회 조건과 생성 시각을 포함합니다.

구현 세부 코드와 배치 모듈 내부 함수는 단위코드 문서에서 별도로 관리하며, 본 문서에서는 사용자에게 보장해야 할 결과 의미에 집중합니다.

## 운영 모니터링 지표

운영 모니터링은 시스템 처리 상태, 데이터 품질, 모델 성능, 사용자 활용으로 구분했습니다.

- 예측 대상 지점 수와 품목 수

- 최근 정상 결과 생성 시각

## 현업 검수와 사용자 교육
<!--meta: sec=s24; dept=SALES|DATA|BE|DE; level=주니어|시니어; ct_band=하; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
현업 검수는 화면 기능 확인과 예측값 타당성 확인을 분리해 진행했습니다.

기능 검수 항목에는 다음 내용이 포함되었습니다.

- 권한별 지점 조회 범위가 올바른지 확인
- 필터와 정렬 결과 확인
- 예측값과 다운로드 값의 일치 여부 확인
- 보정 입력 및 취소 이력 확인
- 데이터 기준 시각 표시 확인
- 오류 및 경고 메시지 확인

예측 검수에서는 판매 패턴이 익숙한 대표 품목을 선정해 담당자의 경험과 모델 결과를 비교했습니다. 모델이 담당자의 예상과 다른 경우에는 즉시 오류로 판단하지 않고 데이터 기준, 프로모션 반영 여부, 품절 이력, 비교 기간을 확인했습니다.

사용자 교육은 다음 순서로 구성했습니다.

1. 예측값은 확정 발주량이 아니라 의사결정 지원값이라는 점을 설명합니다.
2. 화면의 데이터 기준 시각과 상태값을 확인하는 방법을 교육합니다.
3. 품절과 판매량 0의 차이를 설명합니다.
4. 수동 보정 방법과 사유 기록 원칙을 안내합니다.
5. 명절과 신상품은 추가 검토가 필요함을 안내합니다.
6. 오류 의심 시 필요한 증빙 항목과 문의 절차를 공유합니다.

## 운영 협업과 책임 경계
<!--meta: sec=s25; dept=DATA|BE|SALES|DE; level=시니어; ct_band=중; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
운영 중 문의는 데이터 문제, 모델 문제, 화면 문제, 업무 정책 문제로 분류했습니다.

| 문의 유형 | 1차 확인 주체 | 주요 확인 항목 |
|---|---|---|
| 데이터 누락·중복 | 백엔드팀·데이터분석팀 | 기준일, 원천 건수, 매핑 상태 |
| 예측값 급증·급감 | 데이터분석팀 | 판매 이력, 행사, 품절, 모델 입력 |
| 화면 조회 오류 | 백엔드팀 | 권한, 조회 조건, 결과 반영 상태 |
| 발주 정책 문의 | 고객사 업무 담당자·영업팀 | 안전 재고, 승인 절차, 적용 범위 |
| 범위 변경 요청 | 영업팀 | 요구사항, 일정, 비용, 영향도 |

예측 모델이 수치를 생성한다는 이유로 데이터분석팀이 발주 정책까지 결정하지 않도록 책임 경계를 명확히 했습니다. 안전 재고 수준, 공급업체 최소 주문 수량, 물류 제약은 고객사 업무 정책에 속하며 별도 합의 없이 모델 규칙에 포함하지 않았습니다.

긴급 문의 시에는 화면 캡처만 전달하지 않고 지점, 품목, 대상일, 조회 조건, 데이터 기준 시각을 함께 제공하도록 안내했습니다. 이를 통해 동일 조건을 재현하고 데이터와 화면 결과를 대조할 수 있게 했습니다.

## 한계와 잔여 위험
<!--meta: sec=s26; dept=DATA|BE|SALES|DE; level=시니어; ct_band=상; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
프로젝트 완료 후에도 다음 한계가 남아 있습니다.

- 명절 등 비정기 성수기는 학습 가능한 반복 사례가 적습니다.
- 프로모션 정보가 늦게 확정되면 예측값에 반영되지 않을 수 있습니다.
- 품절 데이터가 불완전한 경우 실제 잠재 수요를 과소평가할 수 있습니다.
- 신상품은 유사 품목이 있어도 실제 시장 반응이 다를 수 있습니다.
- 지역 행사와 매장 진열 변경은 구조화된 데이터로 즉시 확보하기 어렵습니다.
- 재고 과잉과 폐기는 예측 외에도 발주 정책, 공급 단위, 유통기한의 영향을 받습니다.
- 판매량이 적은 품목은 비율 오차가 불안정하게 보일 수 있습니다.
- 고객사 업무 정책이 변경되면 기존 예측 결과와 단순 비교하기 어려울 수 있습니다.

이러한 한계는 모델의 실패로만 보지 않고, 데이터 확보 가능성 및 업무 프로세스와 함께 관리해야 합니다. 특히 명절 구간에서는 수동 보정을 제거하는 것보다 보정 근거를 기록하고 사후 성과를 평가하는 것이 현실적인 운영 방식입니다.

## 확장 계획
<!--meta: sec=s27; dept=DATA|BE|SALES|DE; level=시니어; ct_band=상; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
후속 확장 후보는 자동화 수준을 무리하게 높이기보다 데이터와 운영 책임이 준비된 영역부터 검토하도록 제안했습니다.

우선순위 후보는 다음과 같습니다.

1. 지역 행사와 휴점 계획의 구조화 입력
2. 프로모션 변경 시 영향 품목 선택 재계산
3. 예측 불확실성 구간 표시
4. 품절 가능성을 고려한 잠재 수요 추정 개선
5. 신상품 유사 품목 추천 근거 제공
6. 보정 사유별 성과 분석
7. 공급 단위와 최소 주문량을 반영한 권장 수량 계산
8. 지점 간 재고 이동 검토 기능
9. 상품 수명주기 단계별 모델 운영
10. 성수기 전용 검토 화면

완전 자동 발주로 확장하려면 예측 정확도 외에도 승인 책임, 공급업체 주문 조건, 물류 제약, 취소 정책, 재고 비용 기준이 먼저 합의되어야 합니다. 따라서 자동 발주는 단순 기능 추가가 아니라 업무 책임 체계를 포함한 별도 프로젝트로 다루는 것이 적절합니다.

## 인수인계 산출물
<!--meta: sec=s28; dept=DATA|BE|SALES|DE; level=주니어|시니어; ct_band=하; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
프로젝트 종료 시 다음 범주의 산출물을 인계했습니다.

- 요구사항 및 범위 정의서
- 데이터 항목 정의서
- 지점·품목 기준 정보 매핑 규칙
- 데이터 품질 검사 항목
- 예측 대상 분류 기준
- 모델 검증 결과 요약
- 성능 지표 정의서
- 대시보드 사용자 안내서
- 권한 정책과 감사 이력 기준
- 운영 상태 확인 절차
- 수동 보정 정책
- 현업 검수 결과
- 잔여 위험 및 개선 후보 목록

산출물은 개발 완료 상태만 설명하지 않고 운영자가 결과의 의미를 판단할 수 있도록 구성했습니다. 특히 MAPE, 품절 영향, 신상품 대체 예측, 수동 보정값은 오해 가능성이 높아 정의와 예시를 함께 제공했습니다.

## 핵심 용어
<!--meta: sec=s29; dept=DATA|BE|SALES|DE; level=주니어; ct_band=하; related=PRJ-FC-DET-->
<!--forbid: 한빛유통|PRJ-FC-->
- **수요예측**: 미래에 판매될 가능성이 있는 수량을 과거 데이터와 업무 변수를 이용해 추정하는 작업입니다.
- **실제 판매량**: 특정 기간에 실제로 기록된 판매수량입니다. 품절이 있으면 잠재 수요보다 작을 수 있습니다.
- **잠재 수요**: 재고가 충분했다면 발생했을 것으로 추정되는 수요입니다.
- **계절성**: 요일, 월, 계절, 명절처럼 일정한 주기로 반복되는 판매 패턴입니다.
- **프로모션 효과**: 할인이나 행사로 인해 정상 판매 수준과 달라지는 변화입니다.
- **신상품 콜드 스타트**: 과거 판매 이력이 없어 자체 데이터만으로 예측하기 어려운 상태입니다.
- **유사 품목 군집**: 속성이나 판매 패턴이 비슷한 품목을 묶은 그룹입니다.
- **MAPE**: 실제값 대비 절대 오차의 비율 평균입니다.
- **편향**: 예측이 지속적으로 실제보다 높거나 낮은 방향성을 보이는 현상입니다.
- **수동 보정**: 사용자가 현장 정보를 근거로 모델 예측값을 조정하는 작업입니다.
- **기준 시각**: 데이터 또는 예측 결과가 어느 시점까지의 정보를 반영하는지 나타내는 시각입니다.
- **직전 정상 결과**: 최신 작업이 실패했을 때 조회 가능한 가장 최근의 정상 완료 결과입니다.

## 프로젝트 회고와 적용 원칙
<!--meta: sec=s30; dept=DATA|BE|SALES|DE; level=주니어|시니어; ct_band=중; related=PRJ-FC-PUB|INC-SV-DET-->
<!--forbid: 한빛유통|PRJ-FC|INC-->
본 프로젝트에서 확인한 핵심 교훈은 높은 예측 정확도만으로 현업 활용이 보장되지 않는다는 점입니다. 사용자는 예측값의 생성 시점, 적용된 프로모션, 품절 영향, 수동 보정 여부를 함께 이해할 수 있어야 결과를 신뢰할 수 있습니다.

프로젝트 수행 과정에서 정리한 적용 원칙은 다음과 같습니다.

- 모델 성능은 단일 평균 지표만으로 판단하지 않습니다.
- 판매량 0을 곧바로 수요 0으로 해석하지 않습니다.
- 신상품 예측에는 유사 품목 근거와 불확실성을 함께 표시합니다.
- 담당자의 보정은 제거 대상이 아니라 측정하고 학습해야 할 업무 정보입니다.
- 모델 예측값과 최종 발주량의 책임을 구분합니다.
- 실패한 최신 결과를 정상 결과처럼 노출하지 않습니다.
- 데이터 기준 시각과 결과 생성 시각을 사용자에게 공개합니다.
- 일반 기간과 비정기 성수기의 운영 기준을 분리합니다.
- 정확도 개선과 폐기 비용 감소의 인과관계를 과장하지 않습니다.
- 자동화 범위는 기술 가능성보다 업무 책임과 데이터 준비 수준을 기준으로 결정합니다.

도입 후 3개월 동안 평균 MAPE가 22%에서 11%로 감소하고 재고 과잉으로 인한 폐기 비용이 약 15% 줄어든 것은 의미 있는 성과였습니다. 다만 명절 등 비정기 성수기에는 오차가 여전히 크기 때문에 담당자 수동 보정과 사후 검토를 유지하는 것이 현재 운영 조건에 적합하다고 결론 내렸습니다.
