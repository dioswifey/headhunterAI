# 콜드 아웃리치 및 첫 미팅 운영 지침
<!--meta: doc=SLS-05; doc_type=sales_playbook; tier=2; topic=SALES; disclosure=internal; status=active-->

## 아웃리치 원칙과 금지 행위
<!--meta: sec=s1; dept=SALES; level=주니어|시니어; ct_band=중; related=none-->

아웃리치는 상대 조직의 공개된 업무 맥락을 확인한 뒤 시작한다. 확인한 사실과 영업 담당자의 가설을 구분하며, 한 번의 연락에는 회신·미팅·담당 부서 확인 중 한 가지만 요청한다.

성과와 기술 가능성을 과장하지 않으며, 확인되지 않은 내용을 확정적으로 표현하지 않는다. 상대가 연락 중단 또는 수신 거부 의사를 밝히면 사유를 묻기 위한 추가 연락도 하지 않는다.

### 운영 원칙

1. **업무 맥락을 먼저 확인한다.**
   - 공개 자료에서 확인한 변화·과제·일정을 접촉 근거로 사용한다.
   - 공개 사실에서 추정한 내용은 가설임을 표시한다.
   - 개인의 비공개 정보나 출처가 불명확한 자료는 사용하지 않는다.
2. **한 번의 연락에 한 가지만 요청한다.**
   - 첫 연락의 요청은 20분 이내 미팅, 담당 부서 확인 또는 관심 여부 확인 중 하나로 제한한다.
   - 복수 일정 제안과 자료 검토 요청을 한 문장에 함께 넣지 않는다.
   - 첨부자료 확인을 요청했다면 같은 연락에서 회의 확정까지 요구하지 않는다.
3. **과장하거나 단정하지 않는다.**
   - 수행 사실, 일반적 가능성, 고객별 검토 필요 사항을 구분한다.
   - 레퍼런스는 사내 승인 범위에서 정확한 명칭만 사용한다.
   - 공개 정보만으로 예상 효과·정확도·구축 기간을 산출하지 않는다.
4. **거절 의사를 즉시 반영한다.**
   - 거절 또는 수신 거부 확인 당일에 연락 상태를 변경한다.
   - 예약된 후속 메일과 전화 일정을 모두 취소한다.
   - 동일인에 대한 다른 지점·담당자의 우회 연락도 중단한다.

### 금지 행위

| 금지 행위 | 판단 기준 | 허용되는 대체 처리 | 즉시 조치 |
|---|---|---|---|
| 수행하지 않은 레퍼런스 암시 | 참여·구축·검증 사실이 없는데 유사 표현으로 수행한 것처럼 보이게 함 | 승인된 레퍼런스 명칭만 사용 | 발송 중단 및 표현 삭제 |
| 근거 없는 수치 성과 제시 | 출처·측정 조건·승인 기록이 없는 비율, 기간, 비용 절감 수치를 제시함 | 정량 효과는 별도 검토가 필요하다고 설명 | 정정 필요성 보고 |
| 기술적 단정 | 데이터·인프라 확인 전 구현 가능, 정확도, 보안 적합성을 확정함 | 기술 검토 후 판단한다고 안내 | CNS 또는 AIAX 확인 요청 |
| 가격 즉답 | 범위와 조건 확인 없이 금액·할인·무상 범위를 답함 | 제안·가격 소관 문서 계열로 이관 | 해당 답변 보류 |
| 동일인 반복 연락 | 거절 후 연락하거나 활성 시퀀스를 중복 실행함 | 수신 의사와 접촉 이력을 먼저 확인 | 모든 예약 연락 취소 |
| 타사 비방 | 확인되지 않은 장애·품질·인력 정보를 부정적으로 언급함 | 고객 요구와 자사 검토 범위만 설명 | 발언 중단 및 기록 |

금지 행위를 인지한 담당자는 표현의 경중을 임의로 축소하지 않는다. 외부 정정이 필요한지는 SALES 과장 이상이 사실관계와 고객 반응을 확인해 판단한다. 기술 관련 표현은 CNS 또는 AIAX 담당자의 확인을 받는다.

### 발생 시 처리

1. 담당자는 진행 중인 메일·전화·메신저 접촉을 즉시 중단한다.
2. 예약 발송과 다른 담당자에게 배정된 후속 활동을 당일 취소한다.
3. 발생 후 4시간 이내에 SALES 과장 이상에게 사실 그대로 보고한다.
4. 외부 정정이 필요하면 승인된 문안으로 1회만 전달한다.
5. 가격 관련 문의는 제안·가격 소관 문서 계열로 넘기고 임의 답변하지 않는다.
6. 반복 위반은 월간 메시지 검토 대상에 포함하고 승인 전 발송으로 전환한다.

### 재발 방지 기록

- 발생 일시와 접촉 채널
- 대상 어카운트와 상대 역할
- 위반 유형과 발견 경로
- 실제 사용한 문장 또는 발언 요지
- 예약 연락 취소 여부
- 외부 정정 여부와 고객 반응
- 발생 원인과 검토 누락 단계
- 재발 방지 조치와 완료 기한
- 담당자 및 확인자

## 사전 조사 체크리스트
<!--meta: sec=s2; dept=SALES|CNS; level=주니어; ct_band=중; related=SLS-03#s7-->

사전 조사는 최초 아웃리치 직전 공개 정보만으로 수행하며, 어카운트당 10분을 넘기지 않는다. 목적은 고객 내부 사정을 확정하는 것이 아니라 첫 대화에서 검증할 업무 맥락과 질문 1개를 정하는 데 있다.

조사자는 매번 동일한 순서와 항목을 사용한다. 특정 출처가 없으면 추정으로 채우지 않고 `미확인`으로 기록하며, 채널 운영과 접촉 대상 선정은 SLS-03#s7을 따른다.

### 10분 조사 순서

1. 0~2분에는 최근 12개월의 공개 보도자료를 확인한다.
2. 2~4분에는 최근 90일의 채용 공고와 모집 직무를 확인한다.
3. 4~6분에는 최신 공시 또는 사업보고 요약을 확인한다.
4. 6~7분에는 공공 발주계획과 나라장터 공개 정보를 확인한다.
5. 7~9분에는 최근 12개월의 기술 블로그·발표 자료를 확인한다.
6. 9~10분에는 조직 개편 소식과 대화 진입점을 기록한다.
- 10분 안에 확인되지 않은 정보는 추가 추적하지 않고 `미확인`으로 남긴다.
- 규제·보안·기술 해석이 필요한 자료는 원문 링크만 저장하고 접촉 문구에서 단정하지 않는다.

### 고정 조사 항목

| 조사 항목 | 확인 범위 | 뽑아낼 대화 진입점 예시 | 조사로 확정할 수 없는 것 |
|---|---|---|---|
| 공개 보도자료 | 신규 서비스, 운영 확대, 디지털 전환 발표 | “최근 공개된 운영 확대와 관련해 반복 업무 관리도 검토 중인지” | 실제 우선순위와 승인 상태 |
| 채용 공고 | 직무, 요구 역량, 기술 스택 신호 | “데이터·AI 직무 채용과 함께 내부 활용 과제를 준비하는지” | 채용 인력의 실제 배치와 과제 책임자 |
| 공시·사업보고 요약 | 사업 방향, 투자 항목, 주요 위험 | “공개된 효율화 방향에서 우선 확인하는 업무 지표가 있는지” | 실제 예산, 집행 가능 금액, 구매 일정 |
| 공공 발주계획 | 사업명, 예상 시기, 담당 기관, 공개 범위 | “공개 계획의 사전 검토 단계에서 확인할 기술 조건이 있는지” | 최종 발주 여부와 평가 기준 |
| 기술 블로그·발표 자료 | 운영 과제, 데이터 환경, 기술 관심사 | “발표된 운영 환경에서 현재 가장 큰 제약이 무엇인지” | 내부 성능, 장애 현황, 보안 승인 결과 |
| 조직 개편 소식 | 신설 조직, 기능 통합, 책임 범위 변화 | “조직 변경 이후 관련 과제의 검토 창구가 정해졌는지” | 실제 추진 주체와 의사결정 권한 |

공개 정보로 확인 가능한 것은 발표된 사실, 시점, 표면적 방향과 사용된 용어까지다. 실제 예산, 내부 추진 주체, 구매위원회, 데이터 상태, 기술 적합성은 초기 접촉에서 추정하지 않으며 후속 대화에서 확인한다.

### 확인 수준 표시

- `확인`: 원문과 게시일을 저장한 공개 사실
- `가설`: 2개 이상의 공개 사실을 연결한 대화용 추정
- `미확인`: 공개 자료에서 찾지 못한 항목
- `사용 제외`: 출처가 불명확하거나 접촉 문구에 쓰기 부적절한 정보

### 조사 결과 기록 필드

```text
조사일시:
조사자:
어카운트:
대상 역할:
확인 사실 1:
확인 사실 2:
대화 진입점:
확인 질문 1개:
확인 수준:
출처명:
원문 URL:
게시일:
```

### 기록 품질 기준

- 확인 사실과 가설을 한 문장에 섞지 않는다.
- 출처별 게시일과 URL을 각각 남긴다.
- 대화 진입점은 상대 업무와 연결된 한 문장으로 작성한다.
- 질문은 예·아니요만 요구하지 않도록 짧게 작성한다.
- 실제 예산과 내부 추진 주체는 공개 근거가 없으면 `미확인`으로 남긴다.

## 이메일 시퀀스 설계와 예시 문안
<!--meta: sec=s3; dept=SALES; level=주니어|시니어; ct_band=중; related=none-->

콜드 이메일은 4통을 하나의 시퀀스로 설계하며, 각 메일의 역할을 중복하지 않는다. 간격은 영업일 기준으로 계산하고 회신이 오면 남은 예약 메일을 즉시 중단한다. 동일 시퀀스에서는 수신자·제목·본문·요청 중 한 변수만 바꿔 비교한다.

각 메일은 공개 맥락, 확인할 질문, 요청 사항을 구분해 작성한다. 첨부파일은 수신자가 요청한 경우에만 보내며, 추적 목적의 불필요한 대용량 이미지나 실행 파일을 사용하지 않는다.

### 표준 시퀀스

| 순서 | 발송 시점 | 역할 | 단일 요청 |
|---|---:|---|---|
| 1차 | 0영업일 | 공개된 업무 맥락과 연락 이유 제시 | 20분 미팅 가능 여부 |
| 2차 | 3영업일 후 | 유사 과제에서 확인할 관점 제시 | 해당 과제 검토 여부 |
| 3차 | 5영업일 후 | 짧은 질문으로 시기 확인 | 적절한 접촉 시기 |
| 4차 | 7영업일 후 | 시퀀스 종료와 연락 중단 안내 | 필요 시 회신 |

### 제목 작성 규칙

- 제목은 28자 이내로 작성하고 어카운트명 또는 공개 과제명 중 하나만 넣는다.
- `관련 업무 검토 여부 문의`처럼 본문의 목적을 드러낸다.
- 긴급, 필독, 최종 경고 등 압박 표현을 사용하지 않는다.
- 근거 없는 성과 수치와 할인·무료 표현을 넣지 않는다.
- 실제 회신이 아닌 메일에 `Re:` 또는 `Fwd:`를 붙이지 않는다.

### 예시 문안

```text
[1차: 맥락 제시]
제목: 공개된 운영 효율화 과제 문의
안녕하세요. 공개 자료에서 운영 효율화 방향을 확인해 연락드린다.
관련 업무의 AI·AX 적용 가능성을 검토 중이라면 20분 대화가 가능한지 문의드린다.
```

```text
[2차: 사례 관점 제시]
제목: 관련 과제 검토 항목 공유
앞서 연락드린 업무는 데이터 접근 범위와 현업 사용 절차를 먼저 확인해야 한다.
현재 유사한 내부 과제를 검토하고 있는지만 알려주시면 이후 연락 여부를 조정하겠다.
```

```text
[3차: 짧은 질문]
제목: 검토 시기 확인
현재 우선순위가 아니라면 어느 분기 이후가 적절한지 한 가지만 확인 부탁드린다.
회신한 시점 전에는 추가 연락하지 않겠다.
```

```text
[4차: 종료 안내]
제목: 연락 종료 안내
이번 메일을 끝으로 관련 연락을 종료한다.
추후 검토가 필요할 때 회신 주시면 그때 다시 확인하겠다.
```

예시 문안의 공개 맥락과 과제명은 조사 기록에 맞게 바꾼다. 한 메일에 미팅 요청, 자료 검토, 담당자 소개를 동시에 요구하지 않는다.

### 회신 유형별 분기 처리

- **관심:** 남은 시퀀스를 중단하고 5영업일 이내 가능한 첫 미팅 일정을 2개 이내로 제시한다.
  - 기술 가능성이나 가격을 먼저 확정하지 않는다.
- **시기 아님:** 상대가 제시한 시점을 기록하고 그 이전에는 자동·수동 연락을 모두 중단한다.
  - 시점이 없으면 종료일로부터 60일간 재접촉하지 않는다.
- **담당 아님:** 담당 부서명 확인만 요청하고 개인 연락처 전달을 요구하지 않는다.
  - 안내가 없으면 시퀀스를 종료한다.
- **거절:** 당일 수신 거부 상태로 변경하고 모든 채널의 예약 접촉을 취소한다.
  - 다른 지점이나 담당자로 변경해 우회 접촉하지 않는다.

### 종료와 재접촉

- 4차 메일에도 회신이 없으면 시퀀스를 종료하고 종료 사유를 `무응답`으로 기록한다.
- 무응답 종료 후 60일 동안 동일인에게 재접촉하지 않는다.
- 상대가 미래 시점을 지정했거나 먼저 문의한 경우에는 해당 시점에 재접촉할 수 있다.
- 명시적 거절자는 본인이 다시 문의하기 전까지 재접촉하지 않는다.

## 전화 접촉 운영
<!--meta: sec=s4; dept=SALES; level=주니어|시니어; ct_band=중; related=none-->

전화 접촉의 목적은 상대의 업무 맥락을 짧게 확인하고 다음 대화 가능 여부를 판단하는 데 있다. 첫 통화에서 과제를 확정하거나 심층 자격심사를 하지 않는다. 통화는 연결 후 3분 이내를 기본으로 하며, 상대가 대화를 허용한 경우에만 연장한다.

### 통화 구조와 거절 대응

도입 15초 안에 소속, 이름, 연락 목적을 밝힌다. 이후 목적을 한 문장으로 제시하고 한 가지 질문만 한 뒤, 답변에 따라 다음 단계를 제안한다. 거절 의사가 확인되면 설득을 반복하지 않고 아래 종료 기준을 적용한다.

| 구분 | 상황·목적 | 권장 문장 | 하지 말 것·종료 기준 |
|---|---|---|---|
| 통화 구조 | 도입 15초 | “헤드헌터랩 영업팀의 ○○○이다. AI·AX 과제 관련 담당 업무 여부를 확인하려고 연락했다.” | 친분이 있는 것처럼 말하거나 용건을 숨기지 않는다. |
| 통화 구조 | 목적 제시 | “현재 해당 업무의 개선 과제 검토 여부만 짧게 확인하고자 한다.” | 제품 기능, 성과 수치, 제안 내용을 연속해서 설명하지 않는다. |
| 통화 구조 | 한 가지 질문 | “올해 관련 업무를 검토할 계획이 있는가.” | 예산·의사결정자·기술 요건을 한 번에 묻지 않는다. |
| 통화 구조 | 다음 단계 제안 | “관련성이 있다면 30분 초기 미팅 일정을 메일로 제안하겠다.” | 통화 중 일정 확정을 압박하거나 디스커버리를 시작하지 않는다. |

### 담당자 연결 전 단계 응대

대표번호, 안내 데스크, 공용 메일 담당자에게도 회사명과 연락 목적을 동일하게 밝힌다. 임원 지시, 기존 거래, 긴급 장애 등 사실과 다른 사유로 연결을 유도하지 않는다. 담당자 정보 제공이 어렵다는 답변을 받으면 공식 문의 경로만 확인한다.

1. 소속은 “헤드헌터랩 영업팀”으로 밝힌다.
2. 목적은 “AI·AX 관련 업무 담당 여부 확인” 수준으로 제한한다.
3. 담당자 성명보다 담당 부서 또는 공용 연락 경로를 우선 확인한다.
4. 연결 거절 후 다른 내선으로 반복 시도하지 않는다.
5. 안내받은 연락 제한이나 수신 거부 의사는 즉시 기록한다.

- 담당 부서만 확인된 경우 공용 채널로 1회 연락하고 개인 연락처를 추정하지 않는다.
- 동일 조직에서 2회 연결이 거절되면 새로운 근거가 생기기 전까지 30일간 전화하지 않는다.
- 우회 연결, 직급 사칭, 지인 언급, 허위 설문 목적 제시는 금지한다.

### 통화 기록 필수 필드

통화 종료 후 2시간 이내에 승인된 영업 기록 시스템에 결과를 입력한다. 추정과 상대 발언을 구분하고, 상대가 말하지 않은 예산·일정·권한을 임의로 채우지 않는다. 후속 연락이 없는 통화도 종료 사유를 남긴다.

- 통화 일시와 통화 소요 시간
- 발신한 지점과 담당 SALES 구성원
- 어카운트 식별용 내부 코드
- 접촉 경로와 연결된 부서·직무
- 소속·목적 고지 여부
- 상대가 표현한 관심 또는 거절 유형
- 확인한 질문과 답변 요약
- 자료 발송 동의 여부와 발송 대상 주소
- 다음 연락 일자 또는 연락 중단 기한
- 녹음 여부, 고지·동의 확인 상태, 파일 보관 위치

### 녹음 취급 원칙

- 통화 녹음은 기본값으로 설정하지 않는다.
- 녹음 전 적용 요건과 사내 승인 절차를 확인하고 상대에게 녹음 사실과 목적을 알린다.
- 고지 또는 필요한 동의가 확인되지 않으면 녹음하지 않고 서면 기록으로 대체한다.
- 녹음 파일은 개인 단말기, 개인 클라우드, 메신저에 저장하지 않는다.
- 승인된 저장소의 접근 권한은 해당 SALES 담당자와 지정 관리자에게만 부여한다.
- 보관 기간은 90일을 기본으로 하며, 별도 보존 근거가 없으면 기간 종료 후 삭제한다.

## 초기 미팅 아젠다와 역할 분담
<!--meta: sec=s5; dept=SALES|CNS; level=주니어|시니어; ct_band=중; related=DSC-01#s1-->

초기 미팅은 아웃리치에서 확인한 관심을 업무 맥락과 다음 단계 가능성으로 연결하는 대화다. 체크리스트를 순서대로 낭독하지 않고, 맥락을 먼저 제시한 뒤 상대 답변에 따라 다음 질문을 선택한다. 업무·데이터·조직·제약을 심층 진단하는 디스커버리와의 구분은 DSC-01#s1을 따른다.

### 30분형·45분형 아젠다

30분형은 단일 과제와 참석자 2명 이하인 경우에 적용한다. 45분형은 관련 부서가 2개 이상이거나 현재 상황 설명에 시간이 필요한 경우에 적용한다. 종료 4분 전부터는 새 질문을 시작하지 않고 확인 사항과 다음 단계를 정리한다.

| 유형 | 시간 | 분량 | 진행 내용 | 주 진행자 | 제한 사항 |
|---|---:|---:|---|---|---|
| 30분형 | 0~3분 | 3분 | 참석자·목적·종료 시각 확인 | SALES | 회사 소개를 길게 하지 않는다. |
| 30분형 | 3~8분 | 5분 | 연락 배경과 고객 맥락 확인 | SALES | 아웃리치 가설을 사실로 단정하지 않는다. |
| 30분형 | 8~20분 | 12분 | 현재 업무와 문제 인식 확인 | CNS | 기술 해결책을 즉시 설계하지 않는다. |
| 30분형 | 20~26분 | 6분 | 가벼운 BANT 항목 확인 | SALES | 예산액·구매위원회를 추궁하지 않는다. |
| 30분형 | 26~30분 | 4분 | 요약, 미확인 사항, 다음 단계 합의 | SALES | 상대 동의 없이 디스커버리 일정을 확정하지 않는다. |
| 45분형 | 0~5분 | 5분 | 참석자·목적·아젠다 조정 | SALES | 준비된 순서를 고정적으로 강요하지 않는다. |
| 45분형 | 5~12분 | 7분 | 조직과 업무 배경 청취 | SALES | 조직도를 완성하려 하지 않는다. |
| 45분형 | 12~30분 | 18분 | 문제, 영향, 기존 대응 방식 확인 | CNS | 기술 타당성을 현장에서 판정하지 않는다. |
| 45분형 | 30~38분 | 8분 | 가벼운 BANT와 추가 참석자 확인 | SALES | 심층 자격심사로 확대하지 않는다. |
| 45분형 | 38~45분 | 7분 | 공개자료 안내와 후속 절차 합의 | SALES | 제안·가격 단계의 내용을 다루지 않는다. |

### 2인 1조 역할 분담

초기 미팅은 SALES 1명과 CNS 1명의 2인 1조를 기본으로 한다. SALES가 흐름과 시간을 관리하고 CNS가 업무 맥락과 기술 검토 필요 항목을 확인한다. 한 사람이 답변 중일 때 다른 사람은 말을 끊지 않고 미확인 항목을 기록한다.

- SALES는 참석자, 미팅 목적, 종료 시각을 확인한다.
- SALES는 연락 배경, 관심 수준, 다음 단계 의사를 질문한다.
- SALES는 가격, 견적, 계약 조건을 현장에서 설명하지 않는다.
- SALES는 확인되지 않은 기술 범위나 수행 기간을 약속하지 않는다.
- CNS는 현재 업무 흐름, 문제 상황, 기존 대응 방식을 질문한다.
- CNS는 추가 기술 검토가 필요한 항목과 필요한 참석 역할을 정리한다.
- CNS는 즉석 아키텍처, 모델 성능, 데이터 적합성을 확정하지 않는다.
- CNS는 디스커버리 수준의 상세 질문지를 모두 진행하지 않는다.

### BANT 수준의 가벼운 확인

이 단계의 BANT는 다음 대화 필요성을 판단하기 위한 1차 필터로만 사용한다. 초기 접촉 정보는 불완전하고 참석자의 역할도 확정되지 않을 수 있으므로 심층 자격심사를 적용하지 않는다. 복합 의사결정 구조와 상세 구매 절차는 디스커버리 이후 별도 판단 대상으로 넘긴다.

- Budget: 관련 검토 예산 또는 예산 편성 절차의 존재 여부만 묻는다.
- Authority: 참석자의 담당 범위와 추가로 참여할 역할이 있는지만 묻는다.
- Need: 현재 불편, 개선 필요, 검토 계기를 한 문장으로 확인한다.
- Timeline: 검토 시작 시기나 내부 목표 시점의 존재 여부만 확인한다.
- 구체적인 예산액을 답하도록 반복 질문하지 않는다.
- 단일 참석자를 최종 결정권자로 간주하지 않는다.
- 응답이 불명확하다는 이유만으로 부적합 기회로 단정하지 않는다.
- 심층 확인이 필요하면 미확인 항목으로 기록하고 디스커버리로 넘긴다.

### 자료 제시 범위

- 회사 공개 소개자료와 공개된 서비스 범위만 제시한다.
- 레퍼런스는 “콜센터 AI 상담 구축”, “수요예측 대시보드 구축” 이름까지만 언급한다.
- 고객사 식별 정보, 내부 화면, 상세 구성, 성과 수치는 설명하지 않는다.
- 승인되지 않은 내부 제안서, 산출물, 회의록을 화면 공유하지 않는다.
- 비공개 자료를 개인 메일, 메신저, 이동식 저장장치로 반출하지 않는다.
- 화면 공유 전 알림창, 파일명, 다른 고객 관련 탭을 닫는다.
- 추가 자료 요청은 공개 가능 여부를 확인한 뒤 별도로 회신한다.
- 공개 범위가 불명확하면 현장에서 제시하지 않고 확인 후 답변한다.

## 초기 미팅에서 하지 말아야 할 것
<!--meta: sec=s6; dept=SALES|CNS; level=주니어|시니어; ct_band=중; related=DSC-02#s4-->

초기 미팅에서는 고객의 관심을 확보하기 위해 확인되지 않은 범위, 기간, 성능, 비용을 확정해서 말하지 않는다. 답변할 근거가 부족하면 추정치를 제시하는 대신 확인이 필요한 조건과 담당 검토 절차를 안내한다. 미팅 편의를 이유로 다른 고객의 비공개 정보를 사용하지 않는다.

### 금지 행위와 대체 화법

질문을 받은 담당자는 즉답 가능 여부를 먼저 판단한다. 공개된 회사 정보나 진행 절차는 답할 수 있으나, 개별 과제의 실현 가능성과 수행 조건은 기술 검토를 거친다. 기술 실현 가능성 판정 기준은 DSC-02#s4를 참고한다.

| 금지 항목 | 금지 표현·행동 | 판단 사유 | 대체 화법 | 후속 처리 |
|---|---|---|---|---|
| 즉석 견적 | “이 정도면 ○원에 가능하다.” | 범위와 제약이 확인되지 않았다. | “비용은 요구 범위 확인 후 제안·가격 소관 문서 계열로 이관한다.” | 질문과 전제만 기록한다. |
| 기간 단정 | “두 달이면 완료한다.” | 데이터·연동·승인 일정이 미확정이다. | “일정 영향 조건을 확인한 뒤 검토 결과로 답변하겠다.” | 필요한 일정 조건을 정리한다. |
| 실현 가능성 단정 | “기술적으로 문제없다.” | 업무·데이터·인프라 검토 전이다. | “가능 여부는 기술 검토 항목으로 등록하겠다.” | CNS가 검토 책임 부서를 지정한다. |
| 성능 보장 | “정확도 ○%를 달성한다.” | 평가 데이터셋과 기준이 없다. | “측정 기준과 데이터 조건이 확인돼야 판단할 수 있다.” | 검증 조건을 미확인으로 남긴다. |
| 보안 판단 | “해당 환경이면 안전하다.” | 배치·접근·운영 조건이 불명확하다. | “환경별 보안 요건을 사전검토에서 확인하겠다.” | 관련 질의를 별도로 수집한다. |
| 레퍼런스 과잉 설명 | 비공개 화면·성과·구성을 제시한다. | 공개 범위를 벗어날 수 있다. | “공개된 레퍼런스 명칭까지만 안내할 수 있다.” | 추가 요청은 공개 여부를 확인한다. |
| 고객 숫자 재인용 | 미검증 수치를 사실처럼 반복한다. | 산식·기간·출처가 확인되지 않았다. | “고객이 제시한 미검증 수치로 기록하겠다.” | 근거 자료와 기준일을 요청한다. |
| 계약 답변 | 조건 수용 여부를 현장에서 약속한다. | 해당 미팅의 결정 범위를 벗어난다. | “제안·가격 소관 문서 계열로 전달하겠다.” | 질문 원문과 요청 기한을 이관한다. |

### 기술 질문 처리

기술 질문을 받았다는 이유로 전체 구현 방식을 현장에서 설계하지 않는다. 답변 가능한 공개 원칙과 추가 검토가 필요한 개별 조건을 분리한다. 검토가 필요한 질문에는 회신 책임자와 목표 일자를 정하되 결과를 예고하지 않는다.

- 질문을 고객 표현 그대로 기록한다.
- 현재 확인된 전제와 미확인 전제를 구분한다.
- 업무 적합성, 기술 실현 가능성, 데이터 조건을 혼합하지 않는다.
- 현장에서 답할 수 있는 범위를 공개 정보로 제한한다.
- 추가 검토 항목에는 CNS 책임자를 지정한다.
- 데이터 관련 상세 평가는 별도 기술 검토로 넘긴다.
- 회신 목표는 미팅 후 3영업일 이내로 설정한다.
- 검토가 지연되면 목표일 전에 사유와 변경 일자를 알린다.

### 고객 제시 숫자와 레퍼런스 취급

고객이 제시한 처리량, 오류율, 인력, 비용, 목표 성능은 발언 사실 자체를 기록한다. 다만 출처, 산식, 측정 기간을 검증하기 전에는 회사의 판단이나 확정 수치로 인용하지 않는다. 레퍼런스는 공개 범위 안에서만 언급하고 비교 우위를 주장하는 근거로 확대하지 않는다.

- 기록 앞에 `[고객 진술·미검증]` 표시를 붙인다.
- 수치의 기준일과 측정 기간을 확인한다.
- 분모, 제외 조건, 표본 범위를 확인한다.
- 근거 문서가 없으면 추정인지 실측인지 구분한다.
- 검증 전 수치를 외부 회신이나 발표자료에 사용하지 않는다.
- 검증 전 수치를 기술 타당성 결론의 근거로 사용하지 않는다.
- “콜센터 AI 상담 구축”은 명칭 외 내용을 추가하지 않는다.
- “수요예측 대시보드 구축”은 명칭 외 내용을 추가하지 않는다.
- 비공개 자료 요청에는 공개 가능 여부 확인이 필요하다고 답한다.
- 다른 고객과의 수치 비교 요청에는 확인되지 않은 비교를 제공하지 않는다.

### 가격·계약 질문 이관

가격과 계약 관련 질문에는 현장에서 조건을 해석하거나 수용 여부를 답하지 않는다. SALES는 질문 원문과 고객이 요청한 회신 시점만 정리하여 제안·가격 소관 문서 계열로 이관한다. 이관 완료 전에는 잠정 답변을 고객에게 전달하지 않는다.

- 질문 유형을 가격, 범위, 계약, 지급, 책임 조건으로만 분류한다.
- 고객 질문을 축약하거나 유리한 방향으로 바꾸지 않는다.
- 미팅에서 답하지 않았다는 사실을 기록한다.
- 관련 전제와 요청 기한을 함께 전달한다.
- 이관 담당자와 접수 일시를 기록한다.
- 공식 회신 담당자가 정해지면 고객에게 연락 주체를 알린다.
- 구두 의견을 회사의 확정 입장으로 전달하지 않는다.
- 후속 회신은 제안·가격 소관 문서 계열의 승인 절차를 따른다.

## 미팅 후 24시간 처리
<!--meta: sec=s7; dept=SALES; level=주니어; ct_band=하; related=none-->

미팅 담당자는 종료 시점부터 24시간 이내에 후속 처리를 완료한다. 휴일 전날 미팅은 다음 영업일 같은 시각까지 처리하되, 고객에게 약속한 기한이 더 빠르면 해당 기한을 따른다. 사실과 미확인 사항을 구분하며, 고객이 동의하지 않은 해석을 합의 사항으로 기록하지 않는다.

| 처리 항목 | 완료 기준 | 담당 | 기한 | 증빙 |
|---|---|---|---|---|
| 참석자 확인 | 소속·역할·연락 수단을 확인함 | 미팅 담당자 | 4시간 | 참석자 기록 |
| 미팅 요약 | 문제·일정·추진 주체를 사실 기준으로 정리함 | 미팅 담당자 | 8시간 | 미팅 기록 |
| 확인 과제 등록 | 답변 주체와 확인 기한을 지정함 | 미팅 담당자 | 8시간 | 과제 목록 |
| 후속 메일 발송 | 합의·미확인·다음 단계·자료 요청을 포함함 | 미팅 담당자 | 24시간 | 발송 메일 |
| 내부 공유 | 참여한 SALES·CNS 인원에게 동일 기록을 공유함 | 미팅 담당자 | 24시간 | 공유 이력 |
| 이관 후보 표시 | s8 게이트 검토가 필요한지 표시함 | SALES 대리 이상 | 24시간 | 판정 요청 |
| 자료 보관 | 수신 자료의 출처·수신일·접근 범위를 남김 | 자료 수신자 | 24시간 | 자료 목록 |

후속 메일은 새로운 약속을 추가하는 문서가 아니라 미팅에서 확인한 내용을 상호 점검하는 문서로 작성한다. 고객의 정정 회신이 있으면 기존 기록을 삭제하지 않고 정정 일시와 변경 항목을 남긴다.

### 24시간 처리 체크리스트

- 미팅 시작·종료 시각과 진행 방식을 기록한다.
- 실제 참석자와 불참자를 구분한다.
- 고객이 표현한 업무 문제를 원문 취지에 맞게 요약한다.
- 일정은 확정, 목표, 희망, 미정으로 구분한다.
- 고객 측 추진 주체와 현업 참여 가능 여부를 기록한다.
- 확인하지 못한 항목에는 답변 예정자와 기한을 지정한다.
- 고객 요청 자료와 헤드헌터랩 제공 예정 자료를 구분한다.
- 후속 연락일 또는 디스커버리 이관 판정 일정을 등록한다.

>

> - 현재 확인할 업무 문제는 `[문제 문장]`이다.

>
> **확인 필요 사항**
> - `[미확인 항목]`은 `[확인 주체]`가 `[날짜]`까지 확인한다.
>

> - `[날짜]`까지 디스커버리 진행 여부와 참석 가능 일정을 상호 확인한다.
>
> **요청 자료**
> - 검토 가능한 범위에서 `[자료명·기간·형식]`의 제공 가능 여부를 확인 요청드린다.
>
> 사실과 다른 항목 또는 공유가 곤란한 항목이 있으면 알려주시기 바랍니다.

### 기록 필드와 제외 정보

- 어카운트 식별 코드와 담당 지점을 기록한다.
- 미팅 일시, 방식, 소요 시간과 담당자를 기록한다.
- 참석자의 소속 부서, 업무 역할과 연락 수단을 기록한다.
- 특정된 업무 문제와 해당 문제가 발생하는 절차를 기록한다.
- 현업 참여 의향, 개략 일정과 내부 추진 주체를 기록한다.
- 합의된 사실과 확인 필요 사항을 별도 필드로 분리한다.
- 다음 단계, 책임자, 기한과 요청 자료를 기록한다.
- 정보의 출처를 고객 발언, 공개 정보, 내부 판단으로 구분한다.
- 고객이 정정하거나 공개 범위를 제한한 이력을 기록한다.

고객 의도에 대한 추측, 참석자의 성향·능력에 대한 개인 평가, 미팅 목적과 무관한 사생활 정보는 기록하지 않는다. 차별적 표현, 비공개 인사 정보, 건강·가족·정치적 견해 등 민감 발언은 후속 판단에 필요하다는 이유만으로 전재하지 않는다.

### 다음 단계 합의가 없는 경우

- 상태를 디스커버리 이관으로 임의 변경하지 않는다.
- 미합의 사유를 고객 검토 중, 참석자 부재, 일정 미정, 과제 불명확으로 기록한다.
- 고객에게 확인 가능한 선택 일정 2~3개를 제시한다.
- 회신 요청 기한은 발송일부터 5영업일 이내로 둔다.
- 회신이 없으면 마지막 연락일부터 10영업일 후 1회만 재확인한다.

재확인 후에도 일정이나 담당자가 정해지지 않으면 보류 상태와 재검토 예정일을 등록한다. 고객이 연락 중단을 요청하거나 추진 의사가 없다고 밝히면 추가 접촉을 하지 않고 s8의 중단 조건으로 판정한다.

## 디스커버리 이관 판정
<!--meta: sec=s8; dept=SALES|CNS; level=시니어; ct_band=상; related=DSC-01#s2-->

초기 미팅 종료 후 디스커버리 이관 여부를 통과, 보류, 중단으로 판정한다. 초기 단계에서는 BANT 수준의 가벼운 확인만 수행하며, 예산 미확인만으로 중단하지 않는다. 심층 질문과 참석자 구성은 DSC-01#s2를 따른다.

| 판정 | 판단 조건 | 필수 근거 | 후속 조치 | 재판정 시점 |
|---|---|---|---|---|
| 통과 | 해결할 업무 문제가 특정됨 | 문제 문장과 적용 업무 | 이관 자료 작성 | 1영업일 이내 |
| 통과 | 해당 업무의 현업 참여 의향이 있음 | 참여 부서 또는 역할 | 참석 후보 확인 | 1영업일 이내 |
| 통과 | 착수·검토의 개략 일정이 존재함 | 월·분기 또는 기한 | 후보 일정 요청 | 1영업일 이내 |
| 통과 | 고객 내부 추진 주체가 식별됨 | 담당 부서 또는 역할 | 연락 창구 지정 | 1영업일 이내 |
| 보류 | 통과 조건 일부가 없으나 확인 경로와 기한이 있음 | 미확인 항목·답변자·기한 | 재검토일 등록 | 최대 30일 이내 |
| 중단 | 문제가 없거나 현업 참여 의사가 없고 재검토 근거도 없음 | 고객 답변 또는 접촉 중단 요청 | 추가 진행 종료 | 사유 발생 즉시 |
| 중단 | 요청 범위가 회사 수행 범위와 명백히 다름 | 요청 범위 기록 | 해당 사유 안내 | 1영업일 이내 |
| 중단 | 허위 진술·부적절한 정보 취득 등 금지 행위를 요구함 | 요구 내용과 응답 기록 | 관리자 보고 | 당일 |

통과는 네 가지 필수 조건이 모두 확인되고 중단 조건이 없을 때만 적용한다. 보류는 누락 조건을 확인할 주체와 날짜가 있을 때 적용하며, 막연한 기대나 반복 연락 계획만 있는 경우에는 적용하지 않는다.

### 판정 주체와 시한

- 미팅 담당자는 종료 후 24시간 이내에 판정안을 작성한다.
- SALES 대리 이상 1인이 사실 기록과 판정안을 검토한다.
- 통과 판정은 CNS 과장 이상 1인의 수락 확인을 받아 확정한다.
- 중단 판정은 SALES 과장 이상이 사유의 객관성을 확인한다.
- 판정은 원칙적으로 미팅 종료 후 2영업일 이내 확정한다.
- SALES와 CNS의 의견이 다르면 조건별 근거를 분리해 기록한다.
- 이견이 2영업일 내 해소되지 않으면 보류로 두고 재판정일을 지정한다.

### 이관 자료 목록

- 어카운트 코드, 담당 지점과 영업 담당자
- 미팅 일시, 참석자 역할과 고객 측 연락 창구
- 고객이 확인한 업무 문제 문장
- 문제의 발생 업무와 영향을 받는 사용자 범위
- 현업 참여 의향과 디스커버리 참석 후보
- 개략 일정과 일정의 확정 수준
- 내부 추진 주체의 부서 또는 역할
- 확인 필요 사항, 답변 주체와 확인 기한
- 고객이 제공 가능한 자료의 명칭과 제공 가능 시점
- 보안·데이터·인프라 관련 초기 제약의 존재 여부
- 발송한 요약 메일과 고객의 정정 회신
- 통과 조건별 근거와 판정 승인 이력

이관 자료에는 추정값을 확정 사실처럼 기재하지 않으며, 민감한 원문 자료 대신 접근 위치와 권한을 남긴다. 기술 타당성이나 데이터 준비도를 초기 미팅 정보만으로 확정하지 않는다.

### 컨설팅 공수 예약 절차

- SALES 담당자는 통과 확정 당일 CNS에 공수 예약을 요청한다.
- 요청에는 이관 자료와 고객 가능 일정 2~3개를 첨부한다.
- 담당 지점 CNS를 우선 배정하되 타 지점 지원이 필요하면 사유를 적는다.
- CNS는 요청 후 2영업일 이내에 진행 가능 여부를 회신한다.
- 임시 예약은 회신일부터 최대 5영업일 동안 유지한다.
- 고객 일정이 확정되면 담당자와 준비 일정을 확정 상태로 전환한다.
- 5영업일 내 고객 확인이 없으면 임시 예약을 해제하고 보류로 돌린다.
- 참여자와 준비물 확정은 DSC-01#s2를 따른다.

보류 리드에는 누락 조건, 확인 담당자, 마지막 접촉일과 재검토 예정일을 반드시 등록한다. 재검토 예정일은 최대 30일 이내로 두며, 사유 없이 두 차례 연기된 경우 중단 여부를 다시 판정한다.

## 아웃리치 성과 측정과 메시지 개선
<!--meta: sec=s9; dept=SALES|DATA; level=시니어; ct_band=중; related=SLS-04#s7-->

아웃리치 성과는 접촉 대상의 원시 건수와 단계별 전환율을 함께 측정한다. 동일 인물에 대한 반복 발송은 해당 측정 기간의 분모에서 1건으로 중복 제거한다. 자동 회신, 반송, 내부 테스트와 이미 진행 중인 어카운트는 성과 건수에서 제외한다.

| 지표 | 분자 | 분모 | 집계 기준 | 제외 항목 |
|---|---|---|---|---|
| 접촉 도달률 | 정상 수신 메일 또는 실제 연결이 확인된 고유 담당자 수 | 접촉을 시도한 고유 담당자 수 | 채널별·주별 | 반송·결번 |
| 회신률 | 사람이 작성한 유효 회신 담당자 수 | 접촉이 도달한 고유 담당자 수 | 최초 도달 후 14일 | 자동 회신 |
| 미팅 성사율 | 실제 완료된 초기 미팅 수 | 유효 회신 담당자 수 | 회신 후 30일 | 취소·불참 |
| 디스커버리 이관율 | s8 통과가 확정된 건수 | 완료된 초기 미팅 수 | 미팅 후 2영업일 | 보류·중단 |

지표는 채널, 대상 세그먼트, 시퀀스 버전과 담당자 기준으로 분리하되 개인 순위 산정에 단독 사용하지 않는다. 표본이 적은 세부 집단은 전체 평균과 직접 비교하지 않으며, 파이프라인 집계나 수주 예측으로 확장하지 않는다.

### 개선 실험 원칙

- 한 실험에서는 한 변수만 변경한다.
- 비교군과 실험군은 같은 ICP 등급과 유사한 담당 역할로 구성한다.
- 제목을 바꾸는 실험에서는 본문, 발신자, 발송 시각을 유지한다.
- 첫 문장을 바꾸는 실험에서는 제목과 요청 행동을 유지한다.
- 요청 행동을 바꾸는 실험에서는 문제 가설과 시퀀스 간격을 유지한다.
- 발송 시각을 바꾸는 실험에서는 메시지 문안을 유지한다.
- 시퀀스 간격을 바꾸는 실험에서는 메일 수와 각 메일 역할을 유지한다.
- 두 군의 배정은 번갈아 배정하거나 무작위 배정한다.
- 실험 중간에 성과가 낮다는 이유로 문안을 추가 변경하지 않는다.
- 고객의 수신 거부와 연락 중단 요청은 실험 배정과 무관하게 즉시 반영한다.

비교 기간은 최소 10영업일로 하고, 같은 요일 구성을 포함한다. 각 군은 도달한 고유 담당자 100명 이상을 확보하며, 20영업일까지 표본을 채우지 못하면 결과를 방향성 참고로만 기록한다. 미팅 성사와 디스커버리 이관은 합산 완료 미팅이 20건 미만이면 확정 개선으로 판정하지 않는다.

### 성과 하락 원인 분류

- **리스트 품질:** 담당 역할 불일치, 중복 연락, 반송·결번 증가, ICP 제외 대상 혼입을 확인한다.
- **메시지:** 제목과 본문의 맥락 불일치, 문제 가설의 비구체성, 요청 행동의 과도함을 확인한다.
- **타이밍:** 휴일·결산·정기 업무 집중 기간, 발송 시간대, 후속 간격의 부적합을 확인한다.
- **담당 역량:** 후속 누락, 응답 지연, 기록 불완전, 첫 미팅 전환 과정의 차이를 확인한다.
- 원인은 하나로 단정하지 않고 지표와 표본 기록을 근거로 최대 2개까지 지정한다.
- 접촉 도달률이 하락하면 메시지보다 리스트와 전달 가능성을 먼저 확인한다.
- 도달률은 유지되나 회신률이 하락하면 메시지와 타이밍을 우선 확인한다.
- 회신률은 유지되나 미팅 성사율이 하락하면 후속 속도와 일정 제시 방식을 확인한다.
- 미팅 성사율은 유지되나 이관율이 하락하면 대상 적합성과 초기 문제 특정 수준을 확인한다.

### 개선 실험 기록 양식

- 실험 ID와 시퀀스 버전
- 실험 목적과 관찰한 문제 지표
- 유지 변수와 단일 변경 변수
- 비교군·실험군의 대상 조건
- 시작일, 종료일과 적용 채널
- 군별 시도·도달·회신·미팅·이관 건수
- 단계별 전환율과 제외 건수
- 표본 충족 여부와 해석 제한
- 채택, 추가 검증, 기각 중 하나의 결론
- 승인자, 승인일과 적용 예정일
- 이전 버전 복원 조건과 복원 책임자
- 관련 원시 기록의 보관 위치

DATA는 집계 정의와 중복 제거 결과를 검증하고 SALES 과장 이상은 현장 적용 여부를 승인한다. 채택된 변경은 새 시퀀스 버전으로 등록하며 기존 버전과 적용일을 보존한다. 리드 스코어링 기준에 영향을 주는 결과가 확인되면 SLS-04#s7에 따라 별도 검증한다.
