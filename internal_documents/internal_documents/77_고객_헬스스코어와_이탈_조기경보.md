# 고객 헬스 스코어와 이탈 조기 경보
<!--meta: doc=CSM-03; doc_type=playbook; tier=1; topic=CS; disclosure=internal; status=active-->

## 목적과 사용 범위
<!--meta: sec=s1; dept=CNS|DATA; level=주니어|시니어; ct_band=하; related=s2-->
헬스 스코어는 고객 계정의 정착 상태, 지원 부담, 관계 안정성을 하나의 0~100점 지표로 변환하여 한정된 고객성공 공수를 우선 배분하는 운영 도구입니다. 점수 자체보다 어떤 계정에 누가 언제 개입해야 하는지를 결정하는 데 사용합니다.

적용 시작점은 계약 체결 또는 구축 착수 후 측정 가능한 신호가 최초로 생성된 시점입니다. 계약 종료, 해지 또는 운영 인수인계 완료로 헤드헌터랩의 관리 책임이 끝나면 산정을 중단하되 최종 점수와 종료 사유는 보존합니다.

**주요 사용 범위**

| 사용 장면 | 판단 질문 | 산출 결과 | 기본 담당 |
| --- | --- | --- | --- |
| 일일 경보 확인 | 최근 위험 신호가 발생했는가 | 접촉 필요 계정 목록 | CNS |
| 주간 계정 점검 | 공수를 먼저 투입할 계정은 어디인가 | 우선순위와 담당자 | CNS |
| 월간 포트폴리오 점검 | 위험 계정이 특정 유형에 집중되는가 | 세그먼트별 위험 분포 | CNS·DATA |
| 갱신 사전 준비 | 갱신 대화 60일 전 위험을 식별했는가 | 선제 개입 대상 | CNS |
| 모델 검증 | 점수가 실제 축소·이탈을 예측했는가 | 가중치 보정 후보 | DATA |

점수는 고객 담당자의 정성 판단을 없애는 장치가 아닙니다. 데이터 신호를 동일한 기준으로 정렬하고, 담당자가 확인해야 할 계정을 좁히는 1차 필터로 사용합니다.

**적용 대상**

운영·유지보수 계약 고객은 서비스 사용, 지원 활동, 만족도 및 고객 관계 신호를 지속 측정합니다. 동일 고객이 여러 시스템이나 계약을 보유하면 `계정 단위 점수`와 `계약·시스템 단위 하위 점수`를 분리합니다.

구축 중 고객도 적용 대상이지만 운영 고객과 같은 지표를 강제로 사용하지 않습니다. 구축 단계에서는 활동·참여·마일스톤·최근성 중심 산식을 사용할 수 있으며, 두 계약 형태의 세부 지표 차이는 s12에서 정합니다.

| 대상 상태 | 산정 단위 | 최초 산정 시점 | 종료 시점 |
| --- | --- | --- | --- |
| 구축 프로젝트 | 프로젝트 또는 구축 시스템 | 착수 후 첫 주간 데이터 마감 | 운영 전환 또는 계약 종료 |
| 운영·유지보수 | 계약·시스템 및 상위 계정 | 서비스 개시일 | 계약 종료 |
| 구축과 운영 병행 | 프로젝트와 운영 계약 분리 | 각 대상의 개별 시작일 | 각 대상별 종료일 |
| 복수 지점 공동 수행 | 고객 계정 1개, 하위 단위 복수 | 주관 지점 지정 후 | 최종 관리 계약 종료 |

서울·경기·인천 지점은 같은 산식 버전을 사용합니다. 주관 지점 CNS가 계정 판정을 책임지고, DATA는 집계 로직과 데이터 품질을 관리하며, BE와 AIAX는 필요한 이벤트·지원 데이터를 제공하는 역할을 맡습니다.

**범위 경계**

- 영업 기회의 단계, 수주 확률 및 포캐스트는 FCT-01·FCT-02를 따릅니다.
- 온보딩 종료와 운영 전환 판정은 CSM-01·CSM-02를 따릅니다.
- 갱신 가격과 유지보수 요율은 CSM-05를 따릅니다.
- 헬스 스코어의 금지 용도와 오용 판정은 s14에서 정합니다.

헬스 스코어는 고객별 성공 계획이나 장애 기록을 대체하지 않습니다. 원인 확인이 필요한 경우 점수를 구성한 원천 신호까지 내려가 검토해야 합니다.

## 설계 원칙
<!--meta: sec=s2; dept=CNS|DATA; level=시니어; ct_band=상; related=s1|s3-->
헬스 스코어는 설명 가능한 소수 신호로 구성하고, 실제 개입으로 상태를 바꿀 수 있도록 설계합니다. 데이터가 많다는 이유로 변수를 늘리면 중복 신호가 특정 현상을 과대평가하고 담당자가 점수 변동 원인을 설명하기 어려워집니다.

운영 목표는 갱신 직전의 상태 보고가 아니라 선행 경보입니다. 정상적인 갱신 대화를 시작하기 최소 60일 전에 축소·해지 가능성을 구분할 수 있어야 하며, 이 기준을 충족하지 못하면 가중치와 관측 기간을 재검토합니다.

**설계 5원칙**

| 원칙 | 적용 기준 | 위반 판정 |
| --- | --- | --- |
| 신호는 4~6개만 사용 | 독립된 행동·관계·지원 신호를 선택 | 7개 이상이거나 같은 현상을 중복 반영 |
| 영향을 줄 수 있는 신호 선택 | CNS 또는 수행팀의 개입 행동이 연결됨 | 점수가 변해도 실행 가능한 조치가 없음 |
| 선행력으로 가중치 결정 | 이탈·축소를 먼저 알린 신호에 높은 가중치 부여 | 수집 편의나 직급자의 선호로 가중치 결정 |
| 최근성 감쇠 적용 | 오래된 긍정·부정 사건의 영향이 시간에 따라 감소 | 6개월 전 사건이 현재와 동일하게 반영 |
| 세그먼트별 밴드 운영 | 계약 형태·규모·사용 패턴별 임계값 분리 | 전체 고객에 단일 임계값 강제 적용 |

신호 수를 셀 때 하위 지표는 하나의 상위 신호로 묶습니다. 예를 들어 활성 사용자 수, 기능 사용 깊이, 이용 빈도는 각각 별도 신호가 아니라 `제품 사용·정착`의 하위 지표로 취급합니다.

영향 가능성은 헤드헌터랩이 원인을 완전히 통제할 수 있다는 뜻이 아닙니다. 고객 챔피언의 응답 감소처럼 직접 통제할 수 없는 현상도 후임자 확보, 경영진 접촉 또는 성공 기준 재합의로 대응할 수 있으면 포함합니다.

**가중치 결정 절차**

1. 최근 12개월 또는 최소 30개 계약 종료 사례를 확보합니다.
2. 축소·해지일을 기준으로 T-120, T-90, T-60, T-30 시점의 신호를 재구성합니다.
3. 각 신호가 위험 계정과 정상 계정을 구분한 시차와 적중률을 비교합니다.
4. T-60 이전부터 반복적으로 구분력을 보인 신호에 우선 가중치를 배정합니다.
5. 표본이 30개 미만이면 s3의 기본 가중치를 유지하고 정성 보정을 제한합니다.

선행력은 단순 상관계수만으로 판단하지 않습니다. 신호 발생 후 실제 개입할 시간이 남아 있는지, 특정 대형 고객 한 곳이 결과를 왜곡하지 않는지, 같은 원인을 측정하는 다른 신호와 중복되는지를 함께 확인합니다.

**설계 승인 기준**

| 점검 항목 | 통과 기준 | 검토 담당 |
| --- | --- | --- |
| 설명 가능성 | 담당자가 3분 내 점수 하락 원인을 설명 | CNS |
| 데이터 충족률 | 필수 신호의 유효값 보유율 90% 이상 | DATA |
| 선행 경보 | 이탈 계정의 60% 이상을 T-60까지 위험 분류 | CNS·DATA |
| 오경보 관리 | 정상 갱신 계정의 위험 분류율 25% 이하 | DATA |
| 실행 연결성 | 각 밴드에 담당·기한이 지정된 조치 존재 | CNS |

최근성 감쇠의 구체 계수는 s5, 세그먼트 임계값은 s6, 예측 성능의 검증·재보정 주기는 s15에서 정합니다. 신규 산식은 DATA 과장 이상과 CNS 과장 이상의 공동 승인 후 적용합니다.

## 신호 구성과 가중치
<!--meta: sec=s3; dept=CNS|DATA; level=시니어; ct_band=상; related=s2|s4-->
운영·유지보수 계약에는 제품 사용·정착, 지원 활동, 고객 감정, 경영진·챔피언 참여의 네 가지 신호를 기본으로 사용합니다. 모든 하위 지표를 0~100점으로 정규화하고, 높은 점수가 건강한 상태를 뜻하도록 방향을 통일합니다.

기본 산식은 `헬스 스코어 = 사용·정착×0.40 + 지원 활동×0.25 + 감정×0.20 + 경영진·챔피언 참여×0.15`입니다. 계산 결과는 소수점 첫째 자리에서 반올림하여 정수로 표시하되 원본 계산값은 소수점 둘째 자리까지 보관합니다.

**기본 신호 구성**

| 상위 신호 | 가중치 | 포함 하위 지표 | 해석 기준 |
| --- | ---: | --- | --- |
| 제품 사용·정착 | 40% | 활성 사용자, 기능 사용 깊이, 계정 기준선 대비 빈도 | 실제 업무 정착을 가장 직접적으로 보여 예측력이 가장 높음 |
| 지원 활동 | 25% | 티켓 건수, 심각도, 재오픈율, 해결시간 | 부담 증가와 서비스 불안정 여부를 반영 |
| 감정·NPS | 20% | NPS, CSAT, 자유 의견의 부정 신호 | 고객이 인식한 가치와 불만 수준을 반영 |
| 경영진·챔피언 참여 | 15% | 의사결정자 응답, 회의 참석, 챔피언 활동 | 관계 연속성과 내부 지지 기반을 반영 |

지원 활동 점수는 문의가 많을수록 높아지는 구조로 만들지 않습니다. P1·P2 증가, 재오픈률 상승, 해결시간 악화 및 에스컬레이션 급증이 점수를 낮추도록 역방향으로 변환합니다.

경영진·챔피언 참여는 비중이 가장 낮더라도 독립 신호로 유지합니다. 챔피언 이탈은 후속 관계 약화, 의사결정 지연 및 갱신 불확실성으로 이어지는 첫 번째 도미노가 될 수 있기 때문입니다.

**구축 단계 대안 산식**

구축 중에는 완성된 제품 사용 로그와 운영 티켓이 충분하지 않을 수 있으므로 `헬스 = 활동×0.40 + 참여×0.30 + 마일스톤×0.20 + 최근성×0.10`을 사용할 수 있습니다.

| 대안 신호 | 가중치 | 대표 관측 대상 | 점수가 낮아지는 조건 |
| --- | ---: | --- | --- |
| 활동 | 40% | 합의된 작업·검토·테스트 수행 | 예정 활동 미실행 또는 반복 지연 |
| 참여 | 30% | 고객 담당자·의사결정자 관여 | 응답 지연, 회의 불참, 담당 공백 |
| 마일스톤 | 20% | 승인·검수·연동 등 계획 진척 | 기한 미달 또는 승인 반려 |
| 최근성 | 10% | 마지막 유효 상호작용 시점 | 유효 활동 없이 경과일 증가 |

대안 산식은 구축 완료 전 임시 점수로 사용합니다. 공식 오픈 후 운영 데이터가 14일 이상 누적되면 기본 산식으로 전환하되, 전환일 전후 점수는 같은 추세선으로 직접 비교하지 않습니다.

**산식 선택 기준**

| 조건 | 선택 산식 | 판정 책임 |
| --- | --- | --- |
| 운영 로그와 지원 기록이 모두 존재 | 기본 40·25·20·15 산식 | CNS |
| 구축 중이며 사용 로그가 아직 없음 | 활동·참여·마일스톤·최근성 산식 | CNS |
| 운영 중이나 로그 수집이 일시 중단 | 기본 산식 유지, 결측 플래그 부여 | DATA |
| 구축과 운영이 병행됨 | 하위 점수를 각각 산출 | CNS·DATA |

가중치는 계정별로 임의 변경하지 않습니다. 세그먼트 전체의 예측 성능 검증을 거친 버전만 배포하며, 개별 계정의 예외적 사정은 s13의 수동 조정 절차로 기록합니다.

## 신호별 측정 방법과 데이터 출처
<!--meta: sec=s4; dept=DATA|BE; level=시니어; ct_band=상; related=s3|s5-->
측정 지표는 동일한 현상을 지점과 시스템마다 다르게 계산하지 않도록 데이터 사전에 등록합니다. 데이터 사전에는 필드명, 단위, 분모, 시간대, 제외 조건, 원천 시스템, 갱신 주기 및 담당자를 포함합니다.

집계 기준 시간대는 한국 표준시로 통일합니다. 일 단위 지표는 `00:00~23:59`, 주간 지표는 월요일 00:00부터 일요일 23:59까지 계산하며, 배치 완료 목표는 다음 영업일 10:00입니다.

**신호별 측정 정의**

| 신호 | 측정 지표 | 데이터 출처 | 수집 주기 | 결측 처리 |
| --- | --- | --- | --- | --- |
| 제품 사용·정착 | 30일 활성 사용자율, 핵심 기능 사용률, 계정 기준선 대비 이용 빈도 | 애플리케이션 이벤트 로그·집계 API | 일 1회 | 수집 장애와 실제 0건을 구분하고 장애 기간은 미산정 |
| 지원 활동 | 사용자 100명당 티켓, P1·P2 비율, 재오픈률, 중앙 해결시간 | 지원 접수 시스템·장애 기록 | 일 1회 | 종료시간 누락 건은 미해결로 유지하고 품질 플래그 부여 |
| 감정·NPS | 최근 90일 NPS, 최근 30일 CSAT, 확인된 부정 의견 | 설문 결과·회의 기록 | 설문 또는 회의 후 1영업일 | 응답 없음은 중립점수로 대체하지 않고 결측 표시 |
| 경영진·챔피언 참여 | 최근 60일 참석률, 응답 소요일, 마지막 유효 접촉 경과일 | 일정·회의록·활동 기록 | 주 1회 | 역할 정보가 없으면 참여 점수 미산정 |
| 활동 | 계획 대비 완료 활동률, 고객 액션 기한 준수율 | 프로젝트 작업 관리 기록 | 주 1회 | 계획 자체가 없으면 데이터 오류로 분류 |
| 마일스톤 | 예정일 대비 완료율, 지연일, 승인 상태 | 프로젝트 일정·승인 기록 | 주 1회 | 승인 증빙이 없으면 미완료 처리 |

활성 사용자는 측정 기간 중 핵심 업무 이벤트를 1회 이상 수행한 고유 사용자로 정의합니다. 단순 로그인, 자동 새로고침, 모니터링 계정 및 테스트 계정은 활성 사용자에서 제외합니다.

기능 사용 깊이는 고객별 핵심 기능 목록 중 실제 사용된 기능의 비율로 계산합니다. 이용 빈도 지수는 `최근 30일 핵심 이벤트 수 ÷ 해당 계정 기준선 이벤트 수 × 100`으로 계산하며, 기준선은 안정 운영 후 연속 8주 중앙값을 사용합니다.

지원 지표는 고객 규모 차이를 줄이기 위해 활성 사용자 100명당 건수로 정규화합니다. 해결시간은 극단값 영향을 줄이기 위해 평균보다 중앙값을 우선 사용하며, 에스컬레이션 건수가 직전 4주 평균의 2배 이상이면 급증 플래그를 생성합니다.

필수 사용 이벤트가 14일 연속 누락되거나 계정 매핑 실패율이 5%를 초과하면 사용 점수를 배포하지 않습니다. 이 경우 전체 점수 옆에 `데이터 불충분`을 표시하고 s16의 대체 판단을 적용합니다.

고객 시스템의 원천 업무 데이터, 개인정보가 포함된 상세 레코드, 음성·문서 원본은 계약상 수집 범위와 보안 승인이 없는 한 헬스 스코어 목적으로 보관하지 않습니다. 가능한 경우 고객 환경에서 계정별 건수·비율로 집계한 값만 전달받습니다.

DATA는 최초 연동 전에 데이터 항목, 저장 위치, 보존 기간, 접근 권한 및 삭제 책임을 확인합니다. 허용 범위를 확인할 수 없는 필드는 수집을 차단하며, 헬스 스코어 산출 편의를 이유로 계약 범위를 확대하지 않습니다.

## 최근성 감쇠 적용
<!--meta: sec=s5; dept=DATA; level=시니어; ct_band=상; related=s4|s6-->
최근성 감쇠는 오래된 관측값이 현재 상태를 과대평가하거나 과소평가하지 않도록 신호의 영향력을 시간에 따라 줄이는 처리입니다. 6개월 전 사용량이 높았더라도 최근 사용이 확인되지 않았다면 오늘의 건강 상태를 의미하지 않습니다.

감쇠는 사용량·지원 이력·고객 반응·참여 기록처럼 시간이 지나면서 설명력이 낮아지는 신호에 적용합니다. 계약 규모, 사업 형태처럼 시간 경과로 의미가 약해지지 않는 속성에는 적용하지 않습니다.

**적용 산식**

관측값은 0~100점으로 정규화한 후 중립점 50을 기준으로 감쇠합니다. 오래된 좋은 신호와 나쁜 신호 모두 50점 방향으로 수렴하게 하여, 단순히 오래됐다는 이유로 위험 점수가 되지 않도록 합니다.

`감쇠계수 = 2 ^ (-관측 경과일 / 반감기)`

`감쇠 후 점수 = 50 + (감쇠 전 점수 - 50) × 감쇠계수`

`최종 헬스 스코어 = Σ(감쇠 후 신호 점수 × 신호 가중치)`

경과일은 데이터 발생일 다음 날부터 계산합니다. 집계 데이터는 집계 기간 종료일을 발생일로 사용하며, 동일 신호에 여러 관측값이 있으면 가장 최근 확정값을 적용합니다.

**반감기 설정 기준**

| 신호 유형 | 기본 반감기 | 적용 조건 | 설정 근거 |
| --- | ---: | --- | --- |
| 제품 사용·정착 | 30일 | 일·주 단위 사용 로그가 존재함 | 최근 사용 변화의 예측력이 높음 |
| 지원 활동 | 45일 | 티켓과 해결시간이 지속 집계됨 | 단기 장애 영향과 회복을 함께 반영함 |
| 챔피언·경영진 참여 | 60일 | 회의 참석·응답 기록이 월 1회 이상 있음 | 관계 약화가 점진적으로 나타남 |
| NPS·CSAT 등 감정 신호 | 90일 | 조사 주기가 월~분기 단위임 | 조사 빈도가 낮아 과도한 감쇠를 방지함 |
| 계약·가치 마일스톤 | 120일 | 분기 단위 성과 확인이 중심임 | 완료 성과의 유효기간이 상대적으로 김 |

기본 반감기는 최근 12개월 데이터에서 신호 발생 후 이탈·축소와의 관계가 절반 이하로 감소하는 시점을 기준으로 보정합니다. 표본이 30개 계정 또는 이탈·축소 사건 10건 미만이면 기본값을 유지합니다.

관측 주기가 기본 반감기보다 긴 신호는 반감기를 관측 주기의 1.5배 이상으로 설정합니다. 예를 들어 분기 조사 신호에 30일 반감기를 적용하여 정상 고객을 위험으로 분류해서는 안 됩니다.

**적용 전후 예시**

| 신호 | 가중치 | 감쇠 전 점수 | 경과일 / 반감기 | 감쇠계수 | 감쇠 후 점수 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 제품 사용·정착 | 40% | 90.0 | 180일 / 60일 | 0.125 | 55.0 |
| 지원 활동 | 25% | 70.0 | 30일 / 90일 | 0.794 | 65.9 |
| 고객 감정 | 20% | 80.0 | 120일 / 120일 | 0.500 | 65.0 |
| 챔피언 참여 | 15% | 85.0 | 15일 / 60일 | 0.841 | 79.4 |
| 가중 합계 | 100% | 82.3 | - | - | 63.4 |

이 사례는 감쇠 전에는 정상 이상으로 보이지만, 핵심 사용 데이터가 180일 전 기록이므로 감쇠 후 관찰 구간으로 내려갑니다. 점수 하락의 원인은 사용 악화가 아니라 최신 증거 부족이므로 담당자는 신규 사용 데이터를 확보해야 합니다.

데이터 적재 지연이 확인된 기간에는 감쇠 계산을 중단하지 않습니다. 대신 데이터 신뢰도 플래그를 표시하고, 적재 복구 후 원래 발생일을 기준으로 재계산합니다.

## 세그먼트별 임계값
<!--meta: sec=s6; dept=CNS|DATA; level=시니어; ct_band=상; related=s5|s7-->
전체 고객에 동일한 임계값을 적용하면 구축 중 고객의 낮은 사용량을 이탈 위험으로 오인하거나, 대규모 운영 고객의 작은 사용량 하락을 정상 변동으로 놓칠 수 있습니다. 임계값은 계약 규모, 사업 형태, 사용자 수, 계약 경과 기간을 함께 반영합니다.

세그먼트는 월 1회 재판정하며 계약 변경, 공식 오픈, 사용자 수 30% 이상 증감이 발생하면 즉시 다시 판정합니다. 한 계정이 여러 조건에 해당하면 모니터링 강도가 높은 프로파일을 적용합니다.

**세그먼트 판정 입력값**

| 구분 기준 | 구간 | 판정 데이터 | 적용 시 유의점 |
| --- | --- | --- | --- |
| 계약 규모 | 1억원 미만 / 1억~5억원 미만 / 5억원 이상 | 구축은 총 공급가액, 운영은 연간 계약가액 | 부가세와 일회성 직접경비는 제외함 |
| 사업 형태 | 구축 / 운영·유지보수 | 유효 계약 유형 | 구축과 운영 계약이 병존하면 운영 프로파일도 병행 산출함 |
| 사용자 수 | 50명 이하 / 51~300명 / 301명 이상 | 최근 30일 등록 대상 사용자 | 테스트·관리자 전용 계정은 제외함 |
| 계약 경과 기간 | 오픈 전 / 오픈 후 0~90일 / 91~365일 / 366일 이상 | 공식 오픈일 또는 운영 개시일 | 오픈일 미등록 계정은 임계값 적용을 보류함 |

프로파일 판정 순서는 `구축 계약 → 오픈 후 90일 이내 → 대규모 운영 → 표준 운영 → 장기 안정 운영`입니다. 대규모 운영은 연간 계약가액 5억원 이상 또는 사용자 301명 이상 중 하나를 충족하면 적용합니다.

장기 안정 운영은 운영 개시 후 366일 이상이고 최근 2개 분기 동안 중대 경보가 없었던 계정입니다. 해당 조건을 잃으면 다음 산출 시 표준 또는 대규모 운영 프로파일로 환원합니다.

**세그먼트별 밴드 임계값**

| 프로파일 | 탁월 | 정상 | 주의 | 관찰 | 위험 | 심각 |
| --- | --- | --- | --- | --- | --- | --- |
| K 구축 중 | 85~100 | 75~84 | 65~74 | 55~64 | 45~54 | 0~44 |
| E 오픈 후 0~90일 | 90~100 | 80~89 | 70~79 | 60~69 | 50~59 | 0~49 |
| S 표준 운영 | 90~100 | 80~89 | 70~79 | 60~69 | 50~59 | 0~49 |
| L 대규모 운영 | 94~100 | 84~93 | 74~83 | 64~73 | 54~63 | 0~53 |
| M 장기 안정 운영 | 92~100 | 82~91 | 72~81 | 62~71 | 52~61 | 0~51 |

K 프로파일은 사용 정착 전 단계의 구조적 저점을 고려하여 임계값을 5점 낮춥니다. 다만 활성화 마일스톤 기한을 넘긴 경우에는 낮은 임계값을 적용하지 않고 조기 경보를 별도로 발생시킵니다.

L 프로파일은 사용자와 업무 영향 범위가 커서 정상 기준을 4점 높입니다. M 프로파일은 장기 기준선이 충분히 형성된 계정이므로 표준보다 2점 높은 임계값으로 작은 이상 변화를 포착합니다.

동일 임계값 사용 시 대표적인 오탐은 구축 중 사용 로그 부족, 오픈 초기 문의 증가, 소규모 계정의 주간 사용 편차입니다. 대표적인 미탐은 대규모 고객의 부서별 사용 중단, 장기 고객의 완만한 하락, 다수 사용자 중 핵심 부서만 이탈하는 경우입니다.

세그먼트 변경으로 밴드가 달라지면 변경 전·후 점수와 프로파일을 모두 보존합니다. 담당자 평가나 경보 실적을 유리하게 만들기 위한 수동 세그먼트 변경은 허용하지 않습니다.

| 70~79 | 주의 | 하락 신호와 데이터 누락 여부를 검토하고 다음 접촉 질문을 등록함 | 10영업일 이내 | CNS 담당자 |
| 60~69 | 관찰 | 고객 담당자에게 접촉하여 사용·관계·지원 상태를 확인함 | 7일 이내 | CNS 담당자 |
| 50~59 | 위험 | 고객 접촉 후 원인·영향·회복 조건을 기록하고 위험 계정으로 등록함 | 72시간 이내 | CNS 담당자·과장 |
| 0~49 | 심각 | 즉시 내부 알림을 발송하고 당일 고객 접촉 및 관리자 개입을 시작함 | 2시간 내 착수, 당일 접촉 | CNS 과장 이상 |

정상 계정의 QBR 운영은 CSM-04를 참조합니다. 위험·심각 계정의 72시간 대응 절차는 CSM-03 s9를 적용합니다.

대응 기한은 밴드 진입 시각부터 계산합니다. 60점 미만 진입이 휴일 또는 업무시간 외에 발생하면 자동 알림은 즉시 발송하고, 고객 접촉 기한은 다음 영업일 09시부터 계산하되 심각 상태의 내부 착수는 미루지 않습니다.

**자동 작업 생성 규칙**

`점수 산출 → 세그먼트 임계값 대조 → 밴드 판정 → CRM 작업 생성 → 담당자 알림 → 기한 추적`

| 발생 조건 | 자동 생성 항목 | 필수 필드 | 미처리 시 조치 |
| --- | --- | --- | --- |
| 상위 밴드에서 주의로 하락 | 데이터 검토 작업 | 하락 신호, 기준일, 다음 확인일 | 기한 다음 날 과장에게 알림 |
| 관찰 진입 | 고객 접촉 작업 | 접촉 대상, 질문, 7일 기한 | 24시간 초과 시 재알림 |
| 위험 진입 | 위험 계정 대응 작업 | 원인 가설, 영향 범위, 회복 조건 | 과장과 DATA 담당에게 동시 알림 |
| 심각 진입 | 긴급 대응 작업 | 최초 조치 시각, 고객 접촉자, 관리자 | 즉시 부장과 관련 수행팀에 알림 |
| 2개 밴드 이상 급락 | 급락 검증 작업 | 원천 데이터, 오류 여부, 최근 사건 | DATA가 4시간 내 검증 |

동일 밴드가 유지되는 동안에는 중복 작업을 생성하지 않습니다. 기존 작업 종료 후 점수가 다시 하락하거나 14일 이상 같은 위험 밴드에 머물면 후속 작업을 새로 생성합니다.

밴드가 회복되어도 미완료 작업은 자동 종료하지 않습니다. 담당자가 회복 근거와 재발 가능성을 기록한 후 과장 이상이 종료 처리합니다.

점수가 하루 사이 15점 이상 변하거나 2개 밴드 이상 이동하면 DATA가 원천 데이터 적재, 세그먼트 변경, 감쇠 기준일을 검증합니다. 데이터 오류로 확정되기 전에는 고객 대응을 임의로 취소하지 않습니다.

## 이탈 조기 경보 신호 목록
<!--meta: sec=s8; dept=CNS; level=시니어; ct_band=상; related=s7|s9-->
이탈 조기 경보는 해지·축소 의사가 공식화되기 전에 나타나는 행동과 관계 변화를 포착합니다. 좋은 경보 체계는 갱신 대화 최소 60일 전에 위험을 식별할 수 있어야 하며, 계약 종료일만 기준으로 경보를 생성하지 않습니다.

통상 선행 기간은 해당 신호가 처음 관찰된 시점부터 해지·축소 의사 표명까지의 운영 기준 범위입니다. 실제 기간은 계정별로 다르므로 신호 발생일, 확인일, 해소일을 각각 기록합니다.

**선행 신호 목록**

| 신호 | 관찰 방법 | 통상 선행 기간 | 1차 해석 |
| --- | --- | ---: | --- |
| 활성화 마일스톤 미달 | 합의 기한과 실제 완료일 비교 | 30~120일 | 기대 가치에 도달하지 못해 정착이 지연될 가능성 |
| 핵심 업무 흐름 사용량 하락 | 해당 계정 기준선 대비 4주 이동평균 비교 | 30~90일 | 사용 중단, 대체 절차 전환 또는 가치 저하 가능성 |
| 챔피언 참여 감소 | 회의 불참, 응답 지연, 액션 미완료 추세 확인 | 30~120일 | 내부 추진력과 의사결정 연결이 약화될 가능성 |
| 지원 공수 증가와 만족도 하락 | 공수·재오픈·해결시간 상승과 CSAT 하락 동시 확인 | 14~90일 | 품질 불만이 누적되고 신뢰가 저하될 가능성 |
| 고객 담당자 교체 | 회의·메일·조직 연락망 변경 확인 | 30~180일 | 기존 합의와 관계 자산이 단절될 가능성 |
| 예산 주체 변경 | 비용센터, 승인권자, 예산 귀속 조직 변경 확인 | 60~180일 | 계약 필요성이 새 기준으로 재심사될 가능성 |
| 경쟁 제품 언급 | 회의록·문의·기능 비교 요청에서 명시적 언급 확인 | 14~90일 | 대안 검토 또는 교체 타당성 평가가 진행될 가능성 |
| 갱신 관련 질의 성격 변화 | 가격·해지·데이터 반출·계약 축소 질의 증가 확인 | 14~120일 | 갱신 조건 재검토 또는 종료 준비 가능성 |

핵심 업무 흐름의 사용량은 전체 로그인 수로 대체하지 않습니다. 로그인은 유지되더라도 핵심 기능 실행, 결과물 생성, 업무 완료 건수가 하락하면 이탈 선행 신호로 판정합니다.

지원 공수 증가만으로는 위험을 확정하지 않습니다. 신규 기능 적용이나 오픈 초기에는 문의가 일시적으로 늘 수 있으므로 만족도 하락, 재오픈 증가, 해결시간 악화 중 하나 이상이 함께 나타나는지 확인합니다.

**단일 신호와 복합 신호 판정**

| 판정 조건 | 경보 강도 | 처리 기준 |
| --- | --- | --- |
| 일반 단일 신호 1개 | 예비 경보 | 10영업일 동안 추가 변화 여부를 관찰함 |
| 고강도 단일 신호 1개 | 확정 경보 | 경쟁 제품 도입 통보, 챔피언 퇴사, 해지 절차 질의는 즉시 등록함 |
| 서로 다른 유형 신호 2개 | 한 단계 상향 | 30일 이내 동시 발생하면 복합 경보로 처리함 |
| 서로 다른 유형 신호 3개 이상 | 두 단계 상향 | 위험 계정 등록 여부를 즉시 판정함 |
| 사용량 하락과 챔피언 이탈 동시 발생 | 최소 위험 | 점수와 무관하게 72시간 대응 대상으로 지정함 |

동일 원천에서 파생된 신호는 복합 신호로 중복 계산하지 않습니다. 예를 들어 티켓 증가와 지원 공수 증가는 하나의 지원 신호로 묶고, 여기에 CSAT 하락이 확인될 때 복합성을 인정합니다.

복합 신호는 점수에 임의 가산·차감하지 않고 경보 우선순위를 높이는 데 사용합니다. 이미 헬스 스코어 구성 신호에 반영된 사건을 다시 점수 조정하면 동일 위험이 이중 계산됩니다.

담당자 교체나 조직 개편이 확인되면 관계 단절 가능성을 우선 판정합니다. 구체적인 대응 절차는 CSM-03 s11을 적용합니다.

## 경보 발생 시 72시간 내 절차
<!--meta: sec=s9; dept=CNS; level=시니어; ct_band=상; related=s8|s10-->
경보 시점은 자동 알림 생성 또는 담당자의 수동 등록 중 먼저 발생한 때로 확정합니다. CNS 계정 책임자는 경보 시점부터 72시간 타이머를 시작하며, SALES·AIAX·BE·DATA 중 사실 확인에 필요한 담당자를 지정합니다.
경보 대응의 목적은 책임 소재를 단정하는 것이 아니라 사실과 고객 영향을 확인하고, 72시간 안에 고객과 다음 행동을 합의하는 것입니다. 장애 심각도와 복구 목표는 CSM-02를 따릅니다.
**시간대별 필수 절차**
| 구간 | 수행 항목 | 책임자 | 완료 조건 |
| --- | --- | --- | --- |
| 0~4시간 | 원천 데이터·최근 30일 추세·계정 기준선 확인, 중복 경보와 수집 오류 배제 | CNS 계정 책임자, DATA | 실제 경보 또는 오탐으로 판정 |
| 4~24시간 | 고객 영향, 발생 시점, 관련 변경, 미결 이슈를 정리하고 원인 가설 수립 | CNS, 관련 기술팀 | 사실·미확인 사항·가설이 분리된 내부 브리프 작성 |
| 24~72시간 | 고객 접촉, 영향 인식 확인, 임시 조치와 후속 일정 합의 | CNS, 필요 시 SALES | 고객 확인 내용과 담당·기한이 기록된 1차 합의 확보 |
0~4시간에는 단일 수치만 보지 않습니다. 원천 시스템과 CRM 기록을 대조하고, 휴일·정기점검·사용자 조직 이동·배치 실패 등 설명 가능한 변수를 확인합니다.
**구간별 산출물**
| 구간 | 필수 산출물 | 기록 위치 | 승인·확인 |
| --- | --- | --- | --- |
| 0~4시간 | 경보 검증표, 데이터 조회 시각, 오탐 여부 | 계정 헬스 기록 | CNS 과장 이상 |
| 4~24시간 | 1페이지 내부 브리프, 영향 사용자·업무 범위, 가설별 근거 | 위험 계정 폴더 | CNS 계정 책임자 |
| 24~72시간 | 고객 접촉 기록, 합의 액션, 차기 확인 일시 | CRM 활동 및 액션 로그 | 고객 측 담당자 확인 |
내부 브리프는 `확인된 사실 → 미확인 사항 → 원인 가설 → 고객 영향 → 제안할 다음 행동` 순서로 작성합니다. 가설은 최대 3개로 제한하고 각 가설에 확인 방법과 담당자를 붙입니다.
**고객 접촉 순서**
1. 관찰된 변화와 확인 기간을 수치로 제시합니다.
2. 고객이 체감한 영향과 내부 우선순위를 질문합니다.
3. 즉시 가능한 완화 조치와 추가 분석이 필요한 항목을 구분합니다.
4. 다음 확인 시점, 양사 담당자, 완료 기준을 합의합니다.
핵심 업무에 직접 영향이 있거나 고객이 에스컬레이션을 요청한 경우 CNS 관리자 또는 부장급 책임자가 요청 접수 후 24시간 안에 고객에게 연락합니다.
**금지 행동**
- 사실 확인 전에 회사 과실을 인정하거나 포괄적으로 사과하지 않습니다.
- 원인·범위·계약 조건 확인 전에 할인, 무상 기간 또는 크레딧을 언급하지 않습니다.
- 고객 담당자에게 내부 추정 원인이나 특정 팀·개인의 책임을 전달하지 않습니다.
- 72시간 동안 완전한 원인 규명을 기다리며 고객 접촉을 미루지 않습니다.
기술적 원인 규명이 끝나지 않았더라도 확인된 영향, 현재 조치, 다음 업데이트 시각은 전달할 수 있습니다. 72시간 내 고객과 접촉되지 않으면 시도한 채널과 횟수를 기록하고 고객 측 상위 접점으로 전환합니다.

## 위험 계정 관리 회의
<!--meta: sec=s10; dept=CNS|SALES; level=시니어; ct_band=중; related=s9|s11-->
주간 위험 계정 관리 회의는 경보를 단순 공유하는 자리가 아니라 계정별 대응 방향과 자원 책임을 결정하는 회의입니다. CNS가 운영하며 SALES 계정 담당자와 관련 실행팀 책임자가 참석합니다.
회의는 주 1회 45분으로 운영하고, 안건은 회의 전 영업일 15시까지 확정합니다. 긴급 장애 처리는 이 회의를 기다리지 않으며 CSM-02의 에스컬레이션 경로를 적용합니다.
**안건 선정 기준**
| 우선순위 | 선정 조건 | 회의 처리 |
| --- | --- | --- |
| 필수 | 헬스 59점 이하 또는 ‘위험’ 밴드 진입 | 매주 재검토 |
| 필수 | 핵심 업무 사용량 하락, 챔피언 이탈, 심각한 만족도 하락 중 1개 발생 | 대응 책임자 지정 |
| 조건부 | 60~69점 ‘관찰’ 상태가 2주 연속 지속 | 회복 계획 필요 여부 판정 |
| 조건부 | 30일 내 주요 마일스톤·갱신 판단이 있으면서 미결 위험 존재 | 일정 영향 검토 |
계정 책임자는 계정당 1페이지 자료를 회의 시작 4시간 전까지 제출합니다. 자료가 없으면 구두 추정으로 결정하지 않고 데이터 보완 담당과 기한만 정합니다.
**필수 회의 자료**
- 최근 8주 헬스 점수와 신호별 증감
- 확인된 고객 영향, 고객 발언, 마지막 접촉일
- 미결 액션의 담당·기한·지연 일수
- 필요한 내부 공수와 의사결정 요청사항
회의는 `신규 위험 15분 → 기존 고위험 20분 → 관찰 계정 5분 → 액션 확인 5분` 순서로 진행합니다. 계정별 설명은 3분, 질의와 결정은 5분을 넘기지 않습니다.
**결론 유형**
| 결론 | 판정 기준 | 필수 기록 |
| --- | --- | --- |
| 자체 해결 | 기존 담당·예산·권한으로 7일 내 회복 가능 | 실행 항목과 확인일 |
| 자원 투입 | 추가 분석·개발·현장 지원이 있어야 회복 가능 | 투입 팀, 공수 상한, 종료 조건 |
| 경영진 개입 | 고객 의사결정자 정렬 또는 관계 회복이 필요 | 접촉 주체, 메시지, 접촉 기한 |
| 축소 수용 | 범위·사용 규모 축소가 불가피하며 회복 비용이 편익을 초과 | 근거, 잔존 범위, 승인 요청 |
축소 수용은 CNS와 SALES 부장급 공동 검토 대상으로 올리며, 회의 자체가 계약 변경을 승인하지는 않습니다. 가격·요율·갱신 조건은 CSM-05를 참조합니다.
**회의에서 결정하지 않는 것**
- 확인되지 않은 장애 원인과 고객 책임 여부
- 견적, 할인율, 손해배상 또는 계약 문구
- 정식 개발 범위와 납기 변경
- 개인 평가와 팀 성과 귀속
회의 종료 전 모든 액션에 단일 책임자와 날짜를 지정합니다. 회의록은 당일 배포하고, 기한을 넘긴 액션은 다음 회의까지 기다리지 않고 CNS 운영 책임자에게 알립니다.

## 챔피언 이탈·조직 개편 대응
<!--meta: sec=s11; dept=CNS|SALES; level=시니어; ct_band=상; related=s10|s12-->
챔피언은 고객 내부에서 활용을 지지하고 의사결정을 연결하는 인물입니다. 챔피언 1인에게 관계와 정보가 집중되면 인사 이동 한 번으로 사용 맥락, 성과 근거, 예산 지지가 동시에 사라질 수 있습니다.
계정 책임자는 평상시에 고객 측 유효 접점을 최소 3명 확보합니다. 접점은 최소 2개 부서에 걸쳐야 하며, 업무 챔피언·운영 또는 기술 담당·의사결정자 중 어느 한 역할도 공석으로 두지 않습니다.
**사전 분산 기준**
| 접점 역할 | 최소 인원 | 분기 내 접촉 기준 |
| --- | --- | --- |
| 업무 챔피언 | 1명 | 월 1회 이상 실무 접촉 |
| 운영·기술 담당 | 1명 | 운영 현황 또는 이슈 확인 1회 이상 |
| 의사결정자·후원자 | 1명 | 분기 1회 이상 성과·위험 공유 |
접점별 영향력, 관심 KPI, 마지막 접촉일을 기록합니다. 단순 메일 참조자는 유효 접점으로 계산하지 않으며, 질문에 응답하거나 의사결정·실행에 참여한 이력이 있어야 합니다.
**교체 확인 후 30일 플랜**
| 기간 | 수행 항목 | 완료 기준 |
| --- | --- | --- |
| D0~D3 | 퇴사·이동·권한 변경 여부 확인, 임시 담당자와 승인권자 파악 | 고객 측 확인 및 관계도 갱신 |
| D4~D10 | 신규 담당자 온보딩 미팅, 계약 범위·운영 구조·미결 항목 전달 | 신규 담당자의 역할과 우선순위 확인 |
| D11~D20 | 기존 성과와 도입 배경 재설명, 핵심 자료 접근 권한 제공 | 성과 수치에 대한 고객 확인 |
| D21~D30 | 성공 기준·측정 방식·향후 90일 목표 재확인 | 수정된 성공 기준 또는 유지 확인 |
신규 담당자에게는 이전 챔피언의 관점이나 약속을 기정사실로 제시하지 않습니다. `현재 계약 사실 → 검증된 성과 → 남은 위험 → 선택 가능한 다음 행동` 순서로 설명합니다.
신규 담당자가 기존 성과를 인정하지 않으면 근거 자료의 기간·출처·기준선을 함께 재검증합니다. 30일 안에 성공 기준을 확정하지 못하면 헬스 점수의 챔피언 참여 신호를 위험으로 유지합니다.
**조직 개편·인수합병 추가 확인**
- 계약 주체, 비용 부담 조직, 승인권자와 운영 책임자의 변경 여부
- 시스템 통합·폐기 계획과 중복 솔루션 존재 여부
- 데이터 보관 위치, 접근 권한, 보안 검토의 재수행 필요 여부
- 기존 KPI의 유효성, 예산 동결 기간, 조직별 우선순위 충돌
조직 개편 발표만으로 계약 축소나 이탈을 단정하지 않습니다. 다만 승인권자 부재, 예산 소유 조직 변경, 중복 시스템 검토 중 2개 이상이 확인되면 위험 계정 회의 안건으로 등록합니다.
인수합병 관련 미공개 정보는 제한 계정 폴더에 저장하고 참석자 범위를 CNS·SALES 부장급과 지정 실무자로 제한합니다. 확장 기회 판단은 CSM-06을 참조합니다.

## 구축 중 고객과 운영 계약 고객의 지표 차이
<!--meta: sec=s12; dept=CNS|DATA; level=시니어; ct_band=상; related=s11|s13-->
구축 중 계정과 운영 계약 계정은 고객 행동이 발생하는 구조가 다릅니다. 구축 중에는 활성 사용자와 기능 사용 깊이가 형성되지 않았으므로 운영 단계의 사용량 신호를 억지로 0점 처리하지 않습니다.
각 단계는 별도 모델과 기준선을 사용합니다. 점수 범위가 모두 0~100점이더라도 두 단계의 점수는 동일한 위험 수준이나 성과 수준을 뜻하지 않습니다.
**구축 중 대체 신호**
| 신호 | 가중치 | 측정 기준 | 적신호 기준 |
| --- | ---: | --- | --- |
| 마일스톤 정시성 | 35% | 계획 대비 정시 완료 비율 | 핵심 마일스톤 10영업일 이상 지연 |
| 고객 협조 응답 속도 | 25% | 요청부터 유효 응답까지의 중앙값 | 3영업일 초과가 월 3회 이상 |
| 의사결정 지연 횟수 | 25% | 합의 기한을 넘긴 의사결정 건수 | 30일 내 2회 이상 |
| 범위 변경 요청 빈도 | 15% | 승인 전 변경 요청 건수 | 30일 내 3회 이상 또는 일정 영향 발생 |
단순 문의나 결함 수정은 범위 변경 요청에 포함하지 않습니다. 변경 요청은 합의된 범위 밖의 기능·데이터·연동·산출물 요구로 한정하며, 범위 판정 자체는 관련 계약 문서를 따릅니다.
**운영 계약 신호 구성**
| 신호 | 가중치 | 대표 관찰값 |
| --- | ---: | --- |
| 제품 사용·정착 | 40% | 활성 사용자, 기능 사용 깊이, 계정 기준선 대비 빈도 |
| 지원 활동 | 25% | 티켓 심각도, 재오픈, 해결시간, 에스컬레이션 증가 |
| 감정·만족도 | 20% | NPS 또는 CSAT, 정성 피드백 변화 |
| 경영진·챔피언 참여 | 15% | 응답 여부, 회의 참석, 후속 액션 이행 |
운영 단계에서는 사용·정착 신호를 가장 높은 비중으로 둡니다. 지원 공수 증가와 만족도 하락, 핵심 흐름 사용량 감소, 챔피언 참여 감소가 함께 발생하면 단일 신호보다 높은 위험으로 판정합니다.
**단계 전환 규칙**
1. 공식 오픈 전일까지 구축 모델을 적용합니다.
2. 오픈일부터 30일 헬스 체크까지는 구축 점수와 운영 원천 데이터를 각각 보관합니다.
3. 문서화된 운영 인수인계가 완료된 다음 집계일부터 운영 모델을 적용합니다.
4. 운영 기준선은 안정화된 최초 28일 데이터를 사용하며, 데이터 미충족 시 s16의 대체 판단을 적용합니다.
구축 점수와 운영 점수를 같은 표, 순위, 평균 또는 추세선에서 비교하지 않습니다. 경영 보고에서도 `구축 건강도`와 `운영 헬스`를 별도 영역으로 표시하고 단계명을 점수 옆에 붙입니다.
전환 시점의 급격한 점수 변화는 개선이나 악화로 해석하지 않습니다. CNS는 전환일, 적용 모델, 기준선 기간을 기록하고 DATA는 집계 쿼리에서 단계 필터가 누락되지 않았는지 확인합니다.
구축 중 오픈 지연은 사용량 부족으로 표현하지 않으며, 운영 중 낮은 활용률을 마일스톤 지연으로 대체하지 않습니다. 온보딩 일정과 종료 심사는 CSM-01, 운영 인수인계 기준은 CSM-02를 참조합니다.

## 점수 수동 조정과 근거 기록
<!--meta: sec=s13; dept=CNS; level=시니어; ct_band=중; related=s12|s14-->
수동 조정은 자동 산식이 포착하지 못한 검증된 사실을 한시적으로 반영하는 예외 절차입니다. 담당자의 인상이나 고객 발언 한 건만으로 점수를 변경하지 않으며, 원점수는 삭제하거나 덮어쓰지 않습니다.
조정 후 점수는 `자동 산출 점수 + 승인된 조정값`으로 계산합니다. 0점 미만은 0점, 100점 초과는 100점으로 절삭하며, 조정값을 추가로 중첩할 수 없습니다.
**조정 허용 조건과 한도**
| 조건 | 조정 방향 | 기본 한도 | 승인 |
| --- | --- | ---: | --- |
| 데이터 수집 장애로 실제 사용량이 누락되었고 고객 측 증빙이 있는 경우 | 상향 | +5점 | CNS 과장 이상 |
| 자동 집계에 아직 반영되지 않은 중대한 업무 중단·불만이 확인된 경우 | 하향 | -10점 | CNS 과장 이상 |
| 챔피언 퇴사·조직 개편 등 확정된 관계 변화가 발생한 경우 | 하향 | -10점 | CNS 과장 이상 |
| 계약 범위 변경 등으로 기존 기준선이 일시적으로 무효화된 경우 | ±10점 | ±10점 | CNS 차장 이상 |
단일 계정의 총조정 한도는 원칙적으로 ±10점입니다. ±11~15점은 CNS 부장 승인을 받아야 하며, ±15점을 넘는 조정은 금지하고 산식 또는 원천 데이터를 수정합니다.
**조정이 허용되지 않는 사유**
- 담당자의 막연한 낙관·불안, 고객 친밀도 또는 최근 회의 분위기만을 근거로 한 변경
- 밴드별 필수 조치를 피하거나 보고 수치를 개선하기 위한 상향 조정
- 동일 사건을 둘 이상의 신호와 수동 조정에 중복 반영하는 변경
- 갱신·확장 가능성을 높게 보이게 하려는 상업적 목적의 변경
증빙이 상충하면 하향·상향 어느 쪽도 즉시 적용하지 않고 자동 점수를 유지합니다. 사실 확인이 끝날 때까지 계정 기록에 `조정 검토 중` 상태만 표시합니다.
**필수 기록 항목**
| 항목 | 기록 기준 |
| --- | --- |
| 원점수·조정값·최종 점수 | 예: `64 - 8 = 56`과 같이 산식을 그대로 기록합니다. |
| 사유 코드 | 데이터 누락, 중대 사건, 관계 변화, 기준선 변경 중 하나를 선택합니다. |
| 사실과 증빙 | 발생일, 고객 발언 원문 요지, 회의록·티켓·로그 링크를 남깁니다. |
| 영향 신호 | 자동 산식에서 왜 포착되지 않았는지 해당 신호명을 적습니다. |
| 조정자·승인자 | 성명 대신 사내 계정 ID, 부서, 승인 시각을 기록합니다. |
조정 기록은 해당 계정의 월별 점수 스냅샷과 함께 보존합니다. 승인 전 점수를 공식 보고에 사용하지 않으며, 승인 거절 시 자동 점수로 환원합니다.
**유효기간과 재검토**
| 유형 | 최대 유효기간 | 만료 처리 |
| --- | ---: | --- |
| 데이터 장애·집계 지연 | 14일 | 정상 데이터 복구 시 즉시 자동 해제합니다. |
| 사건·관계·기준선 변화 | 30일 | 재증빙과 재승인이 없으면 자동 해제합니다. |
유효기간 연장은 1회, 최대 30일까지만 허용합니다. 같은 사유가 60일을 넘으면 수동 조정이 아니라 기준선 재설정 또는 신호 설계 변경 대상으로 등록합니다.
분기 중 수동 조정 계정이 전체 측정 계정의 20%를 넘거나, 동일 신호 관련 조정이 2개 분기 연속 15%를 넘으면 해당 신호의 데이터 품질·가중치·임계값을 재검토합니다.

## 헬스 스코어를 쓰면 안 되는 용도
<!--meta: sec=s14; dept=CNS; level=시니어; ct_band=중; related=s13|s15-->
헬스 스코어는 내부의 위험 탐지와 우선순위 설정을 위한 확률적 운영 지표입니다. 고객의 성과를 확정하거나 계약상 권리·의무를 판정하는 수치가 아니므로 단독 의사결정 도구로 사용하지 않습니다.
점수 사용자는 산식의 한계, 데이터 누락, 세그먼트별 기준 차이와 오탐 가능성을 고려해야 합니다. 다음 네 가지 용도는 부장 승인이나 고객 요청이 있더라도 허용하지 않습니다.
**금지 용도와 금지 이유**
| 금지 용도 | 금지 이유 |
| --- | --- |
| 고객에게 내부 점수를 그대로 보여주기 | 내부 임계값과 가중치가 고객이 합의한 KPI가 아니며, 점수 방어·게임화와 산식 논쟁을 유발합니다. |
| 담당자 인사 평가의 단독 근거로 사용하기 | 고객 조직 변화, 제품 장애, 계약 범위 등 담당자가 통제할 수 없는 요인의 영향이 큽니다. |
| 갱신 가격 인상의 근거로 제시하기 | 점수는 원가·서비스 범위·물가지수·가치 산정 자료가 아니므로 가격 근거가 될 수 없습니다. |
| 점수만으로 계약 종료를 판단하기 | 예측 점수에는 오탐이 존재하며 계약 조건, 회복 가능성, 고객 의사 확인이 별도로 필요합니다. |
고객과 공유할 때는 점수 대신 검증 가능한 기초 KPI와 합의된 성공 기준을 사용합니다. QBR 자료 구성과 고객 공개 기준은 CSM-04를 참조합니다.
**용도별 허용되는 대체 근거**
1. 고객 보고에는 활성 사용자 수, 기능 이용률, 해결시간, 합의된 가치 KPI 등 출처가 확인되는 측정값을 사용합니다.
2. 인사 평가는 계정 난이도, 실행 품질, 액션 기한 준수, 정성 리뷰 등 복수 자료로 별도 판단합니다.
3. 갱신 가격은 계약 조항, 서비스 범위, 유지관리 난이도와 승인된 가격 기준으로 산정합니다.
4. 계약 종료 검토는 계약상 사유, 미해결 위험, 고객 확인 기록과 경영 판단을 갖춰야 합니다.
헬스 스코어를 보조 자료로 사용할 때도 점수와 최종 판단 사이의 인과관계를 단정하지 않습니다. 의사결정 기록에는 점수 외에 사용한 독립 근거를 최소 2개 적습니다.
**표현 금지 예시와 교정**
| 금지 표현 | 허용 표현 |
| --- | --- |
| “귀사의 헬스 점수는 54점입니다.” | “최근 30일 핵심 기능 이용률이 기준선보다 22% 낮습니다.” |
| “점수가 낮아 가격을 인상합니다.” | “가격 조정 근거와 산식은 갱신 기준서에 따라 별도로 제시합니다.” |
| “담당 계정 점수가 낮아 평가를 하향합니다.” | “기한 준수와 회복 계획 실행 결과를 복수 자료로 평가합니다.” |
| “59점이므로 계약을 종료합니다.” | “계약상 사유와 회복 가능성을 별도 심사합니다.” |
점수를 고객용 등급으로 변환해 `양호·보통·위험`으로 보여주는 행위도 원점수 공개와 동일하게 금지합니다. 고객에게는 관찰 사실, 영향, 합의할 조치만 전달합니다.
내부 보고에서도 점수 순위만으로 지원 공수나 개발 우선순위를 일괄 삭감하지 않습니다. 핵심 업무 영향과 계약상 지원 의무를 함께 확인해야 합니다.
갱신 가격 조정 기준은 CSM-05를 참조합니다.

## 예측 성능 검증과 보정 주기
<!--meta: sec=s15; dept=DATA|CNS; level=시니어; ct_band=상; related=s14|s16-->
예측 성능은 점수가 실제 결과보다 먼저 위험 계정을 구분했는지로 검증합니다. 결과를 확인한 뒤 과거 점수를 수정하면 데이터 누수가 발생하므로, 평가에는 당시 저장된 점수 스냅샷만 사용합니다.
기본 선행 기간은 갱신일 또는 해지 확정일 전 60일입니다. 보조 분석으로 30일·90일 결과를 함께 산출하되, 모델 비교와 분기 승인에는 60일 지표를 사용합니다.
**검증 대상과 판정 단위**
| 항목 | 판정 기준 |
| --- | --- |
| 예측 양성 | 결과일 60일 전 등록된 위험 기준 이하 계정 |
| 실제 양성 | 계약 해지, 미갱신 또는 반복매출 축소가 확정된 계정 |
| 실제 음성 | 동일 범위 이상으로 갱신되어 관찰 기간이 끝난 계정 |
| 평가 단위 | 계약이 아닌 고객 계정 단위이며 중복 계약은 한 결과로 묶습니다. |
| 제외 대상 | 결과 미확정, 고객 귀책 없는 일회성 구축 종료, 점수 스냅샷 누락 건 |
위험 기준은 분기 시작 전에 고정합니다. 검증 결과를 좋게 만들기 위해 분기 종료 후 임계값이나 결과 정의를 바꾸지 않으며, 변경안은 다음 분기부터 적용합니다.
**핵심 성능 지표**
| 지표 | 산식 | 초기 운영 기준 |
| --- | --- | ---: |
| 적중률(Precision) | `TP ÷ (TP + FP)` | 40% 이상 |
| 재현율(Recall) | `TP ÷ (TP + FN)` | 60% 이상 |
| 오탐률(FPR) | `FP ÷ (FP + TN)` | 20% 이하 |
| 기준 대비 향상도(Lift) | `위험군 실제 이탈률 ÷ 전체 실제 이탈률` | 2.0배 이상 |
TP는 사전 경보 후 실제 이탈한 계정, FP는 경보 후 정상 갱신한 계정입니다. FN은 경보 없이 이탈한 계정, TN은 경보 없이 정상 갱신한 계정으로 분류합니다.
단일 지표 충족만으로 성능을 승인하지 않습니다. 적중률이 높아도 재현율이 낮으면 다수의 이탈을 놓치며, 재현율을 과도하게 높이면 오탐으로 대응 공수가 증가합니다.
**분기 보정 절차**
1. DATA가 분기 종료 후 10영업일 이내에 결과 코호트와 T-60 점수 스냅샷을 고정합니다.
2. 세그먼트별 표본 수, 이탈 기저율, 적중률·재현율·오탐률·향상도를 계산합니다.
3. CNS가 FP와 FN 전건을 검토하여 데이터 누락, 임계값 오류, 신호 지연, 예외 사건으로 원인을 분류합니다.
4. DATA와 CNS가 가중치·감쇠·임계값 변경안을 비교하고 과거 8개 분기에 백테스트합니다.
5. 변경 전후 지표와 영향 계정 수를 CNS 부장에게 제출하고 승인된 안을 다음 분기 첫날 적용합니다.
표본이 30개 결과 계정 미만이거나 실제 이탈이 10건 미만이면 가중치와 임계값을 자동 변경하지 않습니다. 최근 8개 분기를 합산하고, 서울·경기·인천 및 계약 유형을 묶어 분석하되 결과표에는 세그먼트별 편차를 병기합니다.
**신호 교체 기준**
- 결측률이 2개 분기 연속 30%를 넘고 대체 데이터 확보 계획이 없는 신호
- 단독 향상도가 2개 분기 연속 1.2배 미만이거나 결과와의 방향이 반대로 나타난 신호
- 동일 신호 때문에 수동 조정된 계정이 2개 분기 연속 15%를 넘는 신호
- 수집 비용이 높으면서 해당 신호 제거 전후 전체 적중률 차이가 3%p 미만인 신호
신호를 교체할 때는 기존 신호와 신규 신호를 최소 1개 분기 병행 수집합니다. 신규 신호가 적중률 또는 재현율을 5%p 이상 개선하거나 결측률을 10%p 이상 낮출 때 정식 전환합니다.
B2B 환경에서는 고객 수와 이탈 사건이 적어 수치가 한두 건에 크게 변동합니다. 분기 결과에는 표본 수와 95% 신뢰구간을 표시하고, FP·FN 계정에 대한 CNS 정성 리뷰를 성능 판정에 병행합니다.

## 운영 데이터 부족 시 대체 판단
<!--meta: sec=s16; dept=CNS; level=시니어; ct_band=중; related=s15|s17-->
핵심 사용 로그를 수집할 수 없거나 최근 14일의 로그 커버리지가 예정 데이터의 60% 미만이면 자동 사용 신호를 0점으로 처리하지 않습니다. 해당 계정은 `대체 판단` 대상으로 전환하고, 관찰 가능한 관계·업무 증거를 이용합니다.
대체 판단은 정상 로그 기반 점수와 동일한 정밀도를 보장하지 않습니다. 계정 간 순위 비교보다 위험 여부 확인에 사용하며, 로그가 정상화되면 다음 산출일부터 자동 점수 체계로 복귀합니다.
**대체 판단 구성**
| 구성 요소 | 가중치 | 확인 자료 |
| --- | ---: | --- |
| 정기 접촉 반응성 | 30% | 회의 참석, 회신 소요일, 약속된 후속 자료 제출 기록 |
| 현업 사용자 인터뷰 | 30% | 업무 사용 여부, 우회 작업, 반복 장애, 중단 의향에 대한 답변 |
| 운영 담당자 체감 평가 | 25% | 정착도·업무 영향·불만 수준을 1~5점으로 평가한 기록 |
| 객관적 운영 증거 | 15% | 산출물 승인, 처리 건수, 교육 참석, 지원 요청 이력 |
각 구성 요소는 0점·50점·100점의 3단계로 판정합니다. 증거가 없으면 0점이 아니라 `미확인`으로 두며, 확인된 요소의 가중치를 100%로 재비례하지 않습니다.
**구성 요소별 판정 기준**
| 요소 | 100점 | 50점 | 0점 |
| --- | --- | --- | --- |
| 정기 접촉 | 최근 30일 내 접촉 완료, 회신 3영업일 이내 | 접촉은 완료했으나 회신 4~7영업일 | 30일 초과 무응답 또는 2회 연속 회의 취소 |
| 현업 인터뷰 | 핵심 업무에서 지속 사용 확인 | 제한적 사용 또는 일부 우회 작업 확인 | 사용 중단·대체 수단 전환 의사 확인 |
| 담당자 체감 | 4~5점이며 구체적 근거 존재 | 3점 또는 근거 일부 부족 | 1~2점이거나 중대한 불만 확인 |
| 운영 증거 | 최근 30일 내 2종 이상 확인 | 1종만 확인 | 증거 없음 또는 예정 활동 미이행 |
현업 인터뷰는 최소 월 1회 실시하며 고객 운영 담당자 외 실제 사용자 1명 이상을 포함합니다. 위험 징후가 확인되면 7일 이내 재인터뷰하여 일시적 불편인지 지속적 사용 중단인지 구분합니다.
운영 담당자 체감 평가는 최소 2주마다 갱신합니다. 평가자는 점수만 입력하지 않고 관찰 사실, 고객 발언 요지와 반대 증거를 각각 한 줄 이상 남깁니다.
**대체 판단 표시 규칙**
- 점수명 앞에 `[대체판단]`을 붙이고 자동 점수와 동일한 색상 표기를 사용하지 않습니다.
- 데이터 부족 사유, 로그 커버리지, 최종 확인일, 평가자, 증빙 링크를 필수 기록합니다.
- 신뢰도는 A·B·C로 표시하며, 4개 요소 확인은 A, 3개는 B, 2개 이하는 C로 판정합니다.
- 보고서에는 `로그 기반 계정`과 `대체 판단 계정`의 수와 비율을 분리해 표시합니다.
대체 판단의 유효기간은 30일입니다. 만료일까지 인터뷰와 접촉 기록을 갱신하지 못하면 점수를 유지하지 않고 `판단 불가`로 변경합니다.
대체 판단이 60일을 넘으면 CNS 과장 이상이 계속 사용 여부를 승인하고 로그 미수집 사유와 복구 계획을 기록합니다. 고객 정책상 로그 제공이 불가능하면 분기마다 대체 증거의 적합성을 재승인합니다.
신뢰도 C 계정에서 위험 판정이 나오면 담당자 단독으로 확정하지 않습니다. CNS 과장 이상이 인터뷰 기록과 객관적 운영 증거를 검토한 뒤 경보 여부를 결정합니다.

## 보고 체계와 공개 범위
<!--meta: sec=s17; dept=CNS; level=주니어|시니어; ct_band=중; related=s16|s18-->
월간 헬스 보고서는 계정별 위험을 조기에 식별하고 미조치 경보를 관리하기 위한 내부 운영 자료입니다. CNS가 작성 책임을 지며 DATA는 산식 실행 결과와 데이터 누락 여부를 검증합니다.

기준월 데이터는 익월 제3영업일 18시에 마감하고, CNS 담당자는 제5영업일까지 보고서를 배포합니다. 마감 후 원천 데이터가 수정되면 기존 파일을 덮어쓰지 않고 정정 사유·변경 점수·수정자를 기록한 개정본을 발행합니다.

**월 보고 구성**

| 구성 블록 | 필수 내용 | 표시 기준 |
| --- | --- | --- |
| 포트폴리오 현황 | 전체 측정 계정 수, 점수 밴드별 계정 수·비율 | 구축 중·운영 계약 분리 |
| 지점별 현황 | 서울·경기·인천별 평균·중앙값·위험 계정 비율 | 계정 수를 분모로 사용 |
| 점수 이동 | 전월 대비 10점 이상 하락·상승 계정 | 이전 점수와 변동 원인 병기 |
| 조기 경보 | 신규·지속·해제 경보와 경과일 | 미조치 경보 우선 정렬 |
| 필수 조치 | 담당자, 기한, 현재 상태, 차단 요인 | 기한 초과 항목 별도 표시 |
| 데이터 품질 | 미산출·부분 산출 계정과 누락 신호 | 완전성 비율 표시 |

지점 귀속은 기준월 말일의 계정 오너 소속 지점으로 확정합니다. 여러 지점이 공동 수행해도 한 계정을 중복 집계하지 않으며, 수행 참여 지점은 보조 속성으로만 표시합니다. 전사 수치는 세 지점의 계정 원장을 합산해 다시 계산하고 지점 평균을 단순 평균하지 않습니다.

**수신 범위**

| 자료 수준 | 기본 수신자 | 허용 범위 |
| --- | --- | --- |

| 지점 집계본 | 해당 지점 CNS·SALES 과장 이상 | 계정명 없이 밴드 분포와 조치 현황 열람 |

고객 실명과 헬스 점수를 함께 담은 자료는 `내부기밀-고객계정`으로 분류합니다. 전사 공용 채널, 전체 메일링 리스트, 개인 메신저, 로컬 PC 다운로드 폴더에는 저장하거나 첨부하지 않습니다.

**취급 통제**

- 파일명에는 고객 실명을 쓰지 않고 내부 계정 ID와 기준월을 사용합니다.

- 오발송 시 수신 철회만으로 종결하지 않고 CNS 부장과 보안 담당자에게 1시간 내 보고합니다.

고객에게는 내부 점수 자체보다 점수의 근거가 된 사용·지원·성과 데이터를 설명합니다. 고객이 원점수 공개를 요청하면 산식 버전, 기준일, 누락 데이터 여부를 먼저 확인하고 지점 부장 승인 후 제한된 회의 자료로만 제시합니다.

계정 상세본의 지점 간 공유는 공동 수행, 전사 위험 회의 또는 담당자 이관에 한해 허용합니다. 단순 벤치마킹 목적이면 고객 식별정보를 제거한 집계본을 사용합니다.

## 용어와 산식 정리
<!--meta: sec=s18; dept=CNS|DATA; level=주니어; ct_band=하; related=s17-->
이 절은 CSM-03에서 사용하는 용어와 계산 기호를 빠르게 찾기 위한 색인입니다. 모든 입력 신호는 점수가 높을수록 건강한 상태가 되도록 0~100점으로 정규화합니다.

운영 점수는 사용·정착, 지원 활동, 감정, 경영진·챔피언 참여의 네 구성요소를 결합합니다. 세그먼트 임계값은 계산 결과를 변경하지 않고 밴드 판정에만 적용합니다.

**점수 계산 전체 산식**

```text
X_i = clip(x_i, 0, 100)
r_i = 2^(-d_i / h_i)
C_k = Σ_i(w_ki × r_i × X_i) / Σ_i(w_ki × r_i)
H_0 = (U × 0.40) + (S × 0.25) + (E × 0.20) + (G × 0.15)
H = clip(round(H_0 + A), 0, 100)
```

분모가 0인 구성요소는 임의로 0점 처리하지 않고 미산출로 표시합니다. 수동 조정값의 허용 범위와 승인 기준은 s13, 데이터 부족 시 판정은 s16을 적용합니다.

| 기호 | 의미 |
| --- | --- |
| `x_i` | 정규화 전 개별 신호값 |
| `X_i` | 0~100점으로 제한한 신호값 |
| `d_i` | 신호 관측 후 경과일 |
| `h_i` | 해당 신호의 반감기 일수 |
| `r_i` | 최근성 감쇠계수 |
| `w_ki` | 구성요소 안에서 신호에 부여한 가중치 |
| `C_k` | 최근성 감쇠가 반영된 구성요소 점수 |
| `U` | 제품 사용·정착 점수 |
| `S` | 지원 활동의 건강도 점수 |
| `E` | NPS·CSAT 등 고객 감정 점수 |
| `G` | 경영진·챔피언 참여 점수 |
| `H_0` | 수동 조정 전 헬스 점수 |
| `A` | 근거와 승인을 갖춘 수동 조정값 |
| `H` | 반올림된 최종 헬스 점수 |

**용어 색인**

| 용어 | 정의 |
| --- | --- |
| 헬스 스코어 | 계정의 정착·지원·감정·관계 상태를 0~100점으로 나타낸 내부 지표 |
| 기준선 | 해당 계정의 정상 사용 빈도와 수준을 비교하기 위한 과거 기준값 |
| 활성 사용자 | 정해진 측정기간에 핵심 업무 행동을 1회 이상 완료한 사용자 |
| 사용 깊이 | 로그인 횟수가 아니라 핵심 기능·업무 흐름을 완료한 정도 |
| 지원 건강도 | 티켓 건수·심각도·재오픈·해결시간을 건강 방향으로 변환한 점수 |
| 챔피언 | 고객 조직 안에서 활용 정착과 내부 의사결정을 추진하는 핵심 관계자 |
| 최근성 감쇠 | 오래된 관측값의 점수 기여도를 시간에 따라 줄이는 처리 |
| 세그먼트 임계값 | 고객 규모·계약 형태별로 밴드를 구분하는 점수 경계 |
| 점수 밴드 | 점수 구간에 연결된 상태 분류와 필수 조치 묶음 |
| 하드 트리거 | 총점과 무관하게 즉시 조기 경보를 발생시키는 중대 사건 |
| 조기 경보 | 이탈 가능성을 조사하고 담당자 조치를 시작하도록 생성된 내부 알림 |
| 오탐 | 경보가 발생했으나 조사 결과 실질적인 이탈 위험이 없었던 경우 |
| 미탐 | 실제 위험 또는 이탈이 있었으나 사전에 경보가 발생하지 않은 경우 |

비교 검증용 대안 산식은 `활동×0.40 + 참여×0.30 + 마일스톤×0.20 + 최근성×0.10`입니다. 표준 운영 점수와 대안 점수는 동일 열에 혼합하지 않으며, 모델명과 산식 버전을 별도로 표시합니다.
