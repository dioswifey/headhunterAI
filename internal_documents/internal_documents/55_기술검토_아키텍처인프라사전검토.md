# 아키텍처·인프라·보안 사전검토 가이드
<!--meta: doc=DSC-05; doc_type=pre_review_guide; tier=2; topic=DISCOVERY; disclosure=internal; status=active-->

## 사전검토의 목적과 산출물
<!--meta: sec=s1; dept=AIAX|CNS; level=주니어|시니어; ct_band=중; related=DSC-01#s7-->

사전검토의 목적은 상세 설계를 완료하는 것이 아니라 제안 이전에 배치 환경과 기술 제약을 확인하는 데 있다. 이 단계에서는 제품, 모델, 장비의 최종 규격을 확정하지 않는다. 확인된 사실과 고객 확인이 필요한 가정을 구분해 이후 판단의 입력으로 사용한다.

### 표준 산출물

산출물은 개념 아키텍처 초안, 제약 목록, 미확정 항목 목록의 3종으로 구성한다. 각 산출물은 선택 가능한 구성과 선택할 수 없는 구성을 구분할 수 있는 수준으로 작성한다. 상세 설계에 해당하는 물리 구성도, 장비별 세부 규격, 운영 절차 전문은 포함하지 않는다.

| 산출물 | 필수 내용 | 상세 수준 | 완료 기준 |
|---|---|---|---|
| 개념 아키텍처 초안 | 사용자·데이터·모델·연계 시스템·보안 경계 | 논리 구성요소와 주요 데이터 흐름 | 경계와 통신 방향을 식별할 수 있음 |
| 제약 목록 | 망·보안·인프라·운영·반입·연동 제약 | 근거, 영향 대상, 회피 가능 여부 | 필수 제약의 담당 확인자가 지정됨 |
| 미확정 항목 목록 | 질문, 가정, 확인 책임자, 확인 기한 | 범위 판단에 영향을 주는 항목 단위 | 상태와 다음 확인일이 기록됨 |
| 검토 근거 묶음 | 고객 답변, 회의 기록, 제공 문서 식별자 | 원문 위치와 확인 일자 중심 | 각 핵심 판단을 근거로 추적할 수 있음 |

### 상세 수준 기준

- 개념 아키텍처에는 시스템 경계, 보안 구간, 외부 연결 지점과 주요 인터페이스를 표시한다.
- 데이터 흐름은 원천, 처리 위치, 저장 위치, 외부 전송 여부와 폐기 지점을 표시한다.
- 서버 수량과 가속기 규격은 확인 근거가 없으면 범위 또는 미확정으로 기재한다.
- 특정 제품명은 고객 표준이나 필수 호환 조건으로 확인된 경우에만 기재한다.
- 제약 목록에는 제약마다 출처, 적용 대상, 일정 영향과 해소 책임자를 연결한다.
- 고객 구두 답변은 답변자 조직, 확인일과 재확인 필요 여부를 함께 기록한다.
- 미확정 항목에는 임의의 낙관적 가정을 넣지 않고 보수적 기본 가정과 영향도를 기록한다.

### 수행 시점과 참여 역할

사전검토는 디스커버리에서 인프라·보안 제약이 식별된 뒤, 제안 범위를 확정하기 전에 수행한다. 표준 소요 기간은 고객 자료 수령 후 영업일 5일이며 폐쇄망 또는 다중 시스템 연계 환경은 영업일 10일까지 적용한다. 기간을 초과할 것으로 예상되면 미확정 항목을 우선 분리한다.

1. CNS는 업무 범위와 고객 요구가 아키텍처 질문에 연결되도록 검토를 조정한다.
2. AIAX는 모델 실행 위치, 모델 공급 방식, 가속기와 추론 경로를 검토한다.
3. BE는 기존 시스템 연동, 인증, 네트워크 통신과 배포 경로를 검토한다.
4. DATA는 데이터 저장·이동·비식별 조건의 확인이 필요할 때 참여한다.
5. SALES는 고객 질의 창구와 일정 조정을 담당하되 기술 판단을 대신하지 않는다.
6. 주니어 담당자는 질의 회수, 근거 정리와 미확정 항목 상태 갱신을 수행한다.
7. 시니어 담당자는 제약의 영향과 대안 가능성을 확인하고 산출물을 승인한다.
8. 고객 측 확인자는 인프라, 보안, 준법, 운영 조직별로 구분해 기록한다.

### 검토 완료와 범위 확정 원칙

- 3종 산출물이 작성되지 않은 상태에서는 제안 범위를 확정하지 않는다.
- 필수 통신 경로, 데이터 외부 전송 여부와 운영 주체 중 하나라도 미확정이면 검토 진행 상태로 둔다.
- 고객 답변이 상충하면 더 엄격한 조건을 잠정 가정하고 양측 조직에 재확인을 요청한다.
- 일정상 답변을 기다릴 수 없으면 해당 항목을 제외 범위 또는 조건부 범위로 분리한다.
- 조건부 범위에는 해제 조건, 확인 책임자, 확인 기한과 미해제 시 영향을 기록한다.
- 제안·가격 관련 판단은 제안·가격 소관 문서 계열에서 처리한다.
- 긴급 요청이라는 사유만으로 보안 경계나 데이터 경로 확인을 생략하지 않는다.
- 사전검토 결과가 DSC-01#s7의 제약 기록과 다르면 최신 확인 근거와 변경 사유를 남긴다.

### 예외 처리

- 공개 정보만으로 구성된 사전 탐색은 아키텍처 가설 작성까지만 허용한다.
- 고객이 질의서 제공을 거부하면 거부 항목과 범위 확정 불가 영향을 기록한다.
- 기존 표준 환경을 재사용하더라도 적용 조직과 데이터가 다르면 차이를 확인한다.
- 재검토 없이 재사용할 수 있는 결과의 유효기간은 확인 완료일부터 90일로 한다.
- 90일 이내라도 망 정책, 시스템 구성 또는 운영 주체가 바뀌면 재검토한다.
- 예외 승인자는 AIAX 차장 이상과 CNS 과장 이상 각 1명으로 한다.
- 예외 승인 기록에는 생략 항목, 근거, 잔여 위험과 재확인 기한을 포함한다.
- 법률·규제 해석이 필요한 항목은 고객의 준법 또는 보안 조직 확인 전까지 확정으로 표시하지 않는다.

## 배치 유형 비교와 선택 기준
<!--meta: sec=s2; dept=AIAX|BE; level=시니어; ct_band=상; related=DSC-01#s7-->

배치 유형은 선호 기술이 아니라 데이터 이동 허용 범위, 응답시간, 사용량과 운영 책임을 기준으로 선택한다. 동일 업무라도 데이터 등급과 연계 시스템 위치에 따라 유형이 달라질 수 있다. 유형 선택은 제품 또는 모델 선택보다 먼저 수행한다.

### 배치 유형 비교

비교 결과는 우열이 아니라 적용 조건의 차이를 나타낸다. 초기 준비 기간은 고객의 계정·장비·망·보안 승인 절차가 시작 가능한 시점부터 계산하며, 사전검토 단계에서는 범위값으로 기록한다.

| 배치 유형 | 데이터·모델 경로 | 확장성·초기 준비 | 운영 주체·변경 난도 | 주된 제약 |
|---|---|---|---|---|
| 퍼블릭 클라우드 | 허용된 데이터를 외부 구간으로 전송하며 관리형 또는 외부 모델 API를 사용할 수 있음 | 확장성 높음, 통상 5~20영업일 | 고객·공급자 분담, 서비스 변경 대응 필요 | 외부 전송 승인, 리전, 계정 권한, 종속성 |
| 프라이빗·온프레미스 | 고객 전용 환경에서 처리하며 모델 파일 또는 전용 엔드포인트를 공급함 | 장비 제약 존재, 통상 20~60영업일 | 고객 운영 비중 높음, 변경 난도 중간 이상 | 조달·설치, 용량 상한, 패치, 내부 표준 |
| 하이브리드 | 민감 처리는 내부, 허용 처리는 외부에서 수행함 | 구간별 확장성 상이, 통상 20~45영업일 | 공동 운영, 변경 난도 높음 | 경계 통제, 데이터 분류, 장애 책임 분리 |
| 폐쇄망 | 데이터와 추론을 내부망에 한정하고 승인된 매체로 모델을 반입함 | 즉시 확장 곤란, 통상 30~90영업일 | 고객 운영 중심, 변경 난도 매우 높음 | 반입 승인, 외부 통신 불가, 라이선스, 의존성 |

### 선택 질문 순서

선택 질문은 아래 순서를 바꾸지 않는다. 앞 단계의 답변이 확정되지 않으면 뒤 단계의 수치만으로 배치 유형을 확정하지 않는다.

1. 데이터 원문, 파생 데이터 또는 프롬프트의 외부 전송이 허용되는지 확인한다.
2. 전송 허용 범위를 데이터 등급, 목적, 리전, 수신 주체와 보관 기간별로 구분한다.
3. 외부 전송이 전면 금지되면 프라이빗·온프레미스 또는 폐쇄망을 우선 검토한다.
4. 일부 전송만 허용되면 분리 처리 가능한지를 확인한 뒤 하이브리드를 검토한다.
5. 허용 응답시간을 평균값이 아닌 정상·피크·최대 허용값으로 확인한다.
6. 실시간 요구는 네트워크 왕복시간, 모델 처리시간과 연계 시스템 지연을 분리한다.
7. 예상 사용량은 일평균·피크 동시 사용자·요청 건수·입출력 크기로 수집한다.
8. 사용량 변동이 3배 이상이면 자동 확장 가능성과 고정 용량의 대기열 처리를 비교한다.
9. 구축 후 계정, 서버, 모델, 로그와 장애 대응을 인수할 조직을 확인한다.
10. 운영 조직이 정해지지 않으면 운영 주체를 미확정 항목으로 등록하고 유형 결정을 보류한다.

### 판단 기록 기준

- 데이터 외부 전송 여부는 허용, 조건부 허용, 금지, 미확인의 4개 상태로 기록한다.
- 응답시간은 밀리초 또는 초 단위의 목표값과 측정 위치를 함께 기록한다.
- 사용량은 현재치와 12개월 예상치를 분리하고 산정 근거를 연결한다.
- 운영 인수 주체는 고객, 헤드헌터랩, 제3운영자, 공동 운영 중 하나로 표시한다.
- 공동 운영은 시스템 구간별 책임과 장애 접수 창구가 확인되어야 선택할 수 있다.
- 복수 유형이 가능하면 1순위와 대안을 기록하고 전환 조건을 명시한다.
- 선택 근거가 보안 정책에 의존하면 정책 문서 식별자와 확인일을 남긴다.
- 데이터 준비도와 반출 가능성의 상세 평가는 DSC-03#s6을 참고한다.

### 고객이 유형을 지정한 경우

- 지정 유형이 내부 표준인지 이번 과제의 선호안인지 먼저 확인한다.
- 지정 결정의 승인 조직, 승인일, 적용 대상 시스템과 유효기간을 확인한다.
- 데이터 경로가 지정 유형의 보안 경계를 벗어나지 않는지 검증한다.
- 모델 공급과 업데이트 방식이 해당 환경에서 지속 가능한지 확인한다.
- 요구 응답시간과 사용량을 지정 환경의 현재 용량으로 처리할 수 있는지 확인한다.
- 운영 조직이 계정·장비·패치·백업·로그를 인수할 수 있는지 확인한다.
- 지정 유형과 필수 요구가 충돌하면 충돌 항목과 가능한 대안을 제약 목록에 남긴다.
- 고객 지정이라는 이유로 타당성 확인을 생략하거나 해당 유형을 확정 사실로 간주하지 않는다.

## 망분리·폐쇄망 환경 검토 항목
<!--meta: sec=s3; dept=AIAX|BE; level=시니어; ct_band=상; related=DSC-03#s6-->

폐쇄망에서도 문서 처리형 AI를 포함한 AI 구성을 검토할 수 있다. 다만 모델, 라이브러리, 패치와 라이선스가 내부망에 들어오는 절차를 먼저 확정해야 한다. 반입·반출 절차가 미확정이면 기능 가능성과 별도로 일정 및 운영 가능성을 미확정으로 판단한다.

### 반입·반출 절차 확인

확인 결과는 가능 여부만 기록하지 않고 신청 주체, 승인 주체, 처리 기간과 허용 매체를 함께 기록한다. 시험 환경과 운영 환경의 절차가 다르면 각각 별도 행으로 관리한다.

| 검토 항목 | 확인 질문 | 필요 근거 | 제약으로 등록하는 조건 |
|---|---|---|---|
| 모델 파일 반입 | 파일 크기·형식·해시 검증과 승인 경로가 있는가 | 반입 절차서, 승인 양식 | 승인 주체 또는 허용 형식이 미정임 |
| 라이브러리·패치 | 정기·긴급 반입 주기와 취약점 검사 절차가 있는가 | 패치 정책, 검사 기준 | 월 1회 미만이거나 긴급 반입 경로가 없음 |
| 라이선스 활성화 | 최초·정기 검증에 외부 통신이 필요한가 | 공급 조건, 통신 요구 목록 | 오프라인 활성화 수단이 확인되지 않음 |
| 로그·산출물 반출 | 로그, 평가 결과와 오류 자료를 어떤 절차로 반출하는가 | 반출 승인 기준, 마스킹 기준 | 장애 분석에 필요한 자료의 반출이 불가함 |
| 외부 저장소 의존성 | 패키지·이미지·모델 저장소를 내부에서 대체할 수 있는가 | 의존성 목록, 내부 저장소 현황 | 재현 가능한 내부 복제 또는 보관 수단이 없음 |
| 이동 매체 통제 | 매체 등록, 악성코드 검사와 폐기 기록이 가능한가 | 매체 통제 절차 | 허용 매체와 검사 책임자가 미정임 |

### 공통 확인 항목과 확인 방법

데이터 외부 전송이 제한되는 금융권·공공기관·통신 환경에서는 다음 3개 항목을 공통 확인한다. 각 항목은 고객 답변만으로 완료하지 않고 구성도, 설정 또는 시험 결과 중 1개 이상의 근거를 확보한다.

1. **외부 API 없이 내부망에서 동작하는지 확인한다.**
   - 모델 추론, 임베딩, 문서 변환, 인증과 모니터링 호출을 포함한 외부 목적지 목록을 작성한다.
   - 방화벽 차단 상태에서 핵심 시나리오를 실행하고 실패하는 기능과 우회 호출을 기록한다.
   - DNS, 시간 동기화, 라이선스 검증처럼 간접적으로 필요한 외부 통신도 포함한다.
2. **민감정보 비식별·가명처리가 설계에 포함되는지 확인한다.**
   - 처리 대상 필드, 변환 시점, 변환 위치와 재식별 정보의 보관 위치를 확인한다.
   - 원문이 모델 입력, 로그, 캐시와 평가 데이터에 남는지를 데이터 흐름도로 검토한다.
   - 적용 필요성과 적정성은 고객의 개인정보·준법 담당 조직 확인을 받는다.
3. **기존 레거시 시스템과 안정적으로 연계되는지 확인한다.**
   - 인터페이스 방식, 지원 프로토콜, 문자 인코딩, 최대 메시지 크기와 호출 제한을 확인한다.
   - 정상·타임아웃·중복·재처리 시나리오와 연계 구간별 책임자를 식별한다.
   - 시험계 접근이 불가하면 인터페이스 명세와 모의 응답으로 검증하고 한계를 기록한다.

### 의존성 처리 기준

- 외부 패키지 저장소에 접근할 수 없으면 승인된 버전의 내부 저장소 또는 오프라인 번들을 사용한다.
- 번들에는 패키지명, 버전, 해시값, 라이선스 정보와 직접·간접 의존성을 포함한다.
- 컨테이너 이미지는 기준 이미지, 레이어 출처와 취약점 검사일을 기록한다.
- 모델 파일은 원본 식별자, 버전, 크기, 해시값과 반입 이력을 연결한다.
- 동적 다운로드가 필요한 구성요소는 설치 전에 고정 파일 방식으로 대체 가능한지 확인한다.
- 대체할 수 없는 외부 의존성은 기능 제외 또는 배치 유형 변경 후보로 등록한다.
- 보안 패치 반입이 지연될 때 허용 가능한 운영 기간은 고객 보안 조직의 확인을 받는다.
- 반출이 금지된 로그는 내부 분석 절차와 현장 접근 가능 여부를 별도로 확인한다.

### 반입 지연의 일정 위험 등록

- 표준 반입 처리 기간이 영업일 5일을 초과하면 일정 위험으로 등록한다.
- 최초 반입 절차가 없거나 처리 기간을 산정할 수 없으면 위험도를 높음으로 둔다.
- 모델 또는 이미지가 2회 이상 반려된 이력이 있으면 재검사 기간을 일정에 반영한다.
- 긴급 패치 경로가 없으면 운영 위험과 일정 위험을 각각 등록한다.
- 위험 기록에는 대상 파일, 신청 예정일, 승인 조직, 예상 소요일과 대체 경로를 포함한다.
- 반입 완료 전 설치·시험 일정을 확정 완료로 표시하지 않는다.
- 고객 승인 지연과 공급 준비 지연은 원인과 책임 주체를 구분해 기록한다.
- 반입·반출 가능 여부가 데이터 준비도에 미치는 영향은 DSC-03#s6에 연결한다.

## 금융권 망분리 규제 동향 반영
<!--meta: sec=s4; dept=AIAX|CNS; level=시니어; ct_band=상; related=none-->

2026년 하반기 공개 발표 기준으로 금융당국은 AI를 이용한 공격 위협에 대응하기 위해 금융권 망분리 규제를 단계적으로 완화·해제하는 작업에 착수했다고 밝혔다. 일정 규모 이상 금융회사가 보안 목적으로 AI를 활용하는 경우 한시적 완화를 적용하고, 보안 역량과 AI 활용 능력이 우수한 회사에는 전면 해제까지 검토한다는 방향이 제시되었다. 이는 개별 금융회사의 적용 승인이나 구체적 설계 허용을 의미하는 것으로 단정하지 않는다.

망분리를 대신할 AI 기반 신 보안체계를 2027년 1분기까지 마련한다는 계획도 제시되었다. AI 보안 가이드라인·체크리스트 마련과 현장점검·개선지도가 함께 추진되는 방향이다. 사전검토 시 발표 자료의 기준일, 적용 대상과 후속 지침 공개 여부를 확인한다.

같은 기간 대규모 개인정보 유출 사고를 계기로 금융회사 수백 곳 규모의 전수점검이 진행되었다. 따라서 규제 완화 방향과 검사·점검 강화가 동시에 진행되는 상황으로 본다. 어느 한쪽만을 전제로 아키텍처 가능 여부를 확정하지 않는다.

### 검토 태도

- 규제 완화 발표를 외부 전송, 외부 API 사용 또는 망연계 허용으로 직접 해석하지 않는다.
- 현행 고객 정책, 적용 가능한 예외, 점검 요구와 향후 변경 계획을 각각 구분한다.
- 규제 해석은 고객의 준법·보안 조직 확인을 받아 확인일과 답변 조직을 기록한다.
- 구두 해석만 확보된 경우 확정이 아니라 고객 확인 중 상태로 표시한다.
- 고객 내부 기준이 공개 정책보다 엄격하면 해당 내부 기준을 설계 제약으로 적용한다.
- 점검 지적사항 또는 개선계획이 있으면 관련 시스템에 미치는 영향만 확인한다.
- 개인정보 처리 관련 판단은 고객 개인정보 담당 조직의 확인을 별도로 받는다.
- 법률·규제의 최종 적용 여부를 헤드헌터랩 단독 판단으로 확정하지 않는다.
- 제안서에 규제 완화를 전제로 한 구성을 확정적으로 기재하지 않는다.
- 제안·가격 관련 표현과 승인 절차는 제안·가격 소관 문서 계열을 따른다.

### 정책 의존 항목 표기

변경 가능성이 있는 설계 항목은 일반 미확정 항목과 구분해 `정책 의존 항목`으로 표시한다. 표기 시 현재 적용 기준과 변경 시 영향을 함께 기록하며, 예상되는 완화만으로 확정 상태를 부여하지 않는다.

### 기록 및 재검토 기준

- 정책 의존 항목에는 현재 적용 가능한 보수적 구성과 변경 후 대안을 함께 기록한다.
- 보수적 구성도 고객 정책 확인 없이 적법하거나 안전하다고 단정하지 않는다.
- 외부 통신 허용 여부는 목적지, 목적, 데이터 종류와 통신 방향별로 확인한다.
- 망분리 완화 가능성과 개인정보 보호 통제 완화 가능성을 동일하게 취급하지 않는다.
- 신 보안체계의 세부 요건이 공개되지 않았으면 구현 요구사항을 추정해 확정하지 않는다.
- 가이드라인 또는 체크리스트가 공개되면 기존 제약 목록과 항목별 차이를 검토한다.
- 현장점검 결과로 개선 요구가 발생하면 관련 설계 항목의 상태를 재검토로 변경한다.
- 정책 의존 항목이 핵심 데이터 경로에 영향을 주면 대체 경로 없이 범위를 확정하지 않는다.
- 공개 발표 후 30일마다 후속 지침 여부를 확인하고 근거 확인일을 갱신한다.
- 고객 내부 정책이 변경되면 5영업일 이내에 개념 아키텍처와 제약 목록을 재검토한다.
- 재검토 결과 변경이 없더라도 확인 자료, 확인자 조직과 검토일을 남긴다.
- 규제 동향 기록은 사실, 고객 해석, 헤드헌터랩의 설계 가정을 분리해 보관한다.

## 컴퓨팅·용량 산정 사전 질의

컴퓨팅·용량 산정은 평균 사용량이 아니라 정상 구간과 최대 구간을 함께 확인해 수행한다.
고객이 제공한 실측값, 추정값, 헤드헌터랩이 설정한 가정을 구분하며 출처와 기준일을 기록한다.
PoC 환경의 자원 조건은 DSC-04#s8을 참고하되 운영 환경의 용량으로 그대로 환산하지 않는다.

| 질의 항목 | 필수 입력값 | 확인 단위·구간 | 산정 반영 대상 |

질의 결과에는 평균값만 기재하지 않고 최대값이 발생한 조건과 지속 시간을 함께 기록한다.
응답시간은 네트워크, 전처리, 검색, 모델 추론, 후처리를 포함하는 종단 기준인지 구분한다.
파일·문서 입력은 페이지 수뿐 아니라 파일 형식, 이미지 포함 비율, 압축 해제 후 크기를 확인한다.

### 입력값이 없는 경우의 가정 설정

- 최근 3개월 실측값이 있으면 해당 값을 우선 사용하고 일시적 장애 구간은 별도 표시한다.
- 실측값이 없으면 고객 업무 담당자의 운영 추정치와 시스템 담당자의 로그 추정치를 각각 받는다.
- 두 추정치의 차이가 20%를 초과하면 더 큰 값을 기준 시나리오로 사용하지 않고 차이 원인을 확인한다.
- 하한은 확인된 최소 업무량 또는 보수적으로 검증된 최근 평균값으로 설정한다.
- 기준값은 확인 가능한 중앙 추정치에 업무일·계절성 조건을 반영해 설정한다.
- 상한은 예상 피크와 증가율을 합산하되 임의의 배수를 근거 없이 적용하지 않는다.
- 계절성·행사성 피크는 상시 피크와 분리하고 발생 횟수와 지속 시간을 적는다.
- 각 가정에는 `ASM-CAP-연번` 형식의 식별자를 부여한다.
- 가정 출처는 고객 진술, 운영 로그, 업무 문서, 헤드헌터랩 추정 중 하나로 표시한다.
- 확인되지 않은 값에는 `미확인` 상태와 산정에 미치는 방향을 함께 기재한다.
- 검증 예정일은 사전검토 종료일부터 10영업일 이내를 원칙으로 정한다.
- 검증 책임자는 고객 담당 조직과 헤드헌터랩 담당 부서 코드를 함께 기록한다.

### 자원군 분리 산정 구조

1. 추론용 자원은 사용자 요청을 실시간 또는 준실시간으로 처리하는 자원으로 산정한다.
   - 동시 요청 수, 입력 길이, 출력 길이, 목표 응답시간을 주요 변수로 사용한다.
   - 모델 프로세스, 검색 호출, 후처리의 최대 동시 실행량을 포함한다.
   - 실시간 추론과 배치 추론이 같은 장비를 쓰면 시간대 충돌 여부를 표시한다.
2. 색인용 자원은 문서 파싱, 청킹, 임베딩 생성, 색인 갱신을 기준으로 산정한다.
   - 초기 전체 색인량과 일별 증분 색인량을 분리한다.
   - 재색인 빈도, 실패 재처리량, 임시 파일 공간을 포함한다.
   - 배치 작업 창 안에 완료할 수 있는 처리량을 검증 조건으로 둔다.
3. 학습·튜닝용 자원은 학습 빈도와 데이터셋 크기가 확인된 경우에만 별도 산정한다.
   - 추론 자원과 공동 사용하면 점유 시간과 우선순위 정책을 기록한다.
   - 학습 계획이 없으면 자원값을 임의로 포함하지 않고 `해당 없음`으로 표시한다.
   - 향후 학습 가능성만 있는 경우 증설 인터페이스와 공간 조건만 확인한다.
4. 저장 자원은 원본, 전처리본, 색인, 모델 파일, 로그를 구분한다.
   - 각 저장 대상에 보존 기간과 삭제 방식을 연결한다.
   - 백업본과 이중화 복제본은 논리 용량과 물리 용량을 나누어 계산한다.

산정 결과는 하한·기준·상한의 범위로 제시하며 특정 장비 수량 하나로 확정하지 않는다.
입력량 변동, 모델 변경, 동시성 패턴, 실제 처리 효율이 사전 단계에서 확정되지 않기 때문이다.
단일 값이 필요한 후속 절차에는 검증 조건과 재산정 시점을 붙이며 제안·가격 소관 문서 계열에서 별도로 처리한다.

### 산정 결과 기록 규칙

- 범위별 입력값, 계산 기준, 제외 항목을 같은 버전의 산정 기록에 보관한다.
- 상한과 하한의 차이가 2배를 초과하면 차이를 만든 상위 3개 변수를 표시한다.
- 모델 후보가 복수이면 후보별 산정 범위를 분리하고 평균값으로 합치지 않는다.
- 성능 시험 전 수치는 `사전 추정`, 시험 후 보정값은 `검증값`으로 표시한다.
- 고객 확인이 필요한 가정은 담당 조직, 회신 기한, 미회신 시 적용할 범위를 기록한다.

## 기존 시스템 연동 사전검토
<!--meta: sec=s6; dept=BE|AIAX; level=시니어; ct_band=상; related=none-->

기존 시스템 연동 검토는 인터페이스의 존재 여부뿐 아니라 실제 사용 승인, 처리 한도, 변경 절차를 확인한다.
연동 대상은 업무 시스템, 인증 시스템, 데이터베이스, 파일 저장소, 메시지 시스템, 운영 도구로 구분한다.
구두로 확인한 연동 가능성은 확정 조건으로 취급하지 않고 문서와 테스트 결과로 보완한다.

| 연동 확인 항목 | 고객 질의 내용 | 확인 증빙 | 미확정 시 영향 |
|---|---|---|---|
| 인터페이스 방식 | API·DB·파일·메시지·화면 방식 | 명세서·구성도 | 구성 재설계 |
| 문서 존재 여부 | 최신 명세와 예제 제공 가능 여부 | 문서 버전·개정일 | 분석 기간 증가 |
| 변경 가능성 | 신규 필드·API·계정 추가 가능 여부 | 변경 정책·승인 기록 | 우회 구성 필요 |
| 배치 제약 | 실행 가능 시간과 최대 처리시간 | 운영 일정표 | 처리 지연 |
| 동시 접속 한도 | 계정·세션·호출량 제한 | 제한 정책·시험 결과 | 병목 발생 |
| 테스트 환경 | 데이터·계정·접속 경로 제공 여부 | 환경 정보·승인서 | 통합시험 지연 |
| 보안·인증 | 인증서·토큰·접근통제 방식 | 보안 지침·접속 절차 | 개발 착수 제한 |
| 담당 조직 | 시스템 소유·운영·보안 조직 | 담당자 역할표 | 의사결정 지연 |
| 협조 절차 | 요청 양식·승인 단계·소요일 | 절차서·SLA | 일정 변동 |

연동 문서는 운영 버전과 일치하는지 확인하며 작성일만으로 최신성을 판단하지 않는다.
테스트 환경이 운영 환경과 다른 경우 데이터 구조, 인증 방식, 호출 한도의 차이를 별도 목록으로 만든다.
연동 가능 판정은 최소 1회의 접속 또는 샘플 송수신 결과가 확보된 뒤 확정한다.

### 레거시 변경이 불가한 경우의 우회 구성

1. 어댑터 또는 중계 API를 별도 배치한다.
   - 부작용은 추가 장애 지점, 변환 로직 유지보수, 응답시간 증가이다.
   - 원본 시스템의 호출 한도가 낮으면 어댑터만으로 처리량 문제가 해소되지 않는다.
2. 읽기 전용 복제본이나 별도 조회 저장소를 사용한다.
   - 부작용은 원본과 복제본 사이의 지연, 정합성 확인, 저장공간 증가이다.
   - 복제 승인과 개인정보 처리 범위가 확인되지 않으면 선택하지 않는다.
3. 지정 폴더 또는 관리형 전송 구간에서 파일을 교환한다.
   - 부작용은 실시간성 저하, 중복 파일, 재처리와 누락 관리 부담이다.
   - 파일명, 완료 표식, 암호화, 실패 재전송 규칙을 사전에 정한다.
4. 화면 자동화 또는 운영자 수동 입력을 제한적으로 사용한다.
   - 부작용은 화면 변경 취약성, 처리량 제한, 운영 인력 의존이다.
   - 핵심 업무의 상시 연동 수단으로 확정하지 않고 임시 방안으로 표시한다.
5. 메시지 큐 또는 이벤트 중계 구간을 추가한다.
   - 부작용은 순서 보장, 중복 처리, 재시도 정책의 설계 부담이다.
   - 기존 시스템이 이벤트 발행을 지원하지 않으면 별도 수집 구성까지 검토한다.

### 연동 지점 수와 일정 영향

- 연동 지점은 시스템 수가 아니라 인증·송신·수신·오류회신이 분리되는 실제 경계 수로 센다.
- 동일 시스템이라도 인터페이스 방식이나 담당 조직이 다르면 별도 연동 지점으로 기록한다.
- 지점별로 문서 분석, 접속 승인, 개발, 단위 확인, 통합시험 공수를 분리한다.
- 신규 연동 지점이 추가되면 선행 의존성과 전체 통합시험 순서를 다시 확인한다.
- 5개 이상 연동 지점은 병렬 시험 가능 여부와 공통 장애 창구를 별도로 지정한다.
- 연동 지점 수가 확정되지 않으면 일정은 최소·기준·최대 범위로만 제시한다.

연동 일정에는 고객 승인 대기와 테스트 환경 준비 기간을 개발 기간과 분리해 표시한다.
담당 조직이 3개 이상이면 공동 검토 회의를 두고 결정사항별 승인 주체를 기록한다.
일정 확정이나 후속 조건 반영은 기술 확인 결과를 넘겨 처리하며 제안·가격 소관 문서 계열의 내용을 작성하지 않는다.

### 연동 책임 경계 기재 규칙

- 각 연동 지점에 `INT-연번` 식별자를 부여한다.
- 송신 시스템, 수신 시스템, 중계 구성과 네트워크 경계를 적는다.
- 인터페이스 제공, 계정 발급, 방화벽 변경, 인증서 발급의 책임 조직을 구분한다.
- 데이터 추출, 변환, 적재, 오류 재처리의 수행 주체를 단계별로 적는다.
- 정상 완료, 부분 실패, 전체 실패의 판정 주체를 지정한다.
- 운영 모니터링, 장애 접수, 원인 분석, 복구 승인 책임을 분리한다.
- 고객 제공 항목에는 제공 예정일과 미제공 시 영향을 함께 기록한다.
- 헤드헌터랩 수행 항목은 부서 코드 BE 또는 AIAX와 담당 역할로 표시한다.
- 공동 책임으로만 기재하지 않고 최종 의사결정 주체를 한 곳으로 지정한다.
- 미확정 책임 경계는 `TBD`와 확인 기한을 병기하며 확정된 것으로 간주하지 않는다.

## 모델 공급 방식과 데이터 경로 검토
<!--meta: sec=s7; dept=AIAX; level=시니어; ct_band=상; related=DSC-02#s4-->

모델 공급 방식은 데이터 경로, 운영 통제, 모델 갱신 방법을 함께 검토해 선정한다.
온프레미스 또는 자체 호스팅이라는 이유만으로 보안성이나 적합성이 자동 확보된다고 판단하지 않는다.
기술 실현 가능성 판정은 DSC-02#s4와 연결하고 미확정 조건은 공급 방식별로 분리한다.

| 공급 방식 | 전제 조건 | 주요 확인 항목 | 주요 제약 |
|---|---|---|---|
| 외부 API | 외부 통신과 데이터 전송 허용 | 학습 사용, 제공 지역, 인증, 버전 | 전송 제한·서비스 의존 |
| 자체 호스팅 | 장비·운영인력·모델 반입 경로 확보 | 라이선스, 패치, 가속기, 관측 | 자원 부담·업데이트 책임 |
| 가명처리 후 외부 호출 | 재식별 위험 검토와 전처리 검증 | 가명처리 위치, 매핑키, 잔존 정보 | 품질 저하·처리 지연 |
| 공통 통제 | 데이터 분류와 책임 주체 확정 | 접근권한, 로그, 장애 대응, 삭제 | 미확정 시 방식 확정 불가 |

가명처리는 외부 전송 허용을 자동으로 의미하지 않으며 고객의 내부 기준과 필요한 검토 절차를 확인한다.
자체 호스팅은 모델 파일 반입, 라이선스 활성화, 패치 전달, 취약점 대응 경로가 운영 가능한지 확인한다.
외부 API와 자체 호스팅을 병행하면 요청 분기 기준과 실패 시 데이터 이동 경로를 각각 표시한다.

### 데이터 경로 도식 필수 표기 요소

- 원문, 개인정보, 가명정보, 메타데이터, 임베딩, 프롬프트, 응답, 로그의 종류를 구분한다.
- 데이터가 생성되는 시스템과 최초 처리 주체를 표시한다.
- 내부망, 업무망, 인터넷 구간, 외부 서비스 경계를 선으로 구분한다.
- 각 경계 통과 지점에 프로토콜, 암호화 여부, 인증 방식을 적는다.
- 전송 전 필터링·비식별·가명처리 위치를 표시한다.
- 원본, 임시 파일, 캐시, 색인, 로그의 저장 여부를 각각 적는다.
- 저장 위치별 보존 기간과 삭제 또는 덮어쓰기 방식을 적는다.
- 고객, 헤드헌터랩, 외부 서비스 제공자의 처리 구간을 구분한다.
- 재처리, 오류 재전송, 백업 과정에서 생기는 추가 경로를 포함한다.
- 국외 이전 여부와 처리·저장 지역의 확인 상태를 표시한다.
- 확인되지 않은 경로는 점선과 `TBD`로 표시하고 확인 책임자를 붙인다.

### 외부 API 사전 확인 항목

- 입력·출력 데이터가 모델 학습, 품질 개선, 서비스 분석에 사용되는지 확인한다.
- 학습 미사용 설정이 기본값인지 별도 신청 또는 설정이 필요한지 확인한다.
- 요청 본문, 응답, 오류 로그, 운영 메타데이터의 보존 기간을 각각 확인한다.
- API 처리 지역과 데이터 저장 지역을 구분해 확인한다.
- 고객이 요구하는 제공 지역을 선택하거나 고정할 수 있는지 확인한다.
- 모델 버전과 엔드포인트 버전을 일정 기간 고정할 수 있는지 확인한다.
- 버전 종료 사전 통지 기간과 강제 전환 조건을 확인한다.
- 호출량 제한, 동시 요청 한도, 입력 길이 제한을 확인한다.
- 장애 공지 채널, 상태 확인 수단, 지원 응답시간을 확인한다.
- 장애 시 대체 모델, 대체 리전, 자체 처리로 전환할 수 있는지 확인한다.
- 대체 경로에서 데이터 종류와 품질 기준이 달라지는지 기록한다.

### 공급 방식 변경 시 영향 범위

- 외부 API에서 자체 호스팅으로 바뀌면 장비, 모델 반입, 배포, 관측, 패치 절차를 재검토한다.
- 자체 호스팅에서 외부 API로 바뀌면 망 통신, 전송 승인, 처리 지역, 데이터 보존 조건을 재검토한다.
- 가명처리 경로가 추가되면 전처리 정확도, 처리시간, 매핑키 관리, 재식별 가능성을 다시 확인한다.
- 모델 계열이 변경되면 입력 형식, 토큰 한도, 출력 구조, 프롬프트 동작을 재시험한다.
- 임베딩 모델 변경은 기존 색인의 재생성 시간과 저장공간에 영향을 준다.
- 버전 고정이 불가능해지면 회귀시험 주기와 결과 승인 절차를 추가한다.
- 데이터 경계가 바뀌면 데이터 경로 도식과 접근권한 목록을 개정한다.
- 운영 주체가 바뀌면 장애 접수, 로그 열람, 패치 승인 책임을 재지정한다.
- 전환 중 두 방식을 병행하면 이중 저장과 결과 불일치 처리 규칙을 정한다.
- 변경 시점이 통합시험 이후이면 기존 시험 결과의 재사용 가능 범위를 판정한다.
- 영향 항목이 미확정이면 일정과 용량을 단일 값으로 확정하지 않는다.

공급 방식 변경은 모델 배포만의 변경으로 보지 않고 데이터, 인프라, 연동, 운영 통제의 변경으로 관리한다.
변경 요청에는 발생 사유, 영향받는 경계, 재검토 항목, 기존 판단의 유효 여부를 기록한다.
기술 검토 후 제안 또는 계약 단계의 조정이 필요하면 제안·가격 소관 문서 계열로 전달한다.

### 검토 결과 기록 항목

- 선택 방식과 제외한 방식의 기술적 사유를 각각 기록한다.
- 데이터 경로 도식의 버전, 작성일, 확인 조직을 기재한다.
- 외부 서비스 확인 내용은 확인일과 근거 문서 위치를 함께 남긴다.
- 미확정 조건에는 책임자, 확인 기한, 미충족 시 대체 방식을 붙인다.
- 보안·개인정보 관련 판단은 고객 담당 조직의 확인 상태와 분리해 적는다.
- 방식 변경 이력은 변경 전후 경로와 재시험 결과를 연결해 보관한다.

## 운영·관측·장애 대응 사전 요건
<!--meta: sec=s8; dept=BE|AIAX; level=시니어; ct_band=상; related=DSC-04#s9-->

운영 요건은 시스템 구성 확정 전에 고객 운영 책임자와 합의한다. 목표값뿐 아니라 측정 구간, 제외 조건, 원천 데이터와 확인 책임자를 함께 기록한다. 운영 전환과 되돌리기 기준은 DSC-04#s9를 참고한다.

### 사전 합의 기준

초기값은 고객의 현행 운영 기준을 우선 적용하고, 기준이 없을 때 아래 권고 범위에서 정한다. 수치는 근거 없이 보장값으로 기재하지 않는다. 고객 승인 전 값은 잠정값으로 표시한다.

| 구분 | 사전 합의 항목 | 권고 기준 또는 범위 | 확인 책임 |
|---|---|---|---|
| 가용성 | 월간 서비스 가용성 목표 | 99.5%·99.9% 중 선택, 계획 중단 포함 여부 명시 | 고객 운영 책임자 |
| 측정 구간 | 운영시간과 가용성 산정 구간 | 24시간×365일 또는 업무시간 기준 | BE |
| 요청량 | 분당·일간 요청 수와 최대 동시 요청 | 평균값과 피크값을 각각 제시 | AIAX·BE |
| 지연 | 응답 지연 측정 지점과 백분위 | 평균과 p95, 필요 시 p99 | BE |
| 실패율 | 전체 요청 대비 실패 요청 비율 | 정상 요청 정의와 재시도 포함 여부 명시 | BE |
| 품질 | 운영 중 확인할 AI 품질 지표 | 과제별 1~3개 지표와 점검 주기 설정 | AIAX |
| 비용 | 사용량 기반 비용 관측 단위 | 일간·월간 집계, 예산 경보 임계값 설정 | 고객 운영 책임자 |
| 로그 | 로그 종류·보존 기간·접근 권한 | 운영·감사·보안 로그별 30~365일 | 고객 보안 책임자 |
| 장애 | 장애 등급과 통보 경로 | 1~3등급, 최초 통보 수단과 수신자 지정 | 공동 |
| 복구 | RTO와 RPO | 서비스별 시간 단위로 각각 기재 | 고객 운영 책임자 |
| 변경 | 정기·긴급 배포 가능 시간 | 월 1~4회 또는 승인된 변경 창 | 공동 |
| 인수 | 교육 대상·횟수·완료 기준 | 역할별 1회 이상, 참석 및 실습 확인 | CNS·BE |

### 측정 및 기록 원칙

- 가용성은 합의한 운영시간을 분모로 계산하며 계획 중단과 고객 책임 구간의 포함 여부를 구분한다.
- 지연은 사용자 요청 수신 지점부터 최종 응답 반환 지점까지를 기본 구간으로 한다.
- 실패율은 HTTP 오류, 타임아웃, 모델 호출 실패와 업무 검증 실패를 구분해 집계한다.
- 품질 지표는 정확도 외에도 무응답률, 근거 미제시율, 검수 반려율 중 과제에 맞는 항목을 선택한다.
- 비용은 모델 사용량, 컴퓨팅 사용량, 저장량과 네트워크 전송량을 분리해 관측한다.
- 로그 시각은 동일한 표준시로 맞추고 서버 간 시각 오차 허용값을 1초 이하로 정한다.
- 개인정보 또는 인증정보가 로그에 남지 않도록 마스킹 적용 위치와 검증 방법을 기록한다.
- 로그 열람 권한은 역할 기반으로 부여하고 열람·내보내기 이력을 남길지 확인한다.

### 장애·변경 운영

- 1등급은 전체 서비스 중단, 보안 침해 의심 또는 광범위한 데이터 오류로 정의한다.
- 2등급은 핵심 기능 일부 중단이나 우회 절차가 필요한 성능 저하로 정의한다.
- 3등급은 제한된 사용자 영향, 단일 기능 오류 또는 운영 문의 수준으로 정의한다.
- 최초 통보 목표는 1등급 15분, 2등급 30분, 3등급 4업무시간을 기준으로 조정한다.
- 통보 경로는 주 연락 수단과 대체 수단을 각각 지정하고 개인 연락처만을 단일 경로로 두지 않는다.
- 복구 절차에는 서비스 재시작, 이전 버전 전환, 데이터 복원과 수동 업무 전환 여부를 포함한다.
- 정기 배포는 승인 마감 시각, 검증 담당자와 배포 후 관찰 시간을 함께 정한다.
- 긴급 변경은 사후 승인 허용 여부와 변경 기록 제출 기한을 최대 1업무일 이내로 정한다.

### 운영 역량에 따른 조정

고객의 전담 운영 인력, 관제 도구, 변경관리 절차와 장애 대응 경험을 확인한 뒤 운영 요건을 조정한다. 역량 부족은 관측 항목 삭제의 근거로 사용하지 않고 자동화 수준과 담당 범위를 조정하는 근거로 사용한다. 보안·감사상 필수인 통제는 편의상 생략하지 않는다.

- 전담 운영 조직이 있으면 고객 표준 장애 등급, 관제 체계와 변경 절차를 우선 적용한다.
- 겸임 운영 조직이면 경보 종류를 5개 이하의 핵심 경보로 시작하고 월 1회 조정한다.
- 상시 관제가 없으면 업무시간 외 자동 통보와 다음 업무일 확인 절차를 별도로 둔다.
- 폐쇄망이면 외부 통보 도구 사용 가능 여부와 내부 대체 수단을 확인한다.
- 클라우드 관리 경험이 부족하면 계정·비용·백업 운영 교육을 역할별로 구분한다.
- 고객이 직접 수행할 수 없는 항목은 담당 공백으로 남기지 않고 책임 주체를 재지정한다.

### 미합의 시 처리

- 가용성 기준이 없으면 용량과 이중화 필요 수준을 확정하지 않는다.
- 로그 기준이 없으면 저장 공간, 마스킹 범위와 감사 대응 수준을 확정하지 않는다.
- 장애 등급과 통보 경로가 없으면 지원 가능 시간과 대응 절차를 확정하지 않는다.
- 배포 창이 없으면 변경 횟수와 운영 전환 일정을 확정하지 않는다.
- 인수 교육 대상이 없으면 교육 완료를 운영 인수 완료로 간주하지 않는다.
- 남은 미합의 항목은 DSC-05#s9의 미확정 항목 목록으로 이관한다.

## 미확정 항목의 기재 규칙
<!--meta: sec=s9; dept=AIAX|CNS; level=시니어; ct_band=상; related=SLS-03#s3-->

사전검토에서 확인되지 않은 사항은 누락하거나 확정값처럼 바꾸지 않는다. 미확정 상태, 확인 책임자, 확인 기한과 결과에 따른 영향 폭을 하나의 기록 단위로 관리한다. 외부 공고나 사전규격 일정에 종속된 사항은 SLS-03#s3을 참고한다.

### 미확정 항목 목록 필드

목록은 고객 답변 대기, 내부 검토 대기, 제3자 확인 대기와 결정 대기로 상태를 구분한다. 각 항목에는 최소값과 최대값을 함께 기록해 범위·일정 영향이 한쪽 값으로 오인되지 않게 한다. 근거 자료가 없으면 추정값을 확정값으로 승격하지 않는다.

1. 항목 ID는 `U-001` 형식의 연속 번호로 부여한다.
2. 항목명은 배치 위치, 연동 방식, 데이터 반출 여부처럼 단일 판단 대상으로 쓴다.
3. 현재 상태는 미수신, 부분 회신, 상충 회신, 결정 대기 중 하나로 기록한다.
4. 확인 책임자는 고객 역할과 헤드헌터랩 부서 코드를 각각 지정한다.
5. 확인 기한은 날짜와 업무 종료 시각을 함께 기재한다.
6. 확인 근거는 문서명, 회신 일시 또는 회의 기록 위치로 남긴다.
7. 의존 항목은 관련 질의 번호와 선행 결정 ID를 연결한다.
8. 종결 조건은 어떤 답변이나 자료가 도착해야 닫히는지 명시한다.

### 영향 폭 산정

- 범위 영향은 대상 시스템 수, 인터페이스 수, 사용자군 수와 배치 환경 수의 최소·최대로 쓴다.
- 일정 영향은 추가 확인·반입·접근 승인에 필요한 최소·최대 업무일로 쓴다.
- 성능 영향은 예상 동시 요청, 처리량 또는 지연 목표의 상·하한으로 쓴다.
- 용량 영향은 저장량, 모델 크기와 로그 보존량의 최소·최대로 쓴다.
- 보안 영향은 추가 통제 필요, 승인 필요, 수행 불가 가능성으로 구분한다.
- 운영 영향은 관제 항목, 운영 인력과 배포 가능 횟수의 변동으로 쓴다.
- 비용 영향이 예상되면 금액을 임의 산출하지 않고 제안·가격 소관 문서 계열의 재검토 필요 여부만 표시한다.

### 문장 작성 지침

미확정 문장은 확인된 사실, 미확정 대상과 확인 후 달라지는 결과를 순서대로 쓴다. 가능성 표현에는 조건을 붙이고 확정 주체가 정해지지 않은 수동형 표현을 피한다. 법률·규제 적용 여부는 확인 주체와 필요한 검토를 기재하며 단정하지 않는다.

| 피해야 할 표현 | 바꿔 쓸 표현 | 추가 기재 사항 |
|---|---|---|
| 내부망에서 문제없이 동작한다 | 외부 연결 없이 동작 가능한지는 모델 반입·활성화 방식을 확인한 뒤 판단한다 | 확인 책임자·기한 |
| 기존 시스템과 연동 가능하다 | 연동 규격과 테스트 환경 확인 후 연동 가능 범위를 확정한다 | 인터페이스 수 |
| 개인정보 이슈가 없다 | 개인정보 처리 여부와 필요한 보호조치는 고객 담당 검토 후 확정한다 | 데이터 항목·검토 주체 |
| 성능은 충분하다 | 동시 요청 수와 목표 지연이 확인되면 성능 충족 여부를 시험한다 | 최소·최대 부하 |
| 일정에 영향이 없다 | 승인 결과에 따라 일정이 최소 0일에서 최대 N업무일 변동될 수 있다 | 영향 구간 |
| 클라우드 사용이 가능하다 | 반출·접속 정책과 계정 발급 승인 후 사용 가능 여부를 판단한다 | 승인권자 |
| 운영 대응이 가능하다 | 운영시간, 장애 등급과 담당 조직 합의 후 대응 범위를 정한다 | 운영 역할 |
| 보안 요건을 충족한다 | 제출된 통제 항목을 기준으로 충족 여부를 검토 중이다 | 미확인 통제 |

### 제안 작성 보류 기준

미확정 항목이 아래 기준을 넘으면 제안 범위가 안정되지 않은 것으로 판단하고 제안·가격 소관 문서 계열로의 이관을 보류한다. 보류는 기회 중단을 뜻하지 않으며 확인 활동은 계속 수행한다. 예외 이관은 AIAX 부장과 CNS 부장의 공동 승인 및 잔여 위험 기록이 있어야 한다.

- 배치 위치, 데이터 반출, 개인정보 처리, 핵심 연동 중 미확정 항목이 3건 이상이면 보류한다.
- 전체 미확정 항목이 7건 이상이면 중요도와 관계없이 보류한다.
- 확인 책임자가 지정되지 않은 항목이 2건 이상이면 보류한다.
- 확인 기한이 제안 작성 착수 예정일보다 늦은 필수 항목이 1건이라도 있으면 보류한다.
- 일정 영향의 최대값이 최소값보다 20업무일 이상 크면 보류한다.
- 대상 연동 시스템 수의 최대값이 최소값의 2배를 넘으면 보류한다.
- 보안 승인 실패 시 수행 불가한 항목이 1건이라도 남아 있으면 보류한다.
- 고객 회신 간 상충이 해소되지 않은 필수 항목이 2건 이상이면 보류한다.

### 상태 코드

- `OPEN`은 질문을 발송했으나 회신이 없는 상태로 기록한다.
- `PARTIAL`은 일부 자료만 도착해 판단할 수 없는 상태로 기록한다.
- `CONFLICT`는 회신 또는 근거가 서로 일치하지 않는 상태로 기록한다.
- `DECISION`은 정보는 확보했으나 고객 결정이 남은 상태로 기록한다.
- `CLOSED`는 근거와 승인 주체가 확인된 상태로 기록한다.
- `DEFERRED`는 현재 범위에서 제외하기로 승인된 상태로 기록한다.

### 발송 절차

질의서 담당자는 CNS로 지정하고 기술 질문의 검수자는 AIAX 또는 BE 과장 이상으로 정한다. 최초 발송본에는 회신 기한, 답변 담당자 지정 요청과 첨부자료 전달 방법을 포함한다. 개인정보 원문이나 접속 비밀번호를 이메일 본문으로 요청하지 않는다.

1. CNS가 고객 창구와 질의서 수신 부서를 확인한다.
2. AIAX와 BE가 대상 환경에 맞지 않는 질문을 삭제하지 않고 해당 없음 선택지를 부여한다.
3. 질문 번호와 문서 버전을 `DSC05-Q-v1.0` 형식으로 기록한다.
4. 필수 항목과 조건부 필수 항목을 발송 전에 구분한다.
5. 최초 회신 기한은 발송일로부터 5업무일 이내로 정한다.
6. 자료 첨부가 필요한 질문에는 허용 파일 형식과 전달 경로를 명시한다.
7. 발송 일시, 수신자 역할과 회신 기한을 사전검토 기록에 등록한다.

### 회수 및 검수

- 회신 접수 후 1업무일 이내에 질문별 답변 유무를 확인한다.
- 예·아니오만 회신되어 상세 조건을 판단할 수 없으면 부분 회신으로 표시한다.
- 답변과 첨부자료가 다르면 상충 회신으로 표시하고 고객 확인을 요청한다.
- 담당 조직이 다른 질문은 고객이 지정한 담당자에게 재배정하도록 요청한다.
- 필수 질문이 해당 없음으로 답변되면 해당 사유를 추가로 받는다.
- 첨부자료의 작성일과 적용 대상 환경이 현재 검토 대상과 같은지 확인한다.
- 구두 답변은 회의일과 답변자 역할을 기록하고 서면 확인을 요청한다.
- 검수 완료본은 원본 회신과 분리하지 않고 동일한 기록 위치에 보관한다.

### 회신 지연 시 처리

회신 기한이 지나면 미회신 항목 수와 영향 영역을 고객 창구에 알린다. 기술팀은 확인되지 않은 값을 임의로 채우지 않고 DSC-05#s9의 미확정 항목으로 전환한다. 반복 지연 시에는 필수 항목만 분리해 재요청한다.

- 기한 1업무일 전 미회신 항목 목록을 1회 안내한다.
- 기한 당일에는 고객 창구에 회신 가능 일자를 확인한다.
- 기한 경과 2업무일에는 필수 항목과 조건부 필수 항목을 구분해 재발송한다.
- 기한 경과 5업무일에는 지연 영향을 CNS 과장과 기술 검토 책임자에게 공유한다.
- 필수 항목 3건 이상이 미회신이면 제안·가격 소관 문서 계열로의 이관을 보류한다.
- 배치 위치나 데이터 반출 여부가 미회신이면 건수와 관계없이 이관을 보류한다.
- 고객이 회신 예정일을 제시하면 해당 날짜를 새 확인 기한으로 기록한다.
- 회신 불가 답변을 받으면 대체 근거와 확인 가능한 담당 조직을 요청한다.
- 지연으로 검토 일정이 바뀌면 최소·최대 업무일 범위로 기록한다.

- 원답변, 보완답변과 첨부자료 위치를 연결한다.
