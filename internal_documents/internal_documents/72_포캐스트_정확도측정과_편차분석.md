# 포캐스트 정확도 측정과 편차 원인 분석
<!--meta: doc=FCT-04; doc_type=revops; tier=1; topic=SALES; disclosure=internal; status=active-->

## 측정의 목적
<!--meta: sec=s1; dept=SALES; level=주니어|시니어; ct_band=하; related=s2|FCT-02#s1-->
**측정 원칙**

포캐스트 정확도 측정의 목적은 영업 담당자의 낙관성이나 역량을 평가하는 것이 아니라, 예측 체계가 반복적으로 만드는 오차를 찾아 교정하는 데 있습니다. 측정 결과는 범주 판정, 금액 추정, 종료예정일 판단, 내부 승인 의존성 등 예측 과정의 어느 부분을 수정해야 하는지 결정하는 근거로 사용합니다.

개별 딜은 고객의 예산 변경, 의사결정 지연, 계약 조건 조정처럼 담당자가 통제할 수 없는 요인으로 변동될 수 있습니다. 따라서 한 건의 적중 여부보다 동일한 방향의 편차가 여러 기간에 반복되는지, 특정 범주·지점·계약 형태에 집중되는지를 우선 확인합니다.

**이 문서가 결정하는 사항**

| 구분 | FCT-04에서 결정하는 내용 | 산출 결과 |
| --- | --- | --- |
| 정확도 산정 | MAPE·WMAPE·편향의 계산 기준 | 범주별 정확도 수치 |
| 편차 판정 | 목표, 허용, 경보 구간 | 정상·주의·개선 필요 판정 |
| 원인 분석 | 편차 원인 코드와 확인 질문 | 원인별 발생 금액·건수 |
| 개선 관리 | 개선 과제의 등록·검증 기준 | 조치 담당·기한·효과 |
| 보고 | 보고 단위와 수신 범위 | 월간·분기 회고 자료 |

포캐스트 범주, 수주 확률, 가중 금액, 제출·마감 규칙은 FCT-02를 따릅니다. FCT-04는 해당 규칙으로 작성된 예측값과 이후 실제값의 차이를 사후 측정하며, 범주 자체의 정의나 가중치를 변경하지 않습니다.

매출·수주 KPI의 선정, 지점·팀 목표 배분, 달성률 귀속은 FCT-06을 따릅니다. 정확도 결과가 낮다는 이유만으로 목표를 하향하거나 KPI 실적으로 환산하지 않으며, 목표 변경이 필요하면 FCT-06의 승인 절차로 별도 처리합니다.

**허용되는 활용과 금지되는 활용**

1. 허용: 특정 범주의 지속적 과대 예측을 확인하고 판정 기준 보완 과제를 등록합니다.
2. 허용: 구축 프로젝트와 운영·유지보수 계약의 오차 구조를 분리해 개선 우선순위를 정합니다.
3. 허용: 지점별 표본 구성과 계약 유형 차이를 통제한 뒤 예측 프로세스를 비교합니다.
4. 금지: 단일 월 또는 단일 딜의 오차만으로 담당자 등급·보상·징계를 결정합니다.
5. 금지: 실제값에 맞추기 위해 과거 스냅샷, 범주 또는 예측 금액을 사후 수정합니다.
6. 금지: 정확도를 높이기 위해 불확실한 활성 기회를 일괄적으로 포캐스트에서 제거합니다.

정확도 개선은 오차를 숨기는 활동이 아니라, 동일한 정보에서 더 일관된 판단을 내리게 만드는 활동입니다. 평가가 필요할 때에는 결과 수치보다 입력 근거의 충실성, 변경 기록의 적시성, 합의된 개선 조치의 이행 여부를 별도 증거로 사용합니다.

## 측정 지표 정의 — MAPE·WMAPE·편향
<!--meta: sec=s2; dept=SALES|DATA; level=시니어; ct_band=상; related=s1|s3-->
**변수와 공통 부호**

각 관측 단위의 예측 금액을 `F_i`, 같은 기간의 실제 확정 금액을 `A_i`, 관측 건수를 `n`으로 둡니다. 편향은 `F_i - A_i`를 사용하므로 양수는 과대 예측, 음수는 과소 예측을 뜻합니다.

실제값은 해당 스냅샷의 측정 대상 기간에 최종 확정된 금액을 사용합니다. 회계 매출 인식이나 정산 금액의 정의는 FIN-xx를 참조하며, 이 문서에서 별도 재정의하지 않습니다.

| 지표 | 산식 | 주로 보여주는 것 | 기본 용도 |
| --- | --- | --- | --- |
| MAPE | `MAPE = (1/n) × Σ(|F_i-A_i|/|A_i|) × 100` | 건별 상대 오차의 평균 | 건별 판단 편차 진단 |
| WMAPE | `WMAPE = Σ|F_i-A_i| / Σ|A_i| × 100` | 전체 금액 대비 절대 오차 | 공식 정확도 보고 |
| Bias | `Bias = Σ(F_i-A_i) / Σ|A_i| × 100` | 과대·과소 예측 방향 | 방향성 교정 |

**MAPE 해석**

MAPE는 각 건의 오차율에 동일한 비중을 부여합니다. 실제 1,000만원을 1,500만원으로 예측한 건은 절대 오차가 500만원이고 오차율은 50%이며, 실제 1억원을 1억500만원으로 예측한 건은 절대 오차가 같아도 오차율은 5%입니다.

따라서 소액 건이 많은 표본에서는 소액 오차가 전체 수치를 크게 움직입니다. 계약 규모가 다른 구축 프로젝트를 함께 비교할 때 MAPE만 사용하면 금액 영향도가 작은 건들이 결과를 지배할 수 있으므로 보조 진단 지표로 사용합니다.

`A_i = 0`인 건은 MAPE를 계산할 수 없습니다. 해당 건은 MAPE 분자·분모와 건수에서 제외하되, 제외 건수와 예측 금액을 함께 표시하며 WMAPE 및 편향 계산에는 포함합니다.

**WMAPE 해석**

WMAPE는 절대 오차 합계를 실제 금액 합계로 나누므로 금액 영향도가 반영됩니다. 헤드헌터랩의 공식 정확도 지표는 WMAPE이며, 특히 Commit 범주의 금액 가중 MAPE를 핵심 지표로 사용합니다.

`Σ|A_i| = 0`이면 WMAPE와 편향을 산출하지 않고 `N/A`로 표시합니다. 예측 금액이 존재했다면 미실현 예측 금액을 별도 기재하여 분모가 없다는 이유로 오류가 사라지지 않게 합니다.

**편향 해석**

편향은 방향을 나타내지만 오차 크기를 대신하지 않습니다. 1억원 과대 예측과 1억원 과소 예측이 동시에 발생하면 편향은 0%가 될 수 있으나, 절대 오차는 2억원이므로 WMAPE는 높게 나타납니다.

| 결과 조합 | WMAPE | Bias | 판정 |
| --- | ---: | ---: | --- |
| 낮음 | 0% 근처 | 0% 근처 | 크기와 방향 모두 안정 |
| 높음 | 양수 | 과대 예측이 우세 |
| 높음 | 음수 | 과소 예측이 우세 |
| 높음 | 0% 근처 | 반대 방향 오차가 상쇄됨 |

보고 시에는 `WMAPE + Bias + 표본 건수 + 실제 금액 합계`를 한 묶음으로 제시합니다. MAPE는 소액 건 민감도를 확인할 필요가 있을 때 같은 표에 추가합니다.

## 범주별 분리 측정 원칙
<!--meta: sec=s3; dept=SALES; level=시니어; ct_band=상; related=s2|s4-->
**분리 측정 단위**

Commit, Best Case, 가중 파이프라인은 서로 다른 확실성과 계산 구조를 가지므로 각각 독립된 모집단으로 측정합니다. 포캐스트 범주 5개인 Commit·Best Case·Pipeline·Omitted·Closed의 판정과 변경 규칙은 FCT-02를 따릅니다.

범주별 측정 대상은 스냅샷 시점의 분류로 고정합니다. 이후 Commit이 Best Case로 변경되거나 Closed로 전환되더라도 최초 측정 모집단을 다시 작성하지 않으며, 범주 이동은 편차 원인 분석용 속성으로 남깁니다.

| 측정 묶음 | 예측값 | 실제값 | 보고 지표 |
| --- | --- | --- | --- |
| Commit | 스냅샷의 Commit 금액 합계 | 기간 내 실제 확정 금액 | MAPE·WMAPE·Bias |
| Best Case | 스냅샷의 Best Case 금액 합계 | 기간 내 실제 확정 금액 | MAPE·WMAPE·Bias |
| 가중 파이프라인 | FCT-02 산식의 가중 금액 | 기간 내 실제 확정 금액 | WMAPE·Bias |
| Omitted | 정확도 모집단에서 제외 | 해당 없음 | 제외 건수·금액 |
| Closed | 신규 예측 정확도 모집단에서 제외 | 기준 실제값에 반영 | 확정 상태 검증 |

가중 파이프라인은 CRM 범주 하나가 아니라 확률을 적용한 계산 결과입니다. 따라서 Pipeline 범주의 원금액과 혼합하지 않고, 동일한 스냅샷에 저장된 가중 결과를 독립적으로 검증합니다.

**혼합 수치가 만드는 왜곡**

Commit에서 2억원을 과대 예측하고 Best Case에서 2억원을 과소 예측하면 합산 편향은 0원이 됩니다. 그러나 Commit 판정은 지나치게 낙관적이고 Best Case 판정은 지나치게 보수적이라는 두 가지 오류가 동시에 존재합니다.

이처럼 범주를 섞은 단일 정확도는 한쪽의 과대 예측과 다른 쪽의 과소 예측을 상쇄합니다. 합계가 실제값과 일치하더라도 범주별 약속 수준과 경영 의사결정 가능성이 훼손되므로 정상으로 판정하지 않습니다.

1. 범주별 WMAPE를 먼저 산출합니다.
2. 같은 범주 안에서 편향을 계산합니다.
3. 표본 건수와 실제 금액 합계를 함께 표시합니다.
4. 범주 간 합산값은 총량 참고치로만 표시합니다.
5. 합산값으로 범주별 경보를 해제하지 않습니다.

**단일 숫자 보고 요구 대응**

한 개의 정확도 숫자만 요구받으면 `Commit WMAPE`를 대표값으로 제출합니다. Commit은 기간 내 확정을 약속한 모집단이므로 운영상 가장 직접적인 예측 책임을 나타내며, 금액 가중 방식이 소액 건의 과도한 영향을 줄입니다.

대표값 옆에는 반드시 `Commit 한정`, 대상 기간, 스냅샷 기준일, 표본 건수, 실제 금액 합계를 표기합니다. Best Case와 가중 파이프라인 결과는 부속 표 또는 링크로 제공하며, 세 범주의 오차를 합산한 새로운 지표를 만들지 않습니다.

경영 보고 양식이 합계만 허용하더라도 상쇄 전 절대 오차 합계는 보존합니다. 범주별 원자료를 삭제하거나 단일 편향값으로 대체하는 방식은 허용하지 않습니다.

## 목표 수준과 허용 범위
<!--meta: sec=s4; dept=SALES; level=시니어; ct_band=중; related=s3|s5-->
**정확도 판정 기준**

정확도는 보고 편의를 위해 `정확도 = 100% - WMAPE`로 표시하며, 공식 판정에는 원래 WMAPE를 함께 사용합니다. WMAPE가 100%를 넘으면 정확도는 음수가 될 수 있고, 이를 0%로 임의 보정하지 않습니다.

목표 구간은 성숙한 예측 운영 상태에서 기대하는 수준입니다. 상한을 넘는 정확도는 불합격이 아니지만, 장기간 100%에 지나치게 근접하면 표본 부족이나 사후 수정 가능성을 별도로 확인합니다.

| 측정 묶음 | 성숙 목표 정확도 | 목표 WMAPE | 허용 구간 | 개선 필요 |
| --- | ---: | ---: | ---: | ---: |
| Commit | 90~95% | 5~10% | 85% 이상·90% 미만 | 85% 미만 |
| Best Case | 80~85% | 15~20% | 70% 이상·80% 미만 | 70% 미만 |
| 가중 파이프라인 | 70~80% | 20~30% | 60% 이상·70% 미만 | 60% 미만 |

가중 파이프라인 목표는 헤드헌터랩의 초기 내부 관리 기준입니다. 외부 성숙도 기준으로 단정하지 않으며, 4개 분기 이상의 동일 산식 표본이 축적되면 s17의 재검토 절차로 조정합니다.

**관찰 중위값과 목표의 구분**

시장 관찰치에서는 Commit 범주의 실제 달성 중위값이 약 85%, Best Case가 약 38%, 가중 파이프라인이 약 22%로 보고됩니다. 이 수치는 각 범주에서 예측 금액 중 실제로 달성된 비율이며, WMAPE 기반 정확도와 같은 지표가 아닙니다.

| 구분 | Commit | Best Case | 가중 파이프라인 |
| --- | ---: | ---: | ---: |
| 관찰된 실제 달성 중위값 | 약 85% | 약 38% | 약 22% |
| 성숙 조직의 관리 목표 | 90~95% 정확도 | 80~85% 정확도 | 내부 기준 적용 |
| 사용 목적 | 외부 수준 참고 | 외부 수준 참고 | 보조 기준선 참고 |

달성 중위값을 그대로 정확도 목표로 복사하지 않습니다. 예측액 대비 실현액 비율은 과대·과소 방향을 보여주지만, 건별 절대 오차와 반대 방향 상쇄를 충분히 나타내지 못하기 때문입니다.

**단계적 도입**

| 적용 기간 | Commit 최소선 | Best Case 최소선 | 가중 파이프라인 최소선 | 운영 방식 |
| --- | ---: | ---: | ---: | --- |
| 도입 1분기 | 기준선만 측정 | 기준선만 측정 | 기준선만 측정 | 경보·개인 평가 미적용 |
| 도입 2분기 | 85% | 70% | 60% | 미달 범주에 원인 분석 의무 |
| 도입 3분기 이후 | 90% | 80% | 70% | 성숙 목표와 허용 구간 적용 |

도입 1분기에는 최소 3회의 월 단위 결과를 확보하고 표본 건수와 금액 분포를 확인합니다. 표본이 월 5건 미만이면 월별 등급을 확정하지 않고 분기 누적으로 판정합니다.

개선 필요 구간이 2회 연속 발생하거나 분기 누적 기준을 미달하면 개선 과제를 등록합니다. 한 차례의 미달만으로 목표나 범주 기준을 변경하지 않으며, 원인 확인 없이 허용 범위를 확대하지 않습니다.

## 측정 시점과 데이터 스냅샷 관리
<!--meta: sec=s5; dept=SALES|DATA; level=시니어; ct_band=상; related=s4|s6-->
포캐스트 정확도는 분기말 결과만 한 번 비교하지 않고, 동일한 종료기간을 예측한 주간 스냅샷별로 측정합니다. 분기말 단건 측정은 최종 수치만 남기므로 조기 과대 예측, 월말 임박 후 범주 하향, 종료예정일 반복 이월을 구분하지 못합니다.

주간 측정은 예측 잔여기간별 오차 추이를 제공합니다. 특히 Commit 범주의 금액 가중 MAPE를 매주 측정하면 정확도가 어느 시점부터 악화되었는지 확인할 수 있으며, 담당자 설명이 아니라 당시 저장된 예측값으로 판단할 수 있습니다.

**표준 스냅샷 시점**

| 구분 | 데이터 기준시각 | 추출시각 | 측정 용도 | 담당 |
| --- | --- | --- | --- | --- |
| 주간 스냅샷 | 직전 영업일 18:00 KST | 매주 월요일 09:00 | 월·분기 종료기간에 대한 주차별 정확도 | DATA |
| 월말 스냅샷 | 월 마지막 영업일 18:00 | 다음 영업일 09:00 | 월 최종 예측과 실제 결과 비교 | DATA |
| 분기말 스냅샷 | 분기 마지막 영업일 18:00 | 다음 영업일 09:00 | 분기 회고의 기준 예측 | DATA |
| 실제 결과 스냅샷 | 종료일 기준, D+3 12:00 확정 | D+3 14:00 | 해당 기간 수주·실패·이월 결과 고정 | SALES·DATA |
| 수시 보존본 | 포캐스트 마감 직후 | 마감 후 30분 이내 | 승인된 예외 변경의 전후 비교 | RevOps |

공휴일에는 다음 영업일에 추출하되 데이터 기준시각은 직전 영업일 18:00으로 유지합니다. 월요일 스냅샷에는 예측 대상 월 또는 분기 종료일까지의 잔여 주차를 `M-4`, `M-3`, `Q-8`처럼 별도 필드로 저장합니다.

**스냅샷 보관 항목**

1. 기회 ID, 계정 ID, 소유자, 지점, 계약 형태를 저장합니다.
2. 단계, 포캐스트 범주, 예측 금액, 가중 금액, 종료예정일을 저장합니다.
3. 스냅샷 기준시각, 추출시각, 배치 ID, 산출 규칙 버전을 저장합니다.
4. 원본 파일은 수정 불가 영역에 CSV 또는 Parquet 형식으로 보관합니다.
5. 파일명은 `FCT_YYYYMMDD_HHMM_기간_규칙버전` 형식을 사용합니다.
6. 스냅샷과 계산 결과는 5년간 보관하고 SALES·DATA·RevOps에 읽기 권한을 부여합니다.

DATA는 적재 후 레코드 수, 총예측액, 범주별 금액, 중복 기회 ID 수를 원천 CRM과 대조합니다. 총예측액 차이가 0.1% 또는 100만원을 초과하거나 레코드 수가 다르면 해당 배치를 계산 대상에서 보류합니다.

**소급 수정 통제**

| 발생 상황 | 과거 스냅샷 처리 | 정확도 처리 | 기록 |
| --- | --- | --- | --- |
| 담당자가 종료예정일·금액을 뒤늦게 수정 | 원본 유지 | 과거 지표 재계산 금지 | 현재 CRM 변경이력만 연결 |
| 실제 계약금액이 사후 정정 | 원본·공표 지표 유지 | 정정 영향액을 별도 주석 | 정정 원인·승인자 기록 |
| 추출 누락을 공표 전에 발견 | 원본을 폐기하지 않고 오류본 표시 | 승인된 재추출본으로 최초 계산 | 구·신 배치 ID 병기 |
| 공표 후 배치 결함 발견 | 당시 지표 유지 | 수정 시뮬레이션을 별도 열로 제시 | SALES 부장·DATA 부장 승인 |

소급 수정된 CRM 현재값으로 과거 정확도를 다시 계산하지 않습니다. 공표 후 발견된 오류는 원지표를 덮어쓰지 않고 `정정 영향 분석`으로 병기하여 당시 판단 품질과 데이터 결함을 분리합니다.

스냅샷 마감·범주 변경 규칙은 FCT-02, CRM 필드 수정과 감사 기준은 FCT-05를 참조합니다.

## 계산 예시 — 월 단위 실제 계산
<!--meta: sec=s6; dept=SALES|DATA; level=주니어|시니어; ct_band=상; related=s5|s7-->
다음 예시는 4월 첫 영업일 스냅샷으로 4월 말 수주액을 예측한 가상 데이터입니다. 금액 단위는 백만원이며, 실제는 스냅샷에 포함된 기회가 4월 안에 수주로 확정된 금액입니다.

오차는 `예측액 - 실제액`으로 계산합니다. 양수는 과대 예측, 음수는 과소 예측입니다. Pipeline 행의 예측액은 해당 시점의 확률 가중액이며 산출 규칙은 FCT-02를 따릅니다.

**기회별 입력값과 오차**

| 기회 ID | 스냅샷 구분 | 예측액 | 실제액 | 오차 | 절대오차 | 월말 결과 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| C-01 | Commit | 120 | 120 | 0 | 0 | 예정 금액대로 수주 |
| C-02 | Commit | 80 | 0 | +80 | 80 | 다음 달로 이월 |
| B-01 | Best Case | 100 | 80 | +20 | 20 | 범위 축소 후 수주 |
| B-02 | Best Case | 60 | 0 | +60 | 60 | 기간 내 미수주 |
| P-01 | 가중 파이프라인 | 30 | 50 | -20 | 20 | 예상보다 큰 금액으로 수주 |
| P-02 | 가중 파이프라인 | 20 | 0 | +20 | 20 | 기간 내 미수주 |

범주별 WMAPE는 `절대오차 합계 ÷ 실제액 합계 × 100`으로 계산합니다. 편향은 `(예측액 합계 - 실제액 합계) ÷ 실제액 합계 × 100`으로 계산하며, 실제액 합계가 0인 범주는 비율을 산출하지 않고 금액 오차만 보고합니다.

**범주별 계산 결과**

| 구분 | 예측 합계 | 실제 합계 | 순오차 | 절대오차 합계 | WMAPE | 편향 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Commit | 200 | 120 | +80 | 80 | 66.7% | +66.7% |
| Best Case | 160 | 80 | +80 | 80 | 100.0% | +100.0% |
| 가중 파이프라인 | 50 | 50 | 0 | 40 | 80.0% | 0.0% |

Commit 계산은 `80 ÷ 120 × 100 = 66.7%`입니다. 예측액 대비 실제 달성액은 60%이며, 미수주된 C-02 한 건이 오차 전부를 만들었습니다.

Best Case는 실제액 80에 비해 160을 예측하여 100% 과대 편향입니다. B-01의 금액 축소와 B-02의 미수주를 각각 보존했으므로 두 오류의 성격을 구분할 수 있습니다.

가중 파이프라인은 예측 합계와 실제 합계가 모두 50이어서 편향이 0%입니다. 그러나 P-01의 과소 예측과 P-02의 과대 예측이 상쇄된 결과이며, WMAPE는 80%이므로 정확했다고 판정하지 않습니다.

세 구분의 금액을 합쳐 하나의 정확도 숫자로 보고하지 않습니다. Commit, Best Case, 가중 파이프라인은 예측 강도와 해석 목적이 다르며 각각의 WMAPE와 편향을 별도 열로 유지합니다.

## 편차 원인 분류 체계
<!--meta: sec=s7; dept=SALES; level=시니어; ct_band=상; related=s6|s8-->
편차 원인은 예측이 틀렸다는 사실을 담당자의 설명문으로만 남기지 않고 표준 코드로 기록합니다. 코드는 결과가 확정되거나 종료예정일이 다음 기간으로 이동한 날부터 2영업일 이내에 입력합니다.

각 기회에는 주원인 코드 1개와 보조원인 코드 최대 2개를 지정합니다. 주원인은 편차를 직접 발생시킨 사건으로 선택하고, 보조원인은 그 사건의 발생 가능성이나 영향을 키운 요인으로 제한합니다.

**편차 원인 코드표**

| 코드 | 원인 | 정의 | 판별 질문 |
| --- | --- | --- | --- |
| C01 | 고객 의사결정 지연 | 합의된 결정일에 고객 승인권자의 결론이 나오지 않아 이월된 경우 | 승인권자와 결정일이 특정되어 있었으며 그 날짜가 고객 사유로 변경되었는가? |
| C02 | 범위 변경 | 기능·연동·대상 조직·산출물 변경으로 금액 또는 일정이 달라진 경우 | 최초 예측 이후 고객이 요구 범위를 추가·삭제·재구성했는가? |
| C03 | 예산 집행 시점 변경 | 예산은 존재하지만 배정·전용·집행 가능 시점이 변경된 경우 | 구매 의사는 유지되나 예산 사용 가능일만 다음 기간으로 이동했는가? |
| C04 | 경쟁 패배 | 고객이 다른 공급자 또는 내부 대체안을 선택하여 실패한 경우 | 고객 또는 신뢰 가능한 접점에서 대안 선택 사실을 확인했는가? |
| I01 | 내부 견적·검토 지연 | 헤드헌터랩의 견적, 기술 검토, 승인 또는 제안 산출이 계획일을 넘긴 경우 | CNS·AIAX·BE·DATA·SALES의 내부 완료 지연이 고객 일정에 영향을 주었는가? |
| J01 | 담당자 과대 판정 | 객관적 진척보다 높은 범주·금액·종료 가능성을 담당자가 적용한 경우 | 당시 근거로 범주를 유지할 수 없는데도 낙관 판단을 입력했는가? |
| C05 | 계약 절차 소요 과소 추정 | 고객 구매·법무·보안·전자계약 절차의 리드타임을 짧게 추정한 경우 | 사업 의사결정 후 남은 계약 단계가 예측일 안에 끝날 수 없었는가? |
| D01 | 데이터 입력 오류 | 실제 상황과 다른 금액·날짜·범주·상태가 CRM에 입력된 경우 | 원천 증빙은 맞지만 CRM 값 또는 추출 매핑이 달랐는가? |

C01과 C05는 의사결정 완료 여부로 구분합니다. 구매 결정 전 승인 지연은 C01, 구매 결정 후 계약 문서·보안·조달 절차의 장기화는 C05로 기록합니다.

C02와 D01은 실제 사건 발생 여부로 구분합니다. 고객 요구가 바뀌었다면 C02이고, 요구는 그대로인데 CRM 금액만 잘못 입력되었다면 D01입니다.

**코드 판정에 필요한 최소 증빙**

| 증빙 수준 | 인정 자료 | 사용 기준 |
| --- | --- | --- |
| 1순위 | 고객 이메일, 회의록, 승인 일정, 계약 절차표 | 고객 원인 코드의 기본 증빙 |
| 2순위 | 내부 견적 요청일, 검토 티켓, 승인 로그 | I01·D01 판정 자료 |
| 3순위 | 담당자 메모와 관리자 확인 | 외부 자료가 없을 때 보조 증빙 |
| 불인정 | 근거 없는 구두 추정, 사후 기억만으로 작성한 설명 | 단독 판정 근거로 사용 금지 |

복수 사건이 연속된 경우 최종 결과와 시간적으로 가장 가까운 사건을 자동 선택하지 않습니다. 해당 사건이 없었다면 예측 결과가 달라졌을지를 검토하여 주원인을 정하고, 근거 링크와 발생일을 함께 저장합니다.

원인 코드는 개인 책임을 확정하는 인사자료가 아닙니다. 동일 코드의 반복 빈도, 영향액, 발생 시점을 집계하여 예측 과정의 구조적 결함을 찾는 데 사용합니다.

## 원인별 점검 질문과 1차 조치
<!--meta: sec=s8; dept=SALES; level=시니어; ct_band=상; related=s7|s9-->
원인 분석은 코드 입력으로 종료하지 않습니다. 각 코드에는 재발 가능성을 낮추는 1차 조치를 연결하며, 조치는 고객 결과를 되돌리는 활동이 아니라 다음 예측에서 같은 오류를 줄이는 통제 활동이어야 합니다.

관리자는 원인 확정 후 기한과 완료 증빙을 지정합니다. 다른 부서가 조치 주체인 경우에도 SALES 담당자가 요청을 등록하고 완료 여부를 확인하며, 범주 재판정 자체는 FCT-02를 따릅니다.

**원인별 점검과 1차 조치**

| 코드 | 추가 점검 질문 | 다음 발생을 줄이는 1차 조치 | 조치 주체 | 완료 기한 |
| --- | --- | --- | --- | --- |
| C01 | 승인권자, 결정 기준, 실제 결정 예정일을 고객에게 확인했는가? | 의사결정자·검토자·결정일을 한 장의 결정 경로표로 기록하고 고객 확인 근거를 연결합니다. | 담당자, 영업 관리자 | 코드 확정 후 2영업일 |
| C02 | 변경 요청일과 금액·일정 영향이 각각 기록되어 있는가? | 기준 범위와 변경 범위를 분리한 영향 확인서를 작성하고 CNS의 일정 검토를 받습니다. | 담당자, CNS | 3영업일 |
| C03 | 예산 승인과 실제 집행 가능일을 구분하여 확인했는가? | 예산 배정일·집행 개시일·회계기간을 별도 필드로 기록하고 증빙 없는 날짜는 예측 근거에서 제외합니다. | 담당자, 영업 관리자 | 2영업일 |
| C04 | 가격, 기능, 관계, 일정 중 패배 요인이 확인되었는가? | 30분 승패 리뷰를 열어 확인된 패배 요인 1개와 검증되지 않은 추정치를 분리 기록합니다. | 영업 관리자, 담당자 | 실패 확정 후 5영업일 |
| I01 | 요청일, 약속일, 실제 완료일 중 어느 구간에서 지연됐는가? | 병목 업무에 요청자·완료 책임자·내부 완료일을 지정하고 지연 예상 시 1영업일 안에 관리자에게 알립니다. | SALES 및 해당 CNS·AIAX·BE·DATA | 원인 확정 후 2영업일 |
| J01 | 범주를 지지하는 고객 증빙 없이 담당자 판단만 사용했는가? | 최근 오판 5건을 관리자가 재채점하고, 이후 4주 동안 해당 담당자의 범주 상향을 사전 검토합니다. | 영업 관리자 | 재채점 5영업일, 통제 4주 |
| C05 | 고객 법무·구매·보안·서명 단계별 예상일을 확보했는가? | 고객 절차 체크리스트에 단계별 담당자와 리드타임을 입력하고 최근 유사 계약 3건의 중앙값과 비교합니다. | 담당자, 영업 관리자 | 3영업일 |
| D01 | 사람의 오입력, 필드 매핑, 자동화 중 어느 지점에서 오류가 생겼는가? | 현재 레코드를 수정하고 동일 오류 탐지 쿼리 또는 입력 검증 규칙을 추가합니다. | 담당자, RevOps·DATA | 레코드 1영업일, 통제 5영업일 |

C04의 경쟁 패배 원인이 고객에게 확인되지 않았다면 추정치를 확정 코드처럼 보고하지 않습니다. 확인 전에는 증빙 수준을 표시하고, 후속 접촉에서도 확인되지 않으면 관리자가 사용 가능한 내부 증거로 판정을 종료합니다.

I01은 지연된 부서명만 적는 방식으로 완료 처리하지 않습니다. 요청 접수시각, 약속 완료시각, 실제 완료시각이 있어야 병목 구간과 지연시간을 계산할 수 있습니다.

**조치 완료 판정**

| 상태 | 판정 기준 | 관리자 처리 |
| --- | --- | --- |
| 완료 | 산출물·CRM 링크·검증 규칙 등 재사용 가능한 증빙이 존재 | 완료일과 확인자를 기록합니다. |
| 부분 완료 | 개별 기회는 수정했으나 다음 기회에 적용할 통제가 없음 | 재발 방지 항목을 추가 지정합니다. |
| 기한 초과 | 완료 기한을 1영업일 이상 경과 | 지점 SALES 부장에게 에스컬레이션합니다. |
| 효과 미확인 | 조치는 완료했으나 동일 코드가 30일 내 재발 | 조치 강도를 높여 개선 과제로 전환합니다. |

동일 코드가 한 달에 3건 이상 발생하거나 영향액이 해당 월 예측액의 10% 이상이면 개별 조치로 종결하지 않습니다. 관리자는 공통 원인을 확인하여 개선 과제 후보로 등록하며, 등록과 추적 기준은 s15를 적용합니다.

## 분기 포캐스트 회고 운영
<!--meta: sec=s9; dept=SALES; level=시니어; ct_band=중; related=s8|s10-->
분기 포캐스트 회고는 분기 종료일로부터 10영업일 이내에 90분으로 실시합니다. 목적은 실제 수주 결과와 분기 중 예측 변화 사이에서 반복 가능한 편차 패턴을 찾는 것입니다.
회의에서는 담당자의 낙관성이나 판단 능력을 직접 평가하지 않습니다. 동일 원인이 여러 기회·지점·범주에서 반복되었는지와 현행 측정 방식으로 조기에 탐지할 수 있었는지를 확인합니다.
**참석자와 역할**
| 구분 | 참석 기준 | 역할 |
| --- | --- | --- |
| 운영 책임자 | RevOps 또는 SALES 과장 이상 1명 | 자료 확정, 회의 진행, 원인 코드 통제 |
| 의사결정자 | 지점별 SALES 부장 또는 위임받은 차장 | 패턴 판정, 개선 과제 승인 |
| 실무 참석자 | 해당 분기 기회 소유자 중 주요 편차 건 담당자 | 당시 판단 근거와 고객 신호 설명 |
| 조건부 참석자 | CNS 및 AIAX·BE·DATA 기술 책임자 | 기술·범위 요인이 있는 안건의 사실 확인 |
실무 참석자는 자기 기회가 안건에 포함된 시간에만 참석할 수 있으며, 원인 소명만을 위한 별도 호출은 금지합니다.
**사전 준비 자료**
운영 책임자는 회의 2영업일 전까지 아래 자료를 동일 기준일과 동일 통화 단위로 확정합니다. Commit·Best Case·Pipeline은 합산 정확도로 상쇄하지 않고 각각 분리합니다.
| 자료 | 필수 내용 | 작성 기준 |
| --- | --- | --- |
| 정확도 리포트 | 범주별 WMAPE, MAPE, Bias | 주간 스냅샷과 분기 최종 실적 비교 |
| 이동 이력 | 금액·종료예정일·범주 변경 | 변경일, 변경 전후 값, 변경 사유 포함 |
| 편차 상위 건 | 절대 금액 편차 상위 10건 | 수주·실패·차기 분기 이월을 구분 |
| 패턴 집계 | 원인 코드별 건수와 금액 | 단일 담당자 사례가 아닌 반복 횟수 표시 |
자료 제출 후 수치를 수정해야 하면 원본을 덮어쓰지 않고 수정 사유와 수정 시각을 별도 기록합니다.
**진행 순서**
진행자는 개별 딜 설명이 회의의 절반을 넘지 않도록 시간 제한을 적용합니다. 증빙이 없는 추정은 결론이 아니라 추가 확인 항목으로 남깁니다.
1. 10분: 분기 전체와 범주별 정확도·편향 방향을 확인합니다.
2. 20분: 절대 금액 편차 상위 건의 최초 발생 시점과 탐지 가능 시점을 확인합니다.
3. 25분: 동일 원인이 3건 이상 또는 편차 금액의 20% 이상을 차지하는 패턴을 묶습니다.
4. 20분: 현행 규칙·데이터·검토 절차 중 통제 가능한 원인을 판정합니다.
5. 15분: 개선 과제와 소유자, 완료기한, 검증 지표를 승인합니다.
**산출물**
회고록에는 확정 패턴, 예외 판단, 개선 과제를 구분해 기록합니다. 개선 과제는 분기당 3건 이내로 제한하고 단순 교육 요청보다 재발 차단 효과가 큰 항목을 우선합니다.
| 산출물 | 필수 필드 | 완료 기준 |
| --- | --- | --- |
| 편차 패턴 목록 | 원인 코드, 건수, 금액 영향, 탐지 시점 | 증빙 기회가 2건 이상 연결됨 |
| 개선 과제 | 소유자, 기한, 변경 대상, 검증 지표 | 최대 3건이 승인됨 |
| 판단 보류 목록 | 부족한 증빙, 확인 담당, 확인기한 | 회의 후 5영업일 내 보완됨 |
회의록에 개인별 순위나 비난성 표현을 넣지 않으며, 개선 과제의 등록·추적은 FCT-04 s15 기준을 적용합니다.

## 담당자 개인 정확도의 활용 범위와 금지 사항
<!--meta: sec=s10; dept=SALES; level=시니어; ct_band=상; related=s9|s11-->
담당자 개인 정확도는 예측 역량을 교정하기 위한 진단 정보로만 사용합니다. 동일 담당자의 예측이 반복적으로 과대 또는 과소 방향을 보이는지 확인하되, 고객군·계약 유형·기회 금액의 차이를 분리하지 않은 단순 비교는 하지 않습니다.
개인 단위 결과는 해당 담당자, 직속 영업 관리자, RevOps로 열람 범위를 제한합니다. 지점 전체에 이름과 수치를 공개하면 보수적 예측, 범주 하향, 종료예정일 임의 이연을 유발할 수 있습니다.
**허용되는 활용**
| 활용 용도 | 적용 방식 | 필요한 보호 조건 |
| --- | --- | --- |
| 코칭 | 오차가 커진 판단 시점과 근거를 사례별 검토 | 실제 고객 신호와 당시 가용 정보 사용 |
| 범주 판정 신뢰 조정 | 담당자 제출값에 관리자 검토 강도를 차등 적용 | 금액을 임의 삭감하지 않고 검토 단계만 조정 |
| 교육 배정 | 반복되는 편향 원인에 맞는 판정 연습 지정 | 최소 2개 분기 자료 확인 |
| 프로세스 진단 | 여러 담당자에게 공통으로 발생한 오류 탐지 | 개인 문제가 아닌 구조적 원인으로 집계 |
신뢰 수준 조정은 영구 등급이 아닙니다. 최근 2개 분기에서 동일 편향이 재발하지 않으면 기본 검토 수준으로 복귀시킵니다.
**표본 수에 따른 해석 기준**
표본 수는 주간 스냅샷 수가 아니라 해당 기간에 수주·실패·이월 결과가 확정된 독립 기회 수로 계산합니다. 같은 기회의 주간 관측치를 여러 건으로 세어 표본을 부풀리지 않습니다.
| 확정 기회 수 | 판정 수준 | 허용 조치 |
| --- | --- | --- |
| 1~4건 | 판단 불가 | 사례 코칭만 실시하고 개인 경향을 표기하지 않음 |
| 5~9건 | 탐색적 신호 | 편향 방향을 참고하되 신뢰 수준 변경 금지 |
| 10~19건 | 제한적 판정 | 금액 집중도 확인 후 관리자 검토 강도 조정 가능 |
| 20건 이상 | 경향 판정 가능 | 최근 4개 분기 이동값으로 지속성 확인 |
기회 1건이 개인 포캐스트 금액의 50% 이상이면 건수 기준을 충족해도 집중 표본으로 표시합니다. 구축과 운영·유지보수 기회는 오차 구조가 다르므로 별도 집계합니다.
**금지 사항**
개인 WMAPE가 높다는 사실만으로 성과 부진이나 업무 태만을 판정하지 않습니다. 정확도는 결과 금액뿐 아니라 담당 포트폴리오의 변동성과 고객 의사결정 구조에 영향을 받습니다.
- 인사 평가, 승진, 보상 또는 징계의 단독 근거로 사용하지 않습니다.
- 담당자 이름이 표시된 정확도 순위표를 게시하거나 회의 화면에 노출하지 않습니다.
- 과대 예측과 과소 예측을 상계한 단일 수치만으로 우수 담당자를 선정하지 않습니다.
- 수주율이 낮다는 이유로 정확도까지 낮다고 간주하거나 두 지표를 대체 사용하지 않습니다.
- 표본이 10건 미만인 담당자를 지점 평균과 직접 비교하지 않습니다.
개인 결과를 코칭에 인용할 때에는 WMAPE와 Bias를 함께 확인합니다. 총오차가 같더라도 지속적인 과대 예측과 양방향 변동은 서로 다른 코칭 원인으로 처리합니다.
담당 변경, 휴직, 신규 입사로 관측 기간이 2개 분기 미만이면 상태를 `관찰 중`으로 표시합니다. 이 기간에는 신뢰 수준 조정이나 조직 간 비교를 적용하지 않습니다.

## 구축 프로젝트 특유의 편차 요인
<!--meta: sec=s11; dept=SALES|CNS; level=시니어; ct_band=상; related=s10|s12-->
구축 프로젝트는 범위·기술·승인 구조가 계약 직전까지 함께 변할 수 있어 금액 편차와 시점 편차가 동시에 발생합니다. 분석 시 최종 계약금액 차이와 종료예정일 이동을 분리하지 않으면 원인이 잘못 귀속됩니다.
특히 연말 예산 집행 기회는 고객의 희망 일정이 실제 구매·계약 처리 능력보다 앞서는 경우가 많습니다. 예산 소진 의사만으로 계약 가능 시점을 확정된 것으로 해석하지 않습니다.
**반복 편차 원인**
| 원인 | 발생 구조 | 포캐스트 영향 |
| --- | --- | --- |
| 범위 확정 지연 | 대상 업무·연동 범위·산출물 경계가 미합의 상태로 잔존 | 견적 변경과 계약일 이월이 동시 발생 |
| 기술 검토 결과 | 데이터 품질, 보안, 인프라, 연동 난이도가 뒤늦게 확인 | 개발 공수와 외부 비용이 증감 |
| 고객 승인 단계 과소 파악 | 현업 합의 뒤 구매·보안·법무·경영 승인 존재 | 종료예정일이 단계별로 순차 연기 |
| 연내 예산 소진 압박 | 4분기 계약 희망 건이 특정 주에 집중 | Commit 과대 편성과 차기 연도 이월 증가 |
같은 기회에서 여러 원인이 발생하면 최초 편차를 만든 원인과 금액을 추가로 바꾼 원인을 구분합니다. 하나의 대표 사유로 모든 변동을 덮지 않습니다.
**탐지 증빙과 해석**
분석자는 고객의 구두 표현보다 문서화된 범위, 기술 검토 결과, 승인 경로를 우선합니다. 증빙이 없는 낙관적 일정은 영업 판단 오류가 아니라 `고객 절차 미확인`으로 우선 분류합니다.
| 관측 신호 | 확인 증빙 | 편차 해석 |
| --- | --- | --- |
| 요구사항 목록이 계속 증가 | 범위표 버전, 질의응답 이력 | 범위 확정 지연에 따른 금액·일정 변동 |
| 기술 조건부 의견이 남음 | 검토서, PoC 결과, 보안 질의 | 기술 결과에 따른 공수 재산정 가능성 |
| 승인권자 수가 뒤늦게 증가 | 고객 승인 경로, 회의 참석자 변경 | 내부 승인 단계 과소 파악 |
| 12월 특정 주 계약을 반복 요청 | 예산 집행기한, 구매 일정 회신 | 연말 일정 쏠림과 처리 병목 가능성 |
범위표의 버전이 2회 이상 바뀌거나 기술 검토 후 예상금액이 10% 이상 변하면 해당 건을 구조적 금액 편차로 표시합니다.
**분석 처리 기준**
구축 기회의 편차는 `금액`, `계약 시점`, `수주 여부` 세 축으로 기록합니다. 한 축의 적중이 다른 축의 오차를 상쇄하지 않도록 각각 원인을 부여합니다.
- 범위 미확정 상태의 최초 견적과 최종 계약금액 차이는 범위 효과로 분리합니다.
- 기술 검토 전후 금액 차이는 고객 협상 할인과 혼합하지 않습니다.
- 고객 승인 단계 추가로 인한 날짜 이동은 영업 활동 지연과 구분합니다.
- 연말 집중 건은 11월 말과 12월 말 스냅샷의 이월률을 별도 비교합니다.
- 계약일이 30일 이상 이동한 건은 금액 오차가 없더라도 주요 편차 건에 포함합니다.
분석 비교군은 구축 프로젝트끼리 구성하며, 운영·유지보수 갱신 건과 합산한 평균을 사용하지 않습니다.
**사실 확인 책임**
| 담당 | 확인 대상 | 제출 증빙 |
| --- | --- | --- |
| SALES | 고객 승인 경로와 구매 일정 | 고객 회신, 미팅 기록 |
| CNS | 범위 합의 상태와 변경 이력 | 범위표, 요구사항 버전 |
| AIAX·BE·DATA | 기술 조건과 공수 변동 근거 | 기술 검토서, 산정 변경 기록 |
기술 타당성 검토 절차는 DSC-xx를 참조하며, 본 회고에서는 검토 결과가 예측 편차에 미친 영향만 판정합니다.

## 운영·유지보수 갱신 포캐스트의 편차 요인
<!--meta: sec=s12; dept=SALES; level=시니어; ct_band=중; related=s11|s13|CSM-05#s1-->
운영·유지보수 갱신은 기존 거래가 있다는 이유로 신규 구축보다 확실한 매출로 오인되기 쉽습니다. 서비스가 계속 제공되고 있더라도 고객의 갱신 승인, 조건 합의, 계약 문서 처리가 완료된 것은 아닙니다.
갱신 편차 분석은 전액 해지뿐 아니라 금액 축소와 계약 시작일 지연을 포함합니다. 동일 고객의 확장 제안 금액은 기존 범위 갱신분과 분리하여 원인을 판정합니다.
갱신 절차와 가격 조정 기준은 CSM-05를 참조합니다.
**전형적 편차 원인**
| 원인 | 잘못된 가정 | 실제 편차 형태 |
| --- | --- | --- |
| 갱신 자동 가정 | 전년도 계약이 있으므로 동일 조건으로 계속된다고 판단 | 미갱신·계약 공백·승인 지연 |
| 요율 조정 협상 과소 추정 | 인상률 안내만으로 조건 합의가 끝났다고 판단 | 협상 장기화와 시작일 이월 |
| 고객 조직 개편 | 기존 담당자와 예산권자가 유지된다고 판단 | 책임자 변경, 예산 재승인, 의사결정 중단 |
| 축소 갱신 미반영 | 서비스 사용이 계속되므로 전액 갱신된다고 판단 | 계정·범위·지원등급 축소 |
자동 갱신 조항이 있어도 해지 통보기간, 범위 조정권, 예산 중단 가능성이 남아 있으면 분석상 `자동 확정`으로 취급하지 않습니다.
**조기 탐지 신호**
분석자는 갱신 실패 여부만 보지 않고 최초 경고 신호가 언제 나타났는지를 확인합니다. 신호 발생 후에도 금액과 종료예정일이 유지되었다면 예측 갱신 지연으로 판정합니다.
| 관측 신호 | 확인할 사실 | 연결되는 편차 |
| --- | --- | --- |
| 서면 갱신 의사 부재 | 고객 회신일과 승인권자 | 자동 갱신 가정 |
| 인상 근거 반복 요청 | 가격안 버전과 반론 횟수 | 요율 협상 장기화 |
| 담당자·보고선 변경 | 후임자, 예산부서, 결재권자 | 조직 개편 영향 |
| 사용 범위 또는 문의량 감소 | 제외 요청, 사용자 수, 지원 범위 | 축소 갱신 가능성 |
갱신 예정일 30일 전까지 서면 의사나 계약 절차 일정이 확인되지 않은 건은 실제 결과와 무관하게 `탐지 지연 후보`로 남깁니다.
**편차 기록 기준**
갱신 분석에서는 전년도 계약금액을 무조건 기준값으로 사용하지 않습니다. 고객이 확인한 갱신 대상 범위와 예상 조건을 기준으로 금액 변화의 원인을 분해합니다.
- 전액 해지는 `수주 여부 편차`로 기록합니다.
- 계약은 유지되지만 금액이 10% 이상 감소하면 `축소 갱신 편차`를 추가합니다.
- 요율 협상으로 계약 시작일이 30일 이상 이동하면 `협상 기간 편차`로 기록합니다.
- 조직 개편 후 승인권자가 변경되면 기존 담당자의 구두 의사는 확정 증빙에서 제외합니다.
갱신금액 감소와 요율 인상 실패가 동시에 발생하면 서비스 범위 감소분과 단가 조정분을 각각 계산합니다. 하나의 가격 협상 사유로 합산하지 않습니다.
**사실 확인 책임**
| 담당 | 확인 대상 | 제출 증빙 |
| --- | --- | --- |
| SALES | 갱신 의사, 협상 상태, 승인권자 | 고객 회신, 조건안, 승인 경로 |
| 수행 부서 | 제공 범위와 축소 요청 | 운영 현황, 범위 변경 요청 |
| 지점 SALES 책임자 | 주요 이월·축소 건의 원인 판정 | 원인 코드와 판정 메모 |
기존 계약의 관성보다 최신 고객 증빙을 우선하며, 증빙이 없는 전액 갱신 가정은 회고에서 낙관 편향으로 분류합니다.

## 지점별 편차 비교 시 유의점
<!--meta: sec=s13; dept=SALES|DATA; level=시니어; ct_band=상; related=s12|s14-->
지점별 정확도 비교는 서울·경기·인천 지점의 원자료를 단순 나열하는 방식으로 수행하지 않습니다. 딜 건수, 평균 금액, 산업 구성, 신규 구축·갱신 비중이 다르면 동일한 예측 역량이라도 WMAPE와 편향이 다르게 나타납니다.

비교 목적은 우수 지점을 선발하는 것이 아니라 반복 가능한 오차 원인을 찾는 데 있습니다. DATA는 보정 집계를 수행하고, SALES는 지점의 영업 맥락과 특이 거래를 확인합니다.

**필수 보정 항목**

| 보정 항목 | 왜곡 발생 조건 | 보정 방법 | 미보정 시 오해 |
| --- | --- | --- | --- |
| 딜 건수 | 분기 확정 건이 10건 미만 | 최근 4개 분기 이동 집계 병기 | 소수 대형 딜의 적중을 지속적 역량으로 판단합니다 |
| 평균 금액 | 지점 간 평균 계약금액이 2배 이상 차이 | 금액 구간별 WMAPE와 건수 기준 오차율을 함께 산출 | 대형 딜 담당 지점을 일관되게 불리하게 평가합니다 |
| 산업 구성 | 특정 산업 비중이 확정 금액의 50% 초과 | 전사 산업 구성비로 재가중한 표준화 지표 산출 | 산업별 구매·승인 특성을 지점 역량으로 오인합니다 |
| 신규·갱신 비중 | 갱신 금액 비중 차이가 20%p 이상 | 신규 구축과 운영·유지보수 갱신을 분리 집계 | 갱신 비중이 높은 지점의 예측 가능성을 영업력으로 오인합니다 |

**표준 비교 절차**

1. `지점 × 포캐스트 범주 × 신규·갱신 × 산업 × 금액 구간`으로 관측치를 분할합니다.
2. 금액 구간은 확정 금액 기준 `5천만원 미만 / 5천만원 이상~2억원 미만 / 2억원 이상`으로 구분합니다.
3. 각 셀에서 건수, 확정 금액, WMAPE, Bias를 계산한 뒤 전사 공통 구성비로 재가중합니다.
4. 원지표와 보정지표의 차이가 5%p 이상이면 산업·계약 유형 구성 효과를 별도 주석으로 표시합니다.

표준화 지표는 `Σ(셀별 지점 오차율 × 전사 공통 구성비)`로 계산합니다. 비교 대상 셀의 확정 건수가 3건 미만이면 해당 셀 수치를 비공개 처리하고 상위 구간과 합산합니다.

| 비교 판정 | 기준 | 보고 방식 | 허용 결론 |
| --- | --- | --- | --- |
| 비교 가능 | 지점별 확정 10건 이상, 구성 보정 완료 | 원지표·보정지표 병기 | 구조적 차이 여부를 판정합니다 |
| 제한 비교 | 한 지점이라도 5~9건 | 최근 4개 분기 이동값 사용 | 개선 추세만 해석합니다 |
| 비교 유보 | 한 지점이라도 5건 미만 | 전사 합계에만 포함 | 지점 간 우열을 판정하지 않습니다 |
| 대형 딜 영향 | 단일 건이 지점 확정 금액의 30% 초과 | 해당 건 포함·제외 수치 병기 | 집중도 리스크를 표시합니다 |

범주별 실제 달성 특성이 다르므로 Commit, Best Case, Pipeline을 합친 단일 정확도로 지점을 비교하지 않습니다. 한 범주의 과대 예측과 다른 범주의 과소 예측이 상쇄되면 실제보다 안정적인 지표로 보입니다.

보정 결과는 인사평가용 점수로 변환하지 않습니다. 지점별 목표 배분과 KPI 적용은 FCT-06을 참조하며, 단계·범주 입력 기준은 FCT-01과 FCT-02를 참조합니다.

## 정확도 지표가 왜곡되는 전형적 패턴
<!--meta: sec=s14; dept=SALES; level=시니어; ct_band=상; related=s13|s15-->
정확도 목표가 강하게 적용되면 담당자가 실제 예측력을 높이는 대신 숫자가 좋아 보이도록 입력 시점·범주·금액을 조정할 수 있습니다. 탐지 지표는 조작을 확정하는 증거가 아니라 원자료 확인이 필요한 경보로 사용합니다.

SALES는 매주 Commit WMAPE와 함께 범주 이동, Omitted 유출입, 최초 금액 대비 수주 금액 변화를 점검합니다. 임계값 초과 건은 담당자 설명과 변경 이력을 확인한 뒤 데이터 오류, 정상 변경, 지표 왜곡 행동으로 구분합니다.

**전형적 패턴과 탐지 기준**

| 패턴 | 관찰되는 행동 | 1차 탐지 지표 | 경보 기준 |
| --- | --- | --- | --- |
| 보수적 Commit | 가능성이 높은 건도 Best Case에 유지 | Best Case 수주 누출률 | Best Case에서 직접 수주된 금액이 전체 수주액의 25% 초과 |
| 마감 직전 범주 변경 | 기간 말에 Commit을 낮추거나 Omitted로 이동 | 마감 7일 내 하향 이동률 | 해당 금액이 직전 주 Commit의 15% 초과 |
| 금액 축소 후 증액 | 낮은 금액으로 예측한 뒤 수주 시 확대 | 수주 증액률 | 확정 금액이 마감 14일 전 금액보다 20% 이상 증가 |
| 불확실 건 제외 | 활성 협상 건을 Omitted로 이동 | Omitted 후 당기 수주율 | Omitted 이동 후 30일 내 수주가 10% 초과 |
| 분모 축소 | 예측이 어려운 열린 건의 종료일을 차기로 이동 | 종료예정일 이월률 | 마감 14일 내 당기 금액의 20% 초과 이월 |

`Best Case 수주 누출률 = Best Case에서 Commit을 거치지 않고 수주된 금액 ÷ 전체 수주 금액`으로 계산합니다. 2개 분기 연속 20%를 넘으면 범주 판정 습관을 점검하고, 25% 초과 시 원인 분석을 필수 등록합니다.

`마감 7일 내 하향 이동률 = Commit에서 Best Case·Pipeline·Omitted로 이동한 금액 ÷ 이동 전 Commit 금액`으로 계산합니다. 고객 승인 지연 등 근거가 CRM에 기록된 변경도 비율에는 포함하되 판정 시 정상 변경으로 분리합니다.

**교차 탐지 규칙**

1. Commit 정확도는 90% 이상이지만 Commit 포착률이 60% 미만이면 보수적 제출 가능성을 확인합니다.
2. WMAPE가 개선되면서 Omitted 금액 비중이 전 분기 대비 10%p 이상 증가하면 분모 축소 여부를 확인합니다.
3. 수주 증액률과 마감 직전 범주 변경률이 동시에 임계값을 넘으면 거래별 변경 이력을 전수 확인합니다.
4. 특정 담당자·지점에서 동일 패턴이 2회 연속 발생하면 개인 해명보다 입력 규칙과 승인 통제를 먼저 점검합니다.

| 확인 결과 | 판정 | 처리 |
| --- | --- | --- |
| 고객 의사결정 변경 근거 존재 | 정상 변동 | 근거 링크만 보존합니다 |
| 금액·범주 수정 근거 누락 | 데이터 품질 문제 | 2영업일 내 기록을 보완합니다 |
| 목표 회피 목적의 반복 변경 | 왜곡 행동 | 영업 부장에게 에스컬레이션합니다 |
| 시스템 자동화 오류 | 구조적 오류 | RevOps 수정 과제로 전환합니다 |

단일 경보만으로 담당자 평가나 징계를 결정하지 않습니다. 계약 범위 확정, 고객 예산 변경, 내부 승인 지연처럼 정상적인 사유가 존재할 수 있으므로 거래 활동 기록과 변경 시각을 함께 확인합니다.

범주 변경의 승인·마감 규칙은 FCT-02를, CRM 변경 권한과 감사 절차는 FCT-05를 참조합니다.

## 개선 과제 등록과 추적
<!--meta: sec=s15; dept=SALES; level=시니어; ct_band=중; related=s14|s16|FCT-02#s1-->
분기 회고에서 확인된 문제는 회의록의 자유 서술로 남기지 않고 개선 과제로 등록합니다. 과제는 정확도 오차를 유발한 통제 가능한 원인, 변경할 운영 요소, 완료 증거를 한 묶음으로 관리합니다.

등록 기한은 회고 종료 후 2영업일 이내입니다. SALES 운영 담당이 과제 번호를 발급하며, 실행 책임자는 한 명만 지정하고 협조 부서는 별도 필드로 기록합니다.

**개선 과제 등록 양식**

| 필드 | 입력 기준 | 예시 형식 |
| --- | --- | --- |
| 과제 ID | `FCT04-연도분기-일련번호` | `FCT04-2026Q3-03` |
| 원인 코드 | 승인 지연·금액 변동·범주 오판·데이터 오류 등 | 범주 오판 |
| 근거 지표 | 기준값, 실제값, 영향 금액 | 하향 이동률 18%, 1.4억원 |
| 적용 범위 | 전사·지점·계약 유형·특정 프로세스 | 신규 구축 |
| 개선 조치 | 동사로 시작하는 단일 실행 항목 | Commit 증빙 필드 추가 |
| 책임자·협조 부서 | 책임자 직급과 부서, 협조 부서 | SALES 과장 / DATA |
| 완료기한 | 등록일 기준 최대 60일 | 2026-11-30 |
| 완료 증거 | 설정 화면, 개정 문서, 교육 기록, 재측정 결과 | 4주 재측정표 |

과제 우선순위는 `영향 금액 × 재발 가능성 × 통제 가능성`으로 판정합니다. 각 요소를 1~3점으로 부여하며, 곱이 18점 이상이면 P1, 8~17점이면 P2, 1~7점이면 P3로 지정합니다.

| 등급 | 최초 조치기한 | 점검 주기 | 에스컬레이션 |
| --- | --- | --- | --- |
| P1 | 5영업일 이내 | 매주 | 10영업일 지연 시 SALES 부장 |
| P2 | 15영업일 이내 | 격주 | 20영업일 지연 시 지점 부장 |
| P3 | 30영업일 이내 | 월간 | 30영업일 지연 시 RevOps 담당 |

상태는 `등록 → 원인 검증 → 실행 중 → 효과 측정 → 완료`만 사용합니다. 실행물을 만들었더라도 최소 4주 또는 다음 월 마감 1회에서 지표 개선이 확인되기 전에는 완료 처리하지 않습니다.

효과 측정에는 변경 전 4주와 변경 후 4주의 동일 지표를 사용합니다. 표본이 확정 5건 미만이면 완료 여부를 유보하고 최대 다음 분기까지 관찰 기간을 연장합니다.

과제가 범주 기준, 가중치, 제출 마감 또는 판단 보정 규칙 변경을 요구하면 FCT-02 개정 요청으로 이관합니다. 기존 규칙과 다른 임시 운영은 SALES 부장 승인, 적용 종료일, 영향 대상을 기록한 경우에만 허용합니다.

완료 과제는 다음 분기 회고에서 재발 여부를 한 번 더 확인합니다. 동일 원인 코드가 2개 분기 안에 재발하면 기존 과제를 재개하지 않고 후속 과제로 등록하여 최초 조치의 실패 원인을 연결합니다.

## 보고 양식과 수신 범위
<!--meta: sec=s16; dept=SALES; level=주니어|시니어; ct_band=중; related=s15|s17-->
보고서는 의사결정에 필요한 정확도, 편향 방향, 주요 변동, 요청 조치만 담습니다. 주간 보고는 Commit 관리와 즉시 수정에 집중하고, 분기 보고는 범주별 추세와 구조적 원인 및 개선 효과를 다룹니다.

고객사는 `업종+익명 식별자`로 표기합니다. 예시는 `제조업 고객사-03`이며 고객 실명, 담당자 실명, 계약서 원본, 제안서 원문은 정확도 보고서에 포함하지 않습니다.

**주간 1쪽 보고 구성**

| 블록 | 필수 내용 | 표시 기준 |

| 핵심 지표 | Commit WMAPE, Bias, 실제 달성률 | 전주 대비 증감 %p 병기 |

주간 보고 파일은 수정 권한을 SALES 운영 담당과 DATA 검증 담당에게만 부여합니다. 수신자는 열람 권한을 원칙으로 하며, 재배포가 필요한 경우 SALES 부장 승인을 받습니다.

## 측정 체계 자체의 재검토 주기
<!--meta: sec=s17; dept=SALES|DATA; level=시니어; ct_band=하; related=s16|s18-->
측정 체계는 수치가 불리하게 보인다는 이유로 변경하지 않습니다. 재검토 대상은 산식, 측정 모집단, 목표·허용 범위, 편차 원인 코드, 데이터 출처이며, 변경안은 기존 기준과 최소 1개 측정 주기 동안 병행 검증합니다.

SALES는 업무 기준과 활용 적합성을, DATA는 산식·데이터 계보·재현성을 책임집니다. 파이프라인 단계 변경은 FCT-01, 포캐스트 범주·가중치 변경은 FCT-02, CRM 필드 변경은 FCT-05를 각각 참조합니다.

**정기 재검토 주기**

| 주기 | 검토 범위 | 완료 기한 | 주관·승인 | 필수 산출물 |
| --- | --- | --- | --- | --- |
| 월간 | 결측, 계산 실패, 표본 급감 등 측정 이상 신호 | 익월 5영업일 | SALES 담당·DATA 검증 | 이상 신호 목록 |
| 분기 | 목표·허용 범위 적합성, 원인 코드 사용 분포 | 분기 종료 후 10영업일 | SALES 과장 이상·DATA 과장 이상 | 분기 적합성 판정 |
| 반기 | MAPE·WMAPE·편향 산식, 모집단·제외 규칙 | 반기 종료 후 15영업일 | SALES·DATA 부장 | 백테스트 결과 |
| 연간 | 지표 세트와 구축·운영 계약별 측정 구조 전수 검토 | 연도 종료 후 20영업일 | SALES·DATA 부장 공동 승인 | 차년도 기준 버전 |
| 수시 | 아래 트리거 발생 항목과 연쇄 영향 | 발생 후 10영업일 | 해당 항목 소유 부서 | 변경 요청서 또는 유지 결정 |

**수시 재검토 트리거**

정기 일정 전이라도 구조적 변화가 확인되면 수시 검토를 개시합니다. 단일 대형 계약으로 일시적 수치 변동이 생긴 경우에는 체계를 즉시 바꾸지 않고, 해당 건을 제외한 민감도 분석을 함께 제출합니다.

| 트리거 | 개시 기준 | 우선 검토 항목 |
| --- | --- | --- |
| 단계 정의 변경 | 단계 추가·삭제·통합 또는 전환 기준 개정 확정 | 스냅샷 비교 가능성, 단계 기반 집계 |
| 사업 구성 변화 | 구축과 운영·유지보수의 예측 금액 비중이 직전 2개 분기 평균 대비 15%p 이상 변동 | 계약 유형별 모집단·목표 |
| 목표 수준 변경 | 승인 목표 금액이 기존 계획 대비 ±10% 이상 변경되거나 정확도 허용 범위가 5%p 이상 조정 | 목표·경보 임계값 |
| 원인 코드 효용 저하 | `기타` 또는 `미분류`가 분기 전체 편차 건수의 10% 이상 | 코드 분할·통합·정의 보완 |
| 지속적 측정 악화 | 동일 방향 편향이 3회 연속 발생하거나 WMAPE가 2회 연속 5%p 이상 악화 | 모집단, 스냅샷, 산식 |
| 데이터 구조 변경 | CRM 원천 필드·통화·금액 단위·실적 확정 방식 변경 | 데이터 매핑과 과거 연속성 |

**변경 판정과 적용 절차**

변경안은 최근 완료 4개 분기 또는 최소 12개 월간 스냅샷으로 백테스트합니다. 표본이 12개 미만이면 보유 전 기간을 사용하고, 표본 부족 사실을 승인 문서에 표시합니다.

1. SALES가 문제, 적용 대상, 기대 효과를 변경 요청서에 기록합니다.
2. DATA가 현행안과 변경안의 WMAPE·편향·결측률 차이를 재계산합니다.
3. 지점, 계약 유형, 포캐스트 범주별로 유리·불리한 영향이 집중되는지 확인합니다.
4. SALES·DATA 부장이 공동 승인하고 적용일·버전·과거 자료 처리 방식을 확정합니다.
5. 다음 측정 주기부터 적용하며 최초 1개 주기는 현행값과 변경값을 병기합니다.

승인된 변경은 과거 보고서를 소급 수정하지 않습니다. 시계열 연결이 불가능하면 적용일에 단절 표시를 남기고, 변경 전후 수치를 하나의 추세선으로 비교하지 않습니다.

## 용어 정리
<!--meta: sec=s18; dept=SALES; level=주니어; ct_band=하; related=s17-->
이 용어표는 FCT-04의 계산 결과와 보고 양식을 읽기 위한 색인입니다. 상세 산식, 목표 범위, 판정 절차는 각 본문 섹션을 기준으로 하며 용어표만으로 예외를 판단하지 않습니다.

금액은 별도 표시가 없으면 부가가치세 제외 계약 기준 금액으로 읽습니다. 포캐스트 범주의 상세 판정은 FCT-02를 적용하며, 회계 매출 인식 용어로 대체하지 않습니다.

| 용어 | 한 줄 정의 |
| --- | --- |
| 예측치 | 특정 스냅샷에서 해당 측정 기간 내 수주될 것으로 기록된 금액입니다. |
| 실적치 | 측정 기간 종료 시 실제 수주 확정되어 예측치와 비교하는 금액입니다. |
| 오차 | `예측치－실적치`이며 양수는 과대 예측, 음수는 과소 예측을 뜻합니다. |
| 절대오차 | 오차의 방향을 제거한 금액으로 `|예측치－실적치|`입니다. |
| 절대백분율오차 | 개별 건 또는 기간의 절대오차를 실적치로 나눈 비율입니다. |
| MAPE | 개별 절대백분율오차의 산술평균입니다. |
| WMAPE | 전체 절대오차 합계를 전체 실적치 합계로 나눈 금액 가중 오차율입니다. |
| 편향(Bias) | 오차의 부호를 유지해 과대·과소 예측 방향과 크기를 나타내는 값입니다. |
| 금액 가중 | 금액이 큰 관측값이 집계 결과에 더 큰 영향을 주도록 계산하는 방식입니다. |
| 스냅샷 | 지정 시점의 예측 금액·범주·종료예정일을 변경 불가능한 비교본으로 저장한 자료입니다. |
| 측정 기간 | 예측치와 실적치를 대조하는 월·분기 등 확정된 시간 구간입니다. |
| 기준시점 | 스냅샷을 추출하고 이후 입력 변경을 해당 회차 계산에서 배제하는 시각입니다. |
| 포캐스트 범주 | Commit·Best Case·Pipeline·Omitted·Closed를 구분하는 CRM 분류입니다. |
| Commit 정확도 | Commit 금액만 분리해 실적과 비교한 금액 가중 정확도입니다. |
| 원인 코드 | 예측 오차가 발생한 직접 원인을 일관된 항목으로 분류하는 식별값입니다. |
| 백테스트 | 변경할 기준을 과거 스냅샷에 적용해 기존 결과와 차이를 검증하는 절차입니다. |

**산식 기호 색인**

보고서와 계산 파일은 아래 기호를 사용합니다. 통화가 다른 건은 승인된 환산 기준으로 단위를 통일한 뒤 산식에 투입합니다.

| 기호 | 의미 | 사용 단위 |
| --- | --- | --- |
| `Fᵢ` | i번째 관측값의 예측치 | 원 |
| `Aᵢ` | i번째 관측값의 실적치 | 원 |
| `eᵢ` | i번째 오차인 `Fᵢ－Aᵢ` | 원 |
| `n` | 계산에 포함된 유효 관측값 수 | 건 또는 기간 수 |

실적치가 0인 관측값은 개별 백분율오차의 분모로 사용하지 않습니다. 해당 관측값의 포함·제외 상태를 표시하고, 집계 가능한 경우 WMAPE와 금액 오차를 함께 보고합니다.
