# 콜센터 AI 상담 구축 프로젝트 — 공개판
<!--meta: doc=PRJ-CC-PUB; doc_type=project; tier=2; topic=CC; disclosure=public; status=done-->

## 프로젝트 개요
<!--meta: sec=s1; dept=AIAX|BE; level=주니어|시니어; ct_band=하-->
제조업 고객사의 고객센터 상담 업무를 보조하는 AI 상담 시스템을 구축했습니다. 상담사가 전화를 받는 동안 AI가 실시간으로 관련 매뉴얼·과거 상담 이력을 검색해 화면에 보여주고, 반복 문의는 챗봇이 1차로 응대합니다.

본 프로젝트는 상담사를 AI로 대체하는 자동화가 아니라, 상담 과정에서 필요한 정보를 더 빠르고 일관되게 찾도록 지원하는 업무 보조 체계 구축에 초점을 두었습니다. 상담사는 AI가 제안한 답변과 근거 문서를 확인한 뒤 실제 안내 여부를 판단하며, 복잡하거나 예외적인 문의는 기존 상담 절차에 따라 담당 조직으로 이관합니다.

프로젝트 수행 범위에는 상담 지식 정리, 검색·생성 기능 구현, 상담사 화면 연동, 챗봇 응대 흐름 구성, 상담 이력 저장, 관리 대시보드 제공, 사용자 검증 및 운영 전환이 포함되었습니다. 고객사명, 계약 규모, 세부 일정, 모델별 설정값 및 정량 성과는 공개 범위에서 제외합니다.

## 추진 배경
<!--meta: sec=s2; dept=CONSULT|AIAX; level=주니어|시니어; ct_band=하-->
제조업 고객센터에는 제품 사용법, 소모품 교체, 보증 기준, 점검 절차, 서비스 접수와 같이 반복적으로 발생하는 문의가 많습니다. 그러나 실제 응대 과정에서는 제품군과 모델별 조건이 다르고, 매뉴얼·FAQ·업무 공지가 여러 위치에 분산되어 있어 상담사가 적절한 근거를 빠르게 찾기 어려울 수 있습니다.

특히 신입 상담사는 문서 위치와 업무 용어를 익히는 데 시간이 필요하며, 숙련 상담사도 개정된 정책이나 드물게 발생하는 예외 문의를 즉시 기억하기 어렵습니다. 동일한 질문에 표현이 다른 답변이 제공되면 상담 품질의 일관성도 낮아질 수 있습니다.

이에 따라 다음 문제를 개선 대상으로 정의했습니다.

- 상담 중 필요한 지식 탐색에 시간이 소요되는 문제
- 문서별 표현과 개정 시점이 달라 답변 기준이 흔들리는 문제
- 반복 문의가 상담 인력에게 지속적으로 집중되는 문제
- 신입 상담사의 초기 업무 적응 부담이 큰 문제
- 상담 결과를 사후에 분류하고 품질을 확인하기 어려운 문제
- 상담 지식이 개인 경험에 의존하고 조직 자산으로 축적되지 않는 문제

## 프로젝트 목표
<!--meta: sec=s3; dept=CONSULT|AIAX|BE|DATA; level=주니어|시니어; ct_band=중-->
프로젝트 목표는 네 가지 축으로 구성했습니다.

1. **탐색 지원**  
   상담 내용과 연관된 매뉴얼, FAQ 및 과거 상담 이력을 찾아 상담사 화면에 제시합니다.

2. **답변 지원**  
   검색된 근거를 바탕으로 상담사가 검토할 수 있는 답변 초안을 생성합니다.

3. **반복 문의 자동화**  
   정형화된 문의는 챗봇이 1차로 응대하고, 해결되지 않는 문의는 상담사에게 연결합니다.

4. **운영 가시성 확보**  
   상담 유형, 응대 흐름, 검색 활용 및 품질 관련 지표를 관리 대시보드에서 확인할 수 있도록 합니다.

목표 간 우선순위는 정확성과 안전성, 상담사 사용성, 응답 속도, 자동화 범위 순으로 설정했습니다. 자동화 비율을 높이기 위해 검증되지 않은 답변을 확대하기보다 근거가 불충분한 경우 상담사 확인 또는 별도 절차로 전환하는 방식을 채택했습니다.

## 적용 범위와 비적용 범위
<!--meta: sec=s4; dept=CONSULT|AIAX|BE; level=주니어|시니어; ct_band=중-->
프로젝트의 주요 적용 범위는 다음과 같습니다.

| 구분 | 적용 내용 |
| --- | --- |
| 상담사 지원 | 문의와 관련된 문서 검색, 답변 초안, 근거 표시 |
| 챗봇 응대 | 반복적이고 표준화된 문의의 1차 응대 |
| 지식 활용 | 상담 매뉴얼, FAQ, 과거 상담 이력의 검색 활용 |
| 업무 연동 | 상담사 화면 연동 및 통화 이력 저장 |
| 운영 관리 | 상담 품질과 응대 시간 관련 지표 확인 |
| 사용자 검증 | 실제 업무 시나리오에 기반한 결과 확인 |

공개판에서 설명하지 않는 범위는 다음과 같습니다.

- 고객사의 구체적인 제품명과 제품별 상담 정책
- 고객사 내부 시스템명과 상세 연동 방식
- 계약 조건, 투입 인원, 예산 및 세부 수행 일정
- 모델 공급자, 모델 버전 및 세부 프롬프트
- 검색 가중치, 평가 기준값 및 운영 임계값
- 개인정보 처리 필드와 내부 보안 설정
- 고객사별 정량 성과와 운영 원가

본 문서는 프로젝트의 목적과 일반적인 구성, 수행 원칙을 설명하기 위한 공개 자료이며, 상세 설계서나 운영 매뉴얼을 대체하지 않습니다.

## 주요 사용자
<!--meta: sec=s5; dept=CONSULT|AIAX|BE|DATA; level=주니어; ct_band=하-->
시스템의 주요 사용자는 상담사, 상담 관리자, 지식 관리자 및 운영 담당자입니다.

| 사용자 | 주요 사용 목적 |
| --- | --- |
| 상담사 | 상담 중 관련 자료 확인, 답변 초안 검토, 상담 결과 기록 |
| 신입 상담사 | 업무 용어 학습, 표준 응대 방식 확인, 근거 문서 탐색 |
| 상담 관리자 | 상담 품질과 응대 흐름 확인, 개선 대상 파악 |
| 지식 관리자 | 매뉴얼·FAQ 등록, 개정 자료 반영, 오래된 자료 정리 |
| 시스템 운영 담당자 | 연동 상태, 처리 흐름 및 서비스 상태 확인 |
| 데이터 분석 담당자 | 상담 유형과 운영 지표를 분석하여 개선 과제 도출 |

사용자별 화면과 권한은 업무 목적에 맞게 구분하는 것을 원칙으로 했습니다. 상담사는 개별 상담 수행에 필요한 기능을 중심으로 사용하고, 관리자는 집계 결과와 품질 추이를 확인하며, 지식 관리자는 검색 대상 자료의 상태를 관리합니다.

## 대표 상담 시나리오
<!--meta: sec=s6; dept=CONSULT|AIAX|BE; level=주니어; ct_band=하-->
대표적인 상담사 지원 흐름은 다음과 같습니다.

1. 고객 문의가 상담사에게 전달됩니다.
2. 상담 내용에서 제품, 증상, 요청 유형 등 핵심 맥락을 파악합니다.
3. 시스템이 관련 매뉴얼·FAQ·과거 상담 이력을 검색합니다.
4. 검색된 자료의 핵심 내용과 출처가 상담사 화면에 표시됩니다.
5. LLM 응답 생성기가 검색 결과를 바탕으로 답변 초안을 작성합니다.
6. 상담사는 근거와 초안을 검토하고 필요한 내용을 수정합니다.
7. 상담사가 고객에게 최종 안내합니다.
8. 상담 결과와 필요한 이력이 저장됩니다.
9. 후속 조치가 필요한 문의는 기존 업무 절차에 따라 이관됩니다.

챗봇의 경우 반복 문의를 먼저 분류하고, 사전에 정의된 범위 안에서 답변합니다. 질문이 모호하거나 여러 조건의 판단이 필요한 경우 추가 질문을 제시하거나 상담사 연결을 안내합니다.

## 시스템 구성
<!--meta: sec=s7; dept=AIAX|BE; level=주니어|시니어; ct_band=중-->
| 구성요소 | 역할 | 담당팀 |
| --- | --- | --- |
| RAG 검색 모듈 | 상담 매뉴얼·FAQ·과거 이력에서 관련 내용 검색 | AI/AX개발팀 |
| LLM 응답 생성기 | 검색 결과 기반 상담사 보조 답변·챗봇 응답 생성 | AI/AX개발팀 |
| 상담 API 서버 | 상담사 화면 연동, 통화 이력 저장 | 백엔드팀 |
| 관리 대시보드 | 상담 품질·응대 시간 지표 확인 | 데이터분석팀 |

각 구성요소는 단일 기능만 수행하는 것이 아니라 상담 업무 흐름 안에서 상호 연결됩니다. RAG 검색 모듈은 질문과 관련된 근거를 찾고, LLM 응답 생성기는 해당 근거를 읽기 쉬운 답변 초안으로 구성합니다. 상담 API 서버는 사용자 화면과 AI 기능 사이의 요청·응답 흐름을 연결하며, 상담 결과를 저장할 수 있도록 지원합니다.

관리 대시보드는 개별 답변을 대신 판단하는 도구가 아니라 전체 상담 운영 상태를 확인하는 수단입니다. 관리자는 상담 유형의 변화, 응대 흐름, 지식 활용 상태 및 검토가 필요한 항목을 확인할 수 있습니다.

## 논리 아키텍처
<!--meta: sec=s8; dept=AIAX|BE; level=시니어; ct_band=상-->
시스템은 사용자 채널, 업무 연계 계층, AI 처리 계층, 지식 계층 및 분석 계층으로 구분할 수 있습니다.

| 계층 | 주요 책임 |
| --- | --- |
| 사용자 채널 | 상담사 화면과 챗봇에서 질문 입력 및 결과 표시 |
| 업무 연계 계층 | 요청 인증, 상담 흐름 연결, 이력 저장, 오류 응답 처리 |
| AI 처리 계층 | 질문 해석, 지식 검색, 근거 조합, 답변 초안 생성 |
| 지식 계층 | 매뉴얼·FAQ·과거 상담 이력의 저장과 검색 활용 |
| 분석 계층 | 상담 및 시스템 사용 결과 집계, 품질 추이 시각화 |

상담 요청은 업무 연계 계층을 통해 AI 처리 계층으로 전달됩니다. AI 처리 계층은 사용 가능한 지식 범위에서 관련 자료를 찾고 답변 초안을 생성한 뒤, 출처 정보와 함께 결과를 반환합니다. 응답 생성에 필요한 근거가 충분하지 않으면 확정적 안내를 피하고 상담사의 추가 확인을 유도합니다.

논리적 계층을 구분한 이유는 AI 모델 변경, 지식 개정, 상담 화면 개선 및 분석 요구사항 추가가 서로에게 미치는 영향을 줄이기 위해서입니다. 공개판에서는 개별 인프라 구성, 네트워크 경로 및 배포 단위를 다루지 않습니다.

## 상담 지식의 유형
<!--meta: sec=s9; dept=AIAX|DATA|CONSULT; level=주니어|시니어; ct_band=중-->
검색 대상 지식은 내용의 성격과 활용 목적에 따라 구분했습니다.

| 지식 유형 | 주요 내용 | 활용 방식 |
| --- | --- | --- |
| 상담 매뉴얼 | 표준 안내 절차, 확인 항목, 처리 순서 | 공식 절차의 근거 |
| FAQ | 빈도가 높은 질문과 표준 답변 | 반복 문의의 빠른 응대 |
| 과거 상담 이력 | 유사 문의와 실제 처리 맥락 | 사례 탐색과 표현 보조 |
| 업무 공지성 자료 | 변경된 안내 사항과 적용 시점 | 최신 기준 보완 |
| 용어·분류 정보 | 제품군, 증상 및 상담 유형 표현 | 질문 해석과 검색 보조 |

모든 자료를 같은 수준의 공식 근거로 취급하지는 않습니다. 표준 매뉴얼과 승인된 FAQ는 우선적인 안내 근거로 활용하고, 과거 상담 이력은 유사 사례를 찾는 참고 자료로 사용합니다. 과거 이력에 포함된 답변이 현재도 유효하다고 자동으로 가정하지 않도록 지식 유형을 구분했습니다.

## 지식 정비 원칙
<!--meta: sec=s10; dept=CONSULT|AIAX|DATA; level=시니어; ct_band=상-->
AI 기능 구현에 앞서 검색 대상 문서의 구조와 품질을 정리했습니다. 문서가 중복되거나 개정 상태가 불명확하면 검색 결과가 기술적으로 정상이어도 잘못된 기준이 노출될 수 있기 때문입니다.

지식 정비 시 다음 원칙을 적용했습니다.

- 동일 주제의 중복 자료는 대표 자료와 참고 자료로 구분합니다.
- 문서 제목만으로 내용을 판단하지 않고 실제 적용 범위를 확인합니다.
- 개정 전후 자료가 함께 존재하면 최신성 판단에 필요한 정보를 관리합니다.
- 표, 주의 문구, 예외 조건이 본문과 분리되지 않도록 점검합니다.
- 짧은 FAQ와 긴 매뉴얼은 서로 다른 탐색 목적을 고려합니다.
- 과거 상담 이력은 공식 정책 문서와 구별해 활용합니다.
- 검색에 부적합한 첨부 파일이나 불완전한 자료는 별도 검토 대상으로 둡니다.
- 민감한 정보는 업무 목적과 접근 권한에 맞게 처리합니다.

지식 정비는 일회성 전처리 작업이 아니라 운영 활동으로 정의했습니다. 제품과 정책이 변경되면 상담 지식도 함께 변경되므로, 자료 등록·검토·개정·폐기의 책임을 명확히 하는 것이 중요합니다.

## RAG 검색 동작 개념
<!--meta: sec=s11; dept=AIAX; level=주니어|시니어; ct_band=중-->
RAG는 질문에 대해 모델이 기억만으로 답하도록 하는 대신, 외부 지식에서 관련 근거를 검색한 후 해당 자료를 바탕으로 답변을 생성하는 방식입니다.

본 프로젝트에서의 개념적 흐름은 다음과 같습니다.

1. 상담 질문에서 검색에 필요한 핵심 표현을 파악합니다.
2. 매뉴얼·FAQ·과거 상담 이력에서 관련 후보를 찾습니다.
3. 질문 맥락과 후보 자료의 관련성을 비교합니다.
4. 답변 생성에 사용할 근거를 선별합니다.
5. 선별된 근거와 질문을 응답 생성 단계에 전달합니다.
6. 상담사 화면에 답변 초안과 근거 출처를 함께 제공합니다.

검색 결과가 많다고 해서 항상 품질이 좋아지는 것은 아닙니다. 관련성이 낮은 자료가 함께 제공되면 답변이 불필요하게 길어지거나 서로 다른 조건이 섞일 수 있습니다. 따라서 검색 결과의 수보다 질문에 맞는 근거를 선별하는 과정이 중요합니다.

세부 검색 알고리즘, 함수 구성 및 구현 코드는 별도의 단위코드 문서에서 관리하며, 본 공개판에서는 업무 관점의 동작만 설명합니다.

## 답변 생성 원칙
<!--meta: sec=s12; dept=AIAX|CONSULT; level=주니어|시니어; ct_band=중-->
답변 생성기는 상담사가 참고할 수 있는 초안을 제공하며, 상담 결과의 최종 책임 주체로 동작하지 않습니다. 생성 결과는 다음 원칙을 따르도록 설계했습니다.

- 검색된 자료의 범위 안에서 답변을 구성합니다.
- 확인되지 않은 조건을 임의로 단정하지 않습니다.
- 고객에게 안내하기 적합한 문장 구조를 사용합니다.
- 단계가 있는 절차는 순서를 구분해 표현합니다.
- 주의사항과 예외 조건은 일반 설명과 분리합니다.
- 근거가 부족하면 추가 확인이 필요하다는 점을 표시합니다.
- 상담사가 출처를 확인할 수 있도록 관련 자료를 함께 제시합니다.
- 내부 참고 표현과 고객 안내 표현을 구분합니다.

답변이 자연스럽게 보이는 것과 사실이 정확한 것은 서로 다른 평가 항목입니다. 문장 완성도가 높더라도 근거가 맞지 않으면 사용할 수 없으므로, 정확성과 근거 일치 여부를 우선적으로 검토했습니다.

## 상담사 화면 설계 원칙
<!--meta: sec=s13; dept=CONSULT|AIAX|BE; level=주니어|시니어; ct_band=중-->
상담사 화면은 통화 중 사용되는 도구이므로 많은 정보를 한 번에 보여주기보다 판단에 필요한 내용을 빠르게 확인할 수 있어야 합니다.

주요 화면 설계 원칙은 다음과 같습니다.

- 답변 초안과 근거 문서를 시각적으로 구분합니다.
- 중요한 절차와 주의사항을 먼저 찾을 수 있도록 구성합니다.
- 관련 문서의 제목과 출처를 확인할 수 있게 합니다.
- 긴 자료는 핵심 부분을 먼저 보여주되 원문 확인 경로를 제공합니다.
- AI 결과를 그대로 확정하는 것처럼 보이는 표현을 피합니다.
- 결과가 없거나 불충분한 경우 상태를 명확히 안내합니다.
- 상담사가 기존 업무 흐름을 크게 이탈하지 않도록 연동합니다.
- 반복 클릭과 불필요한 화면 이동을 줄입니다.

상담사 피드백은 단순 만족도 조사에만 의존하지 않고, 실제 통화 흐름에서 어느 시점에 결과를 확인하는지, 어떤 정보가 판단에 도움이 되는지, 어떤 표현이 혼란을 주는지를 중심으로 수집했습니다.

## 챗봇 1차 응대 원칙
<!--meta: sec=s14; dept=AIAX|BE|CONSULT; level=시니어; ct_band=상-->
챗봇은 모든 문의를 해결하는 범용 상담 채널이 아니라 반복적이고 표준화된 문의를 우선 처리하는 1차 응대 수단으로 정의했습니다.

챗봇이 처리하기 적합한 문의는 다음 특성을 가집니다.

- 질문 의도가 비교적 명확합니다.
- 답변 기준이 공식 자료에 정리되어 있습니다.
- 고객별 복잡한 판단이 필요하지 않습니다.
- 후속 절차가 표준화되어 있습니다.
- 잘못 안내했을 때의 영향과 대응 절차를 사전에 검토할 수 있습니다.

반대로 여러 제품 조건이 동시에 관련되거나, 개별 계약·보증 판단이 필요하거나, 안전상 주의가 필요한 문의는 상담사 확인 대상으로 전환할 수 있도록 구성했습니다. 챗봇이 답변을 반복해서 생성하기보다 해결되지 않은 상태를 인지하고 사람에게 연결하는 것이 중요합니다.

상담사 전환 시에는 고객이 이미 제공한 질문 맥락을 가능한 범위에서 전달하여 같은 내용을 처음부터 반복하지 않도록 하는 것을 사용자 경험 원칙으로 삼았습니다.

## 상담 API와 업무 연동
<!--meta: sec=s15; dept=BE|AIAX; level=주니어|시니어; ct_band=상-->
상담 API 서버는 상담사 화면, AI 처리 기능 및 상담 이력 저장 기능을 연결합니다. 주요 책임은 다음과 같습니다.

- 상담 요청을 정해진 형식으로 접수
- 사용자와 상담 맥락에 필요한 정보 전달
- AI 검색·생성 요청의 처리 상태 관리
- 결과를 상담사 화면에서 사용할 수 있는 형태로 반환
- 상담 결과와 통화 이력 저장 지원
- 오류 발생 시 사용자에게 적절한 상태 전달
- 요청 추적에 필요한 운영 정보 기록
- 권한이 없는 요청의 접근 제한

AI 처리에는 일반적인 화면 조회보다 시간이 더 걸릴 수 있으므로, 요청이 진행 중인지 실패했는지 구분할 수 있어야 합니다. 동일 요청이 반복될 때 상담 이력이 중복 저장되지 않도록 업무 처리의 일관성도 고려했습니다.

공개판에서는 API 경로, 인증 토큰 구조, 데이터베이스 스키마 및 내부 오류 코드를 공개하지 않습니다.

## 근거 표시와 설명 가능성
<!--meta: sec=s16; dept=AIAX|CONSULT; level=주니어|시니어; ct_band=중-->
상담 지원 시스템에서 출처 표시는 단순한 부가 기능이 아니라 상담사가 답변을 신뢰하고 검토하기 위한 핵심 요소입니다.

근거 표시에는 다음 정보가 활용될 수 있습니다.

- 참조한 문서의 제목
- 관련된 문서 구간
- 자료의 유형
- 개정 여부를 판단하는 데 필요한 정보
- 질문과 관련된 핵심 문장
- 원문을 추가로 확인할 수 있는 경로

출처가 표시되더라도 해당 문서가 현재 업무에 적용 가능한지는 별도 판단이 필요할 수 있습니다. 따라서 시스템은 근거 접근성을 높이고, 상담사는 예외 조건과 실제 고객 상황을 검토하는 역할을 수행합니다.

설명 가능성은 모델의 내부 계산을 모두 공개하는 의미가 아니라, 업무 사용자가 “이 답변이 어떤 자료를 참고했는가”를 확인할 수 있도록 하는 데 중점을 두었습니다.

## 품질 검증 체계
<!--meta: sec=s17; dept=AIAX|DATA|CONSULT; level=시니어; ct_band=상-->
품질 검증은 검색 품질, 답변 품질, 사용자 경험 및 업무 적합성으로 나누어 수행했습니다.

| 검증 영역 | 주요 확인 항목 |
| --- | --- |
| 검색 품질 | 질문과 관련된 자료가 상위 결과에 포함되는지 |
| 근거 적합성 | 사용된 자료가 실제 답변 기준으로 적절한지 |
| 답변 정확성 | 답변이 근거 내용과 일치하는지 |
| 완전성 | 필수 절차와 주의사항이 누락되지 않았는지 |
| 표현 품질 | 상담사가 이해하고 수정하기 쉬운 문장인지 |
| 안전성 | 근거가 부족할 때 과도하게 단정하지 않는지 |
| 사용성 | 통화 흐름을 방해하지 않고 결과를 확인할 수 있는지 |
| 연동 안정성 | 요청과 결과, 이력 저장이 정상적으로 연결되는지 |

평가 질문은 반복 문의만으로 구성하지 않고, 표현이 다른 질문, 정보가 일부 누락된 질문, 유사 제품이 혼동될 수 있는 질문, 여러 조건이 결합된 질문 등을 포함했습니다.

자동 평가 결과만으로 운영 가능 여부를 결정하지 않고, 상담 업무를 이해하는 검토자의 판단을 함께 반영했습니다. 생성형 AI의 출력은 표현이 달라질 수 있으므로 단순 문자열 일치보다 의미와 근거의 일치 여부를 중요하게 보았습니다.

## 예외 상황 처리
<!--meta: sec=s18; dept=AIAX|BE|CONSULT; level=시니어; ct_band=상-->
정상적인 검색·생성 흐름 외에도 다음 예외 상황을 고려했습니다.

| 예외 상황 | 처리 원칙 |
| --- | --- |
| 관련 문서를 찾지 못함 | 답변을 추측하지 않고 추가 확인 안내 |
| 서로 다른 기준의 문서가 검색됨 | 최신성·적용 범위를 확인하도록 표시 |
| 질문이 지나치게 짧거나 모호함 | 필요한 정보를 추가로 질문 |
| 생성 처리 시간이 길어짐 | 진행 상태를 안내하고 재시도 가능 여부 제공 |
| AI 기능을 일시적으로 사용할 수 없음 | 기존 상담 절차를 계속 사용할 수 있도록 전환 |
| 상담 이력 저장에 문제가 발생함 | 사용자에게 상태를 알리고 운영 확인 대상으로 기록 |
| 챗봇 범위를 벗어난 문의가 입력됨 | 상담사 연결 또는 별도 접수 절차 안내 |
| 민감한 정보가 불필요하게 입력됨 | 노출과 재사용을 최소화하는 처리 원칙 적용 |

예외 처리는 오류 문구를 보여주는 데 그치지 않고 상담 업무를 계속 수행할 수 있게 하는 것을 목표로 했습니다. AI 기능이 실패하더라도 고객 상담 전체가 중단되지 않도록 기존 절차와의 공존을 고려했습니다.

## 데이터 보호와 접근 통제 원칙
<!--meta: sec=s19; dept=BE|AIAX|DATA; level=시니어; ct_band=상-->
상담 데이터에는 고객 문의 내용과 업무상 민감할 수 있는 정보가 포함될 수 있으므로, 필요한 범위에서만 수집·처리·조회하는 원칙을 적용했습니다.

공개 가능한 수준의 보호 원칙은 다음과 같습니다.

- 사용자 역할에 따라 접근 가능한 기능과 데이터를 구분합니다.
- 상담 목적에 불필요한 정보가 AI 처리에 전달되지 않도록 검토합니다.
- 저장되는 상담 이력과 운영 로그의 목적을 구분합니다.
- 자료 반출과 외부 공유는 승인된 절차를 따릅니다.
- 지식 자료의 공개 범위와 사용자 권한을 함께 고려합니다.
- 테스트 데이터는 실제 운영 데이터와 구분해 관리합니다.
- 운영 확인을 위한 기록에도 불필요한 원문을 남기지 않도록 합니다.
- 보존 목적이 끝난 데이터는 고객사 정책과 관련 절차에 따라 처리합니다.

구체적인 보안 구성과 개인정보 처리 항목은 공개판에서 다루지 않으며, 실제 운영에서는 고객사의 보안·개인정보보호 기준을 우선 적용합니다.

## 운영 대시보드
<!--meta: sec=s20; dept=DATA|BE|AIAX; level=주니어|시니어; ct_band=중-->
관리 대시보드는 상담 운영과 AI 기능 활용 상태를 한눈에 확인하기 위한 도구입니다.

대표적인 확인 영역은 다음과 같습니다.

- 기간별 상담 흐름
- 문의 유형별 분포
- 반복 문의의 변화
- 상담 응대 시간 관련 추이
- AI 검색 및 답변 지원 기능의 활용 상태
- 상담사 전환이 발생한 문의 유형
- 지식 검색 결과가 부족했던 질문
- 품질 검토가 필요한 상담 사례
- 개정 또는 보완이 필요한 지식 후보

대시보드 지표는 개인 평가만을 목적으로 해석하지 않으며, 상담 프로세스와 지식 품질을 함께 개선하는 데 활용하는 것을 원칙으로 했습니다. 예를 들어 특정 유형에서 상담 시간이 길어졌다면 상담사 개인의 문제로 단정하기보다 문서가 복잡한지, 검색 결과가 충분한지, 업무 절차에 예외가 많은지 함께 확인해야 합니다.

## 운영 지표 정의 원칙
<!--meta: sec=s21; dept=DATA|CONSULT|AIAX; level=시니어; ct_band=상-->
운영 지표는 단순 사용량과 실제 업무 효과를 구분해 정의했습니다.

| 지표 영역 | 해석 목적 |
| --- | --- |
| 이용 지표 | 기능이 실제 상담 과정에서 사용되는지 확인 |
| 검색 지표 | 필요한 지식이 탐색 가능한 상태인지 확인 |
| 품질 지표 | 답변과 근거가 업무 기준에 맞는지 확인 |
| 시간 지표 | 상담 과정에서 탐색·응대 부담이 변화했는지 확인 |
| 전환 지표 | 챗봇에서 상담사로 연결되는 주요 원인 파악 |
| 지식 지표 | 신규 작성, 개정 또는 폐기가 필요한 자료 파악 |
| 안정성 지표 | 요청 실패와 처리 지연의 추세 확인 |

지표는 맥락 없이 단독으로 해석하지 않습니다. 챗봇의 상담사 전환 비율이 높아졌더라도 복잡한 문의가 증가한 결과일 수 있고, AI 기능 이용률이 낮더라도 특정 상담 유형에는 기존 화면이 더 효율적일 수 있습니다.

세부 수치와 고객사별 목표 기준은 내부 상세판에서만 관리합니다.

## 부서별 수행 역할
<!--meta: sec=s22; dept=CONSULT|AIAX|BE|DATA; level=주니어|시니어; ct_band=중-->
헤드헌터랩의 컨설팅팀, AI/AX개발팀, 백엔드팀 및 데이터분석팀이 프로젝트 단계별로 협업했습니다.

| 부서 | 주요 역할 |
| --- | --- |
| 컨설팅팀 | 현행 상담 흐름 파악, 요구사항 정리, 적용 범위와 검증 기준 조율 |
| AI/AX개발팀 | 지식 검색, 답변 생성, 챗봇 흐름 및 AI 품질 개선 |
| 백엔드팀 | 상담 화면 연동, API 처리, 이력 저장 및 운영 연계 |
| 데이터분석팀 | 지표 정의, 관리 대시보드 구성, 운영 데이터 분석 |
| 영업팀 | 고객 커뮤니케이션 지원과 사업 범위 협의 지원 |

서울·경기·인천 3개 지점의 인력은 소속 지점과 관계없이 프로젝트 요구에 따라 컨설팅과 개발 업무에 참여할 수 있습니다. 실무 담당자는 산출물만 전달하는 방식보다 요구사항, 데이터, AI 품질, 업무 연동 및 운영 전환을 함께 검토하는 방식으로 협업했습니다.

## 단계별 수행 절차
<!--meta: sec=s23; dept=CONSULT|AIAX|BE|DATA; level=주니어|시니어; ct_band=중-->
프로젝트는 일반적으로 다음 단계로 진행했습니다.

1. **현행 업무 파악**  
   상담 유형, 사용 자료, 사용자 역할 및 기존 화면 흐름을 확인합니다.

2. **적용 범위 정의**  
   AI가 지원할 업무와 기존 절차로 유지할 업무를 구분합니다.

3. **지식 자료 정비**  
   매뉴얼·FAQ·과거 상담 이력의 구조와 활용 가능성을 점검합니다.

4. **기능 설계**  
   검색, 답변 생성, 챗봇, API 및 대시보드 요구사항을 구체화합니다.

5. **구현 및 연동**  
   구성요소별 기능을 개발하고 상담 업무 흐름에 연결합니다.

6. **시나리오 검증**  
   정상 질문, 모호한 질문, 예외 문의 및 실패 상황을 검증합니다.

7. **사용자 확인**  
   상담사가 실제 업무 관점에서 결과와 화면 흐름을 확인합니다.

8. **운영 전환**  
   사용 범위, 문의 절차, 지식 관리 및 품질 확인 방법을 정리합니다.

9. **개선 반복**  
   운영 결과를 바탕으로 지식과 기능의 개선 대상을 도출합니다.

각 단계는 완전히 분리되지 않습니다. 지식 자료를 검토하면서 요구사항이 변경될 수 있고, 사용자 확인 과정에서 화면 구성이나 답변 형식을 다시 조정할 수 있습니다.

## 테스트 시나리오 구성
<!--meta: sec=s24; dept=AIAX|BE|DATA|CONSULT; level=주니어|시니어; ct_band=상-->
테스트는 기능의 정상 작동뿐 아니라 실제 상담 환경에서 발생할 수 있는 표현 차이와 예외 조건을 포함하도록 구성했습니다.

대표 테스트 유형은 다음과 같습니다.

- 공식 FAQ와 거의 동일한 표현의 질문
- 일상적인 표현이나 축약어가 포함된 질문
- 제품명이나 증상 정보가 일부 누락된 질문
- 서로 유사한 제품군이 혼동될 수 있는 질문
- 여러 증상이 한 문장에 포함된 질문
- 절차의 순서와 주의사항이 중요한 질문
- 현재 자료만으로 답할 수 없는 질문
- 오래된 상담 이력과 최신 매뉴얼이 함께 검색될 수 있는 질문
- 챗봇 처리 범위를 벗어나는 문의
- AI 처리 지연 또는 연동 실패가 발생한 상황
- 상담사가 답변을 수정한 뒤 이력을 저장하는 상황
- 권한이 다른 사용자가 관리 기능에 접근하는 상황

테스트 결과는 성공과 실패만 기록하지 않고, 실패 원인을 지식 부족, 검색 부정확, 답변 구성 문제, 화면 사용성, 업무 규칙 미정의 또는 연동 문제로 분류해 개선 담당을 구분했습니다.

## 운영 전환과 사용자 정착
<!--meta: sec=s25; dept=CONSULT|AIAX|BE|DATA; level=주니어|시니어; ct_band=중-->
시스템 구축 완료만으로 현장 정착이 보장되지는 않습니다. 상담사가 결과를 언제 참고하고, 어떤 경우에 추가 확인하며, 오류를 어디에 전달해야 하는지 이해할 수 있도록 운영 전환 절차를 마련했습니다.

사용자 정착을 위해 다음 내용을 안내했습니다.

- AI 답변은 검토 가능한 초안이라는 점
- 답변 근거와 원문을 확인하는 방법
- 결과가 불충분할 때 기존 절차로 전환하는 방법
- 챗봇에서 상담사 연결이 필요한 기준
- 잘못된 검색 결과나 오래된 문서를 신고하는 방법
- 상담 지식의 개정 요청 절차
- 시스템 오류와 답변 품질 문제를 구분해 전달하는 방법
- 관리 대시보드의 지표를 해석하는 기본 원칙

교육은 기능 설명보다 실제 상담 시나리오를 중심으로 구성했습니다. 사용자가 AI의 장점뿐 아니라 한계와 확인 책임도 함께 이해하도록 하는 것이 운영 안정성에 중요합니다.

## 운영상 한계
<!--meta: sec=s26; dept=CONSULT|AIAX|BE; level=주니어|시니어; ct_band=중-->
본 시스템은 상담 업무를 지원하지만 다음과 같은 한계가 있습니다.

- 원본 지식이 오래되었으면 검색 결과도 오래된 기준을 포함할 수 있습니다.
- 질문에 필요한 정보가 부족하면 정확한 답변을 만들기 어렵습니다.
- 유사한 제품이나 정책이 많으면 추가 조건 확인이 필요할 수 있습니다.
- 과거 상담 이력은 현재의 공식 기준과 다를 수 있습니다.
- 자연스러운 문장이라고 해서 항상 정확한 답변은 아닙니다.
- AI 기능의 응답 속도는 일반적인 정적 화면과 다를 수 있습니다.
- 챗봇이 모든 예외 문의를 자동으로 해결할 수는 없습니다.
- 상담사가 현장 맥락과 고객 상황을 최종적으로 판단해야 합니다.

따라서 AI 품질 개선은 모델 조정만으로 해결되지 않으며, 지식 관리, 업무 규칙 정리, 사용자 화면, 연동 안정성 및 상담사 교육을 함께 다뤄야 합니다.

## 도입 효과
<!--meta: sec=s27; dept=AIAX|BE|DATA; level=주니어|시니어; ct_band=중-->
반복 문의 응대 시간이 줄고, 신입 상담사의 평균 응대 정확도가 향상되었습니다. 세부 수치와 고객사 정보는 내부 상세판에서만 다룹니다.

추가로 확인된 정성적 효과는 다음과 같습니다.

- 상담 중 여러 자료를 개별적으로 찾는 부담이 완화되었습니다.
- 답변과 함께 근거를 확인할 수 있어 검토 과정이 명확해졌습니다.
- 자주 발생하는 문의를 체계적으로 파악할 수 있게 되었습니다.
- 상담사별로 다르게 사용되던 표현을 표준화할 기반이 마련되었습니다.
- 검색 결과가 부족한 질문을 통해 지식 공백을 발견할 수 있게 되었습니다.
- 신입 상담사의 교육 과정에서 실제 상담 자료를 탐색하기 쉬워졌습니다.
- 관리자가 상담 품질과 운영 흐름을 함께 확인할 수 있게 되었습니다.
- AI 기능을 일회성 시범이 아닌 지속적인 지식 개선 체계로 운영할 기반을 마련했습니다.

효과 측정 시에는 단순히 챗봇 처리량이나 AI 호출량만 보지 않고, 상담 품질과 업무 지속 가능성을 함께 확인했습니다.

## 프로젝트에서 확인한 교훈
<!--meta: sec=s28; dept=CONSULT|AIAX|BE|DATA; level=시니어; ct_band=상-->
첫째, 콜센터 AI의 품질은 모델 자체뿐 아니라 지식 자료의 상태에 크게 좌우됩니다. 서로 충돌하는 매뉴얼이나 개정되지 않은 FAQ를 그대로 연결하면 생성 결과의 품질을 안정적으로 유지하기 어렵습니다.

둘째, 상담사의 실제 업무 흐름을 고려하지 않은 기능은 기술적으로 우수해도 사용되지 않을 수 있습니다. 통화 중 확인해야 하는 정보의 양, 화면 이동, 출처 확인 방식 및 결과 표시 시간을 함께 설계해야 합니다.

셋째, 답변하지 않는 기준도 중요한 기능입니다. 근거가 없는 상황에서 그럴듯한 문장을 만드는 것보다 추가 확인과 상담사 연결을 안내하는 편이 안전합니다.

넷째, 상담 이력과 공식 매뉴얼의 역할을 구분해야 합니다. 과거 이력은 현실적인 표현과 유사 사례를 제공하지만 공식 정책의 우선 근거가 될 수는 없습니다.

다섯째, 운영 지표는 개선 행동으로 연결되어야 합니다. 검색 실패가 많은 질문은 지식 등록 대상으로, 상담사 전환이 반복되는 유형은 챗봇 범위 재검토 대상으로 활용할 수 있습니다.

## 향후 확장 방향
<!--meta: sec=s29; dept=CONSULT|AIAX|BE|DATA; level=시니어; ct_band=상-->
프로젝트 완료 이후 고려할 수 있는 확장 방향은 다음과 같습니다.

- 상담 지식의 등록·검토·개정 절차 고도화
- 상담 유형별 답변 형식과 검증 기준 세분화
- 질문 맥락을 반영한 검색 품질 개선
- 상담사 피드백을 활용한 지식 보완 후보 추천
- 챗봇 처리 범위의 단계적 확대
- 상담사 연결 사유에 대한 분석 강화
- 제품군별 지식 접근 권한과 표시 방식 정교화
- 품질 검토 대상 상담을 자동으로 선별하는 기능
- 다수 채널에서 일관된 상담 지식을 사용하는 구조
- 운영 대시보드의 원인 분석 기능 강화
- 신규 상담사 교육 자료와 상담 지원 기능의 연계
- 업무 정책 변경 시 영향받는 지식을 찾는 관리 기능

확장 기능은 자동화 범위를 무조건 넓히는 방식이 아니라, 품질 검증과 운영 책임을 함께 정의한 뒤 단계적으로 적용하는 것을 원칙으로 합니다.

## 난이도별 기술 이해 가이드

프로젝트를 이해하기 위한 기술 관점을 난이도별로 정리하면 다음과 같습니다.

| 난이도 | 핵심 이해 내용 |
| --- | --- |
| 기초 | AI가 상담 관련 문서를 찾아 답변 초안을 제공한다는 업무 흐름 |

주니어는 먼저 사용자 질문이 어떤 구성요소를 거쳐 결과로 반환되는지 설명할 수 있어야 합니다. 이후 검색 결과가 부정확할 때 지식, 검색, 생성 및 화면 중 어느 영역을 확인해야 하는지 구분하는 연습이 필요합니다.

시니어는 기술 선택뿐 아니라 업무 위험, 지식 관리 책임, 실패 시 대체 절차, 품질 기준과 운영 비용까지 함께 판단해야 합니다.
