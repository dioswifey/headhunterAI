# 기술 검토 결과 보고서 및 수주 권고·비권고 판단 기준
<!--meta: doc=DSC-06; doc_type=review_report_standard; tier=2; topic=DISCOVERY; disclosure=internal; status=active-->

## 보고서의 성격과 작성 책임
<!--meta: sec=s1; dept=CNS|AIAX; level=시니어; ct_band=상; related=DSC-02#s1-->

기술 검토 결과 보고서는 영업 의사와 분리된 기술 검토 의견서로 운용한다. 고객의 구매 의향이나 영업상 중요성만으로 기술 판정을 상향하지 않는다. 보고서는 확인된 사실, 미확인 사항, 평가 근거와 위험을 기준으로 작성한다.

CNS가 작성과 취합을 주관하고 AIAX가 기술 실현성 및 수행 조건을 공동 검토한다. DATA·BE의 전문 검토가 필요한 경우 해당 부서 의견을 첨부하되 보고서 작성 책임은 CNS와 AIAX에 유지한다.

| 역할 | 기본 책임 | 허용 행위 | 제한 사항 |
|---|---|---|---|
| CNS 주관 작성자 | 과제 범위, 업무 적합성, 조직 준비도 취합 | 추가 확인 요청, 판정 초안 작성 | 미확인 사실의 임의 확정 금지 |
| AIAX 공동 작성자 | 기술 실현성, 수행 여력, 기술 위험 검토 | 기술 조건 제시, 점수 조정 의견 제출 | 영업 기대를 근거로 한 상향 금지 |
| SALES 담당자 | 고객 정보, 일정, 경쟁 상황 제공 | 사실 오류 정정 및 이의 제기 | 기술 결론 직접 수정 금지 |
| DATA·BE 검토자 | 데이터·연동 관련 전문 의견 제공 | 근거 자료와 제한 조건 기재 | 검토 범위 밖 결론 확정 금지 |
| 검토 패널 | 점수와 권고 수준 심의 | 보완 요구, 반대 의견 기록 | 근거 없는 예외 승인 금지 |
| SALES 부장 | 최종 추진 여부 결정 | 권고 범위 내 추진 승인 | 기술 보고서 원문 변경 금지 |

기술 권고는 최종 추진 결정을 지원하지만 그 자체로 제안·가격 소관 문서 계열의 승인을 대신하지 않는다. 최종 추진 결정은 해당 지점 SALES 부장이 하며, 조건부 또는 임계값 미달 예외는 정해진 공동 승인을 거친다. 결정이 기술 권고와 다르면 차이와 승인 근거를 보고서에 남긴다.

### 작성 및 검토 절차

1. CNS가 디스커버리 종료 후 2영업일 이내에 보고서 초안을 개설한다.
2. AIAX는 초안 수령 후 2영업일 이내에 기술 항목을 검토한다.
3. 필요한 경우 DATA 또는 BE에 검토 기한 2영업일을 부여한다.
4. SALES는 고객 제공 자료와 일정 정보를 제출하고 사실 오류를 확인한다.
5. CNS와 AIAX는 근거가 다른 점수에 대해 항목별 의견을 병기한다.
6. 검토 패널은 최종 점수, 권고 등급과 미확인 사항을 확정한다.

### 보고서 필수 작성 대상

- 신규 AI 또는 AX 구축 범위를 포함하는 기회
- 기존 시스템과의 연동 또는 데이터 이관이 필요한 기회
- 개인정보 또는 민감 가능 정보의 처리가 예상되는 기회
- 망분리·폐쇄망·온프레미스 제약이 제시된 기회
- 외부 모델이나 외부 API 사용 여부가 미확정인 기회
- 데이터 확보 가능성이 검증되지 않은 기회
- 2개 이상 지점 또는 3개 이상 수행 부서가 참여하는 기회
- 기술 범위가 디스커버리 이후에도 확정되지 않은 기회

### 예외 승인

- 제출 기한이 최초 인지 시점부터 3영업일 미만인 경우에만 생략 예외를 신청할 수 있다.
- 예외 신청자는 미작성 사유, 제출 기한과 미확인 위험을 1페이지 이내로 기록한다.
- CNS 부장과 AIAX 부장이 모두 승인해야 예외가 성립한다.
- SALES 단독 승인으로 보고서 작성을 생략하지 않는다.
- 예외 승인 시에도 기술적 확약이나 성능 단정을 기록하지 않는다.
- 최소 사전검토에는 범위, 데이터, 인프라, 수행 여력과 중단 위험을 포함한다.
- 정식 보고서는 외부 제출 또는 내부 자원 확정 전까지 보완한다.
- 불가피하게 선행한 경우 승인일부터 2영업일 이내에 사후 보고서를 완료한다.

### 효력 및 기록

- 승인된 보고서의 유효기간은 확정일부터 30일로 한다.
- 범위·데이터·배치 환경이 변경되면 유효기간과 무관하게 재검토한다.
- 미확인 항목이 해소되면 원문을 덮어쓰지 않고 개정본을 발행한다.
- SALES의 이의 제기는 근거 자료와 함께 별도 의견으로 보존한다.
- 기술 결론 변경은 CNS와 AIAX 공동 검토를 거친다.
- 최종 추진 결정과 기술 권고의 차이는 승인자·일시·사유로 기록한다.
- 보고서가 없는 필수 작성 대상은 제안·가격 소관 문서 계열로 이관하지 않는다.

## 표준 목차와 장별 필수 기재 사항
<!--meta: sec=s2; dept=CNS|AIAX; level=주니어|시니어; ct_band=중; related=DSC-03#s9-->

보고서는 동일한 목차와 항목 순서를 사용한다. 해당 사항이 없더라도 장을 삭제하지 않고 해당 없음의 판단 근거를 기재한다. 상세 근거는 본문을 반복하지 않고 첨부 식별자로 연결한다.

본문 분량 상한은 검토자가 핵심 판단과 근거를 확인하는 데 필요한 범위로 제한한다. 상한을 넘는 원자료, 회의 기록과 점검 결과는 첨부로 분리한다.

| 장 | 필수 기재 사항 | 분량 상한 | 작성 책임 | 금지 사항 |
|---|---|---:|---|---|
| 1. 요약 판정 | 총점, 등급, 핵심 조건, 결정 요청 | 1쪽 | CNS | 본문과 다른 결론 |
| 2. 과제 개요 | 대상 업무, 사용자, 범위, 제외 범위 | 1쪽 | CNS | 미합의 범위의 확정 표현 |
| 3. 확인 사실과 출처 | 사실, 확인일, 제공자 역할, 자료 식별자 | 2쪽 | CNS | 출처 없는 수치 |
| 4. 미확인 항목 | 확인 필요 사항, 영향, 담당자, 기한 | 1쪽 | CNS·SALES | 추정을 사실로 대체 |
| 5. 축별 채점 결과 | 6요인 점수, 근거, 가중치, 계산값 | 2쪽 | CNS·AIAX | 근거 없는 점수 조정 |
| 6. 위험과 완화 | 위험, 발생 조건, 영향, 완화 가능성 | 2쪽 | AIAX | 완화 미확정 사항의 해소 처리 |
| 7. 권고와 조건 | 권고 등급, 선행 조건, 해제 기준 | 1쪽 | CNS·AIAX | 기술 검토 밖의 조건 작성 |
| 8. 반대 의견 | 이견 내용, 근거, 처리 결과 | 1쪽 | 패널 간사 | 소수 의견 삭제 |
| 9. 첨부 | 자료 목록, 버전, 작성일, 보관 위치 | 목록 2쪽 | CNS | 고객 식별 정보의 불필요한 복제 |

고객 발언은 발언 취지와 검토자의 해석을 구분해 기록한다. 수치에는 단위, 기준 시점과 출처를 함께 기재하며 확인되지 않은 법적 판단은 단정하지 않는다. 원자료에 고객 식별 정보가 있으면 보고서 본문에는 필요한 최소 범위만 옮긴다.

### 작성 규칙

- 각 사실에는 문서, 회의, 시스템 조회 또는 질의 회신 중 하나의 출처를 연결한다.
- 회의 출처에는 일자와 참석자의 부서 또는 역할만 기록한다.
- 직접 확인하지 못한 고객 발언은 `고객 진술`로 표시한다.
- 검토자의 해석은 `검토 의견`으로 표시해 사실과 구분한다.
- 범위 수치는 대상 건수, 사용자 수, 기간과 단위를 함께 적는다.
- 추정치는 계산 기준과 오차 가능성을 함께 기재한다.
- 미확인 항목에는 확인 책임자와 목표 기한을 지정한다.
- 동일 근거를 여러 장에 복사하지 않고 최초 기재 위치를 참조한다.
- 레퍼런스는 `콜센터 AI 상담 구축`, `수요예측 대시보드 구축`의 문서 ID만 연결한다.

### 요약 1페이지 칸 구성

- 문서 ID·버전·작성일
- 기회 식별용 내부 관리번호
- 대상 지점과 참여 부서
- 과제명과 검토 대상 범위
- 6요인 가중 평균 점수
- 권고 등급과 판정일
- 최고 위험 3건
- 미확인 핵심 항목 3건
- 추진 전 필수 조건
- 조건별 책임자와 해제 기한
- 반대 의견 존재 여부
- 검토자와 승인자

### 첨부 및 버전 관리

- 첨부에는 연속된 식별번호를 부여한다.
- 외부 자료는 수신일과 원본 보관 위치를 기록한다.
- 화면 캡처에는 확인 일시와 확인 주체를 적는다.
- 개정 시 변경 장, 변경 사유와 변경자를 이력에 남긴다.
- 점수 변경은 이전 점수와 새 근거를 함께 보존한다.
- 삭제된 내용은 복구 가능한 이력으로 유지한다.
- 최종본 파일명에는 내부 관리번호, 버전과 확정일을 포함한다.
- 열람 권한은 참여 부서와 승인권자로 제한한다.

## 가중 채점 모델
<!--meta: sec=s3; dept=CNS|AIAX; level=시니어; ct_band=상; related=DSC-02#s2-->

가중 채점 모델은 기회별 논쟁을 동일한 평가 축과 계산 방식으로 전환하기 위해 사용한다. 점수는 추진 결정을 자동 확정하는 값이 아니라 근거의 일관성과 누락 여부를 확인하는 수단이다. 모든 점수에는 확인 자료 또는 미확인 표기가 있어야 한다.

일반적인 입찰 참여 판단에는 수익성, 수행 여력, 범위 적합도, 고객의 질, 경쟁 상황과 위험이 사용된다. 기술 수행 역량, 재무 건전성, 차별 요소, 과거 수행 실적과 발주기관과의 관계를 추가하기도 한다. 본 보고서는 그중 기술 검토로 확인할 수 있는 6요인만 채점한다.

### 일반 기준과 본 모델의 경계

- 수익성과 재무 조건은 제안·가격 소관 문서 계열에서 판단한다.
- 경쟁 상황과 차별 요소는 확인 사실로 첨부할 수 있으나 본 점수에는 직접 반영하지 않는다.
- 고객의 질은 고객 조직 준비도 중 협조 체계와 의사결정 가능성으로 한정해 해석한다.
- 과거 수행 실적은 현재 범위와의 관련성이 확인될 때만 범위 적합 근거로 사용한다.
- 발주기관과의 관계는 기술 점수 상향 근거로 사용하지 않는다.
- 법적·윤리적 중단 사유는 평균 점수와 별도로 중대 위험으로 표시한다.

| 평가 요인 | 정의 | 배점 | 가중치 | 필수 근거 |
|---|---|---:|---:|---|
| 범위 적합 | 요청 범위가 당사 수행 영역과 명확히 대응하는 정도 | 1~5점 | 20% | 범위표, 제외 범위 |
| 기술 실현성 | 요구 기능을 제약 환경에서 구현·검증할 가능성 | 1~5점 | 25% | DSC-02, DSC-05 결과 |
| 데이터 준비도 | 데이터 접근성·품질·라벨 확보 가능성 | 1~5점 | 15% | DSC-03 결과 |
| 고객 조직 준비도 | 의사결정, 담당자, 운영 수용 체계의 준비 수준 | 1~5점 | 15% | DSC-01 기록 |
| 수행 여력 | 필요한 역할과 기간에 내부 인력을 배치할 가능성 | 1~5점 | 15% | 부서별 가용성 확인 |
| 위험 | 중대 위험의 수, 영향과 완화 가능성을 역산한 수준 | 1~5점 | 10% | 위험 목록, 완화 근거 |

총점은 각 요인 점수에 가중치를 곱한 값을 합산해 산출한다. 계산 전 원점수는 정수로 입력하고 총점은 소수점 둘째 자리에서 반올림해 한 자리로 표시한다. 위험 요인은 위험이 낮고 완화 가능성이 높을수록 높은 점수를 부여한다.

### 1~5점 판단 문구

- 1점: 수행을 막는 중대한 결함이 확인되었고 현실적인 해소 근거가 없다.
- 2점: 주요 결함이 있으며 해소 책임자나 기한이 확인되지 않았다.
- 3점: 수행 가능성은 있으나 복수의 조건 또는 추가 검증이 필요하다.
- 4점: 주요 요건이 확인되었고 남은 제한 사항을 관리할 수 있다.
- 5점: 핵심 요건과 근거가 모두 확인되었고 중대한 미확인 사항이 없다.

### 점수 근거 규칙

- 근거가 상충하면 낮은 점수를 우선 적용하고 반대 근거를 병기한다.
- 자료가 없다는 사유만으로 자동 1점을 부여하지 않고 영향 수준을 검토한다.
- 핵심 근거가 미확인이면 해당 요인에 4점 이상을 부여하지 않는다.
- 조건부 해소를 전제로 채점하면 조건, 책임자와 기한을 함께 기록한다.
- 동일 사실을 두 요인에 반영할 때에는 중복 영향 여부를 설명한다.
- 중대 위험은 총점과 별도로 상단 요약에 표시한다.
- 평균 점수가 높아도 중단 사유가 있으면 적극 추진으로 판정하지 않는다.

### 가중치 변경 절차

1. 가중치는 특정 기회의 자료를 열람하기 전에 연간 기준으로 합의한다.
2. 기본 가중치의 합계는 100%로 유지한다.
3. 변경안은 CNS 부장과 AIAX 부장이 공동 발의한다.
4. 변경 사유에는 대상 기회가 아닌 업무 환경 또는 검증 결과를 제시한다.
5. 특정 기회의 등급을 올리기 위한 사후 변경은 허용하지 않는다.
6. 변경 전 기존 보고서의 점수는 재계산하지 않는다.
7. 신규 가중치는 시행일 이후 개설된 보고서부터 적용한다.
8. 변경 이력에는 이전 값, 변경 값, 승인자와 시행일을 기록한다.
9. 연간 재검토 외 긴급 변경은 검토 패널 전원의 동의를 받는다.

### 계산 검증

- 작성자와 공동 검토자는 각각 1회 계산 결과를 대조한다.
- 누락 요인이 있으면 총점을 확정하지 않는다.
- 가중치 합계가 100%가 아니면 보고서를 반려한다.
- 수기 보정 점수는 사용하지 않는다.
- 등급 판정에는 확정된 한 자리 총점만 사용한다.

## 판정 임계값과 등급별 후속 절차
<!--meta: sec=s4; dept=CNS|AIAX; level=시니어; ct_band=상; related=DSC-04#s5-->

판정은 확정된 5점 척도 가중 평균을 기준으로 한다. 임계값 미달 시 기본 결정은 `추진하지 않음`으로 하며, 담당자가 별도 중단 승인을 받을 필요는 없다. 점수가 경계에 있으면 반올림된 최종 점수를 사용한다.

등급은 기술 권고 수준을 나타내며 제안·가격 소관 문서 계열의 결정을 대신하지 않는다. 중대한 법률·보안·데이터 처리 위험이 미해소 상태이면 총점과 관계없이 조건부 추진 이하로 제한한다.

| 가중 평균 | 판정 | 후속 절차 | 승인 권한 | 기록 요건 |
|---:|---|---|---|---|
| 4.0~5.0 | 적극 추진 | 다음 소관 문서 계열로 이관하고 잔여 위험을 인계 | SALES 부장 | 총점, 핵심 근거, 잔여 위험 |
| 3.0~3.9 | 여력이 있으면 조건부 추진 | 조건 책임자·기한 확정 후 이관 여부 결정 | SALES·CNS·AIAX 부장 공동 | 조건, 해제 기준, 재확인일 |
| 2.0~2.9 | 전략적 이유가 없으면 사양 | 기본 종결하며 예외 신청 시 재심의 | SALES·CNS·AIAX 부장 전원 | 사양 사유 또는 전략 예외 근거 |
| 1.0~1.9 | 비권고 | 추진하지 않고 결함 해소 전까지 재개 금지 | CNS·AIAX 부장 확정 | 중대 결함, 재검토 가능 조건 |

비권고 또는 사양 판정은 고객이나 담당자의 책임을 평가하는 표현으로 작성하지 않는다. 확인된 결함, 미확인 사항과 수행 영향만 기록한다. 사실이 변경되면 기존 결론을 삭제하지 않고 재검토본을 발행한다.

### 등급별 후속 처리

- 적극 추진은 판정일부터 2영업일 이내에 다음 담당 조직으로 이관한다.
- 적극 추진이라도 잔여 위험의 책임자와 확인 시점을 지정한다.
- 조건부 추진은 모든 필수 조건에 책임 부서와 해제 기한을 배정한다.
- 조건부 해제 기한은 원칙적으로 판정일부터 10영업일 이내로 한다.
- 기한 내 조건이 해제되지 않으면 자동으로 추진 보류 상태로 전환한다.
- 2.0~2.9점은 별도 예외가 없으면 사양으로 종결한다.
- 1.0~1.9점은 전략적 중요성만으로 추진 상태로 전환하지 않는다.
- 종결된 건은 신규 사실 또는 결함 해소 자료가 있을 때만 재개한다.

### 전략적 예외 근거

- 전략적 이유는 연간 타겟 산업 또는 지점 계획과의 연결로 제시한다.
- 단순 매출 기대, 고객 인지도 또는 담당자의 주관적 기대는 단독 근거로 인정하지 않는다.
- 예외 신청에는 기술 결함을 감수해야 하는 이유를 구체적으로 적는다.
- 미충족 요인별 완화 조치, 책임 부서와 완료 기한을 포함한다.
- 추가 투입 인력과 기존 수행 건에 미치는 영향을 확인한다.
- 고객이 제공해야 할 자료나 조치가 있으면 확인 방식과 기한을 적는다.
- 경쟁 상황은 보조 근거로만 사용하고 기술 결함을 상쇄하지 않는다.
- 예외 적용 기간은 승인일부터 15영업일을 넘지 않는다.

### 예외 승인 단계

1. SALES 담당자가 전략적 예외 신청서를 작성한다.
2. CNS와 AIAX 작성자가 기술 결함 및 완화 가능성을 재확인한다.
3. CNS 부장과 AIAX 부장이 각각 찬반 의견을 기록한다.
4. SALES 부장이 사업상 필요성과 내부 자원 영향을 확인한다.
5. 세 부서 부장이 모두 승인해야 2.0~2.9점 기회를 조건부로 전환한다.
6. 한 부서라도 반대하면 기본 결정인 추진하지 않음을 유지한다.
7. 1.0~1.9점은 예외 승인 대상이 아니며 사실 변경 후 재평가한다.
8. 예외 승인 후 조건이 미충족되면 별도 의결 없이 승인을 종료한다.

### 판정 기록

- 판정 기록에는 원점수, 가중 평균, 등급과 판정일을 포함한다.
- 승인자는 전자 기록으로 이름, 직급, 부서와 승인 시각을 남긴다.
- 반대 의견은 최종 결정과 함께 보존한다.
- 점수와 다른 최종 결정을 내리면 적용 예외 조항을 명시한다.
- 재평가 시 이전 판정과 변경 근거를 연결한다.
- 판정 기록은 보고서와 동일한 열람 권한으로 관리한다.

## 비권고 사유 유형
<!--meta: sec=s5; dept=CNS|AIAX; level=시니어; ct_band=상; related=SLS-02#s6-->

비권고는 현재 확인된 조건으로 기회를 계속 추진하기 어렵다는 내부 판단이다. 단일 우려나 담당자의 인상만으로 결정하지 않으며, 확인 사실·미확인 사항·추정치를 구분해 기록한다. 어카운트 제외 판단과의 구분은 SLS-02#s6을 따른다.

| 사유 유형 | 판정 기준 | 필수 증빙 | 조건부 전환 여부 | 전환 요건 |
|---|---|---|---|---|
| 필요한 데이터가 사실상 존재하지 않음 | 원천 데이터가 없고 대체 수집·생성 경로도 확인되지 않음 | 데이터 인벤토리, 보유 부서 회신, 표본 확인 기록 | 제한적 가능 | 수집 책임자·수집량·완료일이 확정되고 표본이 확인됨 |
| 성공 기준 합의가 불가능함 | 고객 관여자 간 핵심 지표·허용 오차·판정 방식이 상충함 | 회의록, 지표 후보표, 미합의 쟁점 목록 | 가능 | 승인 권한자가 단일 기준을 서면 확정함 |

| 운영 인수 주체 없음 | 배포 후 운영·모니터링·변경 승인 책임 조직이 없음 | 운영 역할 질의서, 인수 후보 조직 회신 | 가능 | 운영 책임 조직과 인수 기준이 확정됨 |
| 일정이 물리적으로 불가능함 | 필수 선행 작업과 검토 기간을 합산하면 요구 완료일을 초과함 | 역산 일정표, 외부 의존 일정, 최소 소요일 근거 | 가능 | 완료일 또는 범위가 조정되고 선행 일정이 확정됨 |

비권고 사유는 가장 중대한 1개를 주사유로 지정하고 나머지를 부사유로 기록한다. 동일 사실이 여러 유형에 해당하면 영향이 직접적인 유형에만 배정하고 중복 점수를 부여하지 않는다.

### 판정 및 기록 기준

- 증빙은 고객 확인 자료, 시스템 조회 결과, 표본 검증, 회의록, 담당자 진술 순으로 신뢰도를 구분한다.
- 담당자 진술만 있는 경우에는 진술자·직책·확인일과 추가 확인 필요 여부를 함께 적는다.
- 미확인 사항을 부정 사실로 간주하지 않으며, 확인 시한이 지났을 때만 미확인 위험으로 판정한다.
- 기술 상한은 단일 수치로 단정하지 않고 데이터·환경·평가 방식에 따른 추정 범위를 기록한다.
- 수행 여력은 회사 전체가 아니라 필수 역할과 요구 기간을 기준으로 확인한다.
- 일정 판정에는 고객 승인, 보안 검토, 데이터 제공 등 외부 의존 기간을 포함한다.
- 법률·규제 관련 우려는 확정 판단으로 쓰지 않고 고객의 담당 조직 또는 별도 검토 필요 사항으로 남긴다.
- 비권고 근거에는 작성자, 검토자, 기준일, 사용한 문서 버전을 기록한다.

### 조건부 전환 판단

- 조건부 전환은 원인이 해소 가능한 경우에만 허용하며 단순한 기대나 구두 약속은 요건으로 인정하지 않는다.
- 전환 요건은 측정 가능성, 책임자, 기한을 모두 갖추며 세부 작성은 DSC-06#s6을 따른다.
- 데이터 부재는 수집 계획만으로 해제하지 않고 최소 1개 대표 표본을 확인한다.
- 품질 상한 문제는 요구치 하향, 적용 범위 축소 또는 평가 방식 변경 중 하나가 승인되어야 한다.
- 수행 여력 문제는 후보자 명단이 아니라 부서장의 배정 확인으로 해제한다.
- 환경 제약은 대체 구성의 기술 검토와 고객 환경 담당자의 수용 확인을 모두 요구한다.
- 일정 조정은 목표일만 변경하지 않고 필수 선행 작업의 시작일과 승인일을 함께 갱신한다.
- 전환 요건이 서로 의존하면 선행 조건이 해제되기 전 후행 조건을 완료로 처리하지 않는다.

### 고객 전달 원칙

고객에게는 내부 점수, 위원별 의견, 인력 가용성 상세를 그대로 전달하지 않는다. 확인된 제약과 계속 검토하기 위해 필요한 조치만 사실 중심으로 설명하며, 고객 책임으로 단정하는 표현을 사용하지 않는다. 전달 전 SALES 기회 담당자와 기술 리드가 문안을 공동 확인한다.

1. 전달 제목은 “기술 검토 결과 및 추가 확인 필요 사항”으로 통일한다.
2. 첫 항목에는 검토 범위와 기준일을 명시한다.
3. 확인된 사실과 당사 추정은 별도 문장으로 구분한다.
4. 미확인 사항에는 필요한 자료와 회신 희망일을 적는다.
5. 기술적 한계는 전제 조건과 검증 범위를 함께 제시한다.
6. 내부 인력 사정은 역할 확보 여부로만 전달한다.
7. 대안이 검증되지 않았으면 가능한 방안으로 단정하지 않는다.
8. 고객의 재검토 요청 창구는 SALES 기회 담당자로 단일화한다.
9. 구두 전달 후 1영업일 이내에 동일 내용을 서면으로 남긴다.
10. 제안·가격 관련 문의는 제안·가격 소관 문서 계열로 이관한다.

### 전달 범위와 보관

- 고객 공유본에는 주사유, 확인 근거의 요약, 해제 가능 조건, 회신 필요일을 포함한다.
- 내부 원본에는 부사유, 위원별 이견, 원자료 위치, 조건 해제 책임자를 추가한다.
- 제3자 자료는 공유 권한을 확인하고 필요한 문장만 요약한다.
- 특정 개인의 과실이나 평가 표현은 고객 공유본에 기재하지 않는다.
- 고객이 비권고 사유에 이의를 제기하면 새 증빙을 접수해 재검토 요청으로 기록한다.
- 전달본과 내부 원본의 차이는 문서 이력에서 확인 가능하게 유지한다.

## 조건부 권고의 조건 작성 규칙
<!--meta: sec=s6; dept=CNS|AIAX; level=시니어; ct_band=상; related=DSC-02#s8-->

조건부 권고는 해소 가능한 불확실성이 남아 있으나 지정된 조건을 충족하면 추진할 수 있다는 판단이다. 모든 조건은 측정 가능하고, 책임자가 지정되며, 완료 기한이 명시되어야 한다. 세 요건 중 하나라도 빠지면 조건으로 등록하지 않고 미확인 위험 또는 비권고 사유로 분류한다.

| 조건 대상 | 나쁜 조건 | 좋은 조건 | 확인 증빙 | 해제 확인 주체 |
|---|---|---|---|---|
| 데이터 | 데이터를 충분히 준비한다 | 고객 DATA 담당이 6월 15일까지 대표 표본 1,000건과 필드 정의서를 제공한다 | 표본 파일, 정의서, 수신 기록 | DATA 검토자 |
| 성공 기준 | 정확도를 협의한다 | 고객 승인자가 5월 30일까지 평가 지표·목표값·허용 오차를 서면 승인한다 | 승인 메일, 지표 정의서 | CNS 기술검토 책임자 |
| 환경 | 인프라 문제를 해결한다 | 고객 인프라 담당이 7영업일 내 연산 자원과 통신 경로의 사용 가능 여부를 회신한다 | 환경 확인서, 구성도 | AIAX 기술 리드 |
| 연동 | API를 제공한다 | 고객 시스템 담당이 6월 10일까지 테스트 API 명세와 호출 계정을 제공한다 | API 명세, 계정 발급 기록 | BE 검토자 |
| 운영 | 운영 조직을 정한다 | 고객 책임자가 운영 부서와 장애 접수 책임자를 6월 20일까지 지정한다 | RACI, 담당자 지정 문서 | CNS 검토자 |
| 일정 | 일정을 현실화한다 | 고객 승인자가 필수 보안 검토 10영업일을 반영한 기준 일정을 확정한다 | 기준 일정표, 승인 기록 | 수행 지점 대표 |

조건 문장은 “누가, 무엇을, 어떤 기준으로, 언제까지 완료하는가”의 순서로 작성한다. 완료 여부가 해석에 따라 달라지는 표현은 수치, 문서명, 승인 행위 또는 확인 가능한 상태로 치환한다.

### 조건 등록 기준

- 각 조건에는 `C01`부터 시작하는 고유 번호를 부여한다.
- 책임자는 개인 또는 승인 권한이 있는 조직 역할로 지정한다.
- “고객”, “관련 부서”, “담당자”처럼 범위가 불명확한 책임자 표기는 사용하지 않는다.
- 기한은 날짜 또는 기준 사건 이후 영업일 수로 표시한다.
- 측정 기준에는 건수, 비율, 문서 승인, 접근 성공 여부 중 하나 이상을 포함한다.
- 외부 검토가 필요한 조건은 요청일과 예상 회신일을 분리해 기록한다.
- 당사와 고객이 공동 수행하는 조건은 양측 책임을 각각 나눈다.
- 조건 해제에 필요한 원본 자료의 위치와 열람 권한을 지정한다.
- 조건 변경 시 기존 문장을 삭제하지 않고 변경 사유와 승인자를 이력에 남긴다.

### 조건 해제 확인

- 조건 책임자는 완료 자료를 제출하지만 스스로 해제를 확정하지 않는다.
- 기술 조건은 AIAX·BE·DATA 중 해당 영역의 검토자가 확인한다.
- 업무·평가·운영 조건은 CNS 검토자가 확인한다.
- 복수 영역 조건은 기술 리드와 CNS 검토자가 공동 확인한다.
- 확인자는 증빙의 최신성, 완전성, 대상 범위 일치 여부를 점검한다.
- 일부 충족은 해제로 처리하지 않고 잔여 범위와 새 기한을 기록한다.
- 고객 구두 확인은 임시 증빙으로만 인정하며 2영업일 이내 서면 보완을 요구한다.
- 모든 조건 해제 후 검토 책임자가 조건부 권고를 최종 권고로 변경한다.

### 다음 단계 이동과 예외

조건이 해제되지 않은 상태에서는 제안·가격 소관 문서 계열로 기회를 이관하지 않는다. 다만 조건 해제에 필요한 질의, 자료 검토, 비식별 표본 확인 등 되돌릴 수 있는 준비 활동은 예외 승인을 받아 수행할 수 있다. 예외 승인은 권고 등급 변경으로 간주하지 않는다.

- 예외 요청에는 대상 조건, 수행 활동, 중단 기준, 최대 기간을 적는다.
- 예외 기간은 원칙적으로 5영업일을 넘기지 않는다.
- 고객 데이터 반입, 운영 환경 변경, 외부 비용 발생 활동은 예외 대상에서 제외한다.
- 예외는 검토 패널 의장과 해당 기술 부서장의 공동 승인을 받는다.
- 수행 지점이 정해졌으면 지점 대표의 가용성 확인을 추가한다.
- 예외 활동 결과가 조건을 충족하지 못하면 원래 판정을 유지한다.
- 예외 기간 만료 시 연장하지 않고 패널에 재상정한다.
- 승인 기록에는 허용 범위와 금지 활동을 함께 명시한다.

### 다수 조건과 선후 관계

- 조건이 4개 이상이면 공통 원인별로 묶고 핵심 조건과 파생 조건을 구분한다.
- 핵심 조건이 3개 이상이면 조건부 권고보다 비권고가 적절한지 재검토한다.
- 조건이 7개 이상이면 원칙적으로 패널에 재상정해 판정 등급을 다시 결정한다.
- 선후 관계는 `C01 → C03` 형식으로 표시한다.
- 두 조건을 함께 충족해야 하면 `C01 + C02 → C04`로 표시한다.
- 서로 대체 가능한 조건은 `C05 또는 C06`으로 표시하고 선택 승인자를 정한다.
- 순환 의존이 확인되면 조건 구조를 해소하기 전까지 비권고로 전환한다.
- 선행 조건의 기한은 후행 조건보다 최소 2영업일 앞서도록 설정한다.
- 조건별 완료율을 평균해 전체 해제로 간주하지 않는다.
- 최종 해제는 모든 필수 조건이 개별적으로 완료된 경우에만 인정한다.

## 검토 패널 구성과 회의 운영
<!--meta: sec=s7; dept=CNS|AIAX|SALES; level=시니어; ct_band=상; related=none-->

검토 패널은 영업 기회성, 기술 타당성, 수행 가능성, 재무·운영 위험을 서로 다른 역할에서 검토한다. 패널 구성원은 소속 지점보다 검토 책임을 우선하며, 동일인이 여러 역할을 맡더라도 정족수에서는 1명으로 계산한다. 임계값 미달 기회는 별도 승인 근거가 없으면 비권고를 기본 결정으로 한다.

| 패널 역할 | 헤드헌터랩 구성 | 필수 여부 | 주요 검토 책임 | 의결 권한 |
|---|---|---|---|---|
| 패널 의장 | CNS 차장 이상 | 필수 | 쟁점 정리, 근거 충족 여부, 의결 진행 | 1표 |
| 기회 담당 | SALES 담당자 및 과장 이상 검토자 | 필수 | 고객 요구, 의사결정 구조, 일정 전제 확인 | 1표 |
| 기술 리드 | AIAX 과장 이상 | 필수 | 기술 상한, 데이터·모델·환경 위험 검토 | 1표 |
| 영역 검토자 | BE 또는 DATA 과장 이상 | 해당 시 필수 | 연동·데이터 등 전문 영역 검증 | 1표 |
| 수행 조직 대표 | 수행 예정 지점의 CNS·AIAX 책임자 | 필수 | 역할별 여력, 인수 가능성, 지역 협업 확인 | 1표 |
| 재무 관점 검토자 | SALES 부장 또는 지정 관리자 | 복합 기회 필수 | 재무 건전성 자료, 장기 자원 노출, 회수 위험 확인 | 1표 |

패널은 권고 판단에 필요한 자료가 갖추어진 뒤 개최한다. 제안 내용, 가격 산정, 계약 조건은 심의하지 않으며 관련 사항은 제안·가격 소관 문서 계열로 넘긴다. 전문 영역 위험이 없더라도 기술 리드와 수행 조직 대표는 생략하지 않는다.

### 회의 입력 자료와 사전 배포

- 입력 자료에는 디스커버리 기록, 타당성 검토 결과, 데이터 준비도, 인프라 사전검토를 포함한다.
- 적용 문서는 DSC-01부터 DSC-05까지의 해당 산출물로 한정한다.
- 1페이지 요약본에는 권고안, 총점, 주사유, 조건, 미확인 사항을 적는다.
- 증빙 목록에는 문서명, 작성일, 작성자, 원본 위치를 표시한다.
- SALES 기회 담당자는 고객 일정과 의사결정 구조의 최신성을 확인한다.
- 기술 리드는 기술 가정과 검증되지 않은 추정을 구분한다.
- 수행 조직 대표는 역할별 가용 여부를 기준일 현재 상태로 회신한다.
- 정규 회의 자료는 회의 2영업일 전 15시까지 배포한다.
- 긴급 회의 자료는 최소 1영업일 전 배포하며 긴급 사유를 기록한다.
- 위원은 회의 4시간 전까지 누락 자료와 반대 의견을 사전 등록한다.
- 필수 자료가 2건 이상 누락되면 의장은 회의를 연기한다.

### 소요 시간과 의결 방식

- 정규 회의는 60분을 기본으로 한다.
- 복합 연동, 망분리 또는 2개 이상 지점이 관련되면 최대 90분으로 운영한다.
- 첫 10분은 사실관계와 검토 범위를 확인한다.
- 다음 20분은 기술·데이터·환경 쟁점을 검토한다.
- 다음 15분은 수행 여력과 운영 인수 위험을 확인한다.
- 마지막 15분은 점수 확인, 조건 작성, 의결에 사용한다.
- 정족수는 의장, SALES, 기술 리드, 수행 조직 대표를 포함한 최소 4명이다.
- 필수 역할 중 1명이 불참하면 대리 권한을 사전에 서면 지정한다.
- 합의를 우선하되 합의가 되지 않으면 출석 위원 3분의 2 이상으로 의결한다.
- 판정 임계값과 임계값 미달 처리에는 DSC-06#s4를 적용한다.

### 이해 상충 신고

위원은 자신의 실적, 자원 배정, 기존 판단 또는 외부 관계가 의결에 영향을 줄 가능성을 회의 전에 신고한다. 신고 사실만으로 자동 배제하지 않으며, 의장이 영향 범위와 회피 조치를 정한다. 의장의 이해 상충은 CNS 부장 또는 지정 대리자가 판단한다.

- 고객 관여자와의 개인적 이해관계가 있으면 관계 유형을 신고한다.
- 해당 기회의 활동 성과가 본인 평가에 직접 반영되면 이를 밝힌다.
- 본인이 작성한 핵심 증빙에 중대한 이의가 제기되면 작성 역할을 신고한다.
- 수행 인력 확보를 위해 다른 기회의 축소가 필요한 경우 자원 이해 상충으로 기록한다.
- 외부 파트너 또는 공급 주체와 별도 이해관계가 있으면 신고한다.
- 회피 대상 위원은 토론 자료를 제공할 수 있으나 의결에는 참여하지 않는다.
- 회피로 정족수가 부족해지면 대체 위원을 지정한 뒤 회의를 재개한다.
- 신고, 회피 여부, 대체 위원은 회의록에 남긴다.
- 사후 발견된 이해 상충이 결론에 영향을 줄 수 있으면 2영업일 내 재상정한다.

### 소규모 기회의 간이 검토

- 아래 기준을 모두 충족하는 경우에만 정규 패널을 생략한다.
- 공공입찰 또는 공식 경쟁 절차에 해당하지 않아야 한다.
- 예상 수행 공수가 20인일 이하이고 수행 기간이 20영업일 이하여야 한다.
- 개인정보·민감정보·고객 핵심정보를 처리하지 않아야 한다.
- 외부 시스템 연동, 망분리, 고객 운영 환경 변경이 없어야 한다.
- 단일 지점과 2개 이하 부서만 관여해야 한다.
- 기술 타당성 위험이 낮고 미확인 필수 항목이 없어야 한다.
- 조건부 항목은 1개 이하여야 하며 5영업일 이내 해제 가능해야 한다.
- 기존 레퍼런스는 “콜센터 AI 상담 구축” 또는 “수요예측 대시보드 구축” 문서 ID로만 확인한다.

### 간이 검토 승인

- 간이 검토는 SALES 과장 이상과 CNS 또는 AIAX 과장 이상이 공동 수행한다.
- 두 검토자는 동일인이 될 수 없다.
- 수행 예정 지점 책임자는 역할 가용성을 서면 확인한다.
- 검토 결과는 권고, 조건부 권고, 비권고 중 하나로 기록한다.
- 기준 중 하나라도 충족하지 못하면 정규 패널에 상정한다.
- 간이 검토 기록은 정규 패널 기록과 동일한 보관 기준을 적용한다.

## 반대 의견 기록과 번복 절차
<!--meta: sec=s8; dept=CNS|AIAX|SALES; level=시니어; ct_band=상; related=none-->

검토 패널의 반대 의견은 다수 의견과 관계없이 보고서 본문에 남긴다. 반대 의견을 삭제하거나 합의된 표현으로 임의 축약하지 않는다. 인신 평가, 추정 동기, 근거 없는 낙관·비관은 기록하지 않는다.

### 반대 의견 기록 규칙

반대 의견은 판정 회의 종료 후 1영업일 이내에 기록하고 제기자가 문구를 확인한다. 작성 책임자는 의견과 처리 결과를 분리해 기재한다. 동일 쟁점의 중복 의견은 병합할 수 있으나 제기자와 근거는 각각 남긴다.

| 기록 항목 | 필수 내용 | 작성 기준 | 허용 분량 |
|---|---|---|---:|
| 의견 요지 | 반대하는 판정·점수·조건 | 결론부터 기재 | 150자 |
| 근거 | 문서, 고객 확인, 검토 결과 | 출처와 확인일 포함 | 300자 |
| 제기자 | 부서 코드·직급·패널 역할 | 사내 식별자 사용 | 60자 |
| 처리 결과 | 수용·일부 수용·기각·보류 | 판단 사유 포함 | 200자 |
| 재확인 조건 | 추가 확인 항목과 기한 | 책임 부서 지정 | 150자 |

### 영업 측 이의 제기

SALES는 판정 보고서 배포 후 3영업일 이내에 검토 패널 의장에게 이의를 제출한다. 이의는 구두 요청만으로 접수하지 않으며 기존 판단을 변경할 새 근거를 포함해야 한다. 제안·가격에 관한 주장은 제안·가격 소관 문서 계열로 분리한다.

1. SALES 담당자가 이의 제기서를 작성한다.
2. SALES 과장 이상이 제출 필요성을 확인한다.
3. 검토 패널 의장이 1영업일 이내에 접수 여부를 판단한다.
4. 접수된 이의는 CNS와 관련 기술 부서에 동시에 배포한다.
5. 접수 불가 시 부족한 근거와 보완 기한을 회신한다.

**새 근거의 인정 요건**

- 발주 범위나 요구 조건이 변경된 공식 문서를 제시한다.
- 고객 의사결정자 또는 실무 책임자의 서면 확인을 제시한다.
- 기존 미확인 기술 항목의 시험·분석 결과를 제시한다.
- 투입 가능 인력이나 수행 여력의 확정 자료를 제시한다.
- 기대, 관계, 구두 낙관만을 새 근거로 인정하지 않는다.

### 판정 번복과 승인

1. 작성 책임자가 기존 점수와 새 근거의 대응표를 작성한다.
2. 원 검토 패널 중 3명 이상이 재검토에 참여한다.
3. 변경 대상 항목만 재채점하되 총점과 등급을 다시 계산한다.
4. 반대 의견과 소수 의견을 포함해 재판정 회의록을 작성한다.
5. 승인권자가 번복 또는 기존 판정 유지를 확정한다.
6. 승인 완료 전에는 변경된 판정을 대외적으로 사용하지 않는다.

**승인 권한**

- 동일 등급 내 조건 변경은 검토 패널 의장인 CNS 부장이 승인한다.
- 조건부 권고와 권고 간 번복은 CNS 부장과 기회 담당 부장이 공동 승인한다.
- 기술 비권고를 상향 번복할 때에는 AIAX 부장의 승인을 추가한다.
- 임계값 미달 기회의 예외 추진은 CNS·AIAX·SALES 부장이 공동 승인한다.
- 이의 제기자는 단독 승인자가 될 수 없다.

### 기록 보존과 반복 재검토

번복 전후 보고서, 채점표, 근거와 승인 기록은 하나의 이력 묶음으로 보존한다. 기존 파일을 덮어쓰지 않고 판정일과 버전을 구분한다. 반복 번복은 개별 기회의 예외로만 처리하지 않고 기준 적정성 검토 대상으로 올린다.

- 원 판정본과 각 번복본에 연속 버전 번호를 부여한다.
- 이의 제기서와 접수·반려 결과를 함께 보존한다.
- 항목별 점수 변경 사유와 변경자를 기록한다.
- 승인 일시와 승인자의 부서 코드·직급을 기록한다.
- 동일 항목에서 분기당 3건 이상 번복되면 기준 개정 후보로 등록한다.
- 동일 기회의 재검토는 최초 판정 후 최대 2회로 제한한다.
- 두 번째 재검토 후 추가 이의는 접수하지 않는다.
- 발주 범위가 전면 변경되면 새 기회 코드로 다시 검토한다.
- 기준 개정 후보는 분기 검토 패널에서 가중치·임계값 안건으로 심의한다.

## 보고서 보관·열람과 사후 검증
<!--meta: sec=s9; dept=CNS; level=시니어; ct_band=중; related=SLS-06#s6-->

기술 검토 보고서는 승인본, 근거 자료, 이의 기록과 사후 검증 결과를 연결해 보관한다. 고객 식별 정보는 기회 코드로 대체하고 업무상 필요한 범위에서만 열람한다. 법령, 고객 요구 또는 내부 보안 기준이 더 긴 보관 기간을 요구하는지는 건별로 확인한다.

### 보관 위치와 열람 범위

승인본은 사내 문서관리 저장소의 `DSC-06/연도/기회코드` 경로에 보관한다. 개인 저장장치, 개인 메일함, 승인되지 않은 외부 협업 공간에는 저장하지 않는다. 폴더 관리자는 CNS가 맡고 접근 권한을 반기마다 확인한다.

| 자료 구분 | 기본 보관 기간 | 열람 범위 | 보관·폐기 기준 |
|---|---:|---|---|
| 최종 보고서·채점표 | 승인일 후 5년 | CNS·AIAX·관련 부서장 | 기간 종료 후 폐기 심사 |
| 근거 자료·질의 회신 | 종료일 후 3년 | 검토 패널 | 원천 데이터 최소화 |
| 이의·번복 기록 | 최종 판정 후 5년 | 패널 의장·승인자 | 원본과 변경본 동시 보존 |
| 1페이지 요약본 | 승인일 후 5년 | 관련 부장 이상 | 본문 권한과 연동 |
| 사후 검증 산출물 | 검증일 후 5년 | CNS·기준 개정 패널 | 분석용 비식별본 우선 |
| 개인정보 포함 자료 | 목적 달성 시까지 | 승인된 최소 인원 | 별도 권한과 삭제 확인 |

**외부 공유 금지 항목**

- 고객이 제공한 원천 데이터와 표본 레코드
- 시스템 구성, 보안 통제와 취약 가능성 정보
- 개인정보, 인증정보와 접근 경로
- 패널 구성원의 개별 발언과 소수 의견 원문
- 내부 점수, 가중치 산식과 미확인 위험의 상세
- 제출 의무가 예상되는 경우 CNS 부장과 보안·개인정보 담당 검토를 먼저 거친다.

### 사후 검증 절차

사후 검증은 검토 당시의 예측과 실제 수행 결과를 비교해 판단 기준의 정확도를 확인하는 절차다. 평가는 당시 확보 가능했던 정보에 한정하며 결과를 안 뒤 과거 판단자를 비난하는 방식으로 운영하지 않는다. 실제 수행 자료는 필요한 지표만 사용하고 프로젝트 상세 사례를 재서술하지 않는다.

1. CNS는 매월 종료·중단·착수 기회 목록을 확정한다.
2. 비권고 후 추진된 기회와 권고 후 어려움이 발생한 기회는 전수 선정한다.
3. 그 밖의 권고 기회는 분기별로 20% 이상 표본 선정한다.
4. 검증 회의는 분기 종료 후 15영업일 이내에 실시한다.
5. CNS가 주관하고 AIAX, BE, DATA 중 관련 기술 부서가 참여한다.
6. 검토 당시 보고서와 실제 착수·수행·종료 기록을 입력 자료로 사용한다.
7. 예측 점수와 실제 결과의 차이를 항목별로 분류한다.
8. 산출물은 사후 검증표, 오판 원인 목록과 기준 개정 후보안으로 구성한다.

**필수 비교 항목**

- 판정 등급과 실제 추진·중단 상태
- 예상한 기술·데이터·조직 위험과 실제 발생 여부
- 조건부 권고 조건의 해제 여부와 해제 시점
- 예상 수행 여력과 실제 투입 부담의 차이
- 일정·검수·운영 전환 과정에서 확인된 주요 난점
- 미확인 항목이 결과에 미친 영향

### 양방향 사례의 해석

비권고 후 추진된 기회는 숨은 가능성을 놓친 과소평가 여부를 확인하기 위해 포함한다. 권고 후 어려웠던 기회는 위험을 낮게 본 과대평가 여부를 확인하기 위해 포함한다. 두 유형을 함께 보지 않으면 기준이 일방적으로 보수화되거나 완화될 수 있다.

- 과대평가는 권고했으나 중대한 조건 미충족이 발생한 경우로 분류한다.
- 과소평가는 비권고했으나 핵심 조건을 충족해 정상 추진된 경우로 분류한다.
- 조건부 권고는 조건 해제의 적시성과 충분성을 별도로 평가한다.
- 근거가 부족했던 항목과 가중치가 부적절했던 항목을 구분한다.
- 결과만을 기준으로 당시 합리적 판단을 오류로 단정하지 않는다.

### 기준 개정 반영

1. CNS는 최근 2개 분기의 검증 결과를 항목별로 집계한다.
2. 동일 오판 원인이 3건 이상이면 가중치·임계값 개정안을 작성한다.
3. 개정 전 최근 12개월 자료 10건 이상으로 재계산 결과를 확인한다.
4. CNS·AIAX·SALES 부장으로 구성한 검토 패널이 개정안을 승인한다.
5. 개정 기준은 시행일 이후 새로 접수된 기회부터 적용한다.
6. 이전 기준, 변경 사유, 검증 표본과 승인 이력을 보존한다.
7. 경쟁 정보 관련 디브리핑 연계는 SLS-06#s6을 참고한다.

## 요약 보고 1페이지 양식
<!--meta: sec=s10; dept=CNS|AIAX; level=주니어|시니어; ct_band=중; related=none-->

요약 보고는 승인된 본문의 결론을 경영 검토용 1페이지로 압축한 문서다. 새로운 판단이나 본문에 없는 수치를 추가하지 않는다. 문서는 A4 세로 1페이지를 기준으로 하며 고객 식별 정보 대신 기회 코드를 사용한다.

### 표준 칸 구성

| 칸 | 기재 내용 | 글자 수 상한 | 작성 요령 | 본문 참조 |
|---|---|---:|---|---|
| 기회 식별 정보 | 기회 코드, 산업군, 주관 지점 | 80자 | 고객명·담당자명 제외 | 기본 정보 |
| 검토 범위 | 완료된 검토와 제외 범위 | 100자 | 문서 ID 중심 기재 | 검토 범위 |
| 판정 등급·점수 | 등급, 가중 총점, 판정일 | 60자 | 점수는 소수점 1자리 | 채점표 |
| 결정적 근거 3줄 | 긍정·부정 판단의 핵심 근거 | 줄당 80자 | 한 줄에 근거 하나 | 종합 판단 |
| 조건 목록 | 조건, 책임 부서, 기한 | 240자 | 최대 5개, 우선순위순 | 조건부 권고 |
| 주요 위험 3개와 완화 | 위험별 영향과 완화 조치 | 항목당 100자 | 위험·완화를 한 쌍으로 작성 | 위험 목록 |
| 미확인 항목 | 확인 필요 사항과 예정일 | 180자 | 최대 5개, 책임자 포함 | 미확인 사항 |
| 본문·첨부 참조 | 절·표·첨부 번호 | 120자 | 위치를 직접 식별 | 해당 위치 |
| 작성·검토·승인 | 부서 코드, 직급, 사내 식별자 | 칸당 60자 | 역할별 1인 이상 | 승인 이력 |
| 작성일·버전 | 작성일, 기준일, 버전 | 50자 | `YYYY-MM-DD / vN.N` | 문서 이력 |

### 칸별 작성 요령

각 칸은 상한 이내의 완결된 문장이나 명사형 항목으로 작성한다. 약어는 부서 코드와 문서 ID처럼 사내에서 정의된 것만 사용한다. 점수, 등급, 조건과 승인 상태가 본문과 다르면 요약본을 배포하지 않는다.

- 기회 식별 정보에는 고객명, 사업자번호와 개인 연락처를 넣지 않는다.
- 검토 범위에는 DSC-01부터 DSC-05 중 실제 완료한 문서 ID만 적는다.
- 판정 등급은 승인된 최종 등급의 명칭을 그대로 사용한다.
- 결정적 근거는 총 3줄로 제한하고 각 줄에 근거 출처를 붙인다.
- 조건 목록은 `조건-책임 부서-기한` 순서로 작성한다.
- 주요 위험은 발생 가능성보다 의사결정 영향이 큰 순서로 적는다.
- 완화 조치는 책임 주체와 확인 시점을 포함한다.
- 미확인 항목이 없으면 공란 대신 `없음`으로 기재한다.
- 승인 칸에는 작성, 검토, 승인 일자를 각각 표시한다.
- 글자 수는 공백과 문장부호를 포함해 계산한다.

### 결정적 근거와 위험 작성 규칙

1. 첫 번째 근거에는 범위·업무 적합성 판단을 기재한다.
2. 두 번째 근거에는 기술·데이터 실현 가능성을 기재한다.
3. 세 번째 근거에는 조직·수행 여력 또는 핵심 위험을 기재한다.
4. 근거가 충돌하면 충돌 사실과 우선 판단 이유를 함께 적는다.
5. 위험 3개는 서로 다른 원인과 영향을 가진 항목으로 선정한다.
6. 완화 조치가 확정되지 않았으면 `미확정`과 확인 기한을 적는다.
7. 조건과 위험이 같은 사안을 다루더라도 조건 충족 기준을 별도로 적는다.

### 제외 내용과 본문 참조

1페이지 요약은 검토 결과를 대체하지 않으며 상세 검토 자료를 포함하지 않는다. 독자가 근거를 추적할 수 있도록 `DSC-06#절 번호 / 표 번호 / 첨부 번호` 형식으로 위치를 표시한다. 링크만 기재하지 않고 문서 ID와 위치를 함께 쓴다.

**1페이지에 넣지 않는 내용**

- 디스커버리 질문과 고객 답변의 전체 원문
- 데이터 표본, 로그와 개인정보 포함 화면
- 아키텍처 구성도와 보안 통제의 상세
- 항목별 계산 과정과 패널 개인별 점수
- 반대 의견의 전체 발언과 제기자 식별 상세
- 수행 사례의 상세 설명과 기술스택 카드
- 제안·가격 소관 문서 계열의 내용
- 첨부 자료의 복사본과 중복 설명

**본문 참조 방법**

- 판정 근거는 본문의 절 번호와 채점표 번호를 함께 적는다.
- 조건은 조건 식별번호와 해제 기준이 있는 위치를 적는다.
- 위험은 위험 식별번호와 완화 계획의 위치를 적는다.
- 미확인 항목은 책임 부서와 확인 예정일이 있는 위치를 적는다.
- 전자 링크가 변경되더라도 식별 가능한 문서 ID를 병기한다.

**배포 전 확인**

- 출력 결과가 A4 세로 1페이지인지 확인한다.
- 등급과 총점이 최종 승인본과 일치하는지 확인한다.
- 결정적 근거가 정확히 3줄인지 확인한다.
- 주요 위험과 완화가 각각 3개인지 확인한다.
- 작성·검토·승인 칸과 작성일이 모두 채워졌는지 확인한다.
