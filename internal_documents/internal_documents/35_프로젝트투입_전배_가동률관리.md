# 프로젝트 투입·전배·가동률 관리 지침
<!--meta: doc=HR-03; doc_type=hr; tier=0; topic=ORG; disclosure=confidential; status=active-->
## 목적과 용어
<!--meta: sec=s1; dept=CNS|AIAX|BE|DATA|SALES; level=주니어|시니어; ct_band=하-->
이 지침은 구성원의 프로젝트 배정, 철수, 비가동 관리와 부서·지점 간 전배를 동일한 기준으로 처리하기 위해 적용합니다. 프로젝트 수요와 구성원의 직무·숙련도·근무 가능 시점을 함께 확인하여 특정 인력의 과부하와 장기 벤치를 줄입니다. 가동률 수치는 개인의 성실성을 판정하는 값이 아니라 인력 배치와 프로젝트 공급 상태를 확인하는 운영 자료로 사용합니다.

| 용어 | 이 지침에서의 의미 |
|---|---|
| 투입 | 구성원이 승인된 프로젝트 업무를 실제로 시작하고 작업시간을 기록하는 상태를 말합니다. |
| 배정 | 투입 전에 프로젝트, 역할, 기간, 예상 투입률과 보고 책임자를 정하는 행위를 말합니다. |
| 상주 | 고객이 지정한 사업장 또는 프로젝트 전용 장소에서 정기적으로 업무를 수행하는 근무 형태를 말합니다. |
| 파견 | 고객 또는 협력사 사업장에서 업무를 수행하도록 보내는 운영상 표현을 말하며, 법률상 근로자파견 해당 여부는 인사담당자가 별도로 검토합니다. |
| 전배 | 소속 부서 또는 근무 지점을 변경하여 인사기록과 지휘·보고 체계를 함께 바꾸는 조치를 말합니다. |
| 철수 | 프로젝트 역할을 종료하고 인수인계와 접근권한 정리를 마친 상태를 말합니다. |
| 벤치 | 프로젝트 철수, 계약 지연 또는 후속 배정 대기로 인해 과금 프로젝트에 배정되지 않은 기간을 말합니다. |
| 가용시간 | 해당 기간의 소정근로시간에서 휴가·휴직·법정휴일에 해당하는 시간을 제외한 값입니다. |
| 과금시간 | 고객 계약과 내부 프로젝트 코드에 따라 고객에게 청구하거나 계약상 대가에 포함되는 실제 작업시간입니다. |
| 내부시간 | 과금시간은 아니지만 승인된 제안 지원, 사전 기술검토, 사내 자산화 또는 교육에 사용한 시간입니다. |

배정은 프로젝트 참여를 예정하는 관리 행위이고 투입은 실제 작업 개시를 의미하므로 두 시점은 일치하지 않을 수 있습니다. 예를 들어 B제조 프로젝트에 7월 1일자로 배정되었더라도 고객 계정 발급이 7월 4일에 완료되어 실제 업무를 시작했다면 7월 1일부터 3일까지를 과금시간으로 기록하지 않습니다. 명목상 배정률도 실제 작업시간을 대신하지 않으며, 프로젝트 작업 기록과 책임자의 확인으로 투입 실적을 확정합니다.

1. 프로젝트 책임자는 배정 시작일 5영업일 전까지 역할, 기간, 예상 주간시간, 근무 장소와 철수 예정일을 등록합니다.
2. 소속 부서장은 구성원의 기존 업무와 합산한 예상 총가동률을 확인한 후 배정을 승인합니다.
3. 다른 부서 또는 지점의 인력을 사용하는 경우 양쪽 부서장 또는 지점 책임자가 작업 지휘자와 비용 귀속을 합의합니다.
4. 구성원은 실제 투입 첫날부터 승인된 프로젝트 코드로 작업시간을 기록하고 배정 내용과 다른 경우 2영업일 내 수정 요청합니다.

REQ-xx는 특정 부서의 충원 필요성과 승인 근거를 다루며, 이 지침은 재직 중인 구성원의 회사 공통 배치와 가동률 기록을 다룹니다. 신규 인력 요청 수치가 승인되었더라도 개인별 프로젝트 배정은 이 지침에 따라 별도로 등록합니다. 반대로 일시적인 벤치가 발생했다는 사유만으로 REQ-xx의 충원 승인을 취소하거나 변경하지 않으며, 인력 수요 변경은 해당 요청서의 변경 절차로 처리합니다.

- 적용 대상은 CNS, AIAX, BE, DATA, SALES 소속의 정규직·계약직 구성원과 프로젝트 업무시간을 기록하는 수습 구성원입니다.
- 고객 프로젝트, 내부 구축 프로젝트, 제안 지원, 사전 기술검토, 공용 기술자산 제작과 승인 교육에 적용합니다.
- 휴직자는 휴직 기간 동안 집계 대상에서 제외하며 복직일부터 다시 가용시간을 계산합니다.
- 외부 협력사 인력은 회사 구성원 가동률에 합산하지 않고 계약별 외부 투입 현황으로 구분합니다.
- 단순 좌석 이동, 같은 부서 내 프로젝트 교체와 10영업일 이하의 타 지점 출장 지원은 전배로 처리하지 않습니다.

상주 또는 파견 형태의 배정에서는 고객이 일상적인 업무지시와 근태승인을 직접 수행하는 구조인지 배정 승인 전에 확인합니다. 법률상 근로자파견 가능성이 있거나 고객 지시 범위가 불명확하면 프로젝트 책임자가 인사담당자에게 검토를 요청하고, 검토 완료 전에는 상주 시작일을 확정하지 않습니다. 전배와 철수의 세부 승인·인수인계 절차는 각 해당 섹션에서 정한 기한을 우선 적용합니다.

## 가동률 산식과 구분
<!--meta: sec=s2; dept=CNS|AIAX|BE|DATA|SALES; level=시니어; ct_band=상-->
가용시간은 집계기간의 소정근로시간에서 휴가, 휴직과 법정휴일에 해당하는 시간을 제외하여 계산합니다. 반차와 시간 단위 휴가는 실제 승인시간만 차감하며, 교육·출장·대기시간은 가용시간에서 차감하지 않고 작업 성격에 따라 과금시간, 인정 내부시간 또는 비인정 시간으로 분류합니다. 가용시간이 0시간인 구성원은 가동률을 0%로 표시하지 않고 집계 대상 제외로 표시합니다.

| 지표 | 산식 | 사용 목적 |
|---|---|---|
| 과금가동률 | 과금시간 ÷ 가용시간 × 100 | 고객 대가와 연결된 인력 활용 수준을 확인합니다. |
| 총가동률 | 과금시간과 인정 내부시간의 합계 ÷ 가용시간 × 100 | 제안·기술준비·자산화 등을 포함한 실제 업무 활용 수준을 확인합니다. |
| 비가동률 | 가용시간에서 과금시간과 인정 내부시간을 뺀 시간 ÷ 가용시간 × 100 | 미배정, 승인 없는 대기와 기록 누락 규모를 확인합니다. |

같은 시간은 하나의 분류에만 기록하며 과금시간과 내부시간에 중복 산입하지 않습니다. 고객 회의 2시간 뒤 동일 프로젝트의 제안 자료를 3시간 작성했다면 계약 범위에 포함되는 고객 회의만 과금시간으로 기록하고, 별도 승인된 제안 작성 3시간은 인정 내부시간으로 기록합니다. 고정가 계약은 해당 월 청구서 발행 여부와 관계없이 계약 범위 내 실제 작업시간을 과금시간으로 분류할 수 있으나, 무상 하자보수나 계약 범위 밖 지원은 계약 책임자의 확인을 거칩니다.

| 내부활동 | 인정 조건 | 증빙 |
|---|---|---|
| 제안 지원 | SALES 요청번호와 제안 책임자 승인이 있고 역할·산출물이 지정된 경우 인정합니다. | 제안 요청번호, 작성 문서 또는 검토 의견을 남깁니다. |
| 사전 기술검토 | 고객 요구 검토, 아키텍처 초안, 데이터 적합성 확인 등 수주 전 기술작업으로 승인된 경우 인정합니다. | 검토 요청, 작업 결과와 투입시간을 남깁니다. |
| 사내 자산화 | 재사용 대상, 완료 기준과 저장 위치를 부서장이 사전에 승인한 경우 인정합니다. | 저장소 링크, 버전 또는 배포 기록을 남깁니다. |
| 교육 | 직무 연관성이 있고 월 시작 전 부서장이 시간 범위를 승인한 경우 인정합니다. | 교육명, 수료 기록과 승인시간을 남깁니다. |

승인 없는 개인 학습, 일반적인 사내 공지 열람, 친목 행사, 기록하지 않은 대기, 개인 용무와 재작업 사유를 확인할 수 없는 반복 작업은 인정 내부시간에 포함하지 않습니다. 부서 정기회의와 회사가 의무 참석으로 지정한 교육은 실제 업무시간으로 관리하되 총가동률 산식의 인정 내부시간에는 포함하지 않고 별도 공통운영시간으로 집계합니다. 장애 대응이 고객 계약 또는 유상 유지보수 범위에 해당하면 과금시간으로 분류하고, 내부 시스템 장애 대응이면 승인된 내부 프로젝트 코드가 있는 경우에만 인정 내부시간으로 분류합니다.

**예시 1 — AIAX 사원 주니어의 월간 계산**

| 항목 | 시간 | 계산 처리 |
|---|---:|---|
| 월 소정근로시간 | 168시간 | 가용시간 계산의 기준으로 사용합니다. |
| 연차휴가 | 8시간 | 가용시간에서 차감합니다. |
| 과금 프로젝트 개발 | 112시간 | 과금시간으로 기록합니다. |
| 승인된 사내 테스트 자산화 | 20시간 | 인정 내부시간으로 기록합니다. |
| 승인 없는 개인 학습 | 6시간 | 비인정 시간으로 분류합니다. |
| 기타 공통운영·대기 | 22시간 | 과금시간과 인정 내부시간에 산입하지 않습니다. |

주니어의 가용시간은 168시간에서 연차 8시간을 뺀 160시간입니다. 과금가동률은 112시간을 160시간으로 나눈 70.0%이며, 총가동률은 132시간을 160시간으로 나눈 82.5%입니다. 승인 없는 개인 학습 6시간은 실제 근무시간 기록에는 남지만 총가동률 분자에는 포함하지 않습니다.

**예시 2 — CNS 차장 시니어의 월간 계산**

| 항목 | 시간 | 계산 처리 |
|---|---:|---|
| 월 소정근로시간 | 176시간 | 가용시간 계산의 기준으로 사용합니다. |
| 법정휴일과 연차휴가 | 16시간 | 가용시간에서 차감합니다. |
| A사 과금 컨설팅 | 96시간 | 과금시간으로 기록합니다. |
| 승인된 C금융 제안 지원 | 32시간 | 인정 내부시간으로 기록합니다. |
| 사전 기술검토 | 16시간 | 인정 내부시간으로 기록합니다. |
| 부서 운영과 미배정 대기 | 16시간 | 총가동률 분자에 포함하지 않습니다. |

시니어의 가용시간은 176시간에서 16시간을 뺀 160시간입니다. 과금가동률은 96시간을 160시간으로 나눈 60.0%이며, 총가동률은 144시간을 160시간으로 나눈 90.0%입니다. 제안 지원과 사전 기술검토의 승인번호가 없다면 해당 48시간은 인정 내부시간에서 제외하고 총가동률을 60.0%로 정정합니다.

개인별 월간 비율은 소수점 둘째 자리에서 반올림하여 소수점 첫째 자리까지 표시합니다. 부서·지점·회사 집계는 개인별 비율의 단순 평균이 아니라 구성원의 과금시간과 인정 내부시간을 각각 합산한 뒤 전체 가용시간으로 나누어 계산합니다. 주간 수치는 잠정치로 표시하고 월 마감 후 수정된 원천기록을 기준으로 확정합니다.

## 직급·부서별 목표 가동률 대역
<!--meta: sec=s3; dept=CNS|AIAX|BE|DATA|SALES; level=시니어; ct_band=상-->
목표 대역은 정상적으로 프로젝트 공급이 이어지는 월에 적용하는 배치 기준입니다. 하한 미만은 즉시 개인 책임으로 판단하지 않고 프로젝트 종료, 계약 지연, 제안 집중기간, 건강상 사유와 입력 누락을 먼저 확인합니다. 상한 초과가 2주 이상 계속되면 야간·휴일근로 여부, 품질검토 시간 부족과 후속 인력 필요성을 점검합니다.

| 직급 | 월 과금가동률 목표 대역 | 인정 내부시간 허용 비중 | 운영상 기대 |
|---|---:|---:|---|
| 사원 | 65~80% | 가용시간의 10~25% | 실무 투입과 승인된 학습·자산화 시간을 함께 확보합니다. |
| 대리 | 70~85% | 가용시간의 10~20% | 독립 수행 비중을 높이되 기술검토와 재사용 자산 제작을 허용합니다. |
| 과장 | 70~85% | 가용시간의 10~20% | 과금 업무와 제안·품질검토 역할을 병행합니다. |
| 차장 | 60~80% | 가용시간의 15~30% | 제안 책임, 다중 프로젝트 검토와 구성원 지원시간을 반영합니다. |
| 부장 | 45~70% | 가용시간의 20~40% | 고객 책임, 수주 지원과 조직 단위 기술·품질 책임을 반영합니다. |

내부시간 허용 비중은 자동으로 인정되는 시간 한도가 아니라 사전 승인된 활동을 배치할 수 있는 범위입니다. 사원이 내부시간 허용 비중 상단을 초과하면 학습계획만 연장하지 않고 10영업일 내 실제 프로젝트 역할 또는 완료 가능한 자산화 과제를 지정합니다. 차장과 부장은 다수 프로젝트의 리뷰를 수행하더라도 프로젝트별 실제 검토시간을 기록하며 직급만을 근거로 정액 시간을 입력하지 않습니다.

SALES 구성원이 유상 컨설팅 계약의 명시된 역할을 수행하는 예외 상황에서는 계약 책임자와 SALES 부서장이 사전에 범위와 시간을 승인합니다. 이 경우 해당 시간은 프로젝트 과금시간으로 기록할 수 있지만 SALES 전체의 목표 가동률 대역을 새로 설정하지 않습니다. 영업상 고객 방문, 견적 협의와 계약 조율은 프로젝트 수주 활동으로 관리하며 과금가동률에 포함하지 않습니다.

완화기간에도 가용시간과 실제 작업시간은 동일한 방식으로 기록하며 목표 대역만 조정합니다. 신규 입사자가 입사 즉시 100% 프로젝트에 배정되더라도 필수 안내, 개발환경 설정과 역할 인수시간을 과금시간으로 임의 전환하지 않습니다. 완화기간 연장이 필요하면 소속 부서장이 종료 3영업일 전까지 사유, 새 배정 일정과 연장기간을 인사담당자에게 제출하며 연장은 1회, 최대 20영업일까지 허용합니다.

## 가동률을 해석할 때의 주의
<!--meta: sec=s4; dept=CNS|AIAX|BE|DATA|SALES; level=시니어; ct_band=상-->
가동률은 투입시간의 구성 비율을 나타내며 산출물 품질, 고객 만족, 납기 준수 또는 문제 해결 수준을 단독으로 증명하지 않습니다. 과금가동률 90%인 구성원이 반복적인 결함으로 재작업을 발생시켰다면 높은 가동률을 성과 우수의 근거로 사용하지 않습니다. 반대로 제안 기술검토와 공용 자산 제작을 맡아 과금가동률이 낮은 구성원은 승인된 결과물과 후속 수주·재사용 효과를 함께 확인합니다.

가동률을 높이기 위해 실제보다 많은 시간을 과금 코드에 입력하도록 요구하거나, 고객 업무와 무관한 시간을 프로젝트에 배분하는 운영을 금지합니다. 프로젝트 책임자는 “이번 달 목표가 부족하니 남는 시간을 A사 코드에 넣으십시오”와 같은 지시를 해서는 안 됩니다. 구성원이 이러한 지시를 받으면 입력하지 않고 소속 부서장과 인사담당자에게 당일 또는 다음 영업일까지 알리며, 이미 입력한 경우 수정 이력을 남겨 정정합니다.

명목 배정률은 인력계획 수치이고 실제 검토시간은 작업기록 수치이므로 서로 다를 수 있습니다. 예를 들어 차장이 B제조 프로젝트에 20% 배정되어 있더라도 해당 주에 설계 검토를 4시간만 수행했다면 40시간의 20%인 8시간을 자동 입력하지 않습니다. 반대로 긴급 검토로 12시간을 사용했다면 실제 12시간을 기록하고 프로젝트 책임자가 배정률 초과 사유와 다음 주 조정안을 확인합니다.

| 해석 장면 | 확인할 자료 | 판단 방식 |
|---|---|---|
| 과금가동률은 높지만 일정이 지연된 경우 | 결함 건수, 재작업시간, 고객 승인일을 확인합니다. | 투입량과 납기·품질을 분리하여 판단합니다. |
| 총가동률은 높고 과금가동률은 낮은 경우 | 제안 승인번호, 자산 저장소와 교육 승인을 확인합니다. | 내부시간의 사업 필요성과 결과물 완성도를 확인합니다. |
| 동일 직급 간 편차가 큰 경우 | 프로젝트 공급 시점, 계약 지연과 역할 차이를 확인합니다. | 개인 비교보다 배정 기회 차이를 먼저 조정합니다. |
| 월말에 가동률이 급상승한 경우 | 일별 입력일, 수정 이력과 승인일을 확인합니다. | 소급 입력의 사실성과 중복 여부를 검증합니다. |

가동률을 인사평가 등급으로 직접 환산하지 않습니다. 과금가동률이 목표 상단을 넘었다는 이유만으로 높은 평가등급을 부여하지 않으며, 하단 미만이라는 이유만으로 낮은 평가등급을 부여하지 않습니다. 인사평가에서는 정해진 목표와 역할에 따른 결과 및 행동 증거를 사용하고, 가동률은 배치 기회와 업무량 맥락을 설명하는 보조자료로만 제공합니다.

가동률은 다음 달 인력 배치, 제안 참여 가능 인원, 계약 시작 지연의 영향과 채용 필요 시점을 판단하는 운영 지표로 사용합니다. 부서장은 월간 과금가동률이 하한보다 10%p 이상 낮은 인원이 3명 이상이면 개인별 사유를 묶어 프로젝트 공급 문제인지 역할 불일치인지 구분합니다. 상한을 5%p 이상 초과한 인원이 부서 인원의 20%를 넘으면 신규 투입보다 업무 재분배와 일정 재협상을 먼저 검토합니다.

**지표 왜곡 신호는 다음과 같이 확인합니다.**

1. 월 마지막 2영업일에 해당 월 전체 작업시간의 30% 이상이 일괄 입력되면 기억에 의존한 소급 기록 가능성을 확인합니다.
2. 서로 다른 프로젝트에 같은 시간대가 중복 기록되거나 하루 기록이 승인된 근무시간을 반복적으로 초과하면 원천기록을 대조합니다.
3. 배정 시작 전이나 철수 완료 후에도 과금시간이 계속 발생하면 실제 작업 요청과 계약 범위를 확인합니다.
4. 산출물·회의기록·코드 변경 없이 동일한 내부활동이 매주 같은 시간으로 기록되면 정액 입력 여부를 점검합니다.
5. 부서의 과금가동률은 상승했지만 매출 대상 프로젝트 수와 계약상 투입규모가 변하지 않았다면 코드 분류 변경이나 비과금 업무 전환 여부를 확인합니다.

왜곡 신호가 발견되었다고 곧바로 고의로 판단하지 않으며 프로젝트 책임자가 3영업일 내 사실관계와 수정 필요 여부를 확인합니다. 단순 코드 선택 오류는 원기록을 정정하고, 반복 오류는 기록 기준을 다시 안내한 뒤 다음 월에 재점검합니다. 허위 입력 지시나 의도적 중복 산입 정황이 있으면 인사담당자가 관련 기록을 보존하고 별도 사실확인 절차로 이관합니다.

## 집계 주기와 데이터 출처

가동률은 주간 잠정 집계, 월간 확정 집계와 분기 추세 집계로 구분합니다. 주간 집계는 다음 2주 내 배정 공백과 과부하를 조정하는 데 사용하고, 월간 집계는 개인·프로젝트·부서별 실제 활용시간을 확정하는 데 사용합니다. 분기 집계는 단일 월의 계약 지연이나 휴가 집중 영향을 분리하여 지점·부서 간 인력 이동과 채용 검토 자료로 사용합니다.

주간 잠정 수치는 미승인 시간과 향후 배정계획을 포함할 수 있으므로 대외 보고나 개인별 확정값으로 사용하지 않습니다. 월간 확정 이후 계약 범위 또는 근태 기록이 변경되면 인사담당자가 수정 사유와 승인자를 기록하고 다음 달 보고서에 전월 수정분을 표시합니다. 분기 집계에서는 월별 분자와 분모를 합산하여 다시 계산하며 세 달의 가동률을 단순 평균하지 않습니다.

| 내부활동 승인 기록 | 제안, 기술검토, 자산화와 교육의 승인시간을 포함합니다. | 활동 요청자가 시작 전에 등록합니다. | 소속 부서장 또는 지정 승인자가 결과물을 확인합니다. |
| 배정·전배 기록 | 배정기간, 예상 투입률, 소속 변경일과 철수일을 포함합니다. | 프로젝트 책임자 또는 인사담당자가 구분하여 입력합니다. | 양쪽 부서장이 변경일과 인수인계를 확인합니다. |

구성원은 작업 당일 기록을 원칙으로 하며 부득이한 경우 다음 영업일 12시까지 입력합니다. 프로젝트 책임자는 매주 월요일 18시까지 전주 기록의 프로젝트 코드, 중복시간과 산출물 참조를 확인합니다. 소속 부서장은 월 종료 후 3영업일 15시까지 내부시간 승인 여부와 미배정 사유를 확정하고, 인사담당자는 5영업일 18시에 월간 집계를 잠급니다.

마감 전 계약 정보가 확정되지 않은 시간은 임시 과금시간으로 처리하지 않고 검토대기 코드에 기록합니다. 계약 담당자가 다음 달 3영업일까지 유상 범위를 확인하면 과금시간 또는 비과금시간으로 재분류합니다. 확인이 끝나지 않은 시간은 월간 과금가동률 분자에서 제외하며, 계약이 소급 확정된 경우 승인 근거와 수정일을 남기고 다음 집계에 반영합니다.

입력이 늦어진 구성원은 마감 후 2영업일 내 지연 사유와 실제 작업 근거를 프로젝트 책임자에게 제출합니다. 프로젝트 책임자가 근거를 확인하면 인사담당자가 잠금 해제를 승인하며, 단순 목표 대역 충족을 위한 수정은 허용하지 않습니다. 동일 구성원이 분기 내 3회 이상 마감에 늦으면 소속 부서장이 기록 장애, 업무 과부하 또는 기준 미숙지 중 원인을 확인하고 다음 달 첫 주에 개선조치를 지정합니다.

- 구성원은 본인의 상세 작업기록과 소속 프로젝트의 본인 배정정보를 열람합니다.
- 프로젝트 책임자는 담당 프로젝트 참여자의 배정기간, 작업시간과 활동유형을 열람합니다.
- 부서장은 소속 구성원의 개인별 자료와 다른 부서에서 제공한 인원의 해당 프로젝트 기록을 열람합니다.
- 지점 책임자는 해당 지점의 개인별 가동률과 부서별 집계자료를 열람합니다.
- 인사담당자는 회사 전체의 근태·배정·가동률 자료와 수정 이력을 열람합니다.
- 경영진에게는 회사·부서·지점 집계와 장기 벤치 현황을 제공하며 개인 상세 작업내용은 업무상 필요한 경우에만 제공합니다.

개인별 가동률 파일을 메신저 공개 채널이나 전체 구성원 공용 폴더에 게시하지 않습니다. 부서 간 인력 요청에는 이름 대신 직급, 직무, 가능 시작일과 최근 4주 예상 가용시간을 우선 제공하고 후보 확정 단계에서 필요한 범위만 공유합니다. 집계자료의 다운로드본에는 작성일과 열람대상을 표시하며, 열람 권한 변경은 소속 변경일 또는 역할 종료일부터 2영업일 내 반영합니다.

## 투입요청과 후보 매칭
<!--meta: sec=s6; dept=CNS|AIAX|BE|DATA|SALES; level=시니어; ct_band=중-->
프로젝트 책임자 또는 부서장은 투입 희망일 15영업일 전까지 인력관리 시스템에 투입요청서를 등록합니다. 제안 단계처럼 착수일이 확정되지 않은 경우에는 예상 개시일과 확정 예정일을 함께 적습니다. 구두·메신저 요청은 후보 탐색의 근거로 사용하지 않으며, 긴급 요청도 당일 내 요청서를 등록해야 합니다.

투입요청서에는 다음 항목을 빠짐없이 작성합니다.

| 항목 | 작성 기준 | 작성 예시 |
|---|---|---|
| 필요 역할 | 직무명이 아니라 수행 책임과 의사결정 범위를 적습니다 | B제조 수요예측 모델의 피처 설계와 검증 책임 |
| 필수 기술 | 투입 첫날부터 독립 수행해야 하는 기술만 적습니다 | Python, 시계열 교차검증, SQL 실행계획 판독 |
| 우대 기술 | 인수인계 또는 투입 후 학습으로 보완할 수 있는 기술을 구분합니다 | 컨테이너 운영 경험, 제조 데이터 경험 |
| 기간 | 시작일·종료일과 연장 가능성을 적습니다 | 7월 6일~10월 30일, 최대 4주 연장 가능 |
| 투입률 | 주 단위 배정률과 변동 구간을 적습니다 | 1~2주 50%, 3주차 이후 100% |
| 수행 지점 | 서울·경기·인천 지점, 고객사 상주지 또는 원격 여부를 적습니다 | 경기 지점 주 3일, A사 사업장 주 2일 |
| 보안 요건 | 고객이 요구한 사전 승인·교육·접근 제한을 적습니다 | 반입 장비 등록, 폐쇄망 계정 발급 필요 |
| 대체 가능성 | 직급·직무·투입률 중 조정 가능한 조건을 적습니다 | 과장 우선이나 대리도 가능, 시작일 1주 조정 가능 |

인사담당자는 접수 후 2영업일 내 필수 항목과 기존 배정 충돌을 확인합니다. 정보가 부족하면 요청자에게 보완 항목과 회신 기한을 지정하며, 보완 전에는 후보 명단을 확정하지 않습니다. 착수까지 10영업일 미만인 요청은 긴급 사유와 지연 발생 경위를 추가로 받아 배치 회의 안건에 올립니다.

정기 배치 회의는 매주 수요일에 개최하며, 화요일 12시까지 접수·보완된 요청을 검토합니다. 참석자는 각 부서장 또는 지정 차장 이상, 인사담당자와 필요한 프로젝트 책임자로 구성합니다. 회의에서는 향후 8주 내 개시 예정 요청, 종료 예정 프로젝트 인력, 주당 20% 이상 가용 가능성이 생기는 구성원을 함께 확인합니다.

후보 매칭은 아래 순서를 적용하며, 앞 단계에서 요건을 충족하지 못한 후보를 다음 기준만으로 우선 선정하지 않습니다.

1. 필수 역량 충족 여부를 실제 수행 산출물, 최근 프로젝트 역할과 기술 인터뷰 기록으로 확인합니다. 자격증 보유만으로 필수 역량 충족을 판정하지 않습니다.
2. 가용 시점은 기존 프로젝트의 승인된 종료일, 인수인계 기간과 이미 확정된 휴가를 반영합니다. 이전 업무가 남아 있는 상태에서 명목상 종료일만으로 가용하다고 판단하지 않습니다.
3. 성장 기회는 해당 구성원의 직급 기대보다 한 단계 넓은 책임을 맡되 시니어 검토가 가능한지를 기준으로 봅니다. 동일 유형 업무를 최근 12개월 동안 2회 이상 반복했다면 새로운 도메인 또는 책임 범위를 우선 검토합니다.
4. 지점 근접성은 주당 이동 횟수, 편도 이동시간과 고객 대면 빈도를 함께 비교합니다. 기술 적합성이 낮은 후보를 이동 편의만으로 배정하지 않습니다.
5. 고객 요구는 계약서 또는 공식 협의 기록에 명시된 경력·등급·상주 조건만 반영합니다. 고객의 막연한 선호나 특정 구성원 지목은 독립적인 우선 기준으로 인정하지 않습니다.

후보에게는 확정 전 프로젝트명, 역할, 예상 기간, 투입률과 근무지를 제공하고 수행 곤란 사유를 확인합니다. 건강정보나 가족관계처럼 배정 판단에 불필요한 개인정보의 제출을 요구하지 않습니다. 일정 충돌이나 기존 인수인계 누락을 제기한 경우 프로젝트 책임자가 사실을 확인한 뒤 후보 상태를 갱신합니다.

동일 후보가 둘 이상의 요청에 경합하면 관련 부서장들이 고객 착수 확정성, 계약상 지연 영향, 대체 후보 유무와 기존 약속 시점을 비교합니다. 합의되지 않으면 인사담당자가 비교표를 작성하고 담당 부문장이 최종 조정합니다. 서로 다른 지점 또는 부문장이 관련된 경합은 대표가 지정한 인력배치 책임자가 결정하며, 먼저 요청했다는 이유만으로 자동 우선권을 부여하지 않습니다.

다음 사유에 해당하면 요청을 보류합니다.

- 필수 역할과 산출물이 구분되지 않아 필요한 역량을 판단할 수 없는 경우에는 요청자가 3영업일 내 범위를 보완하도록 합니다.
- 계약 또는 내부 착수 승인 여부가 불명확한데 전일제 배정을 요구하는 경우에는 확정 예정일까지 조건부 수요로 관리합니다.
- 기존 배정을 종료하지 않은 채 동일 기간 투입률 합계가 상한을 넘는 경우에는 우선순위와 감축 대상을 먼저 정하도록 합니다.
- 보안 요건을 충족할 준비기간이 확보되지 않은 경우에는 계정·교육·출입 승인 완료 가능일을 다시 산정합니다.
- 직급만 지정하고 해당 직급이 필요한 책임 또는 고객 조건을 제시하지 않은 경우에는 역할 수준을 재작성하도록 합니다.

필수 역량 보유자가 없거나 개시일까지 인수인계를 완료할 수 없으면 요청을 거절할 수 있습니다. 거절 결정에는 검토한 후보 범위, 충족하지 못한 조건과 가능한 대체안을 기록합니다. 요청자는 결정 통보 후 2영업일 내 조건을 변경하여 재요청하거나 인력배치 책임자에게 재검토를 요청할 수 있습니다.

## 투입 확정과 개시 절차
<!--meta: sec=s7; dept=CNS|AIAX|BE|DATA|SALES; level=주니어|시니어; ct_band=중-->
투입 확정은 개시일 2주 전까지 구성원과 양쪽 책임자에게 서면 통보하는 것을 원칙으로 합니다. 통보서에는 프로젝트 코드, 역할, 배정기간, 주별 투입률, 근무지, 보고 대상과 인수인계 담당자를 포함합니다. 고객 계약 지연으로 확정이 어려우면 확정 예정일과 그때까지 수행할 내부 업무를 별도로 지정합니다.

개시 2주 이내에 결정된 긴급 투입은 프로젝트 책임자가 단축 사유와 준비 누락 위험을 적어 소속 부서장 승인을 받습니다. 준비기간 단축을 이유로 보안교육이나 계정 승인 절차를 생략하지 않습니다. 시작일까지 필수 접근권한을 확보할 수 없으면 실제 작업 가능일을 기준으로 배정기간과 산출물 일정을 조정합니다.

소속 부서장 또는 지정 시니어는 확정 통보 전후 2영업일 내 본인과 20분 이상 사전 면담을 진행합니다. 면담 결과는 인력관리 시스템에 기록하며, 구성원이 질문하거나 이견을 제기할 시간을 포함합니다. 주니어에게는 역할명만 전달하지 않고 첫 2주 동안 독립 수행할 범위와 검토를 받아야 하는 범위를 나눠 설명합니다.

| 면담 항목 | 확인 내용 |
|---|---|
| 역할 | 본인이 책임지는 작업, 승인받아야 하는 결정과 제외 업무를 확인합니다 |
| 기간 | 개시일·종료일, 연장 가능성과 종료 판단일을 확인합니다 |
| 근무지 | 지점·고객사·원격 일정을 요일 단위로 확인합니다 |
| 기대 산출물 | 첫 산출물의 형식, 제출일, 검토자와 완료 기준을 확인합니다 |
| 협업 구조 | 프로젝트 책임자, 실무 리더, 고객 창구와 장애 보고 대상을 확인합니다 |
| 복귀 시점 | 원소속 복귀 예정일과 종료 전 인수인계 기간을 확인합니다 |
| 기존 업무 | 넘겨야 할 업무, 인계받는 사람과 완료 기한을 확인합니다 |

투입 확정 후 프로젝트 책임자는 개시 준비표의 항목별 담당자와 완료 예정일을 지정합니다. 구성원 본인에게 계정 발급이나 고객 승인 전체를 맡기지 않으며, 요청 주체가 필요한 신청을 시작합니다. 완료 여부는 링크, 승인번호 또는 교육 이수기록처럼 확인 가능한 근거로 표시합니다.

- 사내 프로젝트 계정과 작업 저장소 권한은 개시 전 영업일까지 발급합니다. 권한 범위는 맡은 역할에 필요한 수준으로 신청합니다.
- 필수 보안교육과 고객이 요구한 별도 교육은 고객 시스템 접근 전에 완료합니다. 미이수자는 교육 완료 전까지 비식별 자료를 사용하는 준비업무만 수행합니다.
- 고객사 출입증·방문등록은 최초 방문 2영업일 전까지 신청합니다. 승인이 지연되면 원격 수행 가능 업무와 방문 일정 변경안을 정합니다.
- 지급 장비와 개발환경은 개시 전 작동 여부를 확인합니다. 고객 전용 장비가 늦어지면 대체 장비에 고객 자료를 임의 저장하지 않습니다.
- NDA 또는 프로젝트별 비밀유지 서약이 필요한 경우 서명 주체와 적용 범위를 확인합니다. 서명 완료 전 제한자료 열람을 허용하지 않습니다.
- 기존 업무 인수인계는 항목, 후임자, 미결사항과 참조 위치를 남깁니다. 인계 완료 여부는 기존 프로젝트 책임자가 확인합니다.

투입 첫날 프로젝트 책임자는 60분 이내의 착수 안내를 실시합니다. 안내에는 프로젝트 목표, 현재 단계, 2주 일정, 의사결정 체계, 정기회의와 고객 커뮤니케이션 방식을 포함합니다. 구성원이 첫날 수행할 수 있는 구체 작업과 질문할 담당자를 지정하지 않은 상태로 대기시키지 않습니다.

첫 주에는 다음 항목을 점검합니다.

1. 개시 후 2영업일에 계정·데이터·저장소 접근이 실제로 가능한지 확인합니다. 권한만 발급되고 실행환경이 작동하지 않는 경우도 미완료로 처리합니다.
2. 예정 투입률과 실제 요청 업무량의 차이를 확인합니다. 계획보다 20%p 이상 높은 상태가 3영업일 이어지면 업무 우선순위를 다시 정합니다.
3. 첫 산출물의 입력자료, 예시 결과물과 검토 일정을 확인합니다. 완료 기준이 불명확하면 제출 전에 책임자와 합의하여 기록합니다.
4. 보고 라인이 둘 이상일 때 상충 지시가 있었는지 확인합니다. 상충 시 프로젝트 책임자가 당일 우선순위를 한 가지로 확정합니다.
5. 고객 대면 역할과 내부 역할이 사전 면담 내용과 일치하는지 확인합니다. 단순 명칭 차이가 아니라 책임 범위가 달라졌다면 재조정 대상으로 등록합니다.

투입 조건이 사전 설명과 다르면 구성원은 차이를 발견한 날부터 2영업일 내 프로젝트 책임자에게 역할·기간·근무지·산출물 중 변경된 항목과 업무 영향을 전달합니다. 프로젝트 책임자는 2영업일 내 유지, 수정 또는 추가 확인 중 하나로 답변합니다. 당사자 간 해결되지 않으면 소속 부서장에게 올리고, 소속 부서와 수행 부서의 의견이 다르면 인사담당자가 조정 회의를 잡습니다.

즉시 안전이나 법적 위험이 발생하는 사안이 아니라면 구성원이 임의로 업무를 중단하지 않습니다. 다만 승인받지 않은 고객 시스템 접근, 설명되지 않은 제한자료 반출 또는 계약 범위를 벗어난 대외 확약을 요구받으면 해당 행위를 보류하고 당일 프로젝트 책임자와 소속 부서장에게 알립니다. 재조정 결과는 투입률, 일정 또는 역할 변경일과 함께 시스템에 반영합니다.

첫 주 점검은 개시 후 5영업일까지 프로젝트 책임자가 완료하고 구성원이 확인합니다. 확인되지 않은 문제는 담당자와 해결 기한을 지정하며, 단순히 “적응 중”으로 종결하지 않습니다. 해결 기한이 다음 주를 넘으면 소속 부서장이 배정 유지 가능성을 검토합니다.

## 다중 프로젝트 배정 한도
<!--meta: sec=s8; dept=CNS|AIAX|BE|DATA|SALES; level=시니어; ct_band=상-->
동시 참여 프로젝트는 같은 주에 10% 이상의 배정시간이 예정된 고객 프로젝트와 내부 구축 프로젝트를 기준으로 계산합니다. 월 1회 자문처럼 주당 2시간 이하이고 정기 산출물 책임이 없는 활동은 참여 수에서 제외하되 실제 시간은 기록합니다. 제안 지원이 매주 반복되거나 특정 결과물의 납기를 책임지면 별도 프로젝트로 계산합니다.

| 구분 | 원칙적 동시 참여 상한 | 허용 조건 |
|---|---:|---|
| 주니어 | 1개 | 학습·지원 성격의 두 번째 프로젝트를 포함하여 최대 2개까지 허용합니다 |
| 시니어 실무자 | 2개 | 각 프로젝트의 우선순위와 의사결정자가 명확하면 최대 3개까지 허용합니다 |
| 프로젝트 책임자 | 3개 | 주간 의사결정 시간을 확보하고 실무 산출물 책임이 중복되지 않아야 합니다 |
| 단기 전문가 자문 | 3개 | 프로젝트별 주당 10% 이하이며 호출 가능 시간대를 사전 지정해야 합니다 |

주니어를 2개 프로젝트에 배정할 때는 주된 프로젝트를 70% 이상으로 설정합니다. 두 프로젝트 모두 고객 납기 산출물을 독립적으로 맡기는 방식은 허용하지 않습니다. 시니어의 세 번째 프로젝트는 검토·설계·장애 대응처럼 범위가 제한된 역할이어야 하며, 일상 개발과 고객 보고를 동시에 맡기지 않습니다.

확정 배정률 합계는 정상 근무 가능시간의 100%를 넘지 않도록 합니다. 아직 수주되지 않은 제안이나 개시일이 미정인 업무는 확정 배정과 겹쳐 100%를 초과하도록 예약하지 않고 조건부 수요로 표시합니다. 휴가·교육·필수 내부업무가 예정된 주에는 해당 시간을 제외한 실제 가능시간을 기준으로 작업량을 정합니다.

프로젝트별 배정률이 20% 미만이면 주 1일에도 미치지 않아 맥락 전환과 회의 대기 비중이 커질 수 있습니다. 10~20% 배정은 코드 검토, 모델 검증 또는 특정 문서 승인처럼 경계가 분명한 역할에만 사용합니다. 연속 작업이 필요한 개발·분석 업무를 20% 미만으로 4주 이상 배정하려면 프로젝트 책임자가 작업 단위를 주 단위로 묶는 계획을 제출합니다.

하루에 세 프로젝트의 정기회의가 배치되거나 오전·오후 사이 프로젝트 전환이 2회를 넘으면 생산성 저하 구간으로 봅니다. 이런 일정이 주 2일 이상 발생하면 회의를 통합하거나 프로젝트별 집중 요일을 정합니다. 단순히 개인에게 시간관리를 요구하는 것으로 조치를 대신하지 않습니다.

분할 투입을 승인할 때는 구성원별 우선순위 결정권자를 한 명 지정합니다. 통상 가장 높은 배정률의 프로젝트 책임자가 담당하며, 배정률이 같으면 관련 부서장들이 지정합니다. 결정권자의 이름, 대리자와 응답기한을 배정정보에 기록하지 않으면 다중 배정을 확정하지 않습니다.

업무 충돌이 발생하면 다음 순서로 처리합니다.

1. 구성원은 충돌한 산출물, 각각의 마감일과 필요한 시간을 두 프로젝트 책임자에게 같은 메시지로 전달합니다. 어느 한쪽과만 협의한 뒤 다른 일정이 자동 연기된 것으로 간주하지 않습니다.
2. 우선순위 결정권자는 고객 서비스 중단 위험, 계약상 마감, 선행작업 차단 여부와 대체 인력을 비교합니다. 요청 접수 후 4근무시간 내 실행 순서를 통보합니다.
3. 미뤄지는 프로젝트 책임자는 새 마감일과 영향받는 후속 작업을 기록합니다. 구성원 개인에게 일정 지연 책임을 전가하지 않습니다.
4. 같은 주에 두 번째 충돌이 발생하면 소속 부서장이 배정률 또는 참여 프로젝트 수를 조정합니다. 회의시간만 옮기고 작업량을 유지하는 조정은 해결로 보지 않습니다.

긴급 지원은 운영 장애, 고객 서비스 중단 또는 납기 당일의 중대한 결함처럼 즉시 대응하지 않으면 손실이 확대되는 경우에 요청합니다. 단순 문의, 예정된 검토 또는 미리 알 수 있었던 인력 부족을 긴급 지원으로 표시하지 않습니다. 긴급 요청자는 필요한 기술, 예상 시간, 종료 조건과 기존 업무 중단 영향을 함께 제시합니다.

동일 구성원에게 긴급 지원이 4주 동안 3회 발생하거나 누적 16시간을 넘으면 재계획을 시작합니다. 같은 프로젝트에서 월 2회 이상 긴급 지원을 요청한 경우에는 프로젝트 책임자가 상시 역할 전환, 당직성 대응 범위 또는 지식 이전 계획 중 하나를 제시합니다. 재계획 전까지 추가 긴급 요청은 소속 부서장 승인을 받아야 합니다.

정기회의, 고객회의, 준비회의와 회의 후 의사결정 정리는 해당 프로젝트 배정시간에 포함합니다. 여러 프로젝트가 함께 참여하는 공통회의는 회의 목적을 주도한 프로젝트에 기록하고, 프로젝트별 안건이 분리되어 있으면 실제 안건 시간에 따라 나눕니다. 이동 중 청취처럼 실질 참여가 어려운 시간을 회의 수행시간으로 중복 기록하지 않습니다.

주당 회의시간이 해당 프로젝트 배정시간의 30%를 초과하면 프로젝트 책임자가 참석자와 주기를 검토합니다. 구성원이 정보 공유만 받는 회의는 회의록 열람으로 대체하고, 의사결정 권한이 없는 회의에는 필요한 안건 시간만 참석하도록 조정합니다. 회의 감축 후에도 작업시간이 부족하면 배정률 자체를 변경합니다.

다중 배정 현황은 소속 부서장이 격주로 확인합니다. 검토 대상은 참여 수 상한 초과, 20% 미만 장기 배정, 반복 충돌과 긴급 지원 트리거입니다. 예외를 유지할 경우 종료일, 보호할 핵심 업무와 재검토일을 지정하며 예외 기간은 한 번에 4주를 넘기지 않습니다.

## 지점 간 파견과 상주 운영
<!--meta: sec=s9; dept=CNS|AIAX|BE|DATA; level=주니어|시니어; ct_band=상-->
서울·경기·인천 지점 간 파견은 소속 지점을 유지하면서 일정 기간 다른 지점 또는 해당 지점이 담당하는 고객 현장에서 근무하는 배정을 말합니다. 단순 회의 참석이나 2영업일 이내의 일회성 방문은 파견으로 등록하지 않습니다. 주 3일 이상 다른 지점에서 근무하는 일정이 2주를 넘으면 지점 간 파견 절차를 적용합니다.

파견 요청자는 시작일 15영업일 전까지 파견요청서를 등록합니다. 요청서에는 대상 역할, 파견지, 기간, 주별 출근일, 현지 책임자, 상주 필요 사유, 원격 대체 가능성과 종료 후 복귀 계획을 포함합니다. 고객 요청이 근거라면 공식 요청 기록 또는 계약상 근무 조건을 첨부합니다.

인사담당자는 접수 후 2영업일 내 근무지 변경 범위, 기존 배정과의 충돌, 본인 안내 필요사항을 확인합니다. 소속 부서장은 대체 인력과 기존 업무 인계 가능성을 검토하고, 수요 지점 책임자는 현지 업무·좌석·장비 준비 책임자를 지정합니다. 본인 면담 없이 지점 간 파견을 확정하지 않습니다.

| 기간 구분 | 기준 | 승인 단계 |
|---|---|---|
| 단기 파견 | 연속 4주 이내입니다 | 양 지점 부서장과 본인 확인 후 확정합니다 |
| 중기 파견 | 4주 초과 12주 이내입니다 | 양 지점 부서장, 양 지점 책임자와 인사담당자 검토를 거칩니다 |
| 장기 파견 | 12주 초과입니다 | 중기 승인자 검토 후 담당 부문장 승인을 받습니다 |
| 기간 미정 상주 | 종료 조건만 있고 날짜가 정해지지 않은 경우입니다 | 장기 파견과 동일하게 승인하고 8주마다 계속 여부를 재검토합니다 |

단기 파견의 연장은 누적기간으로 구분합니다. 4주 단기 파견을 3주 연장하면 중기 파견 승인 절차를 다시 거칩니다. 종료 직전에 반복 연장하여 상위 승인 단계를 피하지 않으며, 연장 요청은 기존 종료일 10영업일 전까지 등록합니다.

중기·장기 파견 전 면담에서는 통상 근무지, 출퇴근 가능시간, 고객사 출입 조건, 원격근무 가능일과 복귀 예정일을 확인합니다. 구성원이 제시한 현실적인 이동 제약은 양 지점 책임자가 일정 조정 가능성과 함께 검토합니다. 합의한 근무지가 근로계약 또는 취업규칙상 조건에 영향을 주는지는 인사담당자가 별도로 확인합니다.

파견 중 업무 지시는 현지 프로젝트 책임자가 담당하고, 근태 승인과 휴가 일정 조정은 원소속 부서장이 담당합니다. 고객 현장의 출입기록을 회사 근태기록으로 자동 대체하지 않으며, 구성원은 회사가 지정한 방식으로 근무 시작·종료를 기록합니다. 일정 변경으로 고객 출근일과 지점 출근일이 바뀌면 현지 책임자와 원소속 부서장에게 전 영업일까지 알립니다.

성과에 관한 일상 관찰은 현지 프로젝트 책임자가 기록합니다. 원소속 부서장은 월 1회 현지 책임자로부터 역할 수행, 산출물 품질, 협업상 문제와 지원 필요사항을 확인합니다. 평가기간이 끝나기 전에 파견이 종료되면 현지 책임자는 종료 후 5영업일 내 사실 중심의 수행 의견을 원소속 부서장에게 전달합니다.

현지 프로젝트 책임자는 상주 인력과 주 1회 15분 이상 업무 점검을 실시합니다. 원소속 부서장은 중기 파견자와 월 1회, 장기 파견자와 최소 월 1회 별도 면담하여 업무량, 이동 부담, 역할 변동과 복귀 준비를 확인합니다. 면담에서 제기된 조치사항에는 담당자와 기한을 지정합니다.

파견 중 보고 라인이 충돌하면 구성원은 양쪽 지시의 작업량과 마감일을 함께 제시합니다. 현지 프로젝트 책임자와 원소속 부서장은 당일 업무 우선순위를 합의하며, 합의되지 않으면 양 지점 책임자가 다음 영업일 12시까지 결정합니다. 고객이 직접 추가 업무를 요청한 경우에도 현지 프로젝트 책임자를 거쳐 배정 범위를 변경합니다.

비가동 중 새 프로젝트 후보가 생기면 기존 내부 과제를 즉시 중단하지 않고 인계 가능한 단위까지 정리합니다. 부서장은 후보 면접이나 기술검증에 필요한 시간을 우선 확보하고 내부 과제의 마감일을 조정합니다. 투입이 무산되면 해당 사유와 다음 검토일을 기록하되 구성원에게 같은 준비자료를 반복 작성하도록 요구하지 않습니다.

## 철수와 롤오프 절차
<!--meta: sec=s11; dept=CNS|AIAX|BE|DATA|SALES; level=주니어|시니어; ct_band=중-->
철수는 구성원의 프로젝트 투입을 종료하고 책임과 접근권한을 정리하는 절차입니다. 정상 종료, 고객 일정이나 계약 범위 변경에 따른 조기 종료, 역할 부적합이나 운영상 필요에 따른 교체로 구분합니다. 투입률만 낮추고 핵심 책임을 그대로 유지하는 경우에는 철수로 처리하지 않습니다.

| 철수 유형 | 내부 통보 시한 | 고객 협의 기준 |
|---|---|---|
| 정상 종료 | 예정 종료일 10영업일 전까지 구성원과 원소속 부서장에게 알립니다 | 계약상 통보기한을 우선 적용하며 담당자 변경 여부를 함께 안내합니다 |
| 조기 종료 | 종료 필요성을 안 날부터 2영업일 내 알리고 원칙적으로 5영업일 이상의 인계기간을 둡니다 | 고객 요청일, 잔여 범위와 비용 영향은 프로젝트 책임자가 확인합니다 |
| 교체 | 교체 결정 전 구성원에게 사유와 확인 일정을 알리고 결정 후 1영업일 내 종료예정일을 통보합니다 | 후임자의 투입일과 대외 설명 문구를 합의한 뒤 안내합니다 |

보안사고 의심, 고객의 즉시 접근 차단 요구처럼 계속 투입이 곤란한 경우에는 사전 통보기간을 단축할 수 있습니다. 이 경우 프로젝트 책임자는 단축 사유, 임시 인수자와 남은 인계 방법을 당일 기록합니다. 즉시 철수가 구성원의 귀책을 확정하는 절차로 사용되어서는 안 되며 사실 확인은 별도로 진행합니다.

철수 통보에는 마지막 근무일, 인계 대상, 인수자, 고객 안내 담당자와 계정 종료예정일을 포함합니다. 구성원이 휴가 중이면 공식 전자문서와 등록된 연락수단으로 통보하고 복귀 후 확인 일정을 잡습니다. 통보일과 실제 종료일 사이에 신규 범위를 추가하려면 잔여시간과 인계 영향을 다시 확인합니다.

1. 산출물은 최신본, 승인 상태, 저장 위치와 수정 가능한 원본을 인계합니다. 개인 저장장치나 개인 계정에 있는 업무자료는 승인된 회사 저장소로 옮깁니다.
2. 미결 과제는 현황, 다음 행동, 책임자, 마감일, 고객과 마지막으로 합의한 내용을 목록화합니다. 위험도가 높은 항목은 인수자에게 구두 설명까지 완료합니다.
3. 접근권한은 고객사 계정, 원격접속, 저장소, 협업도구와 배포 권한으로 구분합니다. 유지가 필요한 권한은 인수자 명의로 새로 부여하고 기존 계정을 공유하지 않습니다.
4. 고객 담당자 소개는 이름 전달로 끝내지 않고 담당 범위, 정기회의, 의사결정 경로와 연락 가능한 시간대를 함께 안내합니다. 외부 연락처는 업무 인계 목적 범위에서만 사용합니다.

| 인계 대상 | 완료 확인자 | 완료 기준 |
|---|---|---|
| 업무 산출물과 미결 과제 | 후임자와 프로젝트 책임자 | 후임자가 위치와 다음 작업을 확인하고 질문을 남깁니다 |
| 기술 운영과 배포 절차 | 후임 기술담당자 또는 원소속 기술책임자 | 재현 또는 모의 수행 결과를 확인합니다 |
| 고객 커뮤니케이션 | 프로젝트 책임자 | 담당자 변경 안내와 정기회의 초대 변경을 확인합니다 |
| 계정·장비·자료 반납 | 권한 관리 담당자와 프로젝트 책임자 | 회수·폐기·이관 상태가 모두 기록됩니다 |

고객사 계정은 마지막 업무 종료 후 1영업일 내 비활성화하도록 요청합니다. 고객이 지급한 장비, 출입증과 문서는 종료일까지 반납하며 현장 반납이 불가능하면 프로젝트 책임자가 회수 방법과 기한을 고객과 합의합니다. 회사 장비에 내려받은 고객자료는 승인된 보관본을 제외하고 삭제한 뒤 삭제 확인을 남깁니다.

인계 완료 여부는 프로젝트 책임자가 최종 확인합니다. 프로젝트 책임자가 철수 대상이면 원소속 부서장 또는 지정된 후임 책임자가 확인하며 자기 인계를 스스로 종결하지 않습니다. 필수 항목이 남아 있으면 미완료 항목, 처리자와 완료예정일을 명시한 조건부 종료로 기록합니다.

철수 회고는 종료 후 5영업일 내 30~60분으로 실시합니다. 정상 종료는 프로젝트 책임자가 진행하고, 조기 종료나 교체는 원소속 부서장 또는 인사 담당자가 참여하여 고객 관계와 개인 평가가 섞이지 않게 합니다. 고객의 감정적 표현은 그대로 평가 근거로 옮기지 않고 확인 가능한 사건으로 변환합니다.

- 계획 대비 실제 투입기간과 투입률 차이, 차이가 발생한 날짜와 원인을 남깁니다.
- 인계가 늦어진 산출물, 반복된 미결 과제와 다음 프로젝트에서 바꿀 운영방식을 남깁니다.
- 고객에게 인수된 결과물, 미수용된 결과물과 수용 조건을 구분합니다.
- 재사용 가능한 기술·업무 지식과 저장 위치를 남기되 고객 식별정보는 제거합니다.
- 다시 같은 역할을 맡길 때 필요한 선행조건, 교육이나 지원 인력을 구체적으로 기록합니다.

교체 철수의 사유가 역량, 업무수행 또는 협업 문제와 관련되면 구성원에게 결정 전 소명 기회를 제공합니다. 프로젝트 책임자는 날짜, 요청 업무, 기대 수준, 실제 결과와 이미 제공한 피드백을 제시하며 “고객과 맞지 않음” 같은 포괄적 표현만으로 교체 사유를 확정하지 않습니다. 구성원은 통보 후 2영업일 내 사실관계, 제약조건과 보완조치를 서면 또는 면담으로 설명할 수 있습니다.

소명 내용과 확인되지 않은 주장은 구분하여 기록합니다. 교체 사실은 투입 이력에 남기되 귀책 여부가 확인되지 않았다면 성과 미달로 표시하지 않습니다. 평가에 활용하려면 해당 평가기간에 관찰된 행동과 업무 영향이 별도 근거로 존재해야 합니다.

철수 다음 날부터 원칙적으로 1영업일을 정비시간으로 배정합니다. 3개월 이상 상주했거나 주말·야간 전환 작업이 종료 직전에 있었으면 부서장은 최대 3영업일까지 회복과 정리 기간을 승인할 수 있습니다. 이 기간은 계정 정리, 회고, 건강 확인과 다음 투입 준비에 사용하며 연차 사용을 강제하지 않습니다.

긴급한 후속 투입이 예정되어 있어도 최소 반일의 자료 정리시간을 확보합니다. 즉시 투입이 불가피하면 미완료 인계업무의 담당자와 처리시간을 새 프로젝트 책임자에게 사전에 알립니다. 종료 프로젝트의 무상 추가 대응은 원소속 부서장의 승인 없이 개인에게 직접 배정하지 않습니다.

## 전배 제도
<!--meta: sec=s12; dept=CNS|AIAX|BE|DATA|SALES; level=주니어|시니어; ct_band=상-->
전배는 원소속 부서 또는 주 근무 지점을 변경하여 지속적으로 다른 직무 수요에 배치하는 인사 이동입니다. 단기 프로젝트 지원, 지점 간 파견과 프로젝트별 보고라인 변경은 전배로 처리하지 않습니다. 전배 유형은 사내 공모, 상시 신청과 회사 주도 재배치로 구분합니다.

| 유형 | 최소 재직·체류 요건 | 평가 요건 | 적용 장면 |
|---|---|---|---|
| 사내 공모 | 입사 후 6개월 이상이며 현 부서 체류 6개월 이상이어야 합니다 | 최근 확정 평가가 B 이상이어야 하며 평가 이력이 없으면 수습 종료 결과로 대체합니다 | 공고된 직무, 인원과 근무지에 지원합니다 |
| 상시 신청 | 입사 후 12개월 이상이며 현 부서 체류 12개월 이상이어야 합니다 | 최근 2회 평가 중 D가 없어야 하며 개선계획 진행 중이면 종료 후 신청합니다 | 공모가 없더라도 희망 직무와 이동 사유를 등록합니다 |
| 회사 주도 재배치 | 최소 재직기간과 현 부서 체류기간을 적용하지 않습니다 | 평가등급만으로 대상을 선정하지 않습니다 | 수요 변화, 프로젝트 종료 또는 역량 활용 필요에 따라 회사가 제안합니다 |

육아·가족돌봄, 건강상 제약, 통근지 변경이나 직장 내 괴롭힘 보호조치와 관련된 이동은 체류기간 예외를 검토합니다. 예외 신청에는 필요한 범위의 사실만 확인하며 상세 진단명이나 가족의 민감정보를 과도하게 요구하지 않습니다. 인사 책임자가 5영업일 내 예외 적용 여부를 결정합니다.

사내 공모는 인사시스템의 공모 메뉴로 신청하며 희망 부서, 역할, 근무지, 이동 가능일과 관련 경험을 작성합니다. 상시 신청은 인사 담당자에게 비공개 상담을 먼저 요청할 수 있고 상담만으로 공식 신청이 성립하지 않습니다. 공식 신청일은 신청서가 접수된 날짜로 기록합니다.

현 부서장에게는 자격요건 확인이 끝난 뒤 지원 부서 면담 전까지 통지합니다. 인사 담당자는 접수 후 2영업일 내 신청자에게 통지 예정일을 안내하며, 신청자가 고객 대응이나 보호 필요성을 이유로 통지 시점 조정을 요청하면 최대 5영업일까지 조정할 수 있습니다. 현 부서장의 사전 허락을 신청 접수 요건으로 두지 않습니다.

1. 인사 담당자는 재직기간, 부서 체류기간, 평가요건과 진행 중인 징계·개선절차의 관련성을 확인합니다. 단순히 현재 프로젝트가 바쁘다는 사유로 심사 접수를 막지 않습니다.
2. 지원 부서장은 직무 기본역량, 6개월 내 예상 역할, 기존 인력과의 중복 여부를 검토합니다. 필요하면 60분 이내의 실무 면담이나 기존 업무결과 설명을 요청합니다.
3. 현 부서장은 인계 대상, 대체 가능 시점과 이동 시 발생하는 운영위험을 제출합니다. 신청자의 성향이나 충성도에 관한 의견은 심사 항목으로 사용하지 않습니다.
4. 인사 담당자는 신청 동기, 경력 방향, 근무지 제약과 처우 변경 가능성을 확인합니다. 서로 다른 자료에서 사실이 충돌하면 신청자에게 확인 기회를 제공합니다.

| 심사 항목 | 판단 근거 | 배제하는 판단 |
|---|---|---|
| 직무 적합성 | 수행 사례, 기술 검증 결과와 역할 이해도를 확인합니다 | 학연, 개인적 친분과 비공식 평판을 사용하지 않습니다 |
| 수요 지속성 | 최소 6개월의 예상 업무와 프로젝트 후보를 확인합니다 | 단일 제안 참여만으로 상시 수요를 확정하지 않습니다 |
| 이동 가능성 | 인계 규모, 고객 약속과 후임 확보 가능성을 확인합니다 | 현 부서의 막연한 인력 부족만으로 부결하지 않습니다 |
| 성장 연계성 | 기존 경험의 확장 여부와 보완계획을 확인합니다 | 직급 상승이나 평가등급 보장을 전제로 승인하지 않습니다 |

공모 결과는 접수 마감 후 10영업일 내 통보합니다. 상시 신청은 접수 후 15영업일 내 승인, 조건부 승인 또는 부결로 통보하며 추가 검증이 필요하면 한 차례에 한해 5영업일 연장할 수 있습니다. 연장 시 확인 중인 항목과 새 통보일을 신청자에게 알립니다.

부결 통보에는 미충족 요건, 다시 검토받기 위해 필요한 경험이나 시점과 다음 신청 가능일을 포함합니다. 동일 직무에 대한 재신청은 부결 통보일부터 3개월 후 가능하며, 자격요건이 새로 충족되거나 공모의 역할 범위가 달라진 경우에는 인사 책임자 승인으로 앞당길 수 있습니다. 다른 직무 공모에는 동일한 제한을 자동 적용하지 않습니다.

전배 확정 후 인계기간은 통상 4주로 정합니다. 첫 2주에는 진행 업무와 고객 약속을 정리하고, 3주차에는 후임자 공동 수행, 4주차에는 후임자 단독 수행과 잔여 질문 처리를 진행합니다. 업무량이 적으면 양 부서장과 구성원의 합의로 2주까지 단축할 수 있습니다.

전배일 보류는 계약상 명시된 핵심 마감이 4주 안에 있고 즉시 대체할 사람이 없는 경우, 법정·고객 감사 대응의 담당자 변경이 제한되는 경우, 접근권한 이관에 외부 승인이 필요한 경우에만 허용합니다. 현 부서장은 위험 항목, 대체인력 탐색 결과와 필요한 추가기간을 서면으로 제출합니다. 보류기간은 최초 전배일로부터 최대 4주이며 인사 책임자 승인 없이 다시 연장하지 않습니다.

전배 신청, 상담 또는 공모 참여를 이유로 프로젝트 배제, 낮은 평가, 교육 취소, 정보 차단이나 공개적 비난을 해서는 안 됩니다. “어차피 이동할 사람”이라는 이유로 기존 역할을 회수하거나 과도한 인계를 부과하는 행위도 금지합니다. 신청 이후 불이익이 의심되면 구성원은 인사 담당자에게 사실 확인을 요청할 수 있으며 인사 담당자는 5영업일 내 조사 착수 여부와 보호조치를 안내합니다.

확정된 전배는 이동 부서, 직무, 근무지, 적용일과 보고라인을 공식 문서로 통보합니다. 처우나 근로조건에 변경이 있으면 전배 통보와 구분하여 변경 항목과 적용일을 확인합니다. 지원 부서장은 전배일 전까지 첫 30일 업무, 협업자와 필요한 시스템 권한을 준비합니다.

## 회사 주도 재배치와 조정
<!--meta: sec=s13; dept=CNS|AIAX|BE|DATA|SALES; level=시니어; ct_band=상-->
회사는 프로젝트 수요 감소, 계약 종료, 특정 기술 수요 증가 또는 지점별 인력 불균형이 발생하면 구성원에게 재배치를 요청할 수 있습니다. 재배치는 징계나 저성과 조치를 대신하는 수단으로 사용하지 않습니다. 개인의 평가등급만으로 이동 대상을 정하지 않고 수행 가능한 역할, 현재 업무의 종료 시점과 생활상 제약을 함께 검토합니다.

재배치 제안은 원칙적으로 예정 적용일 15영업일 전까지 서면으로 제공합니다. 긴급한 계약 종료로 기한을 지키기 어려우면 인사 담당자가 단축 사유와 임시 배치기간을 명시합니다. 구두로 먼저 설명했더라도 공식 안내가 제공되기 전에는 확정된 인사명령으로 취급하지 않습니다.

| 설명 항목 | 회사가 제시할 내용 |
|---|---|
| 재배치 사유 | 수요 변화가 발생한 업무, 현재 배치를 유지하기 어려운 기간과 검토한 대안을 설명합니다 |
| 적용 기간 | 한시 배치인지 계속 배치인지, 시작일과 재검토일을 명시합니다 |
| 담당 역할 | 예상 업무, 책임 범위, 보고라인, 고객 접점과 요구 역량을 제시합니다 |
| 근무 조건 | 주 근무지, 상주 빈도, 출퇴근 예상, 원격근무 적용 여부를 알립니다 |
| 처우 확인 | 직급과 기존 처우에 변동이 없음을 확인하며 변동이 있으면 별도 협의 대상으로 표시합니다 |
| 적응 지원 | 교육, 멘토, 인수인계와 초기 성과 확인 방식을 제시합니다 |

직속 부서장과 인사 담당자는 구성원에게 최소 2영업일의 검토기간을 부여합니다. 구성원은 설명일로부터 5영업일 내 수용, 조건부 수용 또는 조정 요청 의견을 제출합니다. 즉시 답변을 요구하거나 회의 중 동의 서명을 받지 않습니다.

의견 청취 면담에는 구성원, 인사 담당자와 이동 전·후 부서장 중 필요한 사람이 참석합니다. 구성원은 희망 역할, 수행이 어려운 업무, 통근·건강·돌봄 제약과 필요한 준비기간을 설명할 수 있습니다. 면담 참석자가 많아 의견 제시가 어렵다고 판단되면 인사 담당자와 별도 면담을 요청할 수 있습니다.

1. 회사는 동일 지점 내 역할 조정, 단계적 투입, 한시적 지원 후 확정과 교육 선행 방안을 먼저 검토합니다. 각 대안의 가능 여부와 제외 사유를 면담 기록에 남깁니다.
2. 구성원은 단순 선호뿐 아니라 업무 수행에 미치는 구체적 영향을 제시합니다. 증빙이 필요한 사유는 필요한 범위와 제출기한을 인사 담당자가 안내합니다.
3. 양측은 적용일, 근무지, 상주일수, 교육기간과 30일 후 재검토 항목을 조정합니다. 합의된 내용은 면담 후 2영업일 내 공유합니다.

건강상 사유는 현재 치료나 회복에 중대한 지장을 주거나 해당 근무형태를 수행하기 어렵다는 의학적 의견이 있는 경우 인정합니다. 상세 질병정보 대신 근무 가능 조건, 이동 제한과 필요한 기간을 확인합니다. 회사는 가능한 범위에서 근무지, 업무강도나 적용일을 조정합니다.

돌봄 사유는 미성년 자녀, 고령 가족 또는 질병·장애가 있는 가족을 정기적으로 돌보며 대체수단을 단기간에 확보하기 어려운 경우를 포함합니다. 구성원은 필요한 시간대와 예상기간을 설명하고, 회사는 시차 조정이나 단계적 이동 가능성을 검토합니다. 가족관계와 일정 확인을 넘어 불필요한 사생활 자료를 요구하지 않습니다.

통근 급변은 편도 예상시간이 기존보다 60분 이상 증가하거나 대중교통 이용이 현저히 곤란해지는 경우를 우선 검토합니다. 단순한 지점 선호는 자동 거절 사유가 아니지만 조정 협의 대상이 될 수 있습니다. 인사 담당자는 실제 출퇴근 경로, 상주 빈도와 재택 가능일을 기준으로 영향을 계산합니다.

| 조정안 | 적용 가능한 장면 | 확인 시점 |
|---|---|---|
| 적용일 연기 | 치료 일정, 돌봄 대체수단 확보나 기존 고객 인계에 시간이 필요한 경우입니다 | 최대 4주 후 적용 여부를 확인합니다 |
| 단계적 투입 | 새 역할의 기술이나 산업 지식을 보완해야 하는 경우입니다 | 2주 단위로 투입률을 조정합니다 |
| 한시 재배치 | 수요 기간이 확정되지 않았거나 업무 적합성을 확인해야 하는 경우입니다 | 30일 또는 60일 후 계속 여부를 결정합니다 |
| 근무지 혼합 | 원거리 이동이 필요하지만 현장 업무가 매일 발생하지 않는 경우입니다 | 월별 상주일과 고객 요구를 점검합니다 |

조정 협의가 결렬되면 인사 책임자, 이동 대상 부서와 이해관계가 없는 부장급 1명, 근로자 의견을 대변할 수 있는 내부 위원 1명으로 2차 검토기구를 구성합니다. 최초안을 만든 부서장은 자료 설명은 할 수 있으나 최종 판단에는 참여하지 않습니다. 검토기구는 요청 접수 후 7영업일 내 재배치 필요성, 대안 검토의 충분성, 개인 제약의 중대성과 조건 변경 여부를 확인합니다.

2차 검토 중에는 기존 배치를 유지하는 것을 원칙으로 합니다. 기존 프로젝트가 이미 종료된 경우에는 근무지 변화가 없는 내부 과제나 교육을 임시 배정합니다. 고객 접근이 필요한 새 역할을 동의나 최종 결정 전에 사실상 수행하게 하지 않습니다.

검토 결과는 원안 유지, 조건 조정, 한시 보류 또는 대체배치로 구분하여 서면 통보합니다. 통보문에는 확인한 사실, 채택하거나 배제한 대안, 적용일과 재검토 가능 시점을 포함합니다. 처우나 근로계약상 핵심 조건의 변경이 필요한 경우에는 재배치 결정만으로 일괄 처리하지 않고 별도 절차를 거칩니다.

재배치 후 첫 2주 동안 이동 부서장은 업무 안내자 1명을 지정합니다. 회사는 필요한 시스템 권한, 역할별 자료와 최대 20시간의 직무 전환 교육을 근무시간 내 제공합니다. 즉시 고객 단독 대응을 요구하지 않고 최소 1회는 기존 담당자 또는 책임자와 공동 수행합니다.

적용 후 10영업일과 30일에 적응 면담을 실시합니다. 면담에서는 실제 역할이 사전 설명과 일치하는지, 통근·업무량 문제가 발생했는지, 추가 교육이나 역할 조정이 필요한지를 확인합니다. 30일 시점에도 중대한 불일치가 있으면 이동 부서장과 인사 담당자가 5영업일 내 보완안을 작성합니다.

## 투입 이력과 경력 관리
<!--meta: sec=s14; dept=CNS|AIAX|BE|DATA|SALES; level=주니어|시니어; ct_band=중-->
투입 이력은 구성원이 어떤 프로젝트에서 어느 범위의 책임을 수행했는지 확인하는 공식 인사자료입니다. 프로젝트 명칭만 나열하지 않고 실제 기간, 역할과 결과물의 근거를 연결합니다. 부서별 개인 문서나 제안용 프로필을 공식 이력보다 우선 자료로 사용하지 않습니다.

| 기록 항목 | 입력 기준 |
|---|---|
| 투입기간 | 실제 업무 시작일과 종료일을 기록하며 계약기간과 다르면 실제 날짜를 우선합니다 |
| 역할 | PM, PL, 컨설턴트, AIAX 엔지니어, 백엔드 개발, 데이터 분석, 제안 지원 등 실제 책임으로 기록합니다 |
| 투입률 | 월별 승인된 배정률과 실제 기록의 차이가 10%포인트 이상이면 사유를 남깁니다 |
| 사용 기술 | 직접 설계·개발·분석에 사용한 기술과 단순 조회한 기술을 구분합니다 |
| 산출물 | 본인이 작성하거나 공동 책임진 결과물의 유형, 기여 범위와 저장 위치를 기록합니다 |
| PM 평가 요약 | 수행기간 중 확인된 강점, 보완점과 재배치 시 참고할 조건을 300자 이내로 기록합니다 |

프로젝트 책임자는 투입 시작 후 5영업일 내 역할과 예정 투입률을 등록합니다. 투입률이나 역할이 변경되면 변경 적용일부터 3영업일 내 수정하며 이전 값을 삭제하지 않고 변경 이력을 보존합니다. 종료 후 5영업일 내 실제 종료일, 산출물과 PM 평가 요약을 확정합니다.

공동 산출물은 구성원이 맡은 부분을 식별할 수 있게 기록합니다. 예를 들어 “A사 AI 플랫폼 구축”만 적지 않고 “검색 평가 데이터셋 설계, 평가 스크립트 작성, 3회 결과 비교”처럼 책임 범위를 남깁니다. 고객의 영업비밀이나 개인정보가 포함된 파일명과 상세 내용은 인사시스템에 복사하지 않고 승인된 저장 위치만 연결합니다.

PM 평가 요약에는 관찰 가능한 업무 사실을 사용합니다. “책임감이 부족함” 대신 “합의한 API 명세 제출일을 두 차례 넘겼으며 변경 예상일을 사전에 공유하지 않음”과 같이 시점, 행동과 영향을 기록합니다. 고객의 주관적 평가를 인용할 때에는 확인된 사건과 프로젝트 책임자의 판단을 구분합니다.

1. 배치 검토에서는 산업 경험, 역할 난이도, 최근 수행 시점과 실제 투입률을 확인합니다. 같은 기술명이 있다는 이유만으로 숙련도를 동일하게 판단하지 않습니다.
2. 인사평가에서는 평가기간 안에 발생한 업무와 PM 평가 근거를 활용합니다. 투입 이력의 프로젝트 규모나 고객 인지도만으로 높은 등급을 부여하지 않습니다.
3. 승진 검토에서는 상위 직급 역할을 반복 수행했는지, 책임 범위가 확장되었는지 확인합니다. 이력 자체가 승진요건을 자동 충족시키지는 않습니다.

외부 제공용 프로필에는 이름, 직급, 총 경력, 관련 프로젝트, 역할과 기술이 포함될 수 있습니다. 고객이 실명 확인을 요구하지 않는 초기 제안 단계에서는 이름을 비식별 표기로 작성하고 고객사는 A사, B제조, C금융과 같은 가명으로 표시합니다. 실명이나 세부 경력을 제공하려면 제공받는 자, 목적, 항목과 보유기간을 구성원에게 알리고 필요한 동의를 받습니다.

구성원이 동의한 범위를 넘어 자격증 사본, 연락처, 사진이나 내부 평가의견을 고객에게 전달하지 않습니다. 수주 가능성을 높이기 위해 경력기간, 역할이나 기술 사용 수준을 확대 기재해서도 안 됩니다. 고객 요청 양식이 과도한 개인정보를 요구하면 SALES 담당자와 인사 담당자가 제공 필요성을 먼저 검토합니다.

정정 요청자는 변경을 원하는 문구와 근거자료를 제출합니다. 당시 프로젝트 책임자가 퇴사했거나 확인이 어려우면 저장소 기록, 회의록, 작업관리 도구와 공동 수행자의 확인을 순서대로 검토합니다. 사실 확인이 끝나지 않은 항목은 임의로 삭제하지 않고 “검토 중”으로 표시합니다.

정정이 받아들여지지 않으면 인사 담당자는 유지한 내용, 확인한 자료와 재검토 가능 조건을 설명합니다. 의견 차이가 평가적 판단에 관한 것이라면 구성원의 반론을 500자 이내로 함께 보관할 수 있습니다. 외부 프로필에는 이의가 진행 중인 평가 문구를 사용하지 않습니다.

경력 다양성은 프로젝트 수보다 문제 유형, 산업, 역할과 기술 책임의 변화로 관리합니다. 동일 산업·동일 역할의 프로젝트를 연속 2회 수행했거나 누적 18개월을 초과하면 다음 배치 검토에서 다른 유형 후보를 1개 이상 함께 제시합니다. 동일 고객의 운영 연장처럼 장기 연속 배치가 필요한 경우에는 책임 범위 확대, 기술 교체 또는 후임 육성 중 하나를 경력계획에 포함합니다.
