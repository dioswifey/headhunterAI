# INC-AI-01 콜센터 AI 응답 오류(환각) — 상세
<!--meta: doc=INC-AI-DET; doc_type=incident; tier=1; topic=CC; disclosure=internal; status=resolved-->

## 개요
<!--meta: sec=s1; dept=AIAX; level=주니어|시니어; ct_band=상; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
2026년 9월, 대한전자 콜센터 AI 상담 시스템 도입 2주 차에 상담사 3명이 "AI가 보여준 환불 규정이 실제 매뉴얼과 다르다"고 보고했습니다. 확인 결과 9건의 상담에서 매뉴얼에 없는 조건(실제로는 존재하지 않는 "구매 후 100일 무상 환불")이 생성되어 노출되었습니다. 고객에게 잘못 안내된 사례는 2건이었고, 담당자가 즉시 정정 연락했습니다.

본 건은 서비스 중단이나 개인정보 유출이 아니라, 검색증강생성(RAG) 응답의 근거 부족 상태에서 대규모 언어 모델이 사실처럼 보이는 정책 문장을 생성한 정확성 장애입니다. 상담사 화면은 정상 작동했고 응답 시간도 평상시 범위였으나, 답변의 내용이 실제 매뉴얼과 달랐기 때문에 업무상 영향도가 높은 장애로 분류했습니다.

내부 심각도는 `SEV-2`로 지정했습니다. 판단 근거는 다음과 같습니다.

- 고객에게 잘못된 정책이 실제 안내된 사례가 존재함
- 환불 조건은 고객 비용 및 분쟁 가능성과 직접 연결되는 민감 업무임
- 동일한 질문이 반복 유입될 경우 오안내가 확산될 수 있음
- 상담사가 육안으로 확인하기 전까지 자동 탐지가 어려웠음
- 서비스 전체 중단은 없었고 영향 상담 건수가 제한적이었음
- 정정 연락을 통해 확인된 고객 영향을 당일 해소할 수 있었음

## 장애 범위와 영향
<!--meta: sec=s2; dept=AIAX; level=주니어; ct_band=하; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
장애 조사 범위는 최초 신고 시점 전후의 상담 기록, RAG 검색 결과, 모델 입력 프롬프트, 모델 원문 출력, 상담사 화면 표시 내용 및 상담 결과 코드로 한정했습니다.

확인된 영향은 다음과 같습니다.

| 구분 | 확인 결과 |
|---|---:|
| 이상 응답이 노출된 상담 | 9건 |
| 실제 고객에게 잘못 안내된 상담 | 2건 |
| 상담사가 안내 전에 차단한 상담 | 7건 |
| 최초 문제를 보고한 상담사 | 3명 |
| 확인된 개인정보 노출 | 0건 |
| 서비스 중단 시간 | 0분 |
| 결제·환불 시스템의 직접 변경 | 0건 |
| 정정 연락이 필요한 고객 | 2명 |
| 정정 연락 완료 | 2명 |

9건은 동일 문구가 완전히 똑같이 반복된 경우만을 뜻하지 않습니다. “구매 후 100일 이내”, “100일까지 무상 환불 가능”, “제품 상태와 관계없이 100일 이내 환불 가능”과 같이 표현은 달랐지만, 실제 매뉴얼에 없는 100일 조건을 포함한 응답을 동일 오류 유형으로 집계했습니다.

상담사에게만 표시되고 고객에게 전달되지 않은 7건도 잠재 고객 영향으로 분류했습니다. 생성형 AI 보조 시스템에서는 최종 전달 여부만으로 위험을 평가하면 상담사의 수동 검증 부담과 반복 가능성을 놓칠 수 있기 때문입니다.

## 탐지 경위
<!--meta: sec=s3; dept=AIAX; level=주니어; ct_band=하; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
최초 탐지는 자동 모니터링이 아니라 상담사의 업무 보고를 통해 이루어졌습니다. 서로 다른 상담사 3명이 환불 문의 처리 중 AI 답변과 기존 업무 지식이 맞지 않는다고 판단했고, 상담 품질 담당자에게 화면 캡처와 상담 번호를 전달했습니다.

첫 번째 상담사는 답변에 표시된 “100일” 조건이 익숙하지 않아 매뉴얼을 별도로 검색했습니다. 두 번째 상담사는 동일한 조건이 반복 표시되자 시스템 오류 가능성을 의심했습니다. 세 번째 상담사의 독립 보고까지 접수되면서 단일 오입력이나 개인 해석 문제가 아닌 공통 시스템 문제로 판단했습니다.

초기 탐지 과정에서 효과적이었던 행동은 다음과 같습니다.

- 상담사가 AI 답변을 확정 규정이 아닌 보조 정보로 취급함
- 기존 매뉴얼과 다른 숫자 조건을 발견하고 재확인함
- 상담 번호와 화면 캡처를 함께 제출함
- 구두 보고에 그치지 않고 품질 담당 경로로 공식 등록함
- 유사 문의를 처리하는 상담사에게 임시 주의 사항을 공유함

반면 시스템 차원에서는 근거 없는 정책 숫자를 자동 감지하지 못했습니다. 이 점은 후속 조치에서 별도 모니터링 규칙을 추가하게 된 직접적인 계기가 되었습니다.

## 장애 당시 처리 흐름
<!--meta: sec=s5; dept=AIAX; level=주니어; ct_band=중; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
장애 당시 환불 질문은 다음 순서로 처리되었습니다.

1. 상담 음성 또는 상담사 입력에서 고객 질문을 텍스트로 정리
2. 질문에서 제품명, 구매 시점, 환불 의도 등의 핵심 표현 추출
3. 매뉴얼 저장소에서 관련 문서 조각 검색
4. 검색된 문서 조각을 질문과 함께 LLM 프롬프트에 삽입
5. LLM이 상담사용 답변 초안 생성
6. 상담사 화면에 답변 초안 표시
7. 상담사가 내용을 확인한 뒤 고객에게 안내

정상적인 경우에는 3단계에서 환불 규정이 포함된 매뉴얼 조각이 검색되고, 4단계 프롬프트가 해당 원문만을 근거로 답하도록 모델을 유도합니다.

문제가 발생한 9건에서는 질문 표현이 매뉴얼 용어와 충분히 맞지 않았거나 검색 후보가 주변 문맥 위주로 구성되었습니다. 예를 들어 고객은 “마음이 바뀌었는데 언제까지 돌려줄 수 있느냐”고 질문했지만, 매뉴얼은 “단순 변심 반품 가능 기간”이라는 표현을 사용했습니다. 검색 결과에는 반품 접수 절차와 제품 상태 확인 항목은 포함되었으나 정확한 기간 조건은 포함되지 않았습니다.

시스템은 이 상태를 “근거 없음”으로 판단하지 않고 검색 결과가 존재한다는 이유만으로 생성 단계에 전달했습니다. 모델은 부족한 기간 조건을 일반적인 환불 정책 형태로 보완했고, 그 결과 실제 매뉴얼에 없는 숫자 조건이 생성되었습니다.

## 관찰된 오류 유형
<!--meta: sec=s6; dept=AIAX; level=주니어; ct_band=하; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
조사 결과 오류는 다음 세 가지 표현 유형으로 분류되었습니다.

### 유형 A: 존재하지 않는 기간 생성

- “구매 후 100일 이내에는 무상 환불이 가능합니다.”
- “수령일로부터 최대 100일까지 환불을 신청할 수 있습니다.”

정확한 기간 근거가 없는데도 모델이 숫자를 생성한 유형입니다.

### 유형 B: 조건 범위 확대

- “제품을 사용했더라도 100일 이내면 환불할 수 있습니다.”
- “포장을 개봉한 경우에도 동일한 환불 기준이 적용됩니다.”

원문에 없는 기간뿐 아니라 사용 여부와 포장 상태 조건까지 확대 해석한 유형입니다.

### 유형 C: 확정적 표현 사용

- “고객님은 무상 환불 대상입니다.”
- “해당 건은 예외 없이 환불 처리됩니다.”

검색 결과만으로 대상 여부를 판단할 수 없는데도 추가 확인이 필요하다는 표현 없이 확정적으로 안내한 유형입니다.

세 유형은 모두 답변 문장 자체가 자연스럽고 상담 문체에 맞았기 때문에 단순 맞춤법 검사나 문장 품질 평가로는 탐지하기 어려웠습니다.

## 원인
<!--meta: sec=s7; dept=AIAX; level=주니어|시니어; ct_band=상; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
RAG 검색에서 관련 매뉴얼 조각을 찾지 못했을 때도 LLM이 질문에 답하려 시도하면서, 학습 데이터에 있던 일반적인 환불 정책 패턴을 섞어 그럴듯한 답을 생성했습니다. 검색 결과가 비어 있거나 유사도가 낮을 때의 예외 처리가 없었습니다.

직접 원인은 다음 조건이 동시에 충족된 것입니다.

1. 정확한 환불 기간을 포함한 문서 조각이 상위 검색 결과에 포함되지 않음
2. 검색 결과의 유사도가 낮았지만 생성 단계가 계속 실행됨
3. 프롬프트가 “근거가 없으면 답변하지 말라”고 지시했으나 시스템적으로 강제하지 않음
4. 생성 결과에 포함된 숫자가 검색 원문에 실제로 존재하는지 검증하지 않음
5. 상담사 화면에서 답변과 근거 원문을 즉시 비교하기 어려움

근본 원인은 모델이 환각을 일으킬 수 있다는 사실 자체가 아니라, 환각 가능성을 전제로 한 차단 설계가 누락된 것입니다. 자연어 지시만으로 모델 행동을 제한하려 했고, 검색 실패를 명시적인 시스템 상태로 정의하지 않았습니다.

## 검색 실패의 세부 조건
<!--meta: sec=s8; dept=AIAX; level=시니어; ct_band=상; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
문제 상담의 검색 로그를 분석한 결과, 문서가 완전히 검색되지 않은 경우와 관련 문서가 검색되었지만 핵심 조건이 빠진 경우가 혼재했습니다.

내부 분석에서는 검색 상태를 다음과 같이 구분했습니다.

| 상태 | 설명 | 장애 당시 처리 |
|---|---|---|
| 정상 검색 | 질문에 필요한 기간·조건·예외가 모두 포함됨 | LLM 호출 |
| 부분 검색 | 주제는 일치하지만 핵심 기간 또는 예외가 누락됨 | LLM 호출 |
| 주변 문맥 검색 | 반품 접수 등 인접 업무만 검색됨 | LLM 호출 |
| 저유사도 검색 | 상위 결과가 질문과 약하게 관련됨 | LLM 호출 |
| 무검색 | 사용할 문서 조각이 없음 | LLM 호출 가능 |
| 정책 충돌 | 서로 다른 버전의 조건이 함께 검색됨 | 별도 판정 없음 |

장애 당시에는 결과 개수가 하나 이상이면 검색 성공으로 간주했습니다. 이 기준은 “관련 문서가 하나라도 존재하는가”만 확인했으며, “답변에 필요한 사실이 충분히 포함되어 있는가”는 확인하지 않았습니다.

사후 재현에서 문제 9건의 상위 검색 결과는 환불이라는 큰 주제에는 관련이 있었지만, 답변에 필요한 기간 근거가 부족했습니다. 검색 결과가 의미상 관련되어 보이는 것과 답변을 확정할 수 있을 정도로 충분한 것은 서로 다른 조건임을 확인했습니다.

## 프롬프트 통제의 한계
<!--meta: sec=s9; dept=AIAX; level=주니어|시니어; ct_band=중; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
장애 당시 프롬프트에는 제공된 문서를 바탕으로 답변하라는 지시가 포함되어 있었습니다. 그러나 다음과 같은 한계가 있었습니다.

- “문서만 사용하라”는 문장이 있었지만 위반 시 호출을 중단하는 로직은 없었음
- 근거가 부족할 때 사용할 고정 응답 형식이 정의되지 않았음
- 숫자, 기간, 금액과 같은 고위험 사실의 별도 검증 절차가 없었음
- 검색 문서가 비어 있을 때도 일반 상담 문체를 유지하도록 요청함
- 친절하고 완결된 답변을 생성하라는 지시가 보수적 답변보다 강하게 작동함
- 모델이 답변 불가를 선택했는지 평가하는 후처리기가 없었음

특히 “상담사가 바로 읽을 수 있도록 자연스럽고 완전한 문장으로 작성”하라는 요구는 근거가 불완전한 상황에서도 모델이 빈 정보를 채워 문장을 완성하도록 유도할 수 있었습니다.

개선 후에는 프롬프트 지시를 보조 통제로만 사용하고, 검색 신뢰도 판정과 민감 주제 제한은 모델 외부 로직에서 수행하도록 책임을 분리했습니다.

## 기여 요인
<!--meta: sec=s10; dept=AIAX; level=시니어; ct_band=상; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
직접 원인 외에도 장애 발생과 탐지 지연에 영향을 준 기여 요인은 다음과 같습니다.

### 문서 표현과 상담 표현의 차이

매뉴얼은 “단순 변심 반품 가능 기간”, “청약 철회 제한”과 같은 공식 용어를 사용했지만 실제 고객 질문은 “마음이 바뀌었다”, “그냥 돌려주고 싶다”와 같은 구어체였습니다. 이 표현 차이에 대한 질의 확장 사전이 충분하지 않았습니다.

### 문서 조각 경계

일부 매뉴얼에서는 환불 가능 기간과 예외 조건이 서로 다른 문단에 배치되어 있었습니다. 검색된 조각에 기본 절차는 포함되었지만 다음 문단의 제한 조건이 빠지는 사례가 있었습니다.

### 성공 여부 중심의 시험

기존 시험은 정답 문서가 검색되고 올바른 답변이 생성되는 정상 흐름에 집중했습니다. 검색 결과가 없거나 불충분할 때 시스템이 안전하게 답변을 거부하는지에 대한 시험 비중이 낮았습니다.

### 상담사 화면의 근거 가시성 부족

상담사 화면에는 생성 답변이 크게 표시되었고 근거 문서는 별도 동작을 해야 확인할 수 있었습니다. 긴급한 상담 상황에서 원문 대조가 자연스러운 업무 흐름에 포함되지 않았습니다.

### 민감 주제의 공통 처리

환불·보증 질문도 배송 조회나 제품 사용법과 동일한 생성 경로를 사용했습니다. 틀렸을 때의 위험도가 다른데도 동일한 신뢰도 기준과 화면 정책이 적용되었습니다.

## 사전 시험에서 발견하지 못한 이유
<!--meta: sec=s11; dept=AIAX; level=주니어|시니어; ct_band=중; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
배포 전 평가 세트에는 환불 문의가 포함되어 있었지만, 주로 매뉴얼 용어와 유사한 질문으로 구성되어 있었습니다. 따라서 관련 문서가 정상 검색되는 경우의 정확도는 확인했지만 검색이 실패하는 표현 변형은 충분히 포함하지 못했습니다.

누락된 대표 시험 유형은 다음과 같습니다.

- 고객 구어체만 사용한 질문
- 제품명이나 구매일이 없는 불완전한 질문
- 환불과 교환 의도가 섞인 질문
- 정책 기간을 유도하는 질문
- 실제 매뉴얼에 없는 숫자를 질문에 포함한 경우
- 검색 결과가 0건인 경우
- 관련 문서가 검색되지만 핵심 조건 문장이 없는 경우
- 이전 정책과 현재 정책의 표현이 비슷한 경우
- 모델이 “모르겠다” 대신 일반 상식을 사용하려는 경우

평가 지표도 정답과의 문장 유사도에 치우쳐 있었습니다. 안전한 답변 거부가 필요한 질문에서 “확인 필요”라고 응답하면 정답 문장과 다르다는 이유로 낮은 점수를 받을 수 있었고, 이 때문에 거부 품질을 독립적으로 평가하지 못했습니다.

## 즉시 완화 조치
<!--meta: sec=s12; dept=AIAX; level=주니어; ct_band=하; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
장애 인지 직후 다음 조치를 순서대로 적용했습니다.

1. 환불·보증 질문에 대한 생성형 답변을 임시 중지
2. 해당 주제에는 “매뉴얼을 직접 확인해 주십시오”라는 고정 안내 표시
3. 상담사 공지 채널에 잘못된 100일 조건을 사용하지 않도록 안내
4. 문제 상담의 입력, 검색 결과, 프롬프트 및 출력 로그 보존
5. 최근 상담 기록에서 “100일”, “무상 환불” 조합 검색
6. 고객 전달 여부를 상담 결과와 녹취 기록으로 교차 확인
7. 고객에게 안내된 2건에 대해 정정 연락 수행
8. 다른 민감 주제에서 유사한 숫자 생성이 있었는지 표본 점검

임시 조치는 답변 품질을 일부 낮추더라도 잘못된 확정 안내를 차단하는 것을 우선했습니다. 환불 관련 문의가 들어오면 처리 시간이 증가할 수 있었지만, 운영 담당자와 협의해 정확성을 응답 속도보다 높은 우선순위로 두었습니다.

## 고객 정정 처리
<!--meta: sec=s13; dept=AIAX; level=주니어; ct_band=중; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
잘못 안내된 2건은 담당 상담사가 즉시 정정 연락했습니다. 정정 절차는 다음 원칙으로 진행했습니다.

- AI 시스템의 내부 동작을 고객에게 책임 전가 방식으로 설명하지 않음
- 이전 안내가 정확하지 않았음을 명확히 고지
- 실제 적용되는 환불 규정을 매뉴얼 기준으로 다시 설명
- 고객이 이미 후속 행동을 했는지 확인
- 추가 비용이나 불편이 발생했는지 확인
- 정정 안내 결과를 상담 이력에 기록
- 재문의 시 동일 내용을 확인할 수 있도록 품질 담당자에게 공유

두 건 모두 정정 연락이 완료되었고, 조사 시점에 추가 비용 청구나 환불 시스템의 잘못된 처리로 이어진 사례는 확인되지 않았습니다. 다만 결과적으로 금전 손실이 없었다는 사실은 장애 심각도를 낮추는 근거로 사용하지 않았습니다. 상담 정책의 잘못된 확정 안내 자체가 재발 방지 대상이기 때문입니다.

## 후속 조치
<!--meta: sec=s14; dept=AIAX; level=주니어|시니어; ct_band=상; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
- 검색 결과 유사도가 기준값 미만이면 LLM 호출 없이 "확인 필요, 상담사 직접 확인" 응답으로 고정
- 응답에 참조한 매뉴얼 조각의 원문을 함께 표시해 상담사가 직접 대조 가능하도록 변경
- 환불·보증 등 민감 주제는 별도 검증된 답변 세트에서만 답하도록 제한
- 배포 전 "검색 결과 없음" 상황을 강제로 만드는 회귀 시험 추가

각 조치의 적용 목적은 다음과 같습니다.

| 조치 | 방지하려는 실패 | 통제 위치 |
|---|---|---|
| 저유사도 호출 차단 | 근거 없는 일반 상식 생성 | LLM 호출 전 |
| 원문 동시 표시 | 상담사의 근거 대조 누락 | 상담사 화면 |
| 검증 답변 세트 제한 | 민감 정책의 자유 생성 | 응답 정책 계층 |
| 무검색 회귀 시험 | 실패 경로의 시험 누락 | 배포 검증 단계 |

후속 조치는 단일 임계값 추가로 종료하지 않았습니다. 검색 품질, 생성 통제, 화면 표시, 업무 절차 및 시험 체계를 함께 변경해야 동일 유형의 오류를 여러 단계에서 차단할 수 있다고 판단했습니다.

## 검색 신뢰도 게이트
<!--meta: sec=s15; dept=AIAX; level=시니어; ct_band=상; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
개선 후 검색 결과는 단순히 “있음” 또는 “없음”으로 판정하지 않고 신뢰도 상태로 구분합니다.

### 통과 조건

다음 조건을 모두 만족해야 자유 생성 경로를 사용할 수 있습니다.

- 상위 검색 문서가 질문의 업무 주제와 일치함
- 답변에 필요한 핵심 속성이 원문에 존재함
- 기간·금액·비율·횟수 등 숫자 조건의 근거 문장이 존재함
- 문서 버전이 현재 유효 상태임
- 상충하는 규정 조각이 함께 검색되지 않음
- 민감 주제 제한 목록에 해당하지 않음

### 차단 조건

다음 중 하나라도 해당하면 LLM 호출을 생략하거나 제한된 답변 경로로 전환합니다.

- 검색 결과가 없음
- 최고 유사도가 운영 기준 미만임
- 상위 결과 간 점수 차이가 작아 문서 선택이 불명확함
- 질문은 기간을 요구하지만 검색 문서에 기간 표현이 없음
- 서로 다른 정책 버전이 동시에 검색됨
- 질문의 대상 제품이나 구매 경로를 식별할 수 없음
- 환불·보증처럼 검증 답변 세트 사용이 의무인 주제임

신뢰도 기준값은 고정된 절대 진리로 취급하지 않습니다. 문서 개편, 임베딩 변경, 고객 표현 변화에 따라 분포가 달라질 수 있으므로 운영 데이터와 회귀 시험 결과를 함께 검토해 조정합니다.

## 민감 주제 응답 정책
<!--meta: sec=s16; dept=AIAX; level=주니어|시니어; ct_band=중; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
민감 주제는 잘못된 답변이 금전, 계약, 법적 의무 또는 고객 권리에 영향을 줄 수 있는 영역으로 정의합니다.

현재 콜센터 AI에서 민감 주제로 취급하는 범주는 다음과 같습니다.

- 환불 가능 기간 및 환불 금액
- 무상·유상 보증 조건
- 위약금과 수수료
- 계약 해지 조건
- 고객 과실 판정
- 보상 대상 여부
- 개인정보 제공 및 삭제 요청
- 법적 책임을 단정하는 표현
- 예외 승인 가능 여부

민감 주제에서는 모델이 정책을 새로 조합하지 않습니다. 사전에 검증된 답변 세트에서 질문 유형에 맞는 문장을 선택하고, 필요한 고객 조건이 부족하면 추가 확인 질문을 제시합니다.

예를 들어 구매일이 없으면 환불 가능 여부를 확정하지 않고 구매일 확인을 요청합니다. 제품 상태가 확인되지 않으면 “가능합니다” 대신 “제품 상태 확인 후 판단됩니다”라는 제한 문구를 사용합니다.

검증 답변 세트의 변경은 작성자와 검토자를 분리합니다. 정책 담당자가 원문 기준을 확인하고, AI/AX개발팀은 시스템 적용 여부와 잘못된 분기 가능성을 검증합니다.

## 근거 표시 화면 개선
<!--meta: sec=s17; dept=AIAX; level=주니어; ct_band=하; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
상담사 화면은 생성 답변과 근거를 한 화면에서 비교할 수 있도록 변경했습니다.

개선된 표시 항목은 다음과 같습니다.

- 답변 초안
- 사용한 매뉴얼 문서명
- 매뉴얼 버전과 적용일
- 참조한 원문 문장
- 검색 신뢰도 상태
- 민감 주제 여부
- 상담사 직접 확인 필요 표시
- 근거 부족 사유
- 잘못된 답변 신고 버튼

신뢰도 상태는 숫자 점수만 표시하지 않고 다음과 같은 업무 언어로 표현합니다.

- `근거 확인됨`: 답변에 필요한 원문이 확인된 상태
- `추가 확인 필요`: 일부 조건이 부족한 상태
- `답변 제한`: 민감 주제 또는 근거 부족으로 자동 답변을 제한한 상태
- `정책 충돌`: 서로 다른 규정이 검색된 상태

상담사가 낮은 유사도 숫자의 의미를 직접 해석하지 않도록 상태와 행동 지침을 함께 제공합니다. `추가 확인 필요` 상태에서는 답변 복사 기능을 제한하고 매뉴얼 확인 버튼을 우선 노출합니다.

## 생성 결과 사후 검증
<!--meta: sec=s18; dept=AIAX; level=시니어; ct_band=상; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
검색 단계가 정상이어도 생성 과정에서 원문에 없는 사실이 추가될 수 있으므로 응답 출력에 대한 사후 검증을 추가했습니다.

검증 대상은 다음과 같습니다.

- 숫자와 단위
- 날짜와 기간
- 금액과 비율
- 가능·불가를 단정하는 표현
- 예외 없음, 무조건, 전액과 같은 절대 표현
- 고객 과실 또는 회사 책임에 대한 판정
- 원문에 없는 절차 단계
- 근거 문서와 반대되는 부정 표현

출력에서 추출한 숫자와 기간 표현은 근거 원문에 동일하거나 허용된 형태로 존재하는지 비교합니다. 원문에 없는 숫자가 발견되면 답변을 상담사에게 전달하지 않고 고정된 확인 필요 응답으로 대체합니다.

단순 문자열 일치만으로는 “7일”과 “일주일”처럼 의미가 같은 표현을 놓칠 수 있으므로 정규화된 기간 단위로 비교합니다. 반대로 서로 다른 제품 조건에서 같은 숫자가 등장할 수 있으므로 숫자 존재 여부만으로 근거가 있다고 판단하지 않고 주변 속성도 함께 확인합니다.

사후 검증은 완전한 사실 판정기가 아니라 추가 안전망입니다. 검색 신뢰도 게이트를 통과하지 못한 요청을 사후 검증만 믿고 생성 단계에 보내는 방식은 허용하지 않습니다.

## 회귀 시험 설계
<!--meta: sec=s19; dept=AIAX; level=주니어|시니어; ct_band=중; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
재발 방지 시험은 정상 답변 시험과 안전한 거부 시험으로 분리했습니다.

### 정상 답변 시험

- 정확한 환불 규정 문서가 검색됨
- 제품과 구매 경로가 명확함
- 기간, 예외, 필요 서류가 모두 근거에 존재함
- 답변의 모든 숫자가 원문과 일치함
- 근거 문서명과 버전이 화면에 표시됨

### 안전한 거부 시험

- 검색 결과를 강제로 0건으로 설정
- 유사도가 기준 미만인 문서만 제공
- 환불과 무관한 배송 문서만 제공
- 기간 조건이 제거된 문서 조각 제공
- 서로 다른 정책 버전 동시 제공
- 질문에 존재하지 않는 “100일” 조건 삽입
- 고객이 확정 답변을 반복 요구하는 상황
- 모델이 일반 상식을 사용하도록 유도하는 질문
- 문서에는 없지만 업계에서 흔한 정책을 질문하는 상황

### 평가 기준

| 평가 항목 | 통과 조건 |
|---|---|
| 근거 충실성 | 답변의 핵심 사실이 원문에 존재 |
| 숫자 일치성 | 기간·금액·비율이 원문과 일치 |
| 거부 정확도 | 근거 부족 시 확정 답변을 생성하지 않음 |
| 출처 표시 | 사용한 원문과 버전이 표시됨 |
| 민감 주제 제한 | 검증 답변 세트 외 자유 생성이 없음 |
| 정책 충돌 처리 | 임의 선택 없이 확인 필요로 전환 |
| 상담사 행동 안내 | 다음 확인 절차가 명확함 |

배포 승인 시 평균 정확도만 보지 않고 고위험 시험 한 건이라도 실패하면 배포를 보류하도록 기준을 변경했습니다.

상담사 신고는 모델 성능 실패뿐 아니라 문서 오류, 오래된 정책, 화면 불편 및 업무 용어 불일치를 함께 수집하도록 유형을 세분화했습니다.

- 특정 문서 개정 이후 무검색률이 급증함
- 모델 또는 검색 설정 변경 직후 차단률 분포가 크게 변함

대응 수준은 세 단계로 구분합니다.

### 관찰

### 제한

같은 유형이 반복되거나 민감 주제에 영향을 줄 가능성이 있는 경우입니다. 해당 주제의 자동 답변을 제한하고 담당자가 검토합니다.

### 중지

고객에게 잘못된 정책이 안내되었거나 시스템 통제가 우회된 경우입니다. 관련 경로를 즉시 중지하고 장애 대응 절차를 시작합니다.

## 지식 문서 관리 개선
<!--meta: sec=s22; dept=AIAX; level=주니어|시니어; ct_band=중; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->

- 예외 조건 포함 여부

환불 기간과 예외 조건처럼 함께 제시되어야 하는 내용은 서로 다른 조각으로 분리되지 않도록 `필수 동반 문단`으로 지정합니다. 검색 단계에서 한 문단만 선택되면 관련 문단을 함께 확장해 전달합니다.

이전 버전 문서는 감사 목적상 보관하되 기본 검색 대상에서는 제외합니다. 현재 문서와 이전 문서가 동시에 검색된 경우에는 모델이 임의로 최신 내용을 선택하지 않고 정책 충돌 상태로 처리합니다.

문서 개정 시에는 기존 질문 세트를 다시 실행해 검색 결과 변화와 답변 제한률 변화를 확인합니다.

INC-AI-01 후속 점검 중, 생성 답변의 내용은 올바르지만 화면에 표시되는 출처 문서가 실제 생성에 사용된 문서와 다른 내부 유사 장애를 추가로 확인했습니다.

원인은 검색 단계에서 생성용 문서 목록은 재정렬된 결과를 사용했지만, 화면 표시용 출처 목록은 재정렬 전 순서를 사용한 것이었습니다. 이 때문에 상담사는 올바른 답변 아래에서 직접 관련이 없는 문서를 첫 번째 근거로 볼 수 있었습니다.

고객에게 잘못된 정책이 안내된 사례는 확인되지 않았지만, 근거 추적성과 상담사 신뢰에 영향을 줄 수 있어 별도 사례로 등록했습니다.

조치 사항은 다음과 같습니다.

- 생성 입력과 화면 출처가 동일한 문서 식별자를 사용하도록 통합
- 답변별 실제 사용 문서 목록을 응답 객체에 고정
- 화면 정렬과 생성 정렬의 일치 여부를 자동 시험
- 문서 식별자, 버전 및 원문 위치를 로그에 함께 기록
- 표시 출처가 생성 입력에 없으면 응답 노출을 차단

이 사례를 통해 “출처를 표시한다”는 기능의 존재만으로는 충분하지 않으며, 표시된 출처가 실제 생성 근거와 동일하다는 보장이 필요함을 확인했습니다.

## 유사 장애 사례 INC-AI-03: 만료 정책 혼입
<!--meta: sec=s27; dept=AIAX; level=시니어; ct_band=상; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
문서 버전 관리 점검 과정에서 종료된 이전 보증 정책이 현재 문서와 함께 검색되는 유사 장애를 발견했습니다. 이전 문서는 감사 목적으로 저장소에 남아 있었고, 제목과 본문이 현재 정책과 유사해 검색 후보에 포함되었습니다.

해당 사례에서는 모델이 이전 문서와 현재 문서의 조건을 섞어 하나의 답변으로 구성할 가능성이 있었습니다. 실제 고객 오안내는 확인되지 않았으며 운영 점검 중 사전 차단했습니다.

원인은 다음과 같습니다.

- 만료 문서에 검색 제외 상태가 지정되지 않음
- 문서 적용 시작일과 종료일이 검색 필터에 연결되지 않음
- 최신 문서를 우선하는 재정렬 규칙만 있고 만료 문서를 배제하지 않음
- 정책 충돌 시 답변을 중단하는 규칙이 없음

조치 후에는 현재 유효 상태의 문서만 기본 검색 대상으로 사용합니다. 과거 문서가 필요한 감사 조회는 운영 검색과 분리된 경로에서 수행합니다. 서로 다른 유효 기간의 문서가 함께 선택되면 모델 호출 전 정책 충돌 상태로 전환합니다.

## 회고와 교훈
<!--meta: sec=s30; dept=AIAX; level=주니어|시니어; ct_band=상; related=PRJ-CC-DET-->
<!--forbid: 대한전자|INC-AI-->
이번 장애에서 확인한 핵심 교훈은 다음과 같습니다.

1. **검색 결과가 존재하는 것과 답변 근거가 충분한 것은 다릅니다.**  
   관련 문서가 한 건 검색되었다는 이유만으로 생성 단계에 전달해서는 안 됩니다.

2. **프롬프트는 안전장치의 일부일 뿐입니다.**  
   “모르면 답하지 말라”는 자연어 지시보다 호출 차단, 정책 분기 및 출력 검증이 우선되어야 합니다.

3. **안전한 답변 거부도 정상 기능입니다.**  
   모든 질문에 완전한 답을 생성하는 것이 성공이 아닙니다. 근거가 부족할 때 확인 필요로 전환하는 것이 더 높은 품질일 수 있습니다.

4. **숫자와 확정 표현은 별도로 검증해야 합니다.**  
   기간, 금액, 비율 및 가능 여부는 자연스러운 문장 안에 포함되어도 업무 위험이 높습니다.

5. **민감 주제는 일반 질의와 다른 정책이 필요합니다.**  
   환불·보증은 제품 사용법과 동일한 생성 자유도를 적용할 수 없습니다.

6. **상담사는 중요한 최종 방어선이지만 유일한 방어선이 되어서는 안 됩니다.**  
   이번 장애는 상담사의 확인으로 확산이 제한되었으나, 시스템이 근거 부족을 먼저 차단해야 합니다.

7. **출처는 표시 여부보다 일치성과 유효성이 중요합니다.**  
   실제 사용한 문서인지, 현재 유효한 문서인지, 필요한 조건을 포함하는지까지 보장해야 합니다.

8. **정상 경로보다 실패 경로를 더 의도적으로 시험해야 합니다.**  
   무검색, 부분 검색, 정책 충돌 및 구어체 질문은 배포 필수 시험에 포함되어야 합니다.

9. **생성형 AI 장애는 모델 하나의 문제가 아닙니다.**  
   문서 구조, 검색, 프롬프트, 후처리, 화면, 상담 절차 및 운영 모니터링이 함께 작동해야 합니다.

10. **고객 영향이 작았다는 결과로 통제 결함을 축소해서는 안 됩니다.**  
    이번에는 상담사 3명의 주의와 즉시 정정 연락으로 영향이 제한되었지만, 동일 원인이 반복되면 더 큰 오안내로 이어질 수 있습니다.
