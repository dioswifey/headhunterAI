# 리드 스코어링 및 MQL·SQL 이관 기준
<!--meta: doc=SLS-04; doc_type=sales_standard; tier=1; topic=SALES; disclosure=internal; status=active-->

## 리드 수명주기 단계 정의
<!--meta: sec=s1; dept=SALES; level=주니어|시니어; ct_band=중; related=SLS-03#s6-->

리드 수명주기는 미검증 접촉(Raw), 문의(Inquiry), MQL, 영업 수락(SAL), SQL 순으로 관리한다. 각 단계는 접촉 건수가 아니라 동일 인물과 어카운트를 기준으로 판정하며, 단계 변경 일시와 근거를 함께 기록한다. 채널별 최초 수집 절차는 SLS-03#s6을 따른다.

### 단계별 정의와 전환 조건

| 단계 | 정의 | 진입 조건 | 이탈 조건 | 기록 주체 | 상태 변경 권한 |
|---|---|---|---|---|---|
| 미검증 접촉(Raw) | 연락처 또는 식별 가능한 조직 정보만 확보된 상태 | 허용된 채널에서 최소 1개 연락 수단 확보 | 문의 확인, 제외 판정, 중복 병합 | 최초 수집 담당자 | SALES 채널 담당자 |
| 문의(Inquiry) | 자료 열람, 행사 등록, 문의 제출 등 관심 행동이 확인된 상태 | 유효 행동 1건 이상과 연락 가능 정보 확인 | MQL 승격, 육성 유지, 제외 처리 | SALES 채널 담당자 | SALES 대리 이상 또는 자동화 규칙 |
| MQL | 마케팅 활동으로 확보한 리드 중 관심도와 이해도가 정해진 임계값 이상인 상태 | 속성·행동 점수가 MQL 임계값 충족 또는 강한 신호 예외 적용 | SAL 수락, 반환, 감쇠에 따른 Inquiry 하향 | SALES 내 채널 운영 담당자 | 승인된 자동화 규칙 또는 SALES 과장 이상 |
| 영업 수락(SAL) | 영업 담당자가 직접 검토하고 후속 접촉 책임을 인수한 상태 | 필수 정보 확인, 중복 점검, 담당자 배정 | SQL 승격, 마케팅 반환, 제외 처리 | 배정된 SALES 담당자 | 담당 SALES 또는 과장 이상 |
| SQL | 영업이 직접 대화하여 필요, 예산, 결정권자 관여를 확인한 상태 | 유효한 양방향 대화와 3개 요건의 확인 근거 기록 | 디스커버리 이관, 보류, 자격 상실 | 배정된 SALES 담당자 | SALES 과장 이상 |

MQL은 관심·이해도에 대한 점수 기반 판정이고, SQL은 영업의 직접 대화로 필요·예산·결정권자 관여를 검증한 판정이다. SAL은 MQL을 영업이 인수했음을 나타내며 SQL과 동일하게 보지 않는다. 이메일 열람이나 자료 다운로드만으로 SQL을 부여하지 않는다.

### 단계 기록 원칙

- 모든 리드는 리드 ID와 어카운트 ID를 각각 가진다.
- 동일 이메일과 동일 인물은 원칙적으로 하나의 활성 리드로 병합한다.
- 단계 진입일은 최초 충족 시각으로 기록한다.
- 단계 이탈일은 다음 상태 확정 시각으로 기록한다.
- 상태 변경 근거는 행동 로그, 통화 기록 또는 미팅 기록으로 남긴다.
- 자유 서술만으로 상태를 변경하지 않는다.
- 자동 승격에는 적용 규칙 버전과 실행 시각을 저장한다.
- 수동 변경에는 변경자, 변경 사유 코드, 승인자를 저장한다.
- DATA는 원천 데이터 오류를 정정할 수 있으나 영업 판정을 대신하지 않는다.

### 집계와 정의 고정

- MQL 집계는 해당 기간에 MQL로 최초 승격한 고유 리드 수로 계산한다.
- SQL 집계는 해당 기간에 SQL로 최초 승격한 고유 리드 수로 계산한다.
- 같은 기간의 MQL과 SQL은 동일한 리드 집합일 필요가 없다.
- 이전 기간 MQL이 이번 기간 SQL로 전환될 수 있다.
- SAL 반환과 무응답으로 MQL이 SQL에 도달하지 않을 수 있다.
- 직접 영업 발굴 리드는 예외 경로로 MQL을 거치지 않을 수 있다.
- 따라서 MQL 수와 SQL 수가 다르게 집계되는 것을 정상으로 판단한다.
- 두 수치를 단순 차감하여 미전환 잔량으로 해석하지 않는다.
- 전환율은 코호트 기준일과 관찰 기간을 명시한 경우에만 비교한다.
- 단계 정의, 필수 필드, 이관 시점은 문서 버전으로 고정한다.
- 정의 변경은 시행일 이전 집계에 소급 적용하지 않는다.

정의를 고정하지 않으면 동일 행동이 기간이나 담당자에 따라 MQL 또는 SQL로 달리 분류될 수 있다. 집계 논쟁이 발생하면 수치를 임의 보정하지 않고 적용된 정의 버전, 상태 이력, 코호트 기준일을 먼저 확인한다.

### 단계 생략 예외

1. 구체적인 업무 과제와 미팅 요청이 포함된 인바운드는 Inquiry에서 MQL로 즉시 승격할 수 있다.
2. 강한 신호가 확인된 MQL은 일반 대기열을 거치지 않고 SAL 검토 대상으로 즉시 이관할 수 있다.
3. 기존 접점이 있는 어카운트의 신규 담당자는 확인된 관계 근거가 있으면 Raw에서 SAL로 이동할 수 있다.
4. 공공조달 공고에서 공식 담당자와 유효 과제가 확인되면 Raw 또는 Inquiry에서 SAL로 이동할 수 있다.
5. 아웃바운드 대상자가 과제 논의에 명시적으로 동의하면 MQL을 생략하고 SAL로 이동할 수 있다.
6. 단계 생략 시 `DIRECT_SALES`, `PUBLIC_PROCUREMENT`, `EXISTING_ACCOUNT`, `STRONG_SIGNAL` 중 사유 코드를 기록한다.
7. 단계 생략은 점수 이력을 삭제하거나 임의로 보정하는 사유가 되지 않는다.
8. SQL은 직접 대화 기록 없이 예외 승격하지 않는다.
9. 필요·예산·결정권자 관여 중 하나라도 미확인이면 SAL에 유지한다.
10. 제외 대상이 뒤늦게 확인되면 기존 단계를 유지하지 않고 제외 상태로 전환한다.

예외 경로는 처리 속도를 위한 절차 단축이며 자격 기준의 완화를 의미하지 않는다. 디스커버리 이관 여부는 초기 접촉 결과를 근거로 판단하고 SLS-05#s8을 따른다.

## 속성 점수 배점표
<!--meta: sec=s2; dept=SALES|DATA; level=주니어|시니어; ct_band=중; related=SLS-02#s4-->

속성 점수는 리드가 헤드헌터랩의 영업 대상과 얼마나 부합하는지를 나타내는 정적 점수다. 산업 구획, 종업원 수, 담당자 직급·직무, 데이터 담당 조직, 지역을 평가하고 확인 가능한 최신 정보만 사용한다. 속성 점수는 행동 의향이나 구매 확정을 의미하지 않는다.

### 기본 배점표

| 평가 항목 | 판정 구간 | 점수 | 확인 근거 | 갱신 기준 | 비고 |
|---|---|---:|---|---|---|
| 산업 구획 | SLS-02 핵심 산업군 / 인접 산업군 / 탐색 산업군 / 제외 산업군 | +12 / +7 / +2 / -20 | 공식 웹사이트, 공시·공공 정보 | 산업 변경 확인 시 | 구획명은 SLS-02#s3 적용 |

| 관계 유형 | 일반 대상 / 경쟁 관계 조직 | 0 / -40 | 공개 정보, 당사 확인 | 발견 즉시 | 제외 검토 대상으로 전환 |
| 문의 목적 | 업무 문의 / 학생·연구 과제 / 구직 문의 | 0 / -40 / -40 | 문의 내용, 직접 확인 | 목적 확인 즉시 | 영업 리드 집계에서 제외 |

배점은 각 항목에서 하나의 구간만 선택하며, 같은 사실을 복수 항목에 중복 반영하지 않는다. 확인되지 않은 회사 규모나 직급을 추정하여 가점을 부여하지 않는다. 상충하는 근거가 있으면 확인일이 최근인 공식 정보 또는 직접 답변을 우선한다.

### 산정 및 보정 원칙

- 기본 속성 점수 상한은 40점으로 한다.
- 감점 적용 후 하한은 -40점으로 한다.
- 상한을 넘는 원점수는 40점으로 절단한다.
- 경쟁 관계, 학생·연구 과제, 구직 문의는 점수와 별도로 제외 검토 플래그를 부여한다.
- 제외 플래그가 있으면 총점만으로 MQL에 자동 승격하지 않는다.
- 개인 이메일은 조직 소속이 확인되어도 감점 사유를 삭제하지 않는다.
- 조직 공식 이메일이 추가 확인되면 개인 이메일 감점을 해제할 수 있다.
- 역할 불명 감점은 부서와 담당 업무가 모두 확인된 시점에 해제한다.
- 종업원 수가 범위로만 확인되면 가장 보수적인 구간을 적용한다.
- 해외 소재는 자동 제외하지 않으며 지역 가점만 부여하지 않는다.
- 수동 보정은 항목별 원점수를 바꾸지 않고 별도 조정 필드에 기록한다.
- 수동 조정값은 -5점부터 +5점까지로 제한한다.

### ICP 등급과의 관계

- ICP 등급은 어카운트 수준의 적합도이며 SLS-02#s4를 따른다.
- 속성 점수는 개별 리드와 접촉 담당자의 적합도를 포함한다.
- ICP 등급 자체를 속성 점수에 추가하지 않는다.
- 산업, 규모, 지역은 승인된 ICP 원천값을 재사용한다.
- 같은 산업 적합성을 ICP 점수와 리드 점수에 각각 더하지 않는다.
- CRM에 ICP 등급이 있으면 해당 등급의 기준 데이터만 속성 판정에 참조한다.
- ICP A등급이라도 담당 역할이 불명확하면 관련 감점을 유지한다.
- ICP 등급이 낮아도 담당자 적합성이 높다는 이유만으로 등급을 변경하지 않는다.
- ICP 정보가 없으면 속성 점수를 산정하되 `ICP_UNASSESSED`를 표시한다.
- ICP 재평가가 완료되면 변경된 원천값부터 다음 점수 계산에 반영한다.
- 과거 점수는 삭제하지 않고 적용일과 모델 버전을 보존한다.

DATA는 속성값의 정합성, 중복, 누락 여부를 점검하고 SALES는 업무상 의미와 최신성을 확인한다. 점수 변경이 MQL 상태에 영향을 주는 경우 자동 변경 로그와 담당자 알림을 함께 생성한다.

### 확인 불가 정보 처리

- 확인 불가 값은 임의의 평균값으로 대체하지 않는다.
- 산업 구획 미확인은 탐색 산업군 점수를 적용하지 않고 0점으로 둔다.
- 종업원 수 미확인은 0점으로 둔다.
- 담당자 직급 불명은 -3점을 적용한다.
- 담당자 직무 불명은 역할 불명 감점과 중복 적용하지 않는다.
- 데이터 담당 조직 미확인은 0점으로 둔다.
- 정보 확인 요청에 응답이 없다는 사실만으로 추가 감점하지 않는다.
- 공개 정보가 24개월 이상 지난 경우 재확인 대상으로 표시한다.
- 수동 확인 완료일과 확인자를 필수 필드로 기록한다.

속성 점수는 최초 등록 시 계산하고 핵심 속성 변경 시 다시 계산한다. 일괄 재계산은 승인된 모델 버전의 시행일 이후 활성 리드에만 적용한다.

## 행동 점수 배점표와 감쇠 규칙
<!--meta: sec=s3; dept=SALES|DATA; level=주니어|시니어; ct_band=상; related=none-->

행동 점수는 리드가 헤드헌터랩의 콘텐츠와 접점에 보인 관심 강도를 나타낸다. 단순 노출보다 자발적 요청과 양방향 접촉에 높은 점수를 부여하고, 반복 행동에는 횟수 상한을 둔다. 봇 트래픽, 내부 테스트, 수신 거부 이후 발생한 자동 이벤트는 계산에서 제외한다.

### 행동 배점과 감쇠율

| 구분 | 행동 또는 경과 기간 | 최초 점수 | 반복 점수 | 적용 상한·감쇠율 | 판정 조건 |
|---|---|---:|---:|---|---|
| 행동 | 사이트 방문·페이지 깊이 | 일반 방문 +1, 핵심 페이지 3개 이상 +3 | 같은 날 추가 방문 0, 다른 날 +1 | 7일간 최대 7점 | 30초 미만·1페이지만 조회한 세션 제외 |
| 행동 | 이메일 열람·링크 클릭 | 열람 +1, 고유 링크 클릭 +3 | 반복 열람 0, 추가 고유 링크 +1 | 캠페인당 최대 5점 | 보안 스캐너 클릭 제외 |
| 행동 | 자료 요청·다운로드 | 첫 자료 요청 +6 | 다른 자료 요청 +2 | 30일간 최대 10점 | 직접 입력한 유효 연락처 필요 |
| 행동 | 세미나 등록·참석 | 등록 +5, 실제 참석 추가 +10 | 추가 행사 등록 +2 | 행사당 최대 15점 | 미참석 시 참석 점수 미부여 |
| 행동 | 문의 양식 작성 | 유효 문의 +15 | 동일 내용 중복 제출 0 | 14일간 최대 15점 | 업무 과제 또는 연락 요청 포함 |
| 행동 | 견적 페이지 조회 | 최초 조회 +8 | 7일 내 재조회 +3 | 14일간 최대 14점 | 가격·계약 자격 판정으로 사용하지 않음 |
| 행동 | 재방문 | 7일 이상 경과 후 재방문 +4 | 30일 내 추가 재방문 +1 | 30일간 최대 6점 | 식별 가능한 동일 리드에 한함 |
| 감쇠 | 최종 유효 행동 후 0~14일 | 해당 없음 | 해당 없음 | 0% 감쇠 | 행동 점수 100% 유지 |
| 감쇠 | 최종 유효 행동 후 15~30일 | 해당 없음 | 해당 없음 | 20% 감쇠 | 기준 행동 점수의 80% 유지 |
| 감쇠 | 최종 유효 행동 후 31~60일 | 해당 없음 | 해당 없음 | 40% 감쇠 | 기준 행동 점수의 60% 유지 |
| 감쇠 | 최종 유효 행동 후 61~90일 | 해당 없음 | 해당 없음 | 70% 감쇠 | 기준 행동 점수의 30% 유지 |
| 감쇠 | 최종 유효 행동 후 91일 이상 | 해당 없음 | 해당 없음 | 90% 감쇠 | 기준 행동 점수의 10% 유지 |

반복 점수는 동일 행동의 기계적 반복으로 점수가 급등하지 않도록 제한한다. 행동 점수 원점수의 상한은 60점이며, 상한 초과분은 다음 기간으로 이월하지 않는다. MQL 총점 임계값과 속성·행동 점수 결합 방식은 SLS-04#s4에서 정한다.

### 행동 로그 계산 원칙

- 최초 점수는 정해진 관찰 기간의 첫 유효 행동에만 부여한다.
- 반복 점수는 표의 기간 상한 안에서만 누적한다.
- 동일 초 단위로 수집된 중복 이벤트는 하나로 병합한다.
- 사내 IP, 품질 점검 계정, 자동화 테스트 계정의 행동은 제외한다.
- 이메일 열람은 클릭이나 회신보다 낮은 신뢰도의 행동으로 취급한다.
- 보안 솔루션의 자동 링크 검사는 사용자 클릭으로 계산하지 않는다.
- 사이트 방문은 동의된 식별 정보와 연결된 경우에만 리드 점수에 반영한다.
- 행사 참석은 출석 로그 또는 운영 담당자의 확인 기록이 있어야 한다.
- 전화·이메일의 명시적 거절은 행동 점수를 추가하지 않고 별도 상태로 기록한다.
- 점수 정정 시 원천 이벤트를 삭제하지 않고 제외 사유를 남긴다.
- 모든 계산에는 행동 규칙 버전과 계산 시각을 기록한다.

### 감쇠 적용 절차

- 감쇠 기준일은 마지막 유효 가점 행동의 발생일로 한다.
- 감쇠는 매일 1회 승인된 자동 작업으로 계산한다.
- 각 구간의 감쇠율은 행동 원점수에 직접 적용한다.
- 전일 감쇠 점수에 다시 감쇠율을 곱하지 않는다.
- 계산 결과의 소수점은 첫째 자리에서 반올림한다.
- 감쇠 후 행동 점수 하한은 0점으로 한다.
- 91일 이후에도 원점수의 10%를 잔존 점수로 유지한다.
- 새로운 유효 행동이 발생하면 해당 시점의 원점수 합계로 구간을 다시 계산한다.
- 반환된 리드도 마지막 유효 행동일을 기준으로 동일하게 감쇠한다.
- 제외 상태의 리드는 감쇠 계산을 중지하되 원점수와 이력을 보존한다.
- 감쇠로 임계값 아래가 되면 다음 일괄 처리에서 단계 하향 검토 대상으로 표시한다.

감쇠는 오래된 관심 신호를 현재 의향으로 오인하지 않기 위한 장치다. 감쇠만으로 SAL 또는 SQL 상태를 자동 하향하지 않으며 담당자가 최근 대화 기록과 후속 일정 유무를 확인한다.

### 강한 신호와 즉시 이관

- 구체적인 업무 과제와 희망 연락 일정이 포함된 문의 양식 제출
- 담당 조직이 확인된 상태에서 디스커버리 미팅을 직접 요청한 경우
- 공공조달 과제의 공식 담당자가 기술 검토 연락을 요청한 경우
- 동일 리드가 7일 안에 견적 페이지를 2회 이상 조회하고 문의를 제출한 경우
- 세미나 참석 후 2영업일 안에 업무 적용 상담을 요청한 경우
- 자료 요청과 회신에서 도입 검토 일정이 함께 확인된 경우
- 강한 신호는 행동 총점과 관계없이 MQL로 표시하고 SAL 검토 대기열에 즉시 이관한다.
- 즉시 이관에는 연락처, 조직명, 행동 근거, 발생 시각이 모두 있어야 한다.
- 조직 식별이 불가능하거나 자동 이벤트로 의심되면 즉시 이관을 보류한다.
- 강한 신호는 SQL 자동 승격 사유로 사용하지 않는다.

즉시 이관은 영업의 확인 순서를 앞당기는 예외이며 필요·예산·결정권자 관여가 검증되었다는 의미가 아니다. 담당 SALES는 원천 행동을 확인한 뒤 SAL 수락 또는 반환을 기록한다.

## MQL 임계값과 SQL 승격 요건
<!--meta: sec=s4; dept=SALES; level=주니어|시니어; ct_band=중; related=DSC-01#s10-->

MQL은 속성 점수와 행동 점수의 합계가 정해진 임계값을 충족하고 필수 조건을 모두 통과한 리드로 정의한다. 합계 점수만 높고 최근 관심 행동이나 유효 연락 수단이 없는 리드는 MQL로 이관하지 않는다. 세부 배점은 SLS-04#s2 및 SLS-04#s3을 적용한다.

### MQL 판정 기준

점수 체계는 속성 40점과 행동 60점의 합계 100점을 기준으로 한다. MQL 임계값은 60점으로 두되, 속성 적합성과 실제 행동을 함께 요구해 한쪽 점수만으로 승격되는 경우를 제한한다. 60점은 복수의 관심 행동과 최소 적합 속성이 함께 확인되는 수준으로 설정한다.

| 구분 | 설정값 | 판정 기준 | 설정 근거 |
|---|---:|---|---|
| 합계 임계값 | 60점 이상 | 속성 점수와 유효 행동 점수의 합계 | 단일 행동 또는 속성만으로 승격되는 경우를 줄인다 |
| 속성 점수 하한 | 20점 이상 | ICP 관련 속성이 최소 수준을 충족 | 관심은 높지만 대상 적합성이 낮은 리드를 제외한다 |
| 행동 점수 하한 | 25점 이상 | 감쇠 적용 후 유효 행동 점수 | 적합 기업이지만 관심 행동이 없는 경우를 제외한다 |
| 최근 행동 조건 | 30일 이내 1건 이상 | 자료 요청, 세미나 참석 등 유효 행동 | 과거 행동만 남은 휴면 리드를 구분한다 |
| 연락 가능 조건 | 유효 수단 1개 이상 | 업무용 이메일 또는 확인된 전화번호 | 영업 후속 접촉이 불가능한 이관을 막는다 |
| 수신 거부 조건 | 미등록 | 전체 수신 거부 또는 연락 금지 여부 확인 | 수신 의사와 채널 제한을 반영한다 |
| 부정 점수 조건 | 적용 완료 | 제외 산업, 개인 문의 등 감점 반영 | 긍정 점수만 누적되는 오류를 방지한다 |
| 수작업 예외 | SALES 과장 승인 | 긴급 문의 등 점수 반영 지연 사유 기록 | 자동 집계 지연에 한해 제한적으로 허용한다 |
| SQL 점수 조건 | 적용하지 않음 | SQL은 영업 대화로 검증 | 행동량을 구매 준비도로 오인하지 않는다 |
| 재판정 주기 | 매일 1회 | 감쇠와 신규 행동 반영 후 재계산 | 오래된 행동의 가치 하락을 반영한다 |

### MQL 필수 조건

- 리드의 소속 조직과 업무용 연락처가 확인되어야 한다.
- 동일 인물 또는 동일 문의의 중복 레코드가 제거되어야 한다.
- 수신 거부와 연락 채널 제한이 최신 상태로 반영되어야 한다.
- 최근 30일 이내 유효 행동이 최소 1건 있어야 한다.
- 속성 점수와 행동 점수가 각각 하한을 충족해야 한다.
- SLS-02#s6의 ICP 제외 기준에 해당하지 않아야 한다.
- 자동 점수 산정일과 사용한 규칙 버전이 기록되어야 한다.

### 임계값 예외 처리

1. 합계 60점 이상이더라도 필수 조건이 누락되면 승격을 보류한다.
2. 합계 55~59점인 긴급 상담 요청은 SALES 과장 승인 후 MQL로 수동 승격할 수 있다.
3. 수동 승격에는 요청 내용, 승인자, 승인 시각과 자동 점수 미달 사유를 남긴다.
4. 합계 60점 미만인 명함 수집, 단순 구독 또는 반복 방문만으로는 승격하지 않는다.
5. 감쇠 적용 후 60점 미만이 된 미이관 리드는 일반 리드 단계로 유지한다.

SQL은 MQL 점수의 추가 상승이 아니라 영업 담당자의 직접 대화로 확인된 사실에 따라 승격한다. 이메일 회신만으로도 사실 확인이 가능하나 추정 문구나 마케팅 행동 기록을 대화 확인으로 대체하지 않는다. 디스커버리 착수 가능 여부는 DSC-01#s10을 함께 적용한다.

### SQL 확인 체크리스트

- 문제 실재: 현재 업무상 문제와 영향을 고객 표현으로 확인한다.
- 추진 주체: 과제를 검토하거나 내부 조정을 담당하는 인물을 확인한다.
- 일정: 검토, 의사결정 또는 착수 목표 시점을 월 단위 이상으로 확인한다.
- 예산: 배정 예산 또는 실행 가능한 재원 경로와 확인 주체를 확인한다.
- 결정 관여: 최종 승인자 또는 승인 절차에 접근 가능한 관여자를 확인한다.
- 대상 범위: 적용 업무, 사용자 또는 조직 범위 중 최소 1개를 확인한다.
- 후속 합의: 다음 미팅, 자료 제공 또는 내부 확인 일정 중 1개를 합의한다.
- 연락 진정성: 본인 확인과 업무 관련성을 검증한다.
- 제외 여부: ICP 제외 사유와 중복 기회 여부를 다시 확인한다.
- 미확인 항목: 추정값 대신 `미확인`으로 표시하고 확인 예정일을 기록한다.

### SQL 승격 근거 문장

- 문제 근거: `고객은 [업무]에서 [문제]가 발생하며 [영향]이 있다고 확인했다.`
- 추진 주체 근거: `[직무/부서]가 과제 검토를 주관하며 [역할]을 수행한다고 확인했다.`
- 일정 근거: `[YYYY-MM]까지 [검토/의사결정/착수]를 목표로 한다고 확인했다.`
- 예산 근거: `[예산 상태 또는 재원 경로]를 [확인 주체]와 확인했다.`
- 결정 관여 근거: `[승인 역할]이 [절차 또는 회의]에 관여한다고 확인했다.`

SQL 승격 기록에는 위 근거 문장 5종과 확인 일시, 확인 채널, 영업 담당자를 함께 남긴다. 문제·추진 주체·일정·예산·결정 관여 중 하나라도 사실 확인이 되지 않으면 SAL 또는 디스커버리 준비 상태로 유지한다.

## 영업 수락 판정과 반환 사유 코드
<!--meta: sec=s5; dept=SALES; level=주니어|시니어; ct_band=중; related=none-->

SAL은 영업팀이 이관된 MQL의 정보 완전성, 연락 가능성 및 담당 적합성을 확인하고 후속 접촉 책임을 수락한 상태를 뜻한다. SAL은 SQL과 구분하며, 고객의 문제나 예산을 검증하기 전에도 판정할 수 있다. 영업 담당자는 MQL 배정 후 2영업시간 이내에 수락 또는 반환을 기록한다.

### SAL 판정 절차

판정 시한은 영업 운영시간 내 배정 시각부터 계산한다. 운영시간 외 배정 건은 다음 영업일 업무 시작 시각에 접수된 것으로 본다. 정보 보완이 필요한 경우에도 시한 내 임시 보류 사유와 보완 요청 대상을 기록한다.

1. 리드 ID와 기존 어카운트·담당자 중복 여부를 조회한다.
2. 소속 조직, 업무용 연락처 및 수신 거부 상태를 확인한다.
3. 점수 합계와 MQL 필수 조건 충족 여부를 검토한다.
4. 서울·경기·인천 지점 귀속과 SALES 담당자를 확인한다.
5. 접촉 가능한 리드는 SAL로 수락하고 최초 접촉 시각을 등록한다.
6. 수락할 수 없는 리드는 반환 코드 1개를 주 코드로 선택한다.
7. 복수 사유가 있으면 보조 코드와 확인 근거를 추가 기록한다.

### 반환 사유 코드

| 코드 | 반환 사유 | 적용 기준 | 후속 처리 | 재검토 기준 |
|---|---|---|---|---|
| RT-01 | 연락처 오류 | 이메일 반송 및 전화번호 불통·오번호 확인 | 마케팅 정보 보완 | 보완 후 즉시 |
| RT-02 | 역할 불일치 | 해당 인물이 과제와 무관하고 연결 경로도 없음 | 마케팅 양육 | 적합 역할 확보 시 |
| RT-03 | 과제 부재 | 직접 확인 결과 검토 중인 문제나 과제가 없음 | 양육 또는 폐기 | 신규 행동 발생 시 |
| RT-04 | 시기 아님 | 과제는 있으나 검토 시점이 90일 이후임 | 마케팅 양육 | 확인한 예정일 |
| RT-05 | ICP 제외 | SLS-02#s6 제외 기준에 해당 | 폐기 또는 제외 보관 | 제외 사유 해제 시 |
| RT-06 | 중복 | 동일 인물·조직·문의 레코드가 이미 존재 | 기존 레코드 병합 | 별도 재검토 없음 |

### 반환 코드 집중 시 점검

- RT-01이 월 반환의 30%를 넘으면 입력 검증, 폼 형식 및 데이터 최신성을 점검한다.
- RT-02가 30%를 넘으면 직책·부서 속성 배점과 채널 타게팅 조건을 점검한다.
- RT-03이 30%를 넘으면 행동 점수 배점과 단순 관심 행동의 과대평가 여부를 점검한다.
- RT-04가 30%를 넘으면 행동 감쇠 주기와 캠페인 시점 조건을 점검한다.
- RT-05가 20%를 넘으면 SLS-02#s3 속성 매핑과 제외 규칙 자동화를 점검한다.
- RT-06이 10%를 넘으면 이메일·전화번호·도메인 기준 중복 제거 로직을 점검한다.

### 후속 처리 규칙

- 마케팅 양육 건은 반환일, 재검토 조건 및 담당 캠페인을 기록한다.
- 재검토 예정일은 고객이 밝힌 시점보다 10영업일 앞선 날짜로 설정한다.
- 시점이 불명확한 RT-04는 반환일로부터 90일 후 재검토한다.
- 폐기 건은 삭제와 구분해 상태를 종료하고 근거를 보존한다.
- 연락처 오류는 서로 다른 채널 2개가 모두 무효일 때 폐기 후보로 전환한다.
- 중복 건의 활동 이력은 기존 주 레코드에 병합하고 신규 레코드를 종료한다.
- ICP 제외 건은 제외 사유 코드와 판정 근거 출처를 함께 남긴다.
- 반환 후 새 행동이 발생하면 점수를 재계산하고 필수 조건을 다시 검증한다.

반환은 영업 담당자가 임의로 리드를 제거하는 절차로 사용하지 않는다. 반환 근거가 부족하거나 코드 적용이 불명확한 건은 SALES 과장이 1영업일 이내 재판정한다. 지점 귀속 문제만 있는 경우에는 반환하지 않고 담당자를 재배정한다.

### SAL 기록 필수 항목

- MQL ID와 어카운트 ID
- 배정 시각과 판정 시각
- 판정 담당자와 소속 지점
- SAL 수락 또는 반환 상태
- 반환 주 코드와 보조 코드
- 사실 확인 근거와 확인 채널
- 재검토 예정일 또는 종료 사유

SAL 판정 기록은 최초 값을 덮어쓰지 않고 변경 이력을 유지한다. 반환 후 재이관된 건은 이전 반환 코드, 보완 내용 및 재이관 시각을 연결해 기록한다.

## 영업·마케팅 SLA
<!--meta: sec=s6; dept=SALES; level=시니어; ct_band=상; related=SLS-03#s9-->

영업·마케팅 SLA는 MQL 이관 전후의 정보 품질, 응답 시한 및 상태 갱신 책임을 정한다. SLA 시간은 회사 영업일과 각 지점의 공통 영업시간을 기준으로 계산한다. 채널별 성과 판단은 SLS-03#s9를 함께 적용한다.

### 쌍방 의무와 처리 시한

마케팅은 점수만 전달하지 않고 영업이 판정과 접촉을 수행할 수 있는 정보를 함께 이관한다. 영업은 MQL 배정 후 2영업시간 이내에 접수 확인과 최초 개인화 접촉을 수행한다. 자동 회신만 발송한 경우 최초 접촉으로 계산하지 않는다.

| 주체 | 의무 | 처리 기준 | 시한·주기 | 완료 증빙 |
|---|---|---|---|---|
| 마케팅 | 필수 식별 정보 제공 | 성명, 조직, 직무, 업무용 연락처 | 이관 시 | CRM 필드 |
| 마케팅 | 점수 근거 제공 | 속성·행동 점수와 규칙 버전 | 이관 시 | 점수 이력 |
| 마케팅 | 행동 이력 제공 | 최근 90일 행동 일시·유형 | 이관 시 | 활동 로그 |
| 마케팅 | 중복 제거 | 인물·조직·문의 중복 조회 | 이관 전 | 중복 검사 결과 |
| 마케팅 | 수신 거부 반영 | 채널별 거부와 동의 상태 확인 | 이관 전 | 동의 이력 |
| 마케팅 | 이관 알림 | 배정 담당자와 지점에 알림 | 10분 이내 | 알림 로그 |
| 영업 | SAL 판정 | 수락·반환과 근거 기록 | 2영업시간 이내 | 상태 변경 이력 |
| 영업 | 최초 응답 | 개인화 이메일 또는 전화 시도 | 2영업시간 이내 | 접촉 활동 로그 |
| 영업 | 반복 접촉 | 서로 다른 날짜와 채널을 조합 | 10일 이상, 최소 5회 | 시도별 기록 |
| 영업 | 무응답 반환 | 마케팅 양육 상태로 반환 | 제5회 시도 후 1영업일 이내 | 반환 코드 |
| 영업 | 상태 갱신 | 접촉 결과와 다음 행동일 기록 | 활동 후 1영업일 이내 | CRM 변경 이력 |

### 기준선과 전환 목표

- 외부 벤치마크는 정밀한 행동 점수 설계와 2시간 미만 응답 SLA를 운영하는 조직의 MQL→SQL 전환율을 30~40%로 제시한다.
- 이 범위는 참고값이며 헤드헌터랩의 달성률을 보장하는 값으로 사용하지 않는다.
- 현재 기준선은 문서 시행 직전 8주간의 유효 MQL 코호트 실측값으로 확정한다.
- 8주 데이터가 없으면 현재 기준선을 `미산정`으로 표시하고 시행 후 첫 8주 값으로 확정한다.
- 운영 목표는 기준선 확정 후 분기 MQL→SQL 전환율 30% 이상, 2시간 SLA 준수율 95% 이상으로 둔다.

### SLA 집계 방법

- 집계 단위는 MQL ID 1건이며 재이관은 별도 회차로 구분한다.
- 분모는 해당 기간 영업에 이관된 유효 MQL 수로 한다.
- 2시간 준수율 분자는 시한 내 SAL 판정과 최초 접촉을 모두 완료한 건수로 한다.
- MQL→SQL 전환율은 해당 코호트 중 30일 이내 SQL로 승격한 건수를 분자로 한다.
- 무응답 접촉 횟수는 날짜, 채널 및 시각이 기록된 시도만 인정한다.
- 동일 날짜의 반복 전화는 접촉 시도 1회로 계산한다.
- 시스템 장애와 승인된 휴업일은 예외 시간을 제외한 뒤 다시 계산한다.
- 월 집계는 익월 3영업일까지 확정하며 원본 로그와 수정 이력을 보존한다.

전환율은 MQL 품질과 영업 대응이 함께 반영되는 지표이므로 한 부서의 단독 성과로 판단하지 않는다. 기준선 대비 5%p 이상 변동하면 점수 규칙, 채널 구성, 응답 시간 및 반환 코드를 함께 점검한다. 파이프라인 집계와 수주 예측에는 이 지표를 직접 전용하지 않는다.

### SLA 위반 조치 단계

1. 단건 위반은 담당자가 원인과 보완 조치를 1영업일 이내 기록한다.
2. 월 2건 이상 위반한 담당자는 SALES 과장과 처리 절차를 재점검한다.
3. 지점 준수율이 90% 미만이면 지점별 원인 분석을 3영업일 이내 제출한다.
4. 동일 의무가 2개월 연속 90% 미만이면 담당 부서장이 개선 계획을 승인한다.
5. 중복·수신 거부 누락은 건수와 무관하게 즉시 마케팅 책임자에게 통보한다.
6. 2시간 응답 지연이 월 10건 이상이면 배정 알림과 대체 담당 규칙을 점검한다.
7. 개선 후 4주간 주 단위로 준수율을 확인하고 95% 이상이면 집중 점검을 종료한다.

### 예외와 분쟁 처리

- 고객이 특정 연락일을 지정한 경우 최초 접수 확인만 2시간 내 수행하고 지정일에 접촉한다.
- 담당자 부재가 예상되면 부재 시작 전 대체 담당자를 지정한다.
- 시스템 장애 예외는 장애 시작·종료 시각과 영향 MQL 목록이 있을 때만 인정한다.
- 필수 정보가 누락된 이관은 영업이 보완 요청 시각을 기록하고 SAL 판정을 보류할 수 있다.
- 쌍방 책임이 불명확한 건은 SALES 부장과 관련 부서 책임자가 2영업일 이내 판정한다.
- 판정 결과는 책임 부서, 원인, 재발 방지 항목 및 적용일을 SLA 이력에 남긴다.

SLA 수치는 월별 운영회의에서 확인하되 개별 건의 사실 기록을 우선한다. 목표 미달만으로 점수 임계값을 즉시 낮추지 않으며 최소 8주 코호트와 반환 사유 분포를 검토한 뒤 조정한다. 스코어링 모델 조정은 SLS-04#s7에 따른다.

## 스코어링 모델 검증과 재조정
<!--meta: sec=s7; dept=DATA|SALES; level=시니어; ct_band=상; related=none-->

스코어링 모델은 점수가 높을수록 SQL 전환 가능성이 높아지는지를 실제 결과로 검증한다. DATA가 분기별 검증 데이터를 산출하고 SALES가 오탐·미탐 사례의 업무 맥락을 확인한다. 외부 벤치마크는 참고값으로만 사용하며 내부 임계값을 직접 대체하지 않는다.

### 분기 검증 방법

검증 대상은 관찰 기간 10영업일이 지난 MQL을 기본으로 하며, 동일한 모델 버전과 단계 정의가 적용된 리드끼리 비교한다. 점수 구간별 SQL 전환율을 역산해 단조성이 깨지는 구간을 찾고, 고득점 무전환과 저득점 전환 사례를 각각 표본 검토한다. 반환 사유 코드와 채널 구성의 차이도 함께 확인한다.

| 검증 항목 | 산출 기준 | 이상 판단 기준 | 후속 확인 |
|---|---|---|---|
| 점수 구간 분포 | 0~39, 40~59, 60~79, 80~100 구간별 리드 수 | 한 구간이 전체의 60% 초과 | 배점 집중·누락 이벤트 확인 |
| 전환율 단조성 | 구간별 SQL 수 ÷ 해당 구간 관찰 완료 MQL 수 | 상위 구간 전환율이 하위 구간보다 5%p 이상 낮음 | 채널·속성별 재분해 |
| 고득점 오탐 | 80점 이상이면서 SQL 미전환인 리드 | 해당 구간의 40% 초과 | 반환 사유와 행동 중복 확인 |
| 저득점 미탐 | 60점 미만이면서 SQL 전환된 리드 | 전체 SQL의 15% 초과 | 누락 속성·영업 확인 정보 검토 |
| 사유 코드 분포 | 구간별 반환 사유 코드 비율 | 특정 코드가 전분기 대비 15%p 이상 증가 | 정의 변경·입력 편향 확인 |
| 채널 편향 | 채널별 평균 점수와 전환율 비교 | 점수 차이 15점 이상이나 전환율 차이 5%p 미만 | 채널 행동 배점 검토 |
| 응답 SLA 영향 | 2영업시간 이내 응답군과 초과군 비교 | 두 집단 전환율 차이 10%p 이상 | 모델 문제와 운영 지연 분리 |
| 감쇠 효과 | 감쇠 적용 전후 점수·전환율 비교 | 감쇠 후 순위 역전이 표본의 20% 초과 | 감쇠 주기와 하한 검토 |

### 오탐·미탐 표본 리뷰

1. 고득점 오탐 표본은 분기당 최소 20건을 추출한다.
   - 20건 미만이면 해당 구간 전수를 검토한다.
   - 자료 반복 다운로드, 내부 직원 활동, 봇 접근 여부를 확인한다.
2. 저득점 미탐 표본은 분기당 최소 20건을 추출한다.
   - 실제 SQL 승격 근거와 점수에 반영되지 않은 정보를 확인한다.
   - 영업 담당자의 수작업 보정 여부와 증빙을 대조한다.
3. 표본은 지점·채널·산업이 한 범주에 50%를 초과하지 않게 구성한다.
   - 불가피한 경우 편중 사유를 검증 기록에 남긴다.
   - 동일 어카운트의 복수 리드는 1건으로 제한한다.
4. 리뷰 결과는 배점 오류, 데이터 오류, 운영 오류, 정의 오류로 구분한다.
   - 사례만으로 배점을 변경하지 않고 전체 분포에서 재현되는지 확인한다.
   - 사유 코드가 부정확하면 코드 정정 후 지표를 다시 산출한다.

### 재조정 절차와 변경 폭

- 정기 재조정은 분기 종료 후 15영업일 이내에 수행한다.
- 검증 기준일은 분기 말일로 고정하고 이후 유입 리드는 분석에서 제외한다.
- DATA는 현행 모델과 변경안의 전환 판별 결과를 같은 표본에서 비교한다.
- MQL 임계값 변경은 1회 조정 시 기존 값 대비 ±5점 이내로 제한한다.
- 개별 행동·속성 항목의 배점 변경은 1회당 ±3점 이내로 제한한다.
- 행동·속성 영역 간 가중치 변경은 합계 기준 ±10%p 이내로 제한한다.
- 제한을 넘는 변경은 2개 분기 연속 검증 결과와 SALES 부장 승인을 요구한다.
- 변경안은 DATA 과장 이상과 SALES 과장 이상이 공동 검토한다.
- 적용일은 승인 후 최소 3영업일 뒤로 정하고 모델 버전을 부여한다.

### 과거 리드 재채점과 변경 보류

변경 모델은 적용일 현재 미종결 상태인 리드와 직전 180일 이내 생성된 리드에 재채점한다. 종결된 SQL과 반환 완료 리드는 원점수를 유지하되 검증용 비교 점수만 별도 저장한다. 재채점으로 단계가 바뀌면 담당자에게 변경 사유와 전후 점수를 통지한다.

- 미종결 MQL은 새 임계값에 따라 유지 또는 재검토 대상으로 표시한다.
- 직전 180일 리드는 동일 모델 버전으로 일괄 계산한다.
- 180일을 초과한 기록은 감사·분석 요청이 있을 때만 비교 재채점한다.
- 기존 점수, 새 점수, 모델 버전, 재채점 시각을 함께 보존한다.
- 재채점만으로 SQL을 자동 취소하거나 신규 SQL로 자동 승격하지 않는다.
- 검증 모집단이 100건 미만이거나 SQL 전환이 20건 미만이면 변경하지 않는다.
- 단일 캠페인 유입이 검증 모집단의 40%를 초과하면 캠페인 종료 후 재검증한다.
- 이벤트 누락률이 5%를 초과하거나 중복 병합 오류가 확인되면 조정을 보류한다.
- 단계 정의나 반환 코드가 최근 30일 이내 변경된 경우 안정화 후 검증한다.
- 계절성 행사 기간만으로 전환율이 변한 경우 최소 1개 추가 분기를 관찰한다.
- 보류 사유와 다음 검토일은 모델 변경 기록에 남긴다.

## 자동화 구현 요건과 수작업 보정 범위
<!--meta: sec=s8; dept=DATA|BE; level=시니어; ct_band=상; related=none-->

자동화 시스템은 동일한 입력에 동일한 점수와 단계 판정을 반환해야 한다. BE는 식별·수집·병합 로직을 구현하고 DATA는 점수 산식과 품질 검증 규칙을 관리한다. 원천 로그가 확인되지 않는 추정값은 자동 점수에 포함하지 않는다.

### 데이터와 식별 요건

어카운트, 개인, 행동 이벤트에는 서로 다른 식별 키를 사용하고 연결 관계를 보존한다. 행동 발생 시각과 시스템 수집 시각을 각각 기록해 지연 유입을 구분한다. 개인정보 처리와 보존은 승인된 수집 목적 및 내부 보존 기준을 따른다.

| 데이터 항목 | 필수 필드 | 품질 조건 | 처리 기준 | 기본 보존 기간 |
|---|---|---|---|---|
| 어카운트 식별 | account_id, 지점 귀속 | 활성 레코드 중복률 1% 이하 | 사업자 식별값 또는 승인된 내부 키로 연결 | 관계 종료 후 36개월 |
| 개인 식별 | person_id, account_id | 미연결 비율 3% 이하 | 승인된 식별자 조합으로 동일인 판정 | 마지막 활동 후 24개월 |
| 행동 이벤트 | event_id, event_type | 이벤트 ID 중복률 0.5% 이하 | 중복 이벤트는 최초 정상 건만 반영 | 24개월 |
| 시각 정보 | occurred_at, received_at | 필수 시각 누락률 0.5% 이하 | 한국 표준시로 표시하고 원시 시간대 보존 | 이벤트와 동일 |
| 유입 출처 | source, campaign_id | 미분류 비율 5% 이하 | 출처 미상은 별도 코드로 처리 | 24개월 |
| 속성 정보 | 직책군, 규모 구간, 산업 코드 | 유효값 비율 95% 이상 | 최신 확인값과 확인일 저장 | 갱신 이력 36개월 |
| 동일인 판정 | 이메일·전화 등 승인 식별값 | 충돌 건 자동 병합 금지 | 확정·추정·미확정 3상태로 관리 | 판정 이력 36개월 |
| 중복 병합 | master_id, merged_id | 병합 역추적 가능률 100% | 점수 합산 전 이벤트 중복 제거 | 병합 이력 36개월 |
| 산정 결과 | score, version, calculated_at | 재현 일치율 100% | 입력 스냅샷과 모델 버전 연결 | 36개월 |

### 자동 산정 품질 조건

- 이벤트 수집 성공률은 일 단위 99% 이상으로 관리한다.
- 점수 산정 작업 성공률은 일 단위 99.5% 이상으로 관리한다.
- 정상 수신 이벤트는 30분 이내 점수에 반영한다.
- 지연 수신 이벤트는 발생 시각 기준 감쇠 규칙을 적용한다.
- 동일 이벤트의 재전송은 event_id 기준으로 한 번만 반영한다.
- 병합 해제 시 원래 개인별 이벤트와 점수를 복원할 수 있어야 한다.
- 필수 속성이 없으면 0점 처리하고 임의 평균값을 대입하지 않는다.
- 산정 실패 건은 오류 큐로 분리하고 1영업일 이내 재처리한다.
- 일별 표본 30건 이상을 원천 로그와 대조한다.
- 품질 임계값 미달 시 자동 MQL 승격을 중지하고 담당자에게 알린다.

### 수작업 보정과 사람 판단 항목

1. 사실 정보 정정은 증빙이 확인되면 원천값을 수정해 재산정한다.
   - 사실 정정에는 임의 점수 상한을 두지 않는다.
   - 수정 전후 값과 증빙 위치를 보존한다.
2. 예외 점수 보정은 리드당 합계 ±5점, 1회로 제한한다.
   - 적용 기간은 최대 30일이며 만료 후 자동 원복한다.
   - 보정만으로 SQL을 자동 승격하지 않는다.
3. 결정권자 관여, 예산 확인, 필요의 구체성은 영업 대화로 판단한다.
   - 단순 직책명이나 자료 열람만으로 확인 완료 처리하지 않는다.
   - SQL 승격 요건 충족 여부는 SALES 담당자가 기록한다.
4. 동일인 충돌, 어카운트 귀속 분쟁, 예외적 반환 사유는 사람이 확정한다.
   - 보정자, 보정 시각, 전후 점수, 사유 코드, 근거를 필수 기록한다.
   - 근거가 없는 요청은 반영하지 않고 반려 사유를 남긴다.

### 로직 변경 배포와 공지

산정 로직 변경은 개발·검증·승인·배포 단계를 분리한다. 운영 환경의 직접 수정은 허용하지 않으며 모든 변경에 모델 버전과 배포 이력을 부여한다. 장애 수정이라도 점수 결과가 달라지면 동일한 절차를 적용한다.

1. DATA가 변경 목적, 대상 항목, 예상 영향 범위를 작성한다.
2. BE가 개발 환경에서 단위 검증과 직전 30일 표본 재산정을 수행한다.
3. DATA와 SALES가 임계값 이동 건수와 단계 변경 표본을 확인한다.
4. 승인된 변경은 적용 3영업일 전 담당자에게 공지한다.
5. 배포 후 2영업일 동안 오류율과 단계 변동률을 집중 확인한다.
6. 결과 불일치가 1%를 초과하면 직전 버전으로 되돌린다.

- 공지에는 적용일, 버전, 변경 항목, 영향 대상, 문의 담당자를 포함한다.
- 긴급 배포는 DATA 부장과 BE 부장의 공동 승인을 받는다.
- 긴급 배포 후 1영업일 이내 정식 변경 기록을 보완한다.
- 폐기된 버전의 산식과 배포 파일은 최소 36개월 보관한다.

## 지표 보고 양식과 회의 운영
<!--meta: sec=s9; dept=SALES|DATA; level=주니어|시니어; ct_band=중; related=SLS-01#s9-->

리드 지표는 단계 정의, 집계 기간, 모델 버전, 중복 제거 기준을 함께 표시한다. 주간 보고는 운영 지연과 반환을 확인하고, 월간 보고는 전환 구조와 모델 이상을 확인하는 데 사용한다. 수치만으로 연간 계획을 변경하지 않으며 계획 조정은 SLS-01#s9를 따른다.

### 주간·월간 보고 항목

전환율은 분자와 분모가 동일한 리드 집합과 관찰 기준을 사용해야 한다. MQL→SQL 전환율은 MQL 생성 후 10영업일이 지난 코호트만 확정값으로 표시한다. 관찰 기간이 끝나지 않은 수치는 잠정값으로 구분한다.

| 항목 | 주기 | 산식 | 기준 시점 | 필수 구분 |
|---|---|---|---|---|
| 신규 리드 수 | 주간·월간 | 기간 내 최초 생성된 고유 lead_id 수 | 생성일 | 지점·채널 |
| MQL 생성 수 | 주간·월간 | 기간 내 최초 MQL 승격된 고유 리드 수 | 승격일 | 모델 버전 |
| SQL 생성 수 | 주간·월간 | 기간 내 최초 SQL 승격된 고유 리드 수 | 승격일 | 지점·담당자 |
| MQL→SQL 전환율 | 월간 | 10영업일 내 SQL 승격 MQL 수 ÷ 관찰 완료 MQL 수 × 100 | MQL 코호트 생성일 | 채널·점수 구간 |
| 영업 수락률 | 주간·월간 | 영업 수락 MQL 수 ÷ 영업 검토 완료 MQL 수 × 100 | 검토 완료일 | 수락·반환 |
| 최초 응답 SLA 준수율 | 주간·월간 | 2영업시간 내 응답 MQL 수 ÷ 응답 기한 도래 MQL 수 × 100 | 이관일 | 지점 |
| 무응답 반환율 | 월간 | 접촉 5회 후 반환된 MQL 수 ÷ 접촉 시작 MQL 수 × 100 | 반환일 | 채널 |
| 평균 MQL 점수 | 주간·월간 | MQL 승격 시점 점수 합계 ÷ MQL 수 | 승격일 | 점수 구간 |
| 고득점 무전환율 | 월간 | 80점 이상 SQL 미전환 수 ÷ 관찰 완료 80점 이상 MQL 수 × 100 | 코호트 생성일 | 반환 사유 |
| 반환 사유 비율 | 주간·월간 | 사유 코드별 반환 수 ÷ 전체 반환 수 × 100 | 반환일 | 사유 코드 |

### 보고에서 금지하는 표현과 비교

- MQL과 SQL의 단계 정의가 다른 기간을 하나의 추세선으로 비교하지 않는다.
- 생성일 기준 건수와 월말 상태 기준 건수를 같은 항목처럼 제시하지 않는다.
- 7일 전환율과 10영업일 전환율을 기준 설명 없이 나란히 두지 않는다.
- 고유 리드 수와 행동 이벤트 수를 모두 “리드 수”로 표시하지 않는다.
- 중복 제거 전 지점 합계와 중복 제거 후 전사 합계를 직접 비교하지 않는다.
- 관찰 기간이 끝나지 않은 코호트 전환율을 확정값으로 표현하지 않는다.
- 반환 리드를 제외한 전환율은 제외 조건과 제외 건수를 함께 표시한다.
- 외부 30~40% 벤치마크를 내부 목표 또는 달성 보장값으로 표현하지 않는다.
- 표본 20건 미만의 비율은 단독 결론으로 사용하지 않는다.
- 모델 버전 변경 전후 수치를 보정 설명 없이 증감으로 평가하지 않는다.

### 리드 검토 회의 운영

- 주간 회의는 매주 1회, 30분 이내로 운영한다.
- 월간 회의는 월 종료 후 5영업일 이내, 60분 이내로 운영한다.
- 필수 참석자는 SALES 과장 이상 1명, 지점별 담당자, DATA 담당자다.
- 수집·산정 오류 안건이 있으면 BE 담당자 1명이 참석한다.
- 회의 자료는 시작 4영업시간 전까지 같은 기준 시점으로 배포한다.
- 주간 회의는 SLA 지연, 미처리 MQL, 반환 사유 누락을 우선 확인한다.
- 월간 회의는 점수 구간별 전환율, 오탐·미탐, 채널 편향을 확인한다.
- 회의에서는 데이터 정정, 반환 코드 보완, 표본 리뷰 착수를 결정할 수 있다.
- 담당자 재배정은 어카운트 귀속 기준을 확인한 뒤 결정한다.
- 배점·임계값 변경은 회의에서 즉시 확정하지 않고 s7 절차로 넘긴다.
- 제안·가격 관련 사안은 제안·가격 소관 문서 계열로 이관한다.
- 결정 사항에는 담당자와 완료 기한을 지정하고 다음 회의에서 확인한다.

### 이상치 사전 점검

지표가 전주 또는 전월 대비 20% 이상 변하면 회의 전에 데이터 이상 여부를 확인한다. 비율 지표는 분모가 20건 미만인지 먼저 확인하고, 건수 지표는 영업일 수 차이를 함께 표시한다. 점검 결과는 정상 변동, 데이터 오류, 운영 변경, 정의 변경 중 하나로 분류한다.

- 집계 기간의 시작·종료 시각과 한국 표준시 적용 여부를 확인한다.
- 보고서에 적용된 단계 정의와 모델 버전이 동일한지 확인한다.
- 리드 식별 키 변경이나 중복 병합 작업이 있었는지 확인한다.
- 이벤트 수집 실패와 지연 수신 건수가 임계값을 넘었는지 확인한다.
- 점수 산정 배치의 실패·재실행·부분 완료 여부를 확인한다.
- 단일 캠페인 유입이 전체 신규 리드의 40%를 초과했는지 확인한다.
- 특정 지점이나 채널의 미분류 값이 5%를 초과했는지 확인한다.
- 휴일과 영업시간 설정이 SLA 산식에 정상 반영됐는지 확인한다.
- 감쇠 작업의 실행 시각과 대상 범위가 정상인지 확인한다.
- 단계 상태의 일괄 수정이나 과거 데이터 소급 입력이 있었는지 확인한다.
- 반환 사유 미입력 건과 임시 코드 사용 건을 확인한다.
- 점검 근거와 재산출 결과를 회의 자료에 첨부한다.
