# corpus 적응성 (Corpus Adaptability)

**이 문서가 증명하려는 것**: 우리 면접 질문의 재료는 **살아 있는 corpus**이고, 기업의 정책·스펙·조직이 바뀌어도 **사람이 질문을 다시 쓰지 않고** 따라간다. 그걸 말이 아니라 **측정치**로 보인다.

측정 결과 원본은 `eval_runs/corpus_adaptability_2026-11-17/`에 있다.

## 1. 문제 — 정적 엑셀 질문뱅크는 기업 환경에서 낡는다

| | 정적 엑셀 질문뱅크 | RAG corpus (지금 방식) |
|---|---|---|
| 질문의 출처 | 엑셀 행에 **박아 넣은 완성 질문** | 사내문서(정책·직무기술서·프로젝트·회고) **원본** |
| 회사 정책이 바뀌면 | 사람이 엑셀을 열어 **해당 질문을 찾아 고친다** → 번역도 다시, 적재도 다시 | **문서 파일만 바뀌면 끝** — 적재 파이프라인이 바뀐 문서를 찾아 자동 반영 |
| 갱신 주기 | 비즈니스가 움직이는 속도를 사람이 따라가야 함(현실적으로 밀린다) | 문서가 바뀔 때마다(= 비즈니스가 바뀔 때마다) |
| 메타데이터 | 열을 새로 만들고 전 행을 손으로 채워야 함. 검색 축으로 쓸 수 없음 | 공개 등급·상태·문서 종류·부서·카테고리로 **거르고 순위를 매긴다** |
| 비용 | 변경 1건에도 사람이 질문을 **새로 쓴다** | 바뀐 문서 조각만 재계산 — 실측 **1.46~3.66%** |

핵심은 **"질문을 관리한다"에서 "회사 문서를 관리하면 질문이 따라온다"로 바꾼 것**이다. 회사는 어차피 문서를 관리한다 — 그 문서가 곧 질문의 재료가 된다.

> **과장하지 않기**: 엑셀 질문뱅크도 **적재·번역은 이미 자동**이다(행 해시 증분). 진짜 차이는 두 가지다.
> ① **변경 지점을 누가 찾나** — corpus는 해시로 시스템이 찾고, 엑셀은 사람이 235문항 중 영향받는 문항을 찾아야 한다(문항과 출처 문서가 연결돼 있지 않다).
> ② **질문 문장을 누가 쓰나** — corpus는 **0개**(문서는 담당자가 평소 업무로 고친다), 엑셀은 **문항 수만큼 사람이 새로 쓴다.** 이 구간이 자동화 불가 지점이다.
> 그 밖에 거버넌스 메타데이터(공개 등급 4단계·상태·부서·난이도·문서 종류 47종)는 엑셀 쪽에 **공개 범위 개념 자체가 없다.**

## 2. 증명 — 세 가지 변수를 실제로 흔들어 봤다

실제 운영 corpus를 건드리지 않도록 **격리된 복사본**(별도 문서 폴더 + 빈 벡터 저장소)에서 측정했다.

| 변수 | 무엇을 바꿨나 | 기대 동작 |
|---|---|---|
| **V1 문서 개수** | 80개 기준에서 **추가(+)·삭제(−)** | 추가분만 적재, 기존 문서 재계산 0, 삭제분은 검색에서 사라짐 |
| **V2 문서 제목·종류** | 문서의 종류(`doc_type`)·제목 변경 | 메타데이터가 자동 갱신되고 **코드 수정 없이** 카테고리·가산점이 따라 바뀜 |
| **V3 문서 안 내용** | 정책 수치·절차 한 줄을 **다른 값으로** 수정 | **바뀐 문서만** 재계산, 같은 질문에 **새 내용**이 나옴, sync 1회로 끝 |

### 2.1 측정 결과

**측정 완료 — 2026-11-17 10:45~10:58 (13분).** 실제 운영 corpus·운영 Redis를 건드리지 않은 **격리 복사본**(별도 문서 폴더 + 빈 Chroma + Redis db9)에서 측정했다. 측정 전·후 모두 `questionbank/` 변경 0건·운영 컬렉션 3개 그대로 확인.

### 2.3 V3에서 드러난 한계 — 원인을 정정한다 (2026-11-17 재측정)

**"바뀐 문장이 검색 결과로 올라오는가"는 통과하지 못했다.** 다만 **처음에 적은 원인은 틀렸고, 재측정으로 바로잡는다.**

| | 처음 결론(11-17 오전) | **재측정 결과(11-17 오후)** |
|---|---|---|
| 원인 | 섹션(약 1,000자) 벡터에서 **한 줄이 희석**되어 유사도 하한(0.55)에 못 미친다 | **틀림.** 수정 조각은 하한을 **넘었다** — 0.7244·0.6813(각각 +0.17·+0.13 여유) |
| 실제 차단 지점 | — | **문서당 조각 수 상한 `MAX_PER_DOC=2`**(질의 3개) · **컨텍스트 글자 수 상한 `MAX_CHARS=2000`**(질의 1개) |

무슨 일이 벌어진 것인가 — **후보가 전부 같은 문서였다.**

| 질의 | 수정 조각 순위 | 유사도 | 왜 빠졌나 |
|---|---|---|---|
| Q01 | 하한 통과 후보 12개 중 **4위** | 0.7244 | 후보 12개가 **전부 같은 문서** → 문서당 2개 상한에서 잘림 |
| Q03 | **4위** | 0.6813 | 같은 이유 |
| Q11 | 5위 | 0.6034 | 글자 수 상한(1,598+657 > 2,000) |
| Q14 | 10위 | 0.5580 | 같은 문서 10번째 |

**하한을 낮추는 건 해법이 아니다** — 0.300까지 내려도 15질의 합쳐 **조각 2개**만 더 들어오고, 수정 조각은 **어떤 임계값에서도 상위에 못 든다**(솎기에서 막히므로). 반대로 0.600으로 올리면 조각이 31→21개로 줄고 **결과 0건 질의가 2개** 생긴다. → **0.55는 이미 적정값이므로 바꾸지 않는다.**

**상한을 푸는 것도 해법이 아니다** — 네 질의를 다 살리려면 문서당 상한을 4~10으로, 글자 수를 2,806자까지 동시에 풀어야 하고, 그러면 컨텍스트 2,000자 설계가 통째로 바뀐다.

> **진짜 현상은 '다양성 부족'이다.** Q01·Q03은 후보 12개가 모두 한 문서라, 최종 컨텍스트가 2,000자 상한의 **46~57%(924~1,143자)밖에 안 찬다.** "상한이 좁다"가 아니라 **"다양성이 없어 상한을 못 채운다"**가 맞다.

**개선 후보 재평가**

| 안 | 재측정 후 판정 |
|---|---|
| ⓐ 문단·문장 보조 조각 | **역효과 가능** — 같은 문서를 더 잘게 쪼개면 후보를 그 문서가 더 독점하고, 문서당 2개 상한에서 어차피 깎인다 |
| ⓑ 유사도 하한 낮추기 | **접는다** — 원인이 아니었음이 숫자로 확인됨 |
| **ⓒ 바뀐 조각에서 질문 재생성** | **추천(더 강해짐)** — 조각을 **통째로 읽어** 질문을 만들므로 솎기 자체를 거치지 않는다. 단 **`select_chunks`가 문서당 긴 조각 5개만 골라** 수정 섹션이 탈락하는 결함을 먼저 고쳐야 한다(실측: `JD-DATA-01`의 수정 섹션은 길이 8위/30 → 탈락) |
| (신규) 후보 수 `K=12` 확대 | 미측정. 다양성 문제를 직접 건드리므로 문서당 상한 완화보다 안전한 방향 |

### 2.4 측정 중 발견한 운영 문제 2개 (적응성과 별개, 조치 필요)

1. **지금 도는 api 컨테이너는 11-13 이전 코드다** — 금지 용어 사전·감사 게이트·마스킹 코드가 없다(모듈 import 자체가 실패). 그래서 이 측정도 호스트 코드 복사본으로 돌렸다.
2. **운영 Redis에 금지 용어 사전 키가 0개**다 → 운영 경로의 사내문서 RAG 준비 상태(`rag_ready()`)가 **닫혀 있다.** api를 재빌드할 때 `internal_docs_agent forbid`(또는 ingest/sync)를 같이 돌려야 한다.

### 2.2 이미 확정된 뒷받침 수치 (2026-11-16 측정)

| 수치 | 뜻 |
|---|---|
| 문서 148개 중 변경 0건 → **재임베딩 0회, 31초** (전체 적재는 1,841조각·929초) | **바뀐 게 없으면 비용도 0.** 원본 해시 비교가 제대로 작동한다 |

## 3. 한계 — 솔직히 적는다

| 한계 | 내용 |
|---|---|
| 문서를 **누가 갱신하나** | 파이프라인은 "문서가 바뀌면 자동 반영"까지다. 문서 자체를 최신으로 유지하는 건 기업의 몫이다 |
| 반영 시점 | 파일이 바뀌는 즉시가 아니라 **적재 명령(sync)이 돌 때**다. 주기 실행은 아직 설정하지 않았다 |
| 질문 품질 | 문서가 최신이어도 **문서 → 질문으로 바꾸는 단계**가 실패하면 옛 질문으로 되돌아간다(2026-11-16 실측 8/20) — 개선 중 |
| 측정 규모 | 아래 측정은 격리 복사본에서 한 것이고, 운영 규모(공개 2,235조각) 전체를 매번 흔들어 본 것은 아니다 |
