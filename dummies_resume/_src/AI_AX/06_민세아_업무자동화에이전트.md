## 민세아 | 사내 업무 자동화 에이전트 개발자

> 회계와 영업 쪽 반복 업무를 에이전트 워크플로로 옮기는 일을 3년 넘게 했습니다. 전부 자동으로 넘기지 않고 금액·거래처 기준으로 사람 승인을 거치게 설계했고, 에이전트가 판단을 못 하는 건은 담당자 큐로 넘기는 조건을 수치로 정해 운영했습니다.

### 경력

**브릿지웍스 경영지원DX팀 · 백엔드·자동화 개발자 (정규직)** · 2023.03–2026.10 · 3년 8개월
사내 구성원 400여 명이 쓰는 업무 시스템에 자동화를 붙이는 일을 2명이 담당. 업무 흐름 설계와 사내 시스템 연동이 제 담당이었습니다.

- **업무 에이전트 구현** · Python·FastAPI로 처리 서버를 만들고, LangGraph로 '문서 읽기 → 대조 → 판단 → 승인 요청 → 반영' 흐름을 그래프로 구성. 사람 승인이 필요한 지점에서 실행을 멈추고 상태를 저장한 뒤, 승인 결과가 들어오면 이어서 진행하도록 체크포인트를 PostgreSQL에 둠. 판단 분기마다 pytest로 승인·반려·예외 경로를 고정해 두고, 코드와 업무 규칙 문서를 Git으로 같이 관리.
- **사내 시스템 연동 · 운영** · 그룹웨어 결재 API, CRM API, Slack 알림, 사내 저장소를 연동하고 긴 작업은 Celery·Redis 큐로 분리, 배포는 Docker 이미지로 함. 모델은 OpenAI API를 기본으로 쓰고 개인정보가 섞인 문서는 사내 vLLM(Llama 3 8B)으로 보내도록 경로를 나눔.

### 대표 프로젝트 ① 지출 증빙 대조 에이전트와 승인 단계 설계

**현장 문제** · 지출 신청 건마다 담당자가 영수증·세금계산서 PDF를 열어 **금액·날짜·거래처·계정 과목을 눈으로 대조**했습니다. 월 2,400건이라 마감 주에는 다른 일이 멈췄습니다.

- **본인 역할** · 첨부 문서에서 금액·날짜·사업자 번호를 뽑아 신청 내역과 대조하는 흐름을 만들고, 네 항목이 모두 맞고 조건을 넘지 않는 건만 자동 통과시키도록 구성. **사람 승인 기준은 담당자와 정해 수치로 고정** — 50만 원 초과, 신규 거래처, 문서에서 항목을 못 뽑은 건은 무조건 담당자 확인으로 보냄.
- **검증 방법** · 처음 4주는 자동 판정을 적용하지 않고 **담당자 판정과 나란히 기록만** 해 어긋난 건을 모았고(불일치 63건을 유형별로 분류), 사업자 번호가 도장에 겹쳐 안 읽히는 유형을 찾아 그 유형은 자동 통과 대상에서 제외한 뒤 적용.
- **성과** · ① 자동 통과 비율 **0% → 71%**(월 2,400건 기준). ② 담당자 1건 처리 시간 **4분 12초 → 1분 05초**. ③ 반대 지표: 사후 감사에서 반려된 건 비율이 사람 전수 확인 때 **0.8% → 0.6%** 로, 자동화 뒤에도 늘지 않았음을 두 분기 비교로 확인.

### 대표 프로젝트 ② 영업 문의 메일 분류·배정 워크플로

**현장 문제** · 대표 메일로 들어온 문의를 영업 담당자가 돌아가며 읽고 CRM에 손으로 옮겨, **문의가 몰리는 날은 첫 응답이 다음 날로 넘어가고** 중복 등록도 생겼습니다.

- **본인 역할** · 메일을 요약·분류해 CRM에 리드를 만들고 담당자를 배정하는 워크플로를 구현. 분류 근거(문의 유형·업종·규모)를 리드에 함께 적어 담당자가 왜 그렇게 배정됐는지 볼 수 있게 하고, 확신이 낮은 건은 **담당자 큐로 넘겨** 사람이 고르게 함.
- **현장 예외 처리** · ⓐ 본문 없이 첨부만 보내는 메일은 첨부에서 본문을 뽑아 처리하고, 그래도 비면 큐로 보냄 ⓑ 같은 회사 도메인에서 72시간 안에 들어온 메일은 한 리드로 묶는 규칙을 넣어 중복 등록을 막음 ⓒ CRM API 오류로 등록이 실패한 건은 재시도 3회 후 Slack으로 담당자를 호출.
- **성과** · 8주 운영(영업일 기준) 중위 첫 응답 시간 **5시간 20분 → 48분**, 중복 리드 **주 평균 11건 → 1건**. 분류 정확도는 표본 **400건을 담당자가 검수**해 88%였고, 애매한 건 **14%는 의도적으로 큐로 넘겨** 잘못 배정된 리드 재배정률을 **6.2% → 3.1%** 로 낮춤.

### 인턴

**업무 시스템 구축 회사 · 운영 지원 인턴** · 2022.07–2022.12 · 6개월
- 고객사 결재 양식 전환 작업에서 입력 값 검사 규칙을 정리하고, 전환 실패 건을 원인별로 표로 만들어 담당자에게 전달.

### 학력 · 캡스톤

**국민대학교 경영정보학부 학사** · 관련 과목: 데이터베이스, 업무 프로세스 관리, 프로그래밍 기초

**학부 캡스톤 (4인 팀) · 동아리 회계 정산 도우미** · 2022년 2학기
- 영수증 사진에서 금액·날짜를 뽑아 정산 표에 채우는 부분을 맡고, 값이 안 읽히면 빈칸으로 두고 사람이 채우게 표시.
- 같은 영수증을 두 사람이 올려 중복 집계되는 문제를 찾아, 금액·날짜·가게 이름이 같으면 확인을 띄우도록 고침.
