## 윤세린 | LLM 응용 · 상담 에이전트 엔지니어

> 보험 콜센터의 상담 기록과 약관 문서를 근거로 답하는 사내 상담 에이전트를 3년 넘게 개발·운영했습니다. 검색을 BM25와 벡터 두 갈래로 나눠 재순위까지 붙이고, 모델이나 지시문을 바꿀 때마다 같은 평가셋으로 다시 재는 회귀 평가를 야간 배치로 자동화했습니다.

### 경력

**코어브릿지랩 AI플랫폼팀 · LLM 엔지니어 (정규직)** · 2023.04–2026.11 · 3년 8개월
상담 에이전트 백엔드를 2명이 나눠 담당. 모델 학습은 하지 않고 오픈소스 LLM을 그대로 서빙했으며, 검색·도구 호출·평가가 제 담당이었습니다.

- **검색·생성 서버** · Python·FastAPI로 상담 질의 처리 API를 만들고, 오픈소스 8B 모델을 vLLM으로 서빙. 임베딩·재순위 모델은 별도 Docker 컨테이너로 분리해 모델을 바꿀 때 생성 서버를 멈추지 않게 함.
- **도구 호출** · 보험금 지급 내역 조회처럼 문서로 답할 수 없는 질문은 사내 API를 호출하도록 JSON Schema로 응답 형식을 고정하고, 스키마를 벗어난 응답은 되묻기 1회 후 상담원 연결로 넘김.

**세움데이터 검색서비스팀 · 백엔드 엔지니어 (정규직)** · 2021.09–2023.03 · 1년 7개월
- 상품 문서 검색 API를 담당. Elasticsearch 색인 설계와 동의어·형태소 사전 운영을 맡아, 상담원 검색어 로그에서 0건 결과가 나오는 질의를 모아 사전에 반영.

### 대표 프로젝트 ① 상담 기록·약관 하이브리드 검색과 재순위 도입

**현장 문제** · 벡터 검색만 쓰던 초기 버전은 "무배당 특약 해지 환급금"처럼 **약관 고유 용어가 들어간 질문에서 엉뚱한 조항을 근거로 가져오는 일**이 가장 잦았습니다. 상담원이 근거 문서를 직접 열어 확인하느라 답변을 신뢰하지 않는 상태였습니다.

- **본인 역할** · Elasticsearch BM25 검색과 PostgreSQL·pgvector 벡터 검색을 따로 돌린 뒤 순위를 합치고(RRF), 상위 20건을 cross-encoder 재순위 모델로 다시 정렬해 5건만 생성에 넣도록 파이프라인을 다시 짬.
- **검증 방법** · 2025년 3~5월 상담 기록에서 상담 유형 12종을 고르게 뽑아 **420문항 평가셋**을 만들고, 각 문항에 정답 근거 조항을 사람이 달아 둠. 같은 고객 문의가 여러 번 들어온 건은 한 문항만 남겨 중복으로 점수가 부풀지 않게 함.
- **성과** · ① 근거 포함률(Recall@5) **71% → 89%**. ② 근거 없이 답한 비율 **12.4% → 4.1%**. ③ 반대 지표: 평균 응답 지연 **1.9초 → 2.3초**로 늘었지만 운영 기준 3초 안에 유지, 재순위 모델을 끄는 설정을 남겨 둠.

### 대표 프로젝트 ② 답변 품질 회귀 평가 자동화

**현장 문제** · 지시문이나 모델 버전을 바꿀 때마다 담당자가 질문 20~30개를 손으로 넣어 눈으로 비교했고, 그래서 **품질이 떨어진 변경을 배포한 뒤에 상담원 항의로 알게 되는 일**이 반복됐습니다.

- **본인 역할** · 420문항 평가셋을 야간 배치로 돌려 근거 포함률·근거 없는 답변 비율·응답 지연을 매일 기록하고, 직전 기준선보다 지표가 떨어지면 배포 파이프라인(GitHub Actions)이 멈추게 연결. 답변 채점은 근거 조항 일치 여부로 기계적으로 계산하고, 문장 품질은 사람이 표본 30건만 확인하도록 나눔.
- **현장 예외 처리** · 약관이 개정되면 과거 정답 근거가 사라져 지표가 통째로 떨어지는 문제를 발견. 평가셋 문항에 약관 개정 차수를 달아, 개정된 조항을 쓰는 문항은 자동으로 보류 처리하고 담당자가 정답을 다시 달도록 함.
- **성과** · 품질이 떨어진 변경을 발견하기까지 평균 **6일 → 1일 이내**(8주 운영 기준), 배포 전 수동 검토 시간 **3시간 → 25분**.

### 인턴

**커머스 데이터 스타트업 · 검색 개선 인턴** · 2021.01–2021.06 · 6개월
