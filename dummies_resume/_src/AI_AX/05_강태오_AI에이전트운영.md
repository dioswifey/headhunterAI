## 강태오 | AI 에이전트 서비스 엔지니어 (평가 · 관측 · 최적화)

> 사내 시스템을 도구로 호출하는 여러 단계 에이전트를 Python으로 만들어 3년 넘게 운영했습니다. 에이전트가 왜 실패하는지 트레이스로 분해해 실패 유형별 회귀 평가셋을 만들었고, 모델 라우팅과 캐싱으로 응답 비용과 지연을 절반 수준으로 내리면서 과업 성공률은 지키도록 임계값을 정했습니다.

### 경력

**노바링크테크 AI플랫폼그룹 · AI 에이전트 엔지니어 (정규직)** · 2023.03–2026.11 · 3년 9개월
사내 구성원이 쓰는 업무 에이전트(문서 조회·일정 조정·티켓 처리)를 3명이 담당. 에이전트 실행 흐름과 운영 지표가 제 담당이었습니다.

- **에이전트 실행 흐름** · LangGraph로 '계획 → 도구 호출 → 결과 검토 → 응답' 단계를 상태 그래프로 짜고, 도구는 사내 API를 FastAPI 래퍼로 감싸 JSON Schema로 인수를 검증한 뒤 호출하고, 프롬프트·출력 파서는 LangChain 구성 요소로 조립. 모델은 OpenAI API·Claude API와 사내 vLLM 서빙(Llama 3 8B)을 같은 인터페이스로 바꿔 끼울 수 있게 함.
- **운영 · 배포** · 실행 단계마다 LangSmith 트레이스와 OpenTelemetry 지표를 남기고, 도구 응답은 Redis에 캐싱. 배포는 Docker 이미지로 올리고 GitHub Actions에서 회귀 평가를 통과한 커밋만 나가게 연결.

**크로스비트 플랫폼개발팀 · 백엔드 엔지니어 (정규직)** · 2021.08–2023.02 · 1년 7개월
- 사내 승인·알림 API를 담당. PostgreSQL 스키마 설계와 pytest 기반 회귀 테스트를 맡아, 승인 단계가 바뀔 때마다 기존 흐름이 깨지지 않는지 확인하는 테스트를 늘려 나감.

### 대표 프로젝트 ① 에이전트 실패 유형 분류와 회귀 평가 체계

**현장 문제** · "에이전트가 엉뚱한 일을 한다"는 신고는 많았지만 **무엇이 틀렸는지 재현할 방법이 없어**, 지시문을 고치고 나아진 것 같다고 넘기는 일이 반복됐습니다.

- **본인 역할** · 2개월치 실행 트레이스 1,900건을 단계 단위로 읽어 실패를 유형화. 도구 호출 인수 오류 38%, 조회 대상 오인 24%, 같은 도구 반복 호출 9%, 중간 결과 무시 11%가 나와 유형별로 시나리오를 뽑아 **260개 회귀 평가셋**을 만들었습니다. 채점은 최종 문장이 아니라 '호출한 도구와 인수가 기대와 같은지'로 기계 판정하고, 문장 품질은 표본 40건만 사람이 봄.
- **검증 방법** · 같은 사용자 요청이 여러 번 들어온 건은 한 시나리오만 남겨 점수가 부풀지 않게 하고, 평가셋을 만든 기간(2025.04~05)과 겹치지 않는 2025.06 트레이스로 한 번 더 확인해 과적합을 점검.
- **성과** · ① 과업 성공률 **61% → 84%**(260 시나리오 기준). ② 도구 인수 검증 실패 **12.6% → 2.9%**. ③ 반대 지표: 평균 실행 단계 수 **7.4 → 6.1**로 줄었지만 복잡한 요청에서 단계가 모자라 실패하는 사례가 없는지 유형별로 따로 확인.

### 대표 프로젝트 ② 모델 라우팅·캐싱으로 비용·지연 줄이기

**현장 문제** · 모든 요청을 가장 큰 모델로 처리해 **월 비용이 계속 늘고, 간단한 조회도 10초 넘게 걸려** 사내에서 "느려서 직접 찾는 게 빠르다"는 말이 나왔습니다.

- **본인 역할** · 요청을 도구 호출 개수·문서 조회 필요 여부로 분류해 소형·대형 모델로 나눠 보내는 라우팅을 넣고, 같은 질문의 프롬프트 캐싱과 도구 응답 캐싱(Redis, 유효 10분)을 함께 적용. 라우팅 임계값은 회귀 평가셋을 돌려 **성공률 하락 1%p 이내**를 조건으로 정함.
- **현장 예외 처리** · 소형 모델로 간 요청 중 도구를 2개 이상 엮어야 하는 건에서 인수를 틀리는 사례를 발견해, 도구 두 개 이상이 필요한 요청은 분류 결과와 무관하게 대형 모델로 보내도록 예외를 둠.
- **성과** · 8주 운영(요청 수 비슷한 기간 비교) 기준 월 모델 비용 **1,180만 원 → 520만 원**, p95 응답 **11.2초 → 6.4초**, 반대 지표인 과업 성공률은 **84% → 83%**로 1%p 안에서 유지.
