## 오예린 | 상담 품질 지표 · 실험 분석가

> 커머스 고객센터의 상담 로그로 품질 지표를 정의하고 매일 산출되게 만들었습니다. 상담원이 손으로 달던 '해결' 태그를 재문의 기준으로 바꿔 실제 수준을 드러냈고, 챗봇 답변 화면 변경을 A/B 테스트로 검증해 재문의율 감소를 확인했습니다.

### 경력

**하루리테일 고객경험데이터팀 · 데이터 분석가 (정규직)** · 2024.02–2026.10 · 2년 9개월
고객센터(상담원 60여 명)와 챗봇을 함께 보는 지표를 분석가 2명이 담당. 지표 정의와 실험 설계가 제 담당이었습니다.

- **지표 산출 · 공유** · 상담 로그와 주문 데이터를 PostgreSQL에서 SQL로 묶고 Python·pandas로 가공해 일·주 단위 지표를 산출하고, Airflow로 매일 07:00 갱신되게 적재. 상담 품질 대시보드는 Metabase로 만들어 CS팀 주간 회의에서 함께 봄.
- **분석 요청 대응** · "특정 유형 문의가 늘었다" 같은 모호한 요청을 측정 가능한 질문으로 바꿔 Jupyter 노트북에서 분석하고(쿼리·노트북은 Git으로 관리), 결과는 그래프 2~3장과 다음 행동 제안으로 정리해 CS·제품팀에 전달.

### 대표 프로젝트 ① 상담 해결률·재문의율 지표 재정의

**현장 문제** · 기존 해결률은 **상담원이 종료할 때 직접 고르는 태그**로 집계돼 팀마다 기준이 달랐고, 수치가 91.3%로 높게 나와 "지표는 좋은데 고객 불만 소리는 그대로"라는 상태였습니다.

- **본인 역할** · 해결을 '종료 후 72시간 안에 같은 고객이 같은 유형으로 다시 문의하지 않음'으로 다시 정의. 같은 고객의 재문의를 찾기 위해 주문 번호·문의 유형 코드로 상담을 묶는 SQL을 짜고, 수동 태그와의 차이를 유형별로 비교해 표로 남김.
- **검증 방법** · 새 정의가 맞는지 확인하려고 상담 기록 **표본 300건을 두 사람이 따로 읽어** 해결/미해결을 판정하고(판정 불일치 28건은 함께 다시 읽음), 그 판정과 새 지표가 어긋나는 사례를 모아 72시간 기준·유형 코드 묶음 규칙을 두 차례 고침.
- **성과** · ① 실제 해결률이 수동 태그 기준 **91.3% → 재문의 기준 68.4%** 로 드러나 개선 과제 우선순위가 바뀜. ② 월간 지표 산출이 엑셀 수작업 **2일 → 일배치 자동 갱신**. ③ 지표 정의 문서를 공유한 뒤 부서 간 수치 불일치 문의 **월 12건 → 2건**.

### 대표 프로젝트 ② 상담 실패 유형 분류와 챗봇 답변 A/B 테스트

**현장 문제** · 챗봇을 거친 뒤 상담원으로 넘어오는 문의가 많았지만, **어떤 문의에서 챗봇이 실패하는지 분류 기준이 없어** 개선 요청이 "챗봇이 부정확하다"로만 전달됐습니다.

- **본인 역할** · 3개월치 챗봇 대화 3만 2천 건에서 **표본 1,200건을 직접 읽어 실패 유형 7종**으로 분류. 라벨링 결과는 pandas·NumPy로 집계했고, 상위 2종(상품 조건 오안내·반품 규정 혼동)이 전체 실패의 42%였고, 두 유형 모두 조건을 문장으로만 길게 답하는 공통점이 있어 답변에 조건 요약 카드를 붙이는 변경을 제품팀에 제안.
- **실험 설계** · 주 지표는 재문의율, 반대 지표는 대화 이탈률로 미리 정하고, 검정력 0.8·최소 탐지 차이 2%p로 필요한 표본 크기를 먼저 계산해 **2주·사용자 18,400명을 반반** 배정. 중간에 결과를 보고 멈추지 않도록 종료 시점을 사전에 고정.
- **성과** · 재문의율 **14.2% → 11.6%**(차이 2.6%p, 95% 신뢰구간 1.4~3.8%p, SciPy 카이제곱 검정 p < 0.01, 비율 차이 구간은 statsmodels로 계산), 반대 지표인 대화 이탈률은 **7.1% → 7.3%**로 통계적으로 유의한 차이가 없어 악화 없음을 함께 보고.
